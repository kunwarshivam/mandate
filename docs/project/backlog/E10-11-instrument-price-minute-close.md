- **E10-11 An instrument's price from its latest trusted minute bar (follow-up to [DEC-2152](../decisions/DEC-2152.md); lane SC).** `GET /instruments/{id}/price` serves only the last completed session's trusted daily close, because `mandate-bars`' minute reader (`trailing_minutes`) hands out volumes, not closes. During the regular session the alpaca-iex root also holds minute generations, so a fresher close exists. *Accepted when:* `mandate-bars` gains a minute reader that hands out the last complete one-minute bar's close under the same trust rule as `trailing_minutes` (the symbol's one-minute dataset, no problem or duplicate under `inspect`), tests first and with zero missed mutants, since the crate is safety-critical; and the price read serves it as `timeframe` `1Min` when one is admitted at the API's clock, otherwise the daily close as now. The change is a spec PR for `read-models/instrument-price`'s `timeframe` enum and §3.11 item 11, then the code.
