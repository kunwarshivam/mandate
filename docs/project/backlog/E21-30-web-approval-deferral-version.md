- **E21-30 debt (DEC-2515 item 5): the approval read names its version, so the web app can tell a version 3 request missing its deferred checks from a version 1 or 2 request.** The workspace API's approval read (`GET /approvals/{approval}`) serves the request's `content` but no `schema_version`. `web/src/lib/deferred-checks.ts` therefore reads an absent `deferred_to_binding` as nothing deferred, which is right for versions 1 and 2. A version 3 request without the list is refused by the journal (§9.6 version 3), and rule 292 ties it to its decision within a batch. Across batches (`E21-30-approval-deferral-range-check`), a split writer could still have it served, and the screen would then show no disclosure rather than say it cannot tell. The fix: serve the request's `schema_version` beside `content` (workspace API spec, read model and schema), and have the screen treat a version 3 request without its list as unreadable, which offers Skip only.
