- **E8-17 debt (DEC-2351 item 4): the journal checks stream rule 264 at append.** The deployment manager writes `kill_switch_unapplied` only for a crash loop it reads as unapplied, and `mandate-deploy-manager/tests/unapplied_vectors.rs` holds its reading to the vectors' `kill_switch_unapplied` streams. But `mandate-journal` does not judge rule 264: an `OwnerAlertSent` of that kind naming an ordinary loop, a start, or another process's loop is admitted from any writer. Fold the control stream's held runs in `mandate-journal` as rule 264 states, refuse such an alert `Invalid` at `payload.subject`, and turn the section's streams into append tests, with an independent oracle and each seeded bug caught. When it lands, note one race it exposes: the manager decides a loop is unapplied from the stream as of its last read, and `PgControl::append` takes the head at append time, so an `AgentDeployed` committed in between makes the loop ordinary by rule 264 and its batch would then be refused, halting the pass until the next read. The manager should re-decide from a fresh read on that refusal rather than halt. Size S.
