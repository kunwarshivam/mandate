## Context

`mandate-gateway` is pure: it reaches a model only through its `Transport` trait, and every test
and recorded-response run uses `fake::RecordedTransport`. The inference spec (§3.4, §8.2) says what
an attempt may do; nothing yet sent one over HTTPS. Each item below is a reading of the inference
spec and DEC-998 for that transport, not a change to either.

## Decision

1. **A crate of its own.** `mandate-gateway-http` holds the HTTPS transport, beside
   `mandate-gateway` the way `mandate-sources-http` sits beside `mandate-sources`. It is impure
   (`reqwest`, `rustls`, `tokio`), layer 7, and safety-critical, because it carries the provider key
   (credential handling, AGENTS.md's safety-critical list). Nothing in the trading path depends on
   it, and the gateway stays pure.
2. **Not wired to a live endpoint.** No binary, config, or default builds it in this change. It is
   wired only when DEC-998 item 8 holds (the meter stream is journaled) and DEC-997 is Accepted;
   until lane V2's `SecretSource` lands (#1458) the only key source is `NoKeys`, so a hosted call
   ends `credential_invalid` and sends nothing even if it were wired.
3. **One attempt, synchronously.** `Transport::send` is synchronous, so the transport owns a
   current-thread tokio runtime and drives each attempt on a scoped thread of its own. A caller that
   is itself inside a tokio runtime, `spawn_blocking` included, therefore never meets tokio's
   nested-runtime panic. The workspace's `reqwest` keeps its features (no `blocking`).
4. **Only the allowlisted host, over HTTPS.** The URL is `https://` + the request's `host` + its
   `path`, and is sent only if the host is a lowercase DNS name or IPv4 address with an optional
   port from 1 to 65535, and the URL parses back to exactly that host, port, and path. An explicit
   default port (`:443`) is refused too, since the parser drops it; an endpoint names the bare host.
   A path the
   parser would split or rewrite (a query, a fragment, a backslash, a space, a non-ASCII byte, a
   `..` segment, or no leading `/`) is therefore refused before a byte is sent, never sent changed
   (the gateway already checked the host against the egress allowlist; this keeps the transport
   from reinterpreting it). No proxy is used, so no second host ever sees the request (§8.2), and
   no redirect is followed, so a 3xx is a status, not a second host.
5. **Which failures retry.** A request refused before sending, or a connection or TLS handshake
   that failed, is `ConnectFailed`, which the gateway may retry: nothing reached the provider. A
   request refused for its host, path, or key is refused the same way on each retry, so its
   retries send nothing either. The client keeps no idle connection between attempts, so an
   attempt never reuses a connection the server closed and fails after sending. Any
   failure once the request may have reached it (a timeout, a reset mid-response, a body that
   cannot be read whole) is `TimedOut`: an attempt of unknown cost that settles at the
   reservation's maximum and is never retried (DEC-998 item 12b).
6. **The deadline.** An attempt is given only the time left before its deadline; with none left it
   is `TimedOut` and nothing is sent. The response is read inside the same budget.
7. **A body cap.** A response body over 4 MiB (far above any reply `max_output_tokens` allows) is
   not read further, and the attempt is `TimedOut` (unknown cost).
8. **`Retry-After`.** Only the delay-seconds form is read, as milliseconds; an HTTP date or anything
   else is ignored, and the gateway then waits its default (§3.4).
9. **The key.** It is sent only as `Authorization: Bearer`, on a header marked sensitive; a local
   endpoint sends none. A key that cannot be a header value is refused before sending. The key
   never appears in a `Debug` output, an error, or a log.
10. **Trust.** Production trusts the platform's roots (reqwest's default verifier). Tests trust only
    a certificate authority they generate, through `TlsRoots::Only`, and a test checks that the
    platform roots refuse that test server.
11. **Test certificates.** The tests generate their certificate authority and server certificate
    at run time with `rcgen` (a dev-dependency, `ring` backend, no default features), so no private
    key is ever committed.

## Rationale

Each item keeps the transport to the one host the gateway allowed and to the attempt budget the
gateway reserved for. Item 5 is the safe split of the inference spec's retry rule: a failure is
retried only when nothing can have been billed, so a call never settles above its reservation.
Item 3 removes the one way a synchronous trait over an async client could panic in a caller.

## Alternatives considered

- **reqwest's `blocking` client.** Rejected: it changes a workspace dependency's features for one
  crate, and it panics when called from inside a tokio runtime, which item 3 avoids.
- **An async `Transport` in the gateway.** Rejected for now: it would make the pure crate depend on
  an executor model and change every test; the gateway's callers are synchronous.
- **A committed test certificate and key.** Rejected: a committed private key trips the secret scan
  and teaches the next change that keys in the tree are fine.
- **Mapping every failure to `ConnectFailed`.** Rejected: a failure after the request was sent may
  have been billed, and retrying it could settle a call above its reservation.
