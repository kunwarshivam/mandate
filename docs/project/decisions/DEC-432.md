## Decision

The [inference spec](../../specs/inference.md) v0.1 is the draft contract for every model call and
the model gateway. It restates DEC-67 (no substitution), DEC-04 (opinions only), DEC-120 (the
research cost cap), and HLD §9 and §10, and adds these readings.

**Accepted (agent):**

1. **The call deadline is pinned with the model.** `deadline_ms` is in the registry entry and inside
   the content hash the mandate pins, so it changes only with a new model version the owner
   confirms (rule 11). Policy may set a platform maximum (spec §3.4).
2. **A late response is discarded.** A response completed after its deadline never becomes an
   output, in that evaluation or any later one (INF-3).
3. **No retry on content failures.** Only transport failures retry, only to endpoints serving the
   identical pin, and only within the deadline. A schema failure, identity mismatch, or provider
   refusal ends the call (spec §3.4).
4. **Cost is reserved before the call.** The gateway reserves the call's maximum cost against every
   cap before the first attempt and refuses a call that could take spend above a cap. A reservation
   left by a crash counts as spent for that risk day, and spend never decreases within a risk day.
   Mandate spec §8.5 check 7 is unchanged (spec §7.3).
5. **Prompts hold only the model contract's inputs.** No credential, account identifier, personal
   data, or other workspace's data; a deterministic guard checks before sending. The research
   agent's own memory stays allowed, as mandate spec §8.4 says (INF-8, spec §8.3).
6. **The cache is exact and per workspace.** Same workspace, same identity, same canonical request
   digest; no similarity cache; errors never cached (spec §3.5).
7. **The gateway gives models no tools,** no function calls, and no browsing (INF-5).
8. **Hybrid and on-prem deployments are local-only by default.** A customer may allow hosted
   endpoints in policy (spec §6). This only restricts.
9. **Quantization is part of an open-weight model's identity.** An endpoint serving another
   quantization is a different model under DEC-67, so an aggregator must lock routing to endpoints
   serving the identical weights (spec §4.1, §6).
10. **The reported identity must equal the pin.** A response whose provider-reported model differs
    fails as `identity_mismatch`, and its output counts as missing (INF-2).
11. **`ModelInvocationRecorded` needs these members when it closes:** call id, purpose, identity and
    endpoint, request digest, sampling parameters and seed, prompt and response artifacts,
    reported identity, provider request ID, outcome, attempts, token counts, cost, price table
    reference, cache hit, deadline, and completion time. The caller appends it, as the single writer
    of its stream, and reservations go to a new gateway-owned meter stream. Both are journal spec
    changes for E15-8, spec first; this item does not change the journal spec.
12. **RAID R-07's mitigation means a new mandate version, never a runtime fallback.** "Laya
    self-hosted as fallback; LLM wrapper fallback" is read under DEC-67: if Jev is lost, an owner may
    confirm a new version that pins another model; the gateway never routes to it. R-07's wording is
    updated to say so.

**Proposed (founder):**

13. **The fast tier (Laya, Jev; OD-02).** Neither model is defined or built. Options: build an
    open-weight fast model, use a hosted one, or drop the tier for v1. **Recommendation: drop it for
    v1,** keeping the `fast.` prefix and the call contract, and revisit OD-02 at Phase 3 with its
    bake-off. The retail profile already excludes `fast` until counsel answers question 33.
    Meanwhile: no fast-model code, vendor, or spend.
14. **Providers and hosting.** **Recommendation:** direct provider APIs pinned to dated snapshots
    for the research agent and the compiler on managed; an aggregator only for internal evaluation
    and the spike, with routing locked; self-hosted open weights as the local path after v1.
    Meanwhile: no new paid service; live calls only in the team's internal paper workspaces with the
    key already provided for the spike.
15. **Provider data terms.** **Recommendation:** offer only endpoints whose terms exclude training on
    API data, with the shortest retention available, kept on file per endpoint as part of the
    evaluation gate. Counsel confirms the wording.
16. **Bring-your-own provider keys for hybrid.** **Recommendation:** allow it for hybrid and on-prem,
    so the customer pays the provider directly and token billing at cost plus margin applies only
    to our keys; the meter still counts usage for quotas. Meanwhile: platform keys only, in internal
    workspaces.

## Rationale

The HLD names the model gateway and its duties in one paragraph, and the only model code is a spike.
The gateway sits between untrusted text and the order builder, and it spends money on every call.
Each reading picks the option that adds no risk: an output that might be from another model, late,
resampled, or built from another tenant's data is treated as missing, and missing outputs already
cannot enlarge a buy (MI-10). Items 13 to 16 involve vendors, spending, or legal terms, which DEC-79
reserves.

## Alternatives considered

- **Retry schema failures once.** Rejected: resampling until an output parses selects outputs, and
  the cost is the user's.
- **Let a late response serve the next evaluation.** Rejected: it would be an output computed for
  other inputs, under a deadline it missed.
- **Count spend only on completion.** Rejected: a crash between the provider's bill and the journal
  would undercount and let spend pass the cap.
- **A deadline set in policy rather than pinned.** Kept only as a maximum: the deadline changes which
  outputs arrive, so it is part of the model's behavior the owner pins.
- **A shared cross-workspace response cache.** Rejected: a tenant-isolation risk for a small saving.

## Founder decisions (2026-10-03)

The founder decided items 13 to 16. Where the choice differs from the recommendation above, this
section governs.

| Item | Decision |
|---|---|
| 13. The fast tier | **Use a hosted model in v1**, not the recommended drop. The fast tier is served by a hosted model through the gateway, under the same pinning, deadline, metering, and evaluation-gate rules as any model (items 1 to 12). Which model follows item 14, and its evaluation gate comes first. The retail profile still excludes `fast` until counsel answers question 33 |
| 14. Providers and hosting | **An aggregator for every call**, not the recommended direct APIs. Every model is reached through one aggregator with provider routing locked per pinned model. Item 10 is what keeps DEC-67 whole on this path: a response whose reported provider or model differs from the pin counts as missing. Self-hosted open weights remain the local path after v1 |
| 15. Provider data terms | As recommended: route only to endpoints whose terms exclude training on API data, with the shortest retention available. With an aggregator, both the aggregator's terms and the underlying provider's must meet this; the terms are recorded per endpoint at the evaluation gate, and counsel confirms the wording |
| 16. Bring-your-own provider keys | As recommended: allowed for hybrid and on-prem. Managed deployments use platform keys |

## Post-merge review amendments (2026-10-03, inference spec v0.2)

The independent review of spec v0.1 (PR #551, round 1) found two blockers and three majors. Items 17
to 22 fix them and take four asks from the agent harness spec (its §10.1). Each tightens or
clarifies, so the drafting agent accepts them under DEC-79 and DEC-176. They change no founder
decision above. The review's minors are backlog row E15-12 (freeze rule).

**Accepted (agent):**

17. **What the content hash covers** (blocker 1; refines item 1). `content_hash` is over the entry's
    pinned content: identity, template, retrieval plan, output schema, validation bounds, parameter
    schema, `deadline_ms`, `max_output_tokens`, sampling parameters, methodology, and authorship.
    **`endpoints` and `status` are outside it**, versioned as journaled configuration. Adding,
    removing, or re-probing an endpoint, or changing status, never changes the hash, so it never
    invalidates an owner's pin. INF-2 is unchanged: every endpoint must serve exactly the pinned
    identity, quantization included (spec §4.1).
18. **Mandate spec §8.1 carries the same definition** (blocker 2). Its content-hash sentence now
    lists what the hash covers for a model called through the gateway and says endpoints and status
    are outside it. It pins more than the four parts §8.1 named, so it only tightens (DEC-176). The
    reference cases carry hashes as opaque values, so no case or fixture changes.
19. **The compiler's call record has no stream yet** (major 3). The journal spec and the catalogue
    allow `ModelInvocationRecorded` on the agent stream only. The spec no longer states the control
    stream as the rule. E15-8's journal spec change names the stream; until then the compiler makes
    no call through the gateway, since INF-10 could not hold for it (spec §3.6, §13 question 1).
20. **One meter writer per workspace** (major 4). The gateway may be replicated, but one replica
    holds the meter writer role for a workspace, fenced by epoch, and it alone checks caps and
    appends to `meter:{workspace_id}`. Other replicas reserve through it. A replica that cannot
    reserve, because the holder is unreachable inside the deadline or its own append is fenced,
    refuses the call as `meter_unavailable`: nothing is sent, the output is missing, and the
    operator is alerted. A new holder folds the stream first, and unsettled reservations stay
    counted. `docs/design/infrastructure.md` §3.1's gateway row is aligned in the same change
    (spec §3.3, §3.6, §9).
21. **A late response is never cached** (major 5; closes a hole in item 2). A response completed
    after its deadline, however complete and valid, is not a cache entry, and the INF-3 oracle
    asserts that (spec §3.5, §2.1).
22. **Four asks of the agent harness spec** (its §10.1 asks 1 to 4): the retrieval plan and the
    validation bounds are in the registry entry and inside the content hash, so the pin covers what
    the model is shown (rule 11); a caller can read its own agent's reservations in the meter
    stream; `ModelInvocationRecorded` gains the retrieved-context list and room for the candidates'
    verdicts when E15-8 closes it (added to item 11's list; still a journal spec change, spec
    first); and the prompt guard can be called on its own, with no call and no cost.

**Proposed (founder):**

23. **A prompt record without licensed text** (agent harness spec §10.1 ask 5). For a call whose
    inputs hold licensed text, `prompt_ref` would name the rendered prompt with each licensed item's
    text replaced by its raw-bytes digest, while `request_digest` stays the digest of the full
    prompt. This keeps less than INF-10 says today ("its prompt and response stored as artifacts"),
    and whether such a record meets the retention duty is records wording counsel must confirm, so
    it is the founder's (DEC-79). **Recommendation:** accept it, on two conditions: the stored
    prompt holds each replaced item's digest, source, and item id, so the full prompt can be rebuilt
    and its `request_digest` re-checked while the point-in-time store holds the text; and counsel
    confirms that this record, with the full response, satisfies retention. **Meanwhile:** INF-10
    stands as written and research reads no licensed text.
