# DEC-534: A confirmed mandate beyond a later policy denies only actions that add risk

## Decision

1. **What it covers.** A run reads the effective `policy_set` registration (DEC-505 item 1) and
   folds its levels with `policy::check` against the confirmed mandate. Mandate spec §4.3 lets a
   child only tighten. A mandate confirmed under one policy can still exceed a ceiling of a policy
   registered after it. That mandate is **nonconforming**.
2. **What a nonconforming mandate denies.** The run denies every action that adds risk: an
   `open` or an `increase`. Exits, protective orders and kill switches go through, as
   `AGENTS.md` rules 2, 3 and 13 require.
   - The run itself is not refused. Once a position may be open, refusing the run would also stop
     the exits that reduce it.
   - D4b reports the violations beside the overlay, and D4c applies the denial on the order path.
3. **The way back.** Only a new confirmed mandate version that conforms reopens actions that add
   risk. A later `policy_set` registration that loosens the policy is not a way back on its own.
   Every run checks the confirmed version against the effective policy, so a loosened policy can
   only stop the violation if the confirmed version already meets it.
4. **The owner is alerted with opaque ids only** (`AGENTS.md` rule 6): the agent, the mandate
   version and the policy-set reference, plus generic text. No limit, value or position is
   included. Mandate spec §4.3 calls the state `policy_nonconforming`.
5. **What it does not change.**
   - The overlay governs as §4.3 says: the stricter of the mandate's value and every ancestor's,
     and `auto` evaluates as `ask` when `auto_allowed` is false.
   - A policy set or model registry that cannot be read, or breaks its schema, refuses the run like
     any other configuration object (DEC-505 item 1). It is not treated as nonconforming.

## Rationale

Mandate spec §4.3 has policy changes apply to running agents as an overlay. It also flags a
nonconforming agent and requires a conforming version before any risk-increasing change.

The paper run needs both halves:
- refusing everything would block risk reduction, which `AGENTS.md` rule 13 forbids;
- running as if conforming would let a looser confirmed mandate add risk past a newer ceiling.

Denying only what adds risk is the reading that adds no risk and removes none of the exits.

## Alternatives considered

- **Refuse the whole run.** Rejected: once a position may be open, it blocks the exits and
  protective orders that reduce risk.
- **Clamp each value to the policy and continue.** Rejected: this would trade a mandate the owner
  never confirmed. §4.3 asks for a conforming version, not a silently edited one.
- **Ignore a policy registered after the confirmation.** Rejected: §4.3's overlay applies to
  running agents. The effective policy is the latest registration (DEC-505 item 1).
