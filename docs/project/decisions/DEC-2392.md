## Context

The founder's goal for 2026-10-27 is an agent that monitors its position, acts on news, and sells.
On `main`, every research run is scheduled: agent harness spec §5.3 says "event sources such as a
news burst never bring a run forward", and §6.9 holds event triggers until a mandate spec change
lists them as envelope fields with a debounce and a rate limit (rule 11). `RunStarted.trigger.kind`
already admits `event`, but only for a `monitor` run (journal spec rule 172). Rule 172 does not say
what an event run's `cause` names.

E19-12's backlog row asks for these:
- envelope fields for the sources, the debounce, and the caps;
- no trigger unless a confirmed version enables it;
- a change that adds sources classifies as increasing;
- only allowlisted sources;
- prompt-injection fixtures that never reach an order;
- bursts that never exceed the caps, tested over random sequences;
- opinions only (rule 4).

## Decision

1. **Envelope field.** `behavior.research.event_triggers` is optional. It is `null` or absent for
   none, or `{sources, debounce_s, max_runs_per_day}`:
   - `sources` is `news` and/or `filings`, sorted and unique, with at least one (V-009);
   - `debounce_s` is 300 to 86,400;
   - `max_runs_per_day` is 1 to 24.

   Absent is off, which is every version written before it, so no confirmed version changes
   meaning. It lives under `behavior.research`, as agent harness spec §6.9 and item 9 of its §13
   said, rather than reusing `behavior.cadence.event_sources`. That field is the trading loop's
   evaluation trigger, already confirmed on existing versions with other meanings in mind.
2. **Classification.** Any change to the field, clearing it included, is **increasing** (§9.2), so
   the owner confirms each change with step-up. Clearing `behavior.research` as a whole stays
   reducing. This is the fail-safe reading of §9.2's "every path not listed", stated in a row of its
   own.
3. **Only `monitor`.** A triggered run is always the `monitor` kind, in any mode except `paused` and
   `stopped`. It can only invalidate theses (and, once E19-14 declares it, request exits). Its
   output schema has no `theses` member (§6.9), so the gateway refuses a thesis `schema_invalid`.
   An event can therefore end a position, through mandate spec §8.6 and DEC-NEXIT's exit, but can
   never open or enlarge one. It never sizes or places an order (rule 4).
4. **What triggers.** An item triggers only if all of these hold:
   - it is a news item or filing the data service stored from a source in effect on the allowlist
     (DEC-101, DEC-1130), of a kind `sources` lists;
   - its knowledge time is after the agent's last research call;
   - one of its instruments carries one of the agent's active theses.

   A run then starts only when all of these hold:
   - the risk clock is at least the last research call (its record or its meter reservation, §5.3)
     plus `debounce_s`;
   - fewer than `max_runs_per_day` event runs have started in the risk day;
   - the day's research spend is below `cost_cap_usd_per_day`;
   - no run is in flight.

   Otherwise the item triggers nothing and nothing is journaled for it. The entry must be pinned
   `agentic`; a `single_call` entry's runs stay scheduled. A due event run takes the trigger queue's
   scheduled slot, so it never adds a second queued run.
5. **Journal before acting.** The run's starting batch journals the item first, as an
   `ObservationRecorded` (source, matched instrument, knowledge time, and the item as an artifact),
   then `RunStarted` with `trigger: {kind: event, cause: <that record>}`. New journal rule 271:
   - the cause is an `ObservationRecorded` earlier in the same batch, with an instrument;
   - no earlier `RunStarted` names the same cause, so one item starts at most one run.
6. **HI-8** gains the debounce and the daily cap of event runs, which its property test counts from
   the journal.
7. **Not now.** A price move, a fill, a refusal, an earnings calendar, and transcripts trigger
   nothing. Each would be a new source kind with its own mandate spec change, and a paid source is
   spending, which the founder decides (DEC-79). The policy hierarchy gains no bound on these fields
   yet: the schema's ranges
   bind every workspace, and a policy bound follows with its own row. Alpaca news is enabled by
   the founder's answer to DEC-1130 item 2 (DEC-2394) through a new allowlist version; the
   recorded plane carries news and filing items for tests and the demo.

## Consequences

- **Spec slice first:** mandate spec v0.11 and its schema, agent harness spec §5.3, §6.9 and HI-8,
  and journal spec v0.87. The code follows, in this order:
  - `mandate-spec` parses and validates the field;
  - `mandate-journal` adds rule 271;
  - `mandate-runtime`'s research step admits the trigger and journals the batch;
  - `mandate-research-driver`'s queue takes `Trigger::Event`;
  - the daemon offers stored items to it;
  - the recorded plane feeds one news item into the cell for the demo, with lane DR.
- **Adversaries:**
  - A **news burst** starts at most one run per debounce, and at most `max_runs_per_day` a day.
  - An **injected item** can at most lead the model to invalidate a thesis, which sells a position
    and re-enters only through admission and the re-entry cooldown (HI-10). That is the disclosed
    residual: allowlisted text can make the agent exit early. It cannot make it buy.
  - A **crash loop** cannot call faster than the debounce, because the meter reservation counts as
    the last call.
  - **Spend** stays under the owner's cost cap.
