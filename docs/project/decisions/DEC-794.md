## Decision

No change is made to the CodeQL configuration, and no alert is dismissed, until the founder
decides. #800 merges with the two alerts open: CodeQL is not a required check.

**The evidence.**

1. **The query** is `rust/hard-coded-cryptographic-value`, in the default Rust suite of the "CodeQL
   Advanced" workflow.
2. **The two alerts** are both in `crates/mandate-webpush/src/tests.rs`, a module compiled only under
   `#[cfg(test)]`:
   - a key, at the receiver-side decrypt oracle (about line 92), from RFC 8291 §5 and Appendix A's
     published receiver private key and authentication secret;
   - a salt, in the RFC 8188 vector test (about line 171), from RFC 8188 §3.1's published example.
3. **Both are false positives.** The values are the RFCs' own test vectors, which the tests must use
   to reproduce the RFC outputs byte-exact. No product code reads them: the crate's product files
   (`src/lib.rs`, `src/payload.rs`) take every key from the `VapidSigner` handle, the subscription,
   or the injected `SecureRandom`, and hold no key, salt, or keying material.

**The options for the founder.**

- **(a) Dismiss both alerts as "used in tests".** No configuration changes, and the query keeps
  running everywhere. A later alert of the same kind on these lines would need the same dismissal.
- **(b) A scoped `paths-ignore`** for one test-only path holding the vectors and their fixtures,
  with a test that no product file names that path. This narrows the scan on that path for every
  query.
- **(c) Leave them open.** Nothing blocks a merge, but the code-scanning list carries two known
  false positives.

Recommended: (a), which narrows nothing.

## Rationale

The query is right that a fixed key in product code is a defect, so it should keep running on the
whole crate. A byte-exact RFC vector test cannot avoid the RFC's fixed keys. Whether to dismiss the
alerts or narrow the scan is a decision about a security scan, which DEC-79 and DEC-500 item 2
leave to the founder.

## Alternatives considered

- **Moving the vectors to an ignored directory now.** Tried on #800 at `d05ce63` and reverted: it
  narrows a security scan without the founder's decision, and relocating code to avoid a query is
  not a fix.
- **Generating the keys at test time.** Rejected: the RFC vectors are reproducible only with the
  RFC's own keys.
