## Decision

1. **The disagreement.** DEC-446 says the legacy `ProtectionChanged` writers move to the closed
   form "until the slice that owns them". E1b-P found that some of their records cannot. §9.5 rule
   41: "`orders` is empty except on `placed`, `cancelled`, `passive_start`, and
   `unprotected_start`, where it names at least one order (`payload.orders`); `awaiting` is empty
   except on `interval_limit` and `unprotected_end` (`payload.awaiting`)". `mandate-journal`
   (`protection_changed_rules`) and the reference (`control.py`) read the `awaiting` half as
   "non-empty there" too. Rule 44: "on `passive_start` and `unprotected_start` `intent_id`,
   `entry`, and `agent_id` are null together or non-null together". `Draft::parse` on the
   closed record each site needs, every member present:

   | Record (`protection.rs` writer) | Journal |
   |---|---|
   | A bracket entry's first fill: `unprotected_start` naming only `bracket` (`bracket`) | Invalid at `payload.orders` |
   | The bracket filled after it: `unprotected_end`, `bracket`, empty `awaiting` | Invalid at `payload.awaiting` |
   | Nothing to cover (`re_place`), `acknowledged`, `uncovered` ends | Invalid at `payload.awaiting` |
   | `interval_limit` awaiting nothing (`bound`) | Invalid at `payload.awaiting` |
   | Re-placement before expiry: `replacing`, `entry`, `agent_id`, no intent (`new_day`) | Invalid at `payload.entry` |
   | Handed-on passive start, passive wait, lost protection: a start with no orders | Invalid at `payload.orders` |

   The fold needs each: `ends = action == "unprotected_end" && awaiting.is_empty() && !uncovered`
   is the only way an interval ends, and a re-placement is read from `replacing`, `entry` and
   `agent_id` without an intent. No start reads `orders`.
2. **Option (a), recommended.** Loosen rule 41 to allow empty `orders` on the two starts and empty
   `awaiting` on `unprotected_end` and `interval_limit`; loosen rule 44 to allow `entry` and
   `agent_id` without `intent_id` where `replacing` is true. The fold already reads these shapes,
   so replay is unchanged. It becomes one queued journal-spec PR, then a slice moves the writers.
3. **Option (b).** Fit the fold and writers to the spec as written: a bracket's held legs would
   need a protective order to name before any exists, an interval's end a new action, and a
   re-placement an invented intent: new fold states, replay rework and new vectors, so it costs
   more than (a) and still edits the spec.
4. **Interim, the conservative option.** The writers in item 1 stay legacy and are refused at
   `append` (DEC-446). E1b-P closes every other writer, so a bracket entry filled at once places
   its legs; one filled partly stops at its first `unprotected_start`. E2 waits on this.

## Rationale

§9.5 says its members are "the fold's reads"; (a) makes the rules agree.

## Alternatives considered

Option (b), item 3. Filling `orders` or `awaiting` with an id to pass the check was rejected: the
fold would read it, and an interval would never end.
