## Context

Every run today is a one-shot process: `mandate-paper` opens a cycle, takes the writer epoch of
the agent and account streams, runs, and exits. The founder chose to build toward managed cells,
and to build the service pieces beside the R0 live-order work without touching its files
(`crates/mandate-paper/src/lib.rs`, `crates/mandate-shell/src/control.rs`,
`crates/mandate-shell/src/adapters.rs`, `crates/mandate-shell/src/paper/*`). This is the first
slice of E21-2: a supervised process for one deployment.

## Decision

1. **A new safety-critical crate, `mandate-agentd`, at layer 9, paper only.** It sits beside
   `mandate-paper`, above the shell whose `JournalWriter` stage it implements, with `tokio` its
   only external dependency. Its `forbidden_internal` list keeps it from ever reaching
   `mandate-paper`, the one crate that may declare `live` (DEC-529), and `mandate-cli`, so no
   live build of this process exists. Independently, `Supervisor::start` refuses any
   `Environment` but `Paper` before it takes a lease or calls the host (`Stop::Refused`). A live
   process needs a later decision.
2. **The lease is the writer epochs of the deployment's own streams, taken once.** `Lease::acquire`
   takes the epoch of each stream named in the configuration (the agent stream and the account
   stream), in order, fencing out any earlier writer (journal spec §5.1). The lease is itself a
   `JournalWriter`: its `take_ownership` hands back the epoch it holds while that is still the
   stream's current epoch and answers `Fenced` otherwise; it never takes a newer one. That is
   what makes the lease exclusive across cycles: a one-shot cycle takes a new epoch at every
   open, so two such processes alternating cycles would each fence the other and both act. Its
   `append` writes under the lease's epoch whatever the caller passes, and refuses a stream it
   does not hold as `Fenced` without trying it. A newer process fences an older one, as design
   §3.4 and §7.3 require; the orchestrator should not start two, but safety does not depend on it.
3. **The lease is asked before every cycle and before a drain settles.** A process whose lease
   no longer holds, or whose store cannot say, stops `Fenced` without calling its host again
   (`AGENTS.md` rule 3). A cycle that fails while the lease holds stops the process
   `CycleFailed`, fail-closed; the orchestrator's restart reconciles first (item 5). Release
   appends nothing: the journal has no unlock, and the next process fences the old epochs by
   taking newer ones.
4. **SIGTERM drains.** The binary registers SIGTERM before it announces itself
   (`tokio`'s `signal` feature, which adds `signal-hook-registry`; the workspace forbids the
   `unsafe` a `libc` handler needs). On it the supervisor goes `Draining` (not ready), starts no
   new cycle, and, while the lease holds, calls `Host::settle`, which carries in-flight work to
   its end (a submission to its broker answer, an exit sequence to re-placed protection within
   trading §5.4's bound) and never opens or cancels resting protection (design §7.3). Then it
   releases the lease and exits 0 (`drained`). The drain bound of §7.3 is the host's, since
   only it knows what is in flight; a drain that does not finish is recovered by the next
   process as after a crash.
5. **Start-up reconciliation comes before any cycle.** `Supervisor::start` takes the lease and
   calls `Host::reconcile` (the existing reconciliation: replay, then every submission without a
   broker answer looked up, and resent with its own id only if the broker has none; journal
   §5.2, trading §11). Only on success is the process `Ready`, with its first cycle due at once;
   a reconciliation that fails leaves it `Refused`, never ready, with no cycle.
6. **Not wired yet: the production cycle.** The binary runs only `IdleHost`, which reads its
   streams at every call, over an in-memory journal, behind `--fixture`; without that flag it
   exits 2 with `deployment_host_not_wired`. Hosting a deployment's real cycle needs a change in
   an R0 file, so this slice stops and describes it: `mandate_shell::production_cycle` assembles
   its `Stages` with `adapters`' own journal backend, so a caller cannot hand the cycle the
   lease as `Stages::journal`. The change is a constructor, in `adapters.rs` or beside
   `production_cycle`, that takes the journal stage as a `Box<dyn JournalWriter>`; with it the
   host's `cycle` is `ProductionCycle::run_observed` over the lease. A Postgres store
   (`Epochs` from `PgJournal`'s head) and the kill-switch path of a process that is not ready
   (design §3.4) are later slices of E21-2 outside the R0 files.
7. **Health is two loopback paths with fixed words.** `health::serve` refuses any non-loopback
   address before binding. `/readyz` answers `200 ready` only while the process is `Ready` (lease
   held, reconciliation passed) and `503 not_ready` otherwise, draining included; `/livez`
   answers `200 live` until the process stops, then `503 stopped`; anything else is `404
   not_found`. No body carries an id, symbol, price, quantity, or mandate content (`AGENTS.md`
   rule 6). Liveness here is "not stopped"; design §3.4's heartbeat bound comes with the
   production loop.
8. **Stops have stable codes and exit statuses:** `drained` 0, `refused` 2, `fenced` 3,
   `cycle_failed` 4, printed on one line of stderr.
9. **Proposed, for the founder: one PR, over ES-13's line limit.** The dispatch asked for one PR
   with the tests in their own first commit, shown failing on stubs (23 of 31 fail; the 8 that pass pin
   refusals the stubs already give), as DEC-921 allows for R0 rows. This crate is off the R0
   path, where DEC-77's two PRs still apply, and its `src/` is about 600 lines, over ES-13's 400
   for a safety-critical crate. Every other gate is kept: independent review on a different
   model, every mutant on the crate killed, CI green. If the founder prefers, the lease and
   supervisor split from the health listener and the binary as a stacked PR.

## Rationale

The fence is the journal's, so the lease adds no new primitive: it only stops a long-running
process from re-taking its own streams at every cycle, which is what would let two processes
alternate. Asking the lease before every host call means a fenced process stops before it does
anything, and the journal's own `Fenced` answer still covers a race inside a cycle. Keeping the
host behind a trait lets the supervisor's order (lease, reconcile, cycle, drain) be tested with
doubles now and the production cycle plugged in once the R0 hook exists.

## Alternatives considered

- **A lease table or advisory lock in Postgres.** Rejected: a second fence beside the writer
  epoch, with its own expiry and failure modes, for what the epoch already gives.
- **Let each cycle take ownership, as the one-shot runner does.** Rejected: two processes would
  fence each other in turn and both act.
- **Host the shell's production cycle now.** Rejected: it needs the R0 change of item 6.
- **`signal-hook` directly.** Rejected: `tokio` is already approved and its `signal` feature
  brings only `signal-hook-registry`.
