## Context

Trading spec §5.3 rule 2 (quantity at least `min_order_size`, and a multiple of the increment) and
rule 7 (fractional and notional equity orders are TIF day, and §5.2 keeps fractional orders out of
an OCO or a bracket) bind openings at the risk gate's check 4. Neither had a registered reason code.
DEC-129 item 27 proposed `below_min_order_size` and `quantity_off_increment` to the founder, and
DEC-150 item 4 made rule 2's increment half and rule 7 fail closed like its minimum size: until a
code was registered, `mandate-risk` refused to decide an opening that broke either rule
(`GateError::Unimplemented`, "DEC-129 item 27"), since minting an unregistered code breaks ES-09.

A refusal to decide is safe (the executor's default holds the opening) but tells the owner nothing,
and the cell's first deployed openings meet it: a fractional opening in an instrument whose
registered increment is a whole share is refused, not denied (lane XF's G2b-2 finding, #2605).

## Decision

1. **Three codes are registered** in `docs/specs/reference-cases/trading-domain.yaml`'s
   `reason_codes`, under order constraints. Each names exactly what the gate refused to decide
   before, for an opening or increase:
   - `below_min_order_size`: a quantity below the instrument's `min_order_size` (rule 2);
   - `quantity_off_increment`: a fractional quantity in an equity that is not fractionable
     (rule 2's increment, as the gate checks it today);
   - `fractional_order_tif_or_bracket`: a fractional equity order that is not TIF day, or is a
     bracket's entry (rule 7, §5.2).
2. **The gate denies with the code** at check 4, in §5.3's list order (§9.1): rule 2's codes,
   the minimum first, before rule 3's `would_cross_zero`; rule 7's after rules 5 and 6
   (`working_order_limit`) and before rule 8 (`add_blocked_by_protective_order`).
3. **Nothing else changes.** No check is added: a quantity off a finer grid than whole shares, or a
   crypto pair's increment, is not checked here, as before. Exits are unchanged: the gate checks
   neither rule for a reduction, and the broker judges an exit's size (`AGENTS.md` rule 13). An OCO
   is only protection on whole shares (§5.4), a proposal carries no notional (§5.3 rule 1), and a
   fractional short sale is `would_cross_zero`, so none of them reaches rule 7's code.
4. **The names are provisional.** The founder may rename any of them by a later decision; a rename
   changes the registry and the gate's enum, and nothing else.
5. **DEC-129 item 27's other half stays as it was:** registering `protection_unattributed` is still
   Proposed (founder).

## Rationale

The change only tightens: every opening the gate refused to decide for these rules is now denied,
and no order it refused is allowed. A coded denial is journaled and shown to the owner, so the cause
is visible instead of a refusal. DEC-79 reserves live money, spending, legal and compliance text, and
weakening a safety rule; naming a reason code is none of these, so DEC-176 lets an agent accept
it, and it adopts the names DEC-129 item 27 itself recommended.

## Alternatives considered

- **Keep refusing until the founder names the codes.** Rejected: the refusal is opaque to the owner
  and blocks the cell's demo path on an explanation, not on a risk.
- **One code for both halves of rule 2.** Rejected: the owner's remedy differs (size up, or size
  in whole shares).
- **Check every increment here, crypto's and finer equity grids too.** Not in this decision: it
  would add denials beyond what the gate refused, which is new surface; propose it separately.
