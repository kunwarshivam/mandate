## Decision

1. **The exception.** Three PRs of the P1 stack may exceed ES-13's 400-line split threshold
   (DEC-253). Each figure counts `crates/mandate-passkey/` alone, over the PR's own diff against
   the PR below it:
   - **Tests, part 2:** the software authenticator and its live RFC-vector checks, 404 lines.
   - **Tests, part 3:** the enrolment and structure tests, 435 lines.
   - **The implementation:** 417 lines added and 46 removed, 39 of the removals being the deleted
     ignore lines.

   Parts 1 (265 lines) and 4 (396 lines) are within the limit and need no exception. The
   exception covers these three PRs only, and P2 (E9-4) is held to ES-13 as usual.
2. **DEC-77 holds.** The implementation changes the tests only by deleting ignore lines, and
   every PR passes the mutation gate with 0 missed mutants.

## Rationale

- **Mostly a test double.** About 330 of part 2's lines are the software authenticator (a CBOR
  writer, a base64url encoder, and ES256 and Ed25519 signing) that every passkey test trusts.
  Splitting it from the RFC-vector tests that check it would merge test support that nothing
  exercises.
- **Small overages.** The three PRs exceed the limit by 4, 35, and 17 lines. The next split would
  cut a test file in half, or separate the CBOR parser from the code that reads it.

## Alternatives considered

- **Splitting further** into seven PRs. That doubles the review rounds for about 60 lines of
  overage.
