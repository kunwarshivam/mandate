## Decision

1. **The exception.** Three PRs of the P1 stack may exceed ES-13's 400-line split threshold
   (DEC-253). Each is counted over its own diff against the PR below it, after the stack review's
   round. As in DEC-537, the first figure counts `crates/mandate-passkey/` alone, and the second
   counts everything the PR changes.
   - **Tests, part 3:** the enrolment and structure tests. 448 lines in the crate, 451 in all.
   - **Tests, part 4:** the assertion tests and properties. 445 lines in the crate, 449 in all.
   - **The implementation:** 418 lines added and 48 removed in the crate (39 of the removals are
     the deleted ignore lines); 422 added and 50 removed in all.

   Parts 1 (265 lines in the crate) and 2 (400) are within the limit and need no exception. The
   exception covers these three PRs only, and P2 (E9-4) is held to ES-13 as usual.
2. **DEC-77 holds.** The implementation changes the tests only by deleting ignore lines, and
   every PR passes the mutation gate with 0 missed mutants.

## Rationale

- **Tests and their oracle.** Parts 3 and 4 are test code only, written against the software
  authenticator that part 2 adds, and grew with the cases the stack review asked for. The
  implementation's overage is its CBOR parser, which the mutation gate covers completely.
- **Small overages.** The three PRs exceed the limit by 48, 45, and 18 lines in the crate. The
  next split would cut a test file in half, or separate the CBOR parser from the code that reads
  it.

## Alternatives considered

- **Splitting further** into seven PRs. That doubles the review rounds for about 110 lines of
  overage.
