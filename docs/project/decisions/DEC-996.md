# DEC-996: `ModelInvocationRecorded` is closed on the agent stream, and the model gateway's meter stream is added (journal spec v0.45)

| | |
|---|---|
| **Status** | Accepted (agent: a reversible engineering reading under DEC-79, taken under DEC-176. It admits records that were impossible, picks the stricter of two folds the inference spec left open, and loosens nothing) |
| **Date** | 2026-10-17 (UTC) |
| **Decided by** | `claude-code` (builder, lane I1), under DEC-79 and DEC-176 |
| **Story or claim** | E15-8; DEC-432 items 11, 19, 20, 22; backlog E15-12 minors 7 and 8; claim [#1459](https://github.com/kunwarshivam/mandate/issues/1459) |

Before this decision, `ModelInvocationRecorded` was catalogued on the agent stream with no
registered payload, so `append` refused it as `unknown_schema`, and the meter stream the inference
spec proposes (§3.6) did not exist. No gateway call could be journaled before its output was used
(INF-10), and spend could not fold from the journal (INF-6, INF-7). The compiler's record was
already closed on the control stream (DEC-670). These are the readings this lane takes.

## Decision

1. **Agent-stream members.** Journal spec v0.45 §9.18 closes `ModelInvocationRecorded` on the
   agent stream at schema version 1 with §9.9's members (DEC-432 item 11), `purpose` limited to
   `research`, `llm_signal`, and `fast_signal`, and no draft members, then:
   - `reservation` (`ulid?`), the call's meter reservation, `null` exactly for a refusal or a cache
     hit (rule 146);
   - `observations` (`[ulid]`), the retrieved context as the run's `ObservationRecorded` event ids
     (agent harness spec §10.1 ask 3, DEC-432 item 22), strictly ascending (rule 147);
   - `verdicts`, one per candidate in the response, in order, each `judged` or one of the agent
     harness spec §6.5 check reasons (rule 148). This is the "room for the candidates' verdicts":
     a harness refusal is journaled here, and a candidate handed on is journaled by admission
     (`ThesisProposed`) or by its invalidation record (E19-5). It closes the agent harness spec's
     §6.2 precondition for verdicts.
2. **A refused prompt is not stored.** On the agent stream `prompt_ref` is `null` exactly when the
   outcome is `input_rejected` (rule 145). The guard refuses a prompt because it holds a credential,
   an account identifier, personal data, or another workspace's value (inference §8.3); storing that
   prompt as an artifact would put the very content the guard caught into the journal (INF-8,
   INF-14). The control stream's §9.9 record requires `prompt_ref` for every outcome; that is a
   gap for the compiler's `input_rejected`, recorded as a follow-up below, and until it is closed
   the workspace services must not call the gateway for the compiler (they do not today).
3. **The meter stream.** A new stream type, `meter:{workspace_id}`, owned by the workspace's one
   meter writer, fenced by epoch (DEC-432 item 20). It holds `StreamOpened`, `MeterReserved` (the
   maximum cost, appended before the first attempt), and `MeterSettled` (the actual cost, appended
   once). Rule 153 makes each call reserve once and settle at most once, against its own
   reservation, as the inference spec's idempotency says (§3.4).
4. **What the meter counts** (E15-12 minor 7). The meter stream holds exactly the calls that could
   cost money: those admitted by every cap. A refusal, `meter_unavailable` included, and a cache
   hit have no meter record; they are on the caller's `ModelInvocationRecorded` alone. INF-6's "one
   metering record per call" is that `ModelInvocationRecorded`; the INF-6 and INF-7 oracle counts
   the meter stream's reservations and the callers' records separately.
5. **One crash fold** (E15-12 minor 8). The inference spec says both that a crashed call's
   reservation "stays counted" (§7.3) and that it is "settled as spent at its maximum" (§9). The
   fold here is the first, written once: an open reservation counts at its maximum, forever, and
   nothing settles it later. That never lowers spend and needs no record a restart would have to
   write.
6. **Periods.** A reservation carries its risk day. Daily caps sum one risk day; the monthly cap of
   DEC-997 sums every risk day of one calendar month. No other period exists at this version.
7. **The version number.** v0.44 is taken by an open change (#1450, control-plane records, rules
   137 to 142), so this is v0.45, §9.18, rules 143 to 153. Whichever merges second merges `main`,
   keeps both entries, and renumbers only if the other's numbers moved.
8. **Two PRs** (ES-22). The spec PR carries the spec text, the reference, the `model_gateway`
   vectors, the regenerated fixtures, and this file. `mandate-journal`'s registration of the four
   records and the meter stream type follows in its own code change, with tests written first.
   Until it lands, `mandate-gateway` keeps its meter in its own in-process store behind the same
   fold, and no agent journals a gateway call (the harness research loop, E19, does not run yet).

## Follow-ups

- **The compiler's `input_rejected` prompt** (item 2): a §9.9 version 2 of the control-stream
  record with a nullable `prompt_ref` under the same rule, before the compiler calls the gateway.
- **`mandate-journal` registration** (item 8).

## Rationale

The members are the ones the inference spec and the agent harness spec already asked for; closing
them admits exactly the gateway's records. The meter stream is the inference spec's design, and the
two readings picked (no meter record for a call that cannot cost money; an open reservation counted
at its maximum forever) are the ones that can only refuse more calls.

## Alternatives considered

- **A separate verdict event.** The agent harness spec allows either. Rejected for now: the verdicts
  are a function of one response and are journaled in the same batch, and a second record would need
  its own cause rule. A later version can split it out.
- **Settle a crashed call at its maximum on restart.** Rejected (item 5): it needs a record written
  by whoever restarts, and a writer that crashed again before writing it would leave the same open
  reservation anyway.
- **Store the refused prompt with the secret redacted.** Rejected (item 2): redaction is a second
  parser of the very content the guard found; not storing it is simpler and loses nothing an
  auditor needs, since the outcome, the rule, and the request digest are recorded.
