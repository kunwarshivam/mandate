## Context

The [agent harness spec](../../specs/agent-harness.md) v0.1 describes the research loop (§5.3, §5.4,
§6.2 to §6.5, §7) and the core's new inputs (§10.3). Three things it needs do not exist yet: the
closed agent-stream `ModelInvocationRecorded` and the candidates' verdict record (E15-8), and the
invalidation verdict (E19-5). The spec says no run starts until they do (§6.2 preconditions). The
model gateway (lane I1) and the news and filings readers (lane I3) are being built in parallel, and
the shell's run path is on the R0 path, which this lane may not touch. This decision records how
the first slice is built within those limits.

## Decision

1. **Where the code lives.** `mandate-research-run` (layer 5, safety-critical, pure; DEC-431 item
   20) holds the worker: the retrieval plan, the read-only reader ports, the gateway port, the
   capture records, the call, `settle`, the error-kind treatments, and the strict output parse. It
   cannot name `IntentSink` (HI-1), and its `forbidden_internal` list in `xtask/layers.toml` keeps
   it off every journal crate and the artifact store, which `cargo xtask layers` checks (HI-16;
   E19-3's "an xtask check that it depends on no journal crate"). The harness checks, the
   platform's fill, admission, and the run schedule live in `mandate-runtime` (layer 6): the spec
   puts judging in the core (§6.2 step 5), and a layer-5 crate cannot depend on `mandate-research`,
   which is also layer 5.
2. **A second entry point, no new effect.** The core's research inputs arrive as
   `Input::Research` through `handle_research`, which shares `handle`'s batch, append-doubt, and
   retry rules and returns its effects plus `ResearchRequest`s (start, call, cancel). `handle`
   refuses `Input::Research` (`not_interpreted`), so the trading loop never waits on research
   (HI-7). No `Effect` variant is added: the shell's run path matches `Effect` exhaustively and is
   on the R0 path. A research batch whose append is unresolved blocks every input, the kill switch
   included, exactly as a trading batch does (journal spec §5.1), and `handle` cannot retry it, so
   the shell resolves it by handing `handle_research` the same research input again, at once, before
   anything else. **The run-path hook for after R0:** the shell's research driver, a task that
   calls `handle_research(Poll)` on each tick, stores each item's record and the reply's artifacts
   before handing them in, runs the worker against `mandate-marketdata`'s bars and lane I3's
   readers, calls lane I1's gateway, builds `ResearchContext` from the account stream's working
   universe, the folded lineages and active theses, and the meter stream's reservations, and
   rebuilds the drift fold from the observation artifacts on replay.
3. **The preconditions are read, not assumed.** `Preconditions::read` takes a `RecordCatalog`, and
   `JournalCatalog`, the only production catalogue, registers neither the invalidation verdict nor
   the candidates' verdict record, so no run starts in any deployment until E19-5 and E15-8 change
   its answer. The fields are private, so nothing else can build preconditions that hold. Tests use
   a catalogue double. The third precondition is held by the worker: retrieval drops every licensed
   item (`licensed`), so the plan reads only text that may be kept in full.
4. **Provisional records.** Until E15-8 closes them: `ModelInvocationRecorded` (purpose
   `research`) carries `run_id` (in place of the envelope's `correlation_id`, which a draft cannot
   set), `call_id`, the pinned identity, `outcome`, `reported_identity`, `request_digest`,
   `prompt_ref`, `response_ref`, `cost_usd`, `called_at` (the risk clock the answer arrived at, which
   the schedule counts from), `completed_at`, `retrieved_context` (the run's observation ids), and
   `used` (false for a late answer to a cancelled run). The verdicts are their own event,
   `CandidateVerdictsRecorded`: the run, its call record, an outcome (`judged`, `not_pinned`, or
   `output_rejected` with the parser's code), and one line per candidate in output order. The fold
   reads both as inert. Item 3 keeps every one of these drafts out of a production journal; E15-8
   replaces them with its closed schemas.
5. **Run readings.** One poll judges, cancels, or starts, never two of them, so a cancelled run is
   not replaced in the same step. A run starts only in `normal` mode, so `exits_only` starts none
   until E19-5 can journal an invalidation (backlog E19 follow-up minor 9), and a run in flight is
   cancelled when the mode tightens, the pin changes, the research agent is cleared or withdrawn,
   the universe is pinned, research is disallowed, or the wall-clock bound passes. The bound is in
   risk-clock seconds: the start plus the plan's retrieval timeout plus the call deadline rounded up.
   A run whose `ok` call record is drafted waits until that record folds back; it is then judged
   under the version in effect, so a changed pin gives `not_pinned` verdicts and no thesis (HI-17),
   and a mode that left `normal` drops it unjudged. An empty retrieval ends the run with no call.
   The interval counts from the later of the last folded `called_at` and the last reservation, at
   the owner's `behavior.research.interval_s` raised to the policy floor. Run and call ids are
   derived by `IdGen` at ordinals far above any draft's, with a per-process counter, so they never
   repeat within a process or across epochs.
6. **Corroboration until E17-7** (§13 item 3). A thesis is `independent_source` exactly when its
   cited items about its own instrument come from at least two distinct allowlisted text sources;
   otherwise it has none and §8.5 check 15 refuses it. There is no `market_data` corroboration
   until E17-7 states its rule. This only refuses more.
7. **Harness checks.** §6.5's six, in its table's order. `forbidden_language` is a fixed phrase
   list (price targets, targets, objectives, guarantees, risk-free, "will double", "% upside", and
   the like) over the thesis text and its invalidation, case-insensitive; it errs toward refusing.
   `duplicate_instrument` counts any earlier candidate that resolved to the same instrument. An
   invalidation is `unknown_thesis`, then `unknown_evidence`, then `accepted`; an accepted one is
   only journaled as a verdict, because the removal it causes is E19-5's, and item 3 keeps runs from
   reaching it meanwhile.
8. **The platform's fill.** `thesis_id` is derived by `IdGen` and a new thesis starts its own
   lineage; a thesis for an instrument with an active thesis is a renewal in that lineage and
   revision. `as_of` is the cut-off and `expires_at` the cut-off plus the horizon. The asset class,
   eligibility, and group come from the run's instrument snapshot; an ineligible instrument or its
   group is added to the admission facts, which only refuses more. `evidence_sources` lists the
   sources of the cited news and filings in the order cited, duplicates kept (journal spec §9.4);
   cited bars are evidence but not sources, since market data needs no allowlist entry and check 14
   would otherwise refuse it. `evidence_ref` is null until the shell stores the evidence artifact
   (item 2's hook). The admitted thesis's `ModelOutputRecorded` cites the cited items'
   observations as `evidence` and the response as `thesis_ref`; checks 1 to 3 journal an ignored
   output, and the other checks' refusals journal the thesis record only.
9. **The output's wire form.** The parse uses the canonical parser, so `conviction` and
   `confidence` are decimal strings in the journal's canonical grammar and a JSON float is
   `not_json`; any unknown member, missing member, or out-of-range value rejects the whole output,
   which is never repaired or partly read. Lane I1's output schema is to match; until it lands the
   recorded fake follows this form.
10. **Treatments.** §7.3's table, with two readings: `meter_unavailable` and `input_rejected` alert
    the operator on every occurrence (the spec alerts on repeats; alerting on each is opaque and only
    louder), and the three-in-a-row `deadline_exceeded` alert fires on the third and resets the
    count. Every alert carries only the call record's id and a fixed key (`AGENTS.md` rule 6).
11. **Retrieval readings.** Every reader's answer is filtered again in the worker (knowledge time,
    window, allowlist, licence, scope, duplicates) before the cap, so a reader that leaks cannot
    show the model more (HI-13). A failed read is an empty read. The observation's `instrument_id`
    is the item's symbol where it has exactly one. The drift fold (E17-5) observes each news and
    filing item once, in knowledge-time order, process-locally at retrieval; an item the detector
    refuses as out of order folds nothing.

## Rationale

Each reading keeps the spec's invariants whole without waiting on the lanes in flight: the
preconditions are enforced by data rather than a flag, the provisional records cannot reach a
production journal, and every reading that the spec leaves open is taken toward refusing more or
saying less. The second entry point keeps the R0 path untouched while giving the shell one place
to hook in after R0.

## Alternatives considered

- **Add `Effect::Research` and handle research in `handle`:** the natural shape, but it forces an
  edit to the shell's exhaustive `Effect` match on the R0 path.
- **Gate runs on a boolean in the configuration:** anyone could set it; a catalogue answer cannot be
  set by a caller in production.
- **Put judging in a layer-6 crate beside the runtime:** the runtime would have to depend on it, and
  two crates at one layer cannot depend on each other.
- **Corroborate on any two cited items:** two items from one source would corroborate themselves.
