## Context

`mandate_journal::resolve_trusted_start` (§9.14, DEC-767) checks no row it finds: one whose
`stream_id` column names this workspace while its body is another's passes, and a manifest start
only the hot store vouches for is returned. DEC-787 items 3 and 5 refuse both.

## Decision

1. **The start row is checked before it is used.** After §9.14's lookup finds the record (by the
   row's columns and its body's `payload`, as today), its row must pass journal spec §11 check 1
   (`non_canonical`), check 2 (`column_mismatch`, every column §11 lists, `stream_id` and so the
   workspace included), and check 4 (`rehash_mismatch`), in that order. A `SegmentExported` must
   then also satisfy rule 117 (its `manifest_hash` is its six fields' hash). Any failure refuses.
2. **No check 6, and no other per-event check.** DEC-787 item 3 names checks 1, 2, and 4 only;
   checks 3 and 5 need a neighbour row, and the range walk runs every check on the range itself.
3. **Check 2 closes the column and body workspace mismatch.** The lookup reads the columns, so a
   row of another workspace under this workspace's `stream_id` column is found, and check 2 refuses
   it; the reverse is not found at all, the same refusal (DEC-767).
4. **A manifest start is a type-state.** The resolver returns a manifest start as `ManifestStart`,
   which is not a `TrustedStart`. It becomes one only through `ManifestStart::confirm(cold_bytes)`,
   which requires `Digest::of(cold_bytes) == manifest_hash`, the bytes being the segment's manifest
   object as the cold store returns it (§6.2). A hot-only manifest start is unrepresentable: rung 1
   of the trust ladder, the same approach as DEC-892's verified prefix (pending).
5. **The error is `TrustedStartError { Refused, ColdUnreadable, Unimplemented }`.** `Refused`
   covers no usable record, more than one (item 7), a record that fails item 1, and cold bytes whose digest differs
   (DEC-894 item 1); `ColdUnreadable` covers a manifest object that is absent or cannot be read
   (DEC-787 item 5); `Unimplemented` stays for the crate's stubs (DEC-77). Both map to 422
   `trusted_start` with nothing recorded; `ColdUnreadable` is kept apart because it is retryable and
   raises no alert (E12-7).
6. **The reference vectors catch up.** `cold_records.trusted_starts.rows` holds real control-stream
   rows and `row_cases` the cases of items 1 to 5 and 7, answered by `control.py`'s `start_from_rows`,
   recomputed by `cold.py`'s own oracle, and each seeded bug caught; `records` and `cases` are
   unchanged.
7. **More than one matching row refuses the start** (`ambiguous_start`). When two or more stored
   rows match the request, the resolver neither takes the first nor skips one that fails item 1:
   which record vouches would depend on row order. Refusing is the tighter reading (DEC-176).

## Rationale

A start record that fails a check vouches for nothing, and a type, unlike a step, cannot be
forgotten. Refusing adds no risk: nothing changes state, and the caller can retry.

## Alternatives considered

- **A `confirmed: bool` on `TrustedStart`.** Rejected: a flag can be ignored, a type cannot.
