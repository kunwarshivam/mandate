## Decision

1. **The gap.** DEC-863 item 3 compares six members: instrument, side, quantity, limit price,
   order type and time in force. An order the account stream journals may have no folded request,
   for example a broker-linked replacement. Then its limit price, order type and time in force are
   not known, and item 3 does not say whether it can be a lookalike.
2. **The reading.** Such an order is a lookalike when its instrument, side and quantity alone
   equal the `Unknown` order's. A listed record with no client order id is then not a match, and
   the `Unknown` order stays `Unknown`, with its instrument blocked until the owner reconciles it
   (trading-domain spec §5.3 rule 9).
3. **Tests.** `an_order_with_no_folded_request_is_a_lookalike_on_instrument_side_and_quantity`
   (`crates/mandate-executor/tests/list_adoption.rs`, #1085) pins it.

## Rationale

The members that cannot be compared cannot rule the other order out, so it cannot be told apart
from the record. DEC-863's own rationale holds: a wrong adoption frees the instrument for a second
order, while a wrong `Unknown` only waits for the owner (rules 3 and 13, LT-6). The reading adopts
less, never more.

## Alternatives considered

- **Treating an unknown member as unequal.** That makes such an order never a lookalike. It
  adopts more, and could adopt a stale record of that order, so it is not a tightening.
- **Leaving item 3 silent.** The code and test already take the reading; an unrecorded reading is
  what DEC-176 forbids.
