# DEC-1141: `BacktestRunRecorded` and `EvaluationRunRecorded` are written by a `user` or a `system` actor only

| | |
|---|---|
| **Status** | Accepted (agent: a reversible engineering reading under DEC-79; it resolves a gap in journal spec §9.18 by the reading that only tightens and adds no risk, DEC-176) |
| **Date** | 2026-10-17 (UTC) |
| **Decided by** | The lane I4 builder (Claude Code), under DEC-79 and DEC-176 |
| **Story or claim** | E4-5, E17-8; journal spec v0.45 §9.18; DEC-1001 item 4, DEC-1002 item 7; claim [#1463](https://github.com/kunwarshivam/mandate/issues/1463) |

## Context

Journal spec v0.45 §9.18 closes `BacktestRunRecorded` and `EvaluationRunRecorded` on the workspace
control stream with rules 143 to 145, and says nothing about the actor. The analogous control-stream
records each name theirs: §9.17's control-plane records are written by workspace control services
as a `system` actor (rule 137), and §9.13's `ExportCreated` and `VerificationRun` admit only the
`user` who asked or a `system` process. Without a reading, any envelope actor kind could journal a
backtest a go-live record later names (`AgentDeployed`, §9.18), including an `agent`
(the research agent), a `broker`, or a `platform_operator`. Rule 83 already refuses a `client`.

## Decision

1. **The writer.** Both records are written by workspace services, the control stream's single
   writer (§2). The envelope's `actor` is the principal the run is for: the `user` who asked
   (`POST /backtests`, workspace API §4.2 and its rule that every event names its principal), or a
   `system` actor, the backtest runner or the forward-paper evaluator that ran it. Any other kind,
   `agent`, `broker`, or `platform_operator`, is refused `schema` at `actor.kind`, after rules 143
   to 145. A `client` stays refused by rule 83 first.
2. **No other reading is taken.** `report_version` stays an `integer`: §9.18 gives its value
   (2 for a backtest, 1 for an evaluation) as its meaning, not as a rule, and the vectors' oracle
   checks the base drafts carry it. §9.18's "internal paper workspace only" for an evaluation is
   not checked: whether a workspace is internal is not on the draft, and no rule reads the
   envelope's `environment`.
3. **Where it lives.** `mandate-journal`'s `backtest_records` module and `control.py`'s
   `backtest_violations` enforce item 1; the vectors' `backtest_records` section holds a refused
   draft for each refused kind and a valid draft for each admitted one, cited `DEC-1141`.

## Rationale

The tighter reading refuses only writers no spec names for these records, and it adds no risk: no
fold reads either record, refusing one never blocks a risk reduction, and a backtest the research
agent could journal in its own name is exactly the self-flattering record DEC-1000 and DEC-1002
close against. It matches §9.13's precedent for a record a principal asks for and a process runs.
Item 2's readings would refuse records the spec admits and are left to the spec.

## Alternatives considered

- **`system` only, as rule 137.** Rejected: the workspace API names the asking principal in
  `actor`, so a backtest the owner asked for may carry the owner's `user` actor.
- **No actor check.** Rejected: it leaves an `agent` able to journal a backtest or an evaluation of
  its own theses.
- **Pin `report_version` by value.** Deferred: it is a rule §9.18 does not state, and a report
  version change would then need a record version change as well; a spec change can add it.
