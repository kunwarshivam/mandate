DEC-1151 found that `mandate-spec` asked for the stop-limit offset only for crypto, so a live
Robinhood equity mandate with no offset was confirmed and deployed, and B3 then had no form to
protect its share with (R22). Mandate spec V-008 and DEC-539 item 2 already say what V-008 reads:
the classes the connection's profile protects with a stop-limit, failing closed without the
profile. This change builds that, and scripts the rehearsal's market move through the stop.

## Decision

1. **V-008 and W-002 read the connection's profile.**
   - `ValidationContext` gains `stop_limit_asset_classes`: the classes the connection's
     capability profile protects with a stop-limit, or `None` for the profile absent.
   - V-008 requires the offset, with protection enabled, when any class the universe allows is in
     it. With the profile absent, any allowed class counts, so V-008 fails closed (mandate spec
     §4).
   - W-002's worst case, and `worst_case_stop_distance`, add the offset under the same test
     (DEC-539 item 3).
   - Disabled protection with an offset is still V-008, whatever the profile.
   - Version 1's `crypto_stop_limit_offset` is the offset (DEC-539 item 5). The schema's version 2
     rename is not built here.
2. **Where the classes come from.**
   - **The control-stream fold.** `ValidationContext::from_journal` reads them from the
     connection's latest `ConnectionEstablished`, which now carries its `broker`, by DEC-539 item
     2's fixed table (`mandate_spec::context::stop_limit_asset_classes`):
     - `alpaca`: crypto only, since equities get OCO or bracket legs;
     - `robinhood`: equities and crypto, since equities get a stop-limit only (DEC-529 item 7);
     - any other broker, a record naming none, a revoked connection, or none at all: the profile
       absent.
   - **A connection the stream does not record.** Phase 1's paper connections journal no
     `ConnectionEstablished` and are Alpaca's (DEC-969 item 6, LT-14), so a paper mandate on one
     reads Alpaca's row. A live mandate reads the profile absent: a live connection cannot be
     recorded without its record. This is `unrecorded_stop_limit_asset_classes`, read by the CLI's
     confirm and deploy (`check_rules`) and by the run's control-stream check
     (`confirmed_version`).
   - **The run's own validation context** (`run_context`). A paper connection reads Alpaca's row.
     A live one reads the profile absent, which for v1's two classes is Robinhood's row.
   - **The refcases harness** reads `stop_limit_asset_classes` from the cases' context and from
     `validation_context_defaults` (`[crypto]`). MC-K08, the version-1 case, now passes; the other
     MC-K cases need schema version 2 and fail as before.
   - Consequence for the founder: a live Robinhood mandate with no `crypto_stop_limit_offset` is
     refused `version_invalid` at `version confirm`, and the rehearsal's mandate sets `0.01`.
3. **The rehearsal's market.** The rehearsal simulator answers `POST /rehearsal/market` with
   exactly `{"quotes": {symbol: decimal text}}`:
   - it moves each quote, which triggers every stop the quote reaches;
   - it offers the script's unused fills to every working order, as a place offers them to the
     order it creates;
   - it answers every order's record.

   Only a rehearsal server, which listens on loopback alone, has the route. Any other body is
   `400` with nothing changed. Step 2t uses it: the market falls to 80.5, through B3's stop of
   80.76, and the script's sell fill takes the stop at 80.5, inside its limit of 79.9524. The
   account is flat at the simulator.
4. **What the rehearsal showed next (R23, not decided here).** Step 2u, the same command on the
   account the stop left flat, is refused before any place call, but by the wrong check: `the
   account the connection binds is not flat`. Two things combine:
   - the simulator lists the sold-out position as a row of quantity zero, which DEC-902 item 3
     allows;
   - the lapse counts position rows, not their quantity (`crates/mandate-paper/src/connection.rs`,
     `lapse`).

   Refusing is the safe stop either way. The designed answer is `the connection record is spent`:
   the entry's fill spends the record (DEC-910 item 3), and DEC-529 item 13 allows one order per
   live record. Counting a zero row as flat refuses less, so it is the founder's to accept, with
   its tests first.

## Not closed here

- **The owner's flatten on a second entry.** Each of these needs its own decision or story, so
  the rehearsal does not script them:
  - DEC-529 item 13 and DEC-910 item 3 refuse a second entry on the same live record by design;
    a second entry needs a fresh connection record, which means a new connect check, record,
    version and deployment.
  - The shipping CLI's `mandate agent` command offers `deploy` alone. The owner's exit, pause,
    stop and kill switch exist in `mandate-cli`'s library (`agent.rs`), but no command reaches
    them, so the owner's flatten is not reachable from the CLI.
  - On Robinhood a sell's fill has no published price, the order record nor the position: the
    position's average is the buys'. DEC-1151's `recorded_fills` books buys only. The stop's fill
    is never booked, and the next run's own-fill pass asks the broker by client order id for the
    owned stop, which Robinhood does not offer, so it would stop fail closed (not reached: the
    lapse refuses first).
- **Spec text.** The table in item 2 is DEC-539 item 2's. MC-K08's status follows in a spec PR,
  since `status.toml` is protected (ES-22).

## Rationale

The spec already said what V-008 reads, and DEC-539 gave the table to read until the profile is
an input. Building it refuses exactly the mandates that would deploy unprotected on Robinhood.
Every paper mandate stays as it was, because a paper connection is Alpaca's. The market route
lets the rehearsal show the stop working at the broker. The runs after it show what a sold-out
position meets, without inventing a price for a sale nobody reported.

## Alternatives considered

- **Pass the capability profile itself into validation.** It is cleaner, but `mandate-spec` would
  then read `mandate-domain`'s profile cells. DEC-539 named the fixed table as the step before it.
- **Treat a connection the stream does not record as the profile absent, paper included.** That
  is strictest, but every Phase 1 paper deployment of an equity mandate would then be refused
  V-008, though its connection is Alpaca's by construction.
- **Count a zero position row as flat in the lapse.** It is not decided here, because it refuses
  less (item 4).
