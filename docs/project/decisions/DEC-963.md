## Context

`cargo nextest run -p mandate-paper --features live,rh-sim` failed five tests on `main` at
`2b33843`, the build the R0 rehearsal runs. Each pinned the default build's answer and was never
made to read the build it runs in:

- `tests/connection.rs`: `a_live_record_refuses_the_connector_this_build_does_not_hold`,
  `a_revocation_of_another_connection_does_not_refuse_this_one` and
  `a_re_establishment_after_a_revocation_restores_the_connection` asserted
  `Err(ConnectionRefusal::NotBuilt)` for a live Robinhood record. With `live`, `ROBINHOOD_LINKED`
  is `true` and the record is served, as DEC-910 item 1 says it must be. #1297 had settled that
  these "fail under `live` by design" because CI builds the suite only in the default build.
- `tests/door.rs`: `the_door_names_its_own_refusal_where_the_shell_would_answer_live`, the same
  pin through the run's door.
- `tests/connect_check.rs`: `the_default_binary_refuses_the_connect_check_before_any_login`
  expected the default build's "this build holds no Robinhood host". With `rh-sim` the binary
  refuses for the rehearsal's own reason (no `MANDATE_RH_SIM_ENDPOINT`), and with `live` alone it
  went on to log in to Robinhood's pinned host, which no test may do (rule 8).

The same five fail with `--features live`; with `--features rh-sim` alone only the connect
check failed. So no code was wrong: the expectations were the default build's.

## Decision

1. **Each pin expects what its build serves.** The three connection pins and the door pin
   compare against an oracle read from the test crate's own `cfg!(feature = "live")`, never the
   crate's `ROBINHOOD_LINKED` or `Build`: `connector_not_built` without `live`, the live
   connection over the record's account with it. The connect check, renamed
   `the_binary_refuses_the_connect_check_before_any_login`, now hands the binary a rehearsal
   endpoint off loopback (Robinhood's own address), so every build refuses before any login and
   none can dial: the default build "holds no Robinhood host", `live` refuses the rehearsal
   variable beside its pinned host, and `rh-sim` (alone or with `live`, which it wins over)
   refuses an endpoint off loopback. The expected line is read from `cfg!`. All 235 tests pass in
   the default, `live`, `rh-sim` and `live,rh-sim` builds. Each oracle was shown to fail on a
   seeded bug: the door shut under `live,rh-sim` and the door open in the default build each fail
   the four connection and door pins; `Build::CURRENT` letting `live` win over `rh-sim`, and the
   rehearsal accepting an endpoint off loopback, each fail the connect check. This replaces
   #1297's reading; it only adds builds in which the pins hold.
2. **CI tests the runner's `rh-sim` build.** `cargo xtask ci test-rh-sim` runs
   `cargo nextest run --features rh-sim` for every workspace crate that declares the feature,
   each in its own build: `mandate-mcp`, as before, and now `mandate-paper`, so the connect check
   and the rest of the runner's rehearsal build cannot rot again. An xtask test holds the list
   equal to the crates that declare `rh-sim`. It stays in `fast-pending` rather than a new shard:
   the run rebuilds only `mandate-paper` (no other crate's features change) and took 19 s from a
   clean `mandate-paper` on 4 cores, against `fast-pending`'s 162 s, far inside DEC-464's ten
   minutes; a shard would add a runner and a toolchain install to save seconds. If the job nears
   the limit, `test-rh-sim` moves to a job of its own.
3. **Proposed, for the founder: CI also runs `mandate-paper`'s tests with `live,rh-sim`.**
   DEC-529 item 3 (founder-accepted) lets no CI build enable `live` except one compile-only
   `cargo check`, and `cargo xtask live-feature` enforces it. A `live,rh-sim` build compiles no
   Robinhood host (`MCP_HOST` and its pin are `cfg(all(feature = "live", not(feature =
   "rh-sim")))`), so it could reach no broker, but running it in CI still enables `live` in a CI
   build, which narrows the founder's rule; DEC-79 reserves that. Until the founder decides, the
   most conservative option holds: CI does not run it. Item 1 makes the suite pass in that build,
   and item 2 runs every pin's `rh-sim` half; the `live` halves are checked by the founder's local
   build and the builder's runs recorded above. If accepted, the change is a second
   `test-rh-sim` invocation with `live,rh-sim` for `mandate-paper` and the live-feature check
   allowing exactly that one test form.

## Rationale

A test that is true only in one build, in a crate built three other ways, either fails the
builds nobody runs or gets read as "fails by design" until a real regression hides behind it.
Reading the build from the test's own `cfg` keeps each assertion exact in every build, and an
independent oracle catches a door that opens in the wrong build. Running the rehearsal build in
CI is what keeps it from drifting again; doing it with `live` needs the founder.

## Alternatives considered

- **Gate the pins with `#[cfg(not(feature = "live"))]`.** Rejected: that skips them in the build
  the live order uses, where the served half is the one that matters.
- **Run `live,rh-sim` in CI now.** Rejected for an agent: it narrows DEC-529 item 3 (item 3).
- **Leave the connect check without the rehearsal variable.** Rejected: with `live` alone the
  binary would log in to Robinhood's real host from a test.
- **A new CI job for `test-rh-sim`.** Not needed yet (item 2's timing).
