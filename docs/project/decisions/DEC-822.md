## Context

The workspace API shares one Postgres with the runtime and executor processes. The journal is the
only channel between them, through LISTEN/NOTIFY, and the kill switch must always be up (API-8).
Serverless and sleeping hosts are therefore ruled out, and so are auto-suspending databases.

The L2 lane recommended one small always-on VM. The coordinator offered these options, at prices
quoted from memory that the founder confirms before buying:
- Hetzner CX22, about €5–6 a month;
- Oracle Always Free;
- DigitalOcean, about $24 a month;
- AWS Lightsail, about $24 a month;
- Google Cloud.

## Decision

1. **Host.** One Hetzner Cloud CX22: x86_64, 2 vCPU, 4 GB, Ubuntu 24.04 LTS. The spending is about
   €5–6 a month, and the founder confirms the current price before buying.
   - **Region.** The CX line is offered in Hetzner's EU locations, so the host's data sits in the
     EU. It holds only the founder's own paper data, so DEC-434 item 13's US-region recommendation
     for managed cells does not apply to this demo. Any customer data needs a new decision.
   - **What runs on it.** Postgres 18 and the API, each as a systemd service. The runtime and
     executor join the host only once the per-service controls of item 5 are in place.
2. **Access.** The host sits behind a Cloudflare Tunnel named `owlhead-api`:
   - no inbound HTTP port is open and no origin IP is published;
   - `api.owlhead.ai` is a proxied CNAME to the tunnel;
   - the provider firewall allows only SSH, from the founder's IP where possible.
3. **Who operates it.**
   - **The founder.** The founder creates and operates the VM with their own SSH key. That key and
     the Cloudflare tunnel token are the founder's own credentials. The founder enters them
     directly, and they never appear in the repository, a PR description, an issue or chat.
   - **Agents.** Agents never receive host, Hetzner or Cloudflare access or credentials. No agent
     test or tool calls `api.owlhead.ai` or the real Hetzner or Cloudflare APIs (rule 8).
   - **The L2 lane.** It writes `deploy/`: the runbook, scripts and systemd units, with no secrets.
     The founder reads each script before running it. No script fetches code from outside the
     pinned repository checkout or the pinned package sources the runbook names, and none
     contacts anything but those sources and the tunnel.
4. **Secrets follow OPS-1, with one exception for backups.**
   - **In the vault, only.** Every credential lives in the vault: the L2 lane's minimal local vault
     behind the `Vault` trait, until infrastructure §5's vault replaces it. That covers the SMTP
     password (DEC-820 item 3), the Alpaca OAuth client secret and the OAuth tokens (DEC-821). The
     founder enters each through the vault's import command on the host, never through a file or
     an environment variable.
   - **Outside the vault.** Exactly three values sit outside the vault:
     - the vault key;
     - the session signing key;
     - the Cloudflare tunnel token, which `cloudflared` needs.

     Each is a root-only file (mode 0600), passed to its service with systemd `LoadCredential=`,
     so no live process holds a credential in an environment variable. The database connection
     uses the local socket and needs no password.
   - **The founder's exception for the paper demo.** The founder chose on 2026-10-08 to keep
     Hetzner's whole-disk backups for recovery from losing the VM. Those backups contain the vault
     key and the tunnel token, so the vault's contents could be read from a backup and the tunnel
     could be impersonated. For the paper demo only, the founder
     accepts this exception to OPS-1's rule on backups. The credentials are paper-only and the
     backups live in the founder's own Hetzner account. Before any live credential or customer data
     reaches this host, backups must exclude every secret outside the vault's own encrypted
     snapshots, and that needs a new decision.
   - **Restoring from a backup.** A whole-disk backup is crash-consistent for a running Postgres.
     After a restore, the journal is verified (OPS-8) before anyone trusts it.
5. **Per-service isolation**, which infrastructure §3.1 and §9 and OPS-13 require. The L2 lane's
   units give:
   - each service its own system user;
   - each service its own database role, with only the grants it needs;
   - systemd sandboxing (`ProtectSystem=strict`, `NoNewPrivileges=`, `PrivateTmp=`);
   - default-deny egress through `IPAddressDeny=any`, with an allow list per service. The API
     reaches only Postgres and the Supabase project's host, which it needs for OIDC and JWKS
     verification (DEC-820). The token-exchange process, which is not the executor, reaches only
     the hosts DEC-821 allows. The runtime, once on this host, gets no route to a broker or the
     internet.
6. **The kill switch without Cloudflare.**
   - **The gap.** Cloudflare sits in front of the API, so a Cloudflare outage or account problem
     would cut the web app off from pause and the kill switch (API-8). Cloudflare also terminates
     TLS and sees session tokens. That is accepted for the paper demo only.
   - **The fallback.** The founder can always reach the kill switch and pause with the `mandate`
     CLI over SSH on the host, which needs neither Cloudflare nor the web app. The runbook
     documents it, and the founder tries it once during the rehearsal.
   - **Live.** A live deployment needs a new decision.
7. **Hardening.**
   - SSH by key only, with no password login and no root login once the founder's admin user
     exists.
   - Unattended security updates.
   - The provider firewall as the only inbound path.
   - The API never trusts `CF-Connecting-IP` or any other forwarded header for authentication,
     authorization or lockout, unless the request is verified to have come through the tunnel.

## Rationale

The founder chose the lowest-spend reliable always-on host. The tunnel keeps the host off the
public internet except through Cloudflare.

## Alternatives considered

The founder was offered DigitalOcean, AWS Lightsail and Google Cloud, which cost more but have a
longer track record, and Oracle Always Free, which costs nothing but whose capacity is unreliable.
