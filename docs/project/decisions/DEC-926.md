# DEC-926: The rh-sim build dials loopback only, the feature lives on mandate-mcp alone, and the simulator's OAuth takes the readings that add no risk

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-16 (UTC) |
| **Decided by** | `claude-code` (builder), under DEC-79 (reversible engineering) and DEC-176 (each reading only tightens DEC-922) |
| **Story or claim** | S2, DEC-922 lane B1, claim #1341 |

## Decision

1. **Loopback only, in `mandate-mcp`.** In the `rh-sim` build every URL `mandate-mcp` dials, the
   MCP endpoint (`PinnedEndpoint`) and every authorization-server URL discovery reads, must be on
   a loopback IP literal, `https` or plain `http`; any other host is `McpError::OffLoopback`.
   DEC-922 item 2 is enforced where the dialing happens, so every binary built with the feature
   inherits it, rather than in one binary's argument parsing. The test build keeps its own rule;
   every other build, the `live` one included, is the production build and never takes plain
   `http` (LT-1 unchanged).
2. **The feature lives on `mandate-mcp` alone, and only an explicit flag turns it on.** No crate
   may turn on `rh-sim` in another, by a feature or by a dependency of any kind;
   `cargo xtask live-feature` refuses it. So no workspace build, test run or `live` build ever
   links it; only `cargo xtask ci test-rh-sim` passes `--features rh-sim`, and CI runs that part
   in the `fast-pending` job. `tests/production.rs` runs without the feature and
   `tests/rehearsal.rs` with it.
3. **The simulator binary needs no feature.** `mandate-rh-sim --script <file> [--port <n>]`
   binds `127.0.0.1` only and takes no other argument, so nothing can point it elsewhere. It
   always requires the OAuth login.
4. **The simulator's OAuth.** The issuer is `http://127.0.0.1:<port>/oauth` on the MCP listener.
   Only public clients register, with exactly one `http://127.0.0.1:<port>/callback` redirect.
   An authorization request must carry every member the real login sends, once, for a
   registered client and its own redirect, with an `S256` challenge and the endpoint as
   `resource`, or it is a `400` that redirects nowhere. The page asks the owner to approve or
   deny; a request is decided once. A code is spent by its first redemption whether or not the
   redemption is refused. No refresh token is issued. Codes, client ids and tokens are counters,
   since the core reads no randomness; they guard fake money on loopback only. The simulator
   keeps no code lifetime, as it reads no clock; the client's own `LOGIN_LIFETIME` still holds.
5. **Scripted fills.** A fill applies, after the place has answered, to the first placed order of
   its symbol and side, at its price and its quantity or the whole unfilled quantity. It is used
   up only when the core accepts it, so a queued, terminal or re-sent order leaves it for the
   next match.
6. **HTTP reading.** A request without `content-length` has no body, as a browser's or
   `reqwest`'s `GET` sends it; a request with `transfer-encoding` is never read and closes
   unanswered.

Not decided here: the MCP session that carries the token (O2). `McpTransport` sends no Bearer
yet, so the rehearsal's tool calls through `mandate-mcp` wait on O2; the simulator already
requires the token, and its own tests call the tools with one.

## Rationale

DEC-922 asks for a rehearsal that runs the real login and can never reach a broker. Holding
every dialed URL to loopback in the library makes item 2 true of any binary, whatever its
arguments. Keeping the feature off every dependency edge means feature unification can never
carry it into the workspace's tests or the `live` build. Each OAuth reading is the stricter one
the RFCs allow, so a client that passes the simulator does not lean on leniency the real
authorization server may lack.

## Alternatives considered

- Only allowing loopback `http` in the `rh-sim` build, and leaving `https` hosts open: item 2
  would then rest on the runner's configuration alone.
- A crate forwarding the feature (an `rh-sim` feature on `mandate-rh-sim` or the runner naming
  `mandate-mcp/rh-sim`): one more place that could turn it on, in a build beside `live` or in
  the workspace's own test run, where it would unify into `mandate-mcp` and void
  `tests/production.rs`.
- Approving every authorization request without a page: simpler, but it skips the owner's step
  the real login has.
