## Context

The founder's direction of 2026-10-17: the product is an agent harness for trading, "like Claude
Code for trading", agentic where it thinks and deterministic where it touches money. Lane AH turns
the research run into a bounded loop with tools and records (E19-13). ADR-0005's design input names
four run kinds; this lane owns two, `owner` (the desk) and `explain` (an ASK's card text), plus the
desk and transcript surfaces and HI-26. DEC-192 already decided that "why" is answered from the
journal.

## Decision

1. **Two run kinds on E19-13's loop, nothing of our own.** `owner` and `explain` runs use E19-13's
   loop, gateway path, bounds machinery, metering, and run records, in the agent process beside the
   tick and never in it. This lane adds a tool set, the `answer` tool and its checks, one control-
   stream record, and the surfaces. Owner and explain runs follow E19-13's run rules: one in flight
   per agent, they pre-empt queued runs and never trading, and mode gates them (HI-15).
2. **Read only in slice 1.** Read tools, `note`, and `answer` only (EX-1).
3. **Scope by construction.** The tools read only the agent process's own folds: its agent stream,
   the account-stream records naming its intents or id, and the mandate document of the version in
   effect. No control-stream record: owner input reaches the tools only through the runtime's
   agent-stream copies. No argument names a scope; a foreign or absent ref is the same `not_found`
   (EX-2, EX-3).
4. **Who asks and who reads; no row added or widened.** Sending, one's own thread, an owner run's
   cited and fallback records, and its transcript are the *Chat thread with the agent* row, and the
   asking member only. The decision and order fields an owner run returns (the autonomy outcome and
   its rule, the dry run's verdict and reason code, a refused order's binding-gate verdict and first
   reason code) reach only that operator: DEC-192 (Accepted) says what a "why" answer is assembled from, and
   keeping those fields to the asker is this decision's own tightening under DEC-176.
   An approval's explanation, its cited records, and an explain run's transcript are *View agents,
   positions, decisions*; the explain menu returns the approval read's and the D2 and D4 reads'
   fields plus refs and the admission verdict, all within the view row's "decisions". An ideation or monitoring run's transcript stays *Read records* in slice 1,
   since its results hold licensed text (HI-23). Every field has one projection, workspace API
   §4.6.1's (EX-13). Other members do not see a member's questions at the desk; the journal's
   *Read records* holders see them as they see every record. Clients reach none of the desk's
   routes.
5. **Least context.** Tool results are a redacted projection: no quantity, price, limit value,
   dollar figure, P&L, account reference, broker number, or other agent's id. The question, thesis
   text, and headlines pass a deterministic numeric scrub before they enter a prompt. The web app
   renders the figures from the cited records. What still reaches the provider (symbols, sides,
   times, reason codes, rule names, holdings by symbol) is DEC-2243, Proposed.
6. **The answer and its checks.** The run ends with `answer`; the harness returns the first failing
   check (`empty`, `uncited_segment`, `unknown_citation`, `advice_language`, `too_long`) as the tool
   result, so the model may correct it within the run's `answer` bound; only a passing answer is
   shown. An answer with no segment and at least one `not_recorded` code (a closed list rendered from templates, never model text) shows as "not recorded"
  . Failure shows the deterministic fallback, never model text. The platform
   never re-runs a failed run.
7. **What the checks hold of DEC-192.** They enforce that each sentence cites a record the run read,
   and the cited record is always shown beside it. They cannot tell whether the sentence states
   the record truly. DEC-192's "adds no fact" is therefore held by the template (rung 3) and by
   showing the record (disclosure), not by a check; this is recorded as the reading in force, not a
   change to DEC-192, and templated slots over record fields remain the fallback if the residual
   proves material. The advice check covers the fixture list; paraphrases are a
   disclosed residual for counsel (DEC-2241).
8. **Records.** The runs are on E19-13's records. One new record, `OwnerQuestionSubmitted`, on the
   control stream (journal spec v0.50 §9.23, rules 190 and 191): owner input first, copied by the
   runtime; a guard-refused question is never stored. The asks of agent harness spec §15.6 go to
   E19-13's spec. Journal versions v0.48 and v0.49, §9.21 and §9.22, and rule numbers 165 to 189 are left for lanes I2 and AH, so the three changes never collide; whichever merges out of order renumbers its version only.
9. **Spend is settings, never constants** (the founder's clarification, relayed by the coordinator
   on 2026-10-17: DEC-997's $50 a month is the platform's demo and development spend, not a customer
   limit). Each turn is reserved through the gateway against the agent's daily model budget, the
   workspace's configured budget, and the deployment cap, as E19-13 meters every run. Who pays for
   customers' runs is DEC-2242 (the founder's: a plan allowance or the owner's own key); until
   DEC-2241 and DEC-2243 are accepted too, owner and explain runs call a model only in the
   platform's own demo and development workspaces, on the platform's key.
10. **The approval's explanation.** One `explain` run when the runtime raises an ASK, after its
    `ApprovalRequested` commits; the approval read starts nothing. Outside the
    approval's content and `content_hash`. Shown only when both deployment flags
    `desk.model_answers` and `desk.approval_explanations` are on, each off by default, until the founder decides DEC-2241 item 3.
11. **Bounds** (spec §15.7): owner runs 6 turns, 4 tool calls a turn and 16 a run, 3 `answer`
    calls, 60 s; explain runs 4 turns, 8 tool calls, 2 `answer` calls, 60 s or the approval's
    deadline; 1,000-character questions; 30 questions per member per risk day, 1 in flight.
12. **Preconditions.** No model call before E19-13's INF-5 change and run records are registered,
    `OwnerQuestionSubmitted` is registered, DEC-997 is accepted, and, for the workspace, either
    DEC-2241 and DEC-2243 are accepted (DEC-2242 is) or it is a platform demo or development
    workspace with `desk.model_answers` on (off by default). The desk serves the fallback until
    then. CI and the demo use recorded fakes only. A refused question starts no run; a question no
    run starts within 60 s reads `unavailable` with a fallback computed at read time.
13. **Slice 2 (planned, spec §15.12).** Desk actions become proposal cards built by deterministic
    code and sent only by the owner's own call with step-up (HI-26); its own spec change and DEC
    first.
14. **ADR-0005 §16, as the coordinator directed for this lane.** Each run's tool menu is fixed by
    its trigger before anything untrusted is read (item 2): slice 1's owner and explain menus hold
    no action tool, and slice 2 adds action tools only when the owner chose to make a request.
    Every shown answer records `written_after_reading`, the untrusted results in its context, and
    the desk shows it (item 3, EX-12). Untrusted results are spotlighted, as defence in depth only
    (item 5). Run summaries read through `memory.runs` are structured and untrusted (item 8).

*Note (coordination, not a decision):* lanes AH, I1, and I2 agreed in session messages that this
lane takes its DEC numbers from 2240, and its journal section and rules after theirs.

## Rationale

The journal already holds the real reasons (rule 5), so the honest explanation is assembled from it
and only phrased by a model. Running on E19-13's loop keeps one loop, one set of run records, and one
meter, as the coordinator directed. Keeping slice 1 read-only, scoping by construction, and
redacting figures at the tool boundary puts tenant isolation and least context in code, where a
model cannot argue with it.

## Alternatives considered

- **A separate explainer in the workspace services, with its own records** (this DEC's first
  draft). Rejected on the coordinator's direction: it duplicated E19-13's loop and records.
- **Send figures to the model.** Rejected for now: the "Do not" rule; the cited records show them.
- **Let the model answer freely, or show the raw trace only.** DEC-192 rejected both.
- **Templated answer slots only.** Stronger against misstatement, but too rigid for open questions;
  kept as the fallback of item 7.
