| | |
|---|---|
| **Status** | Accepted (agent: a reversible engineering reading under DEC-79 and DEC-176 — it only adds a refusal on the live arm, changes no paper outcome, and loosens nothing) |
| **Date** | 2026-10-16 (UTC) |
| **Decided by** | An agent (Claude Code, the live-door unspent-placeholder builder), under DEC-79 and DEC-176 |
| **Story or claim** | E7-26; claim [#1333](https://github.com/kunwarshivam/mandate/issues/1333); DEC-529 item 3; DEC-910 item 3; DEC-918 items 1 to 3; DEC-921 ([#1339](https://github.com/kunwarshivam/mandate/pull/1339), one PR with tests committed first) |

## Context

DEC-529 item 3: "The live build refuses to start unless the account is flat (DEC-470 item 1)
and the connection record is unspent." DEC-910 item 3 reads flat off the connector's snapshot
and unspent off the journal's account stream; DEC-918 item 1 wraps that lapse for the run as
`unspent(connection, rows, held)`, whose `rows` are "the journal's own read of the account
stream" and whose `held` is "handed by the live arm's preflight".

#1328 wired the door into `run()` before the live arm existed, so `the_live_door` in
`crates/mandate-paper/src/lib.rs` calls `unspent(&connection, &[], &Held { positions: 0,
open_orders: 0 })`. Those inputs come from no read. An empty account stream and a snapshot of
zero positions and zero orders are exactly what a flat, unspent account produces, so the call
passes every live connection whatever the account holds. Nothing reaches it today: the default
build refuses a live connection `connector_not_built` first, and a `--features live` build is
refused by the shell's own `DeploymentRefusal::Live` behind the door. But the literal is a trap.
When the live arm is wired, the call already looks finished, and a spent record or a non-flat
account would pass silently.

## Decision

1. **The door holds no evidence, so it says so.** A new door frame,
   `unsupplied(connection) -> Result<(), PaperError>` in `crates/mandate-paper/src/door.rs`, is
   the lapse's call wherever the run has neither the account stream's rows nor the snapshot's
   counts. A live connection refuses with `PaperError::Lapse(LapseRefusal::NotSupplied)`,
   reason code `lapse_evidence_not_supplied`, message "the lapse was handed no account-stream
   read and no account snapshot". A paper connection makes no check, as `lapse` makes none on
   one (LT-14; DEC-910 item 3: "a paper run makes no check"). The environment alone decides,
   whatever broker the connection names, matching `lapse`'s own test.
2. **The placeholder goes.** The implementation replaces the `unspent(&connection, &[],
   &Held { .. })` call in `the_live_door` with `unsupplied(&connection)`, so `run()` holds no
   empty-read or zero-count literal. The live arm clears the refusal only by calling `unspent`
   with the rows its journal read returned and the counts its preflight's snapshot listed;
   that PR's review judges that both are real reads (DEC-918 item 1: "re-derived by nothing").
3. **Signatures stay as DEC-918 froze them.** `unspent`, `chosen` and `account_stream` keep
   their signatures and bodies (DEC-918 item 4). `unsupplied` is a fourth frame beside them,
   not a change to `unspent`.
4. **Where the refusal lands.** It is a lapse refusal, so it lands where `unspent` would have,
   after `chosen` and `account_stream`, ahead of the shell's phase-1 fold and every credential
   read (DEC-918 item 3). In the default build no live connection survives `chosen`
   (`connector_not_built`), so the run's answers in every build CI runs are unchanged, and the
   paper path keeps today's run exactly (LT-14). Under `--features live` a live deployment now
   refuses `lapse_evidence_not_supplied` at the door instead of passing the door and refusing
   `DeploymentRefusal::Live` at the fold. That is one more refusal in front of the shell's,
   the side DEC-918 item 3 allows.
5. **What pins it.** One PR under DEC-921, tests committed first (DEC-77's order kept inside
   it): the first commit adds the variant with its message and code (pinned in
   `tests/connection.rs`'s refusal table), the `unsupplied` stub reporting
   `Unimplemented { story: "E7-26" }`, and two pending pins in `tests/door.rs`, each failing at
   the stub: a live connection with no evidence refuses `NotSupplied` (Robinhood and Alpaca
   alike), and a paper connection with no evidence starts as today. The implementation commit
   fills the stub, swaps the call site, and touches the tests only to delete the two `#[ignore]`
   lines. Under DEC-918 item 4 the pins drive the frame, not `run()`. No run-level probe can
   observe the refusal in the default build, because `chosen` refuses every live connection
   first, so the review checks the call-site swap.

## Rationale

The reading only refuses more: a live connection that passed the door now refuses, and nothing
that refused now passes. It changes no paper outcome. A typed refusal is the explicit
`NotSupplied` state the empty literal hid. A reviewer of the live arm sees a refusal that must
be replaced with real reads, where before they saw a call that looked complete. AGENTS.md rule
3: missing evidence resolves to the safe default that adds no risk.

## Alternatives considered

- **Change `unspent` to take an evidence enum (`NotSupplied` or `Read { rows, held }`):**
  rejected. DEC-918 item 4 froze its signature, the merged pins call it with real inputs, and
  `Read { rows: &[], held: zero }` would still be writable. The new frame gets the same result
  without reopening an accepted decision.
- **Make `Held` constructible only from a connector snapshot type:** rejected for now. No live
  snapshot type exists yet (the live arm's preflight is unwritten), and an empty journal read is
  a legitimate answer for a fresh record, so no type makes "an empty read" itself
  unrepresentable. That binding belongs with the live arm's preflight, when the type exists.
- **Leave the literal and document it:** rejected. A guided rung for a trap the type system can
  hold (AGENTS.md trust ladder), and a doc comment was what the literal already had.
- **Gate the door's lapse call on `cfg(feature = "live")`:** rejected. The refusal belongs in
  every build that can choose a live connection, and keeping one unconditional call means no
  build skips it.
