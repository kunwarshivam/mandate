# DEC-861: The founder's OAuth login reads one callback on 127.0.0.1, lives 600 seconds, and keeps only the token (O1b part 2)

## Decision

1. **The listener** binds `127.0.0.1:0` only, and its redirect names the bound port. `accept`
   takes it by value: one connection, one request, one answer, then closed.
2. **The request** line is `GET <target> HTTP/1.1`, with the head complete within 8 KiB, else
   `malformed`. The target goes to `PendingLogin::callback`. The browser gets `200` or `400` with
   fixed text naming no state, code or reason. Any request spends the login (DEC-855 item 1).
3. **The lifetime** runs on a clock started when the login began. At or after 600 seconds the
   request is `login_expired`, its target unread (DEC-691 item 6). Without a callback it waits,
   holding no token, until the founder stops the run.
4. **The exchange** is one form `POST` with exactly `grant_type`, `code`, `redirect_uri`,
   `client_id`, `code_verifier` and `resource` (RFC 6749 §4.1.3, RFC 7636 §4.5, RFC 8707), and no
   `authorization` header. Only `200` is a token, with no redirect followed. `access_token` must
   be non-empty visible ASCII and `token_type` `Bearer` in any case, else `malformed`. A
   `refresh_token` is never read, so a restart logs out. `expires_in` is left to its own slice.
5. **Secrets.** `AccessToken` is a `SecretString`. LT-9's canary test scans the browser's answer,
   every `Debug`, and the exchange's errors for the code, the verifier and the token.

## Rationale

Each refusal ends the login before a token is kept (rule 3); one request leaves nothing to replay.
