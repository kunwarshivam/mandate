## Decision

1. `vercel.json` and its test (`web/src/lib/vercel-policy.test.ts`) are removed. `web/scripts/workers.mjs`
   now refuses any `vercel.json` at the repository root, so a second host's configuration cannot
   come back unnoticed.
2. This ends DEC-1005 item 4, which kept the file, still deploying `main` only, until the cutover.
   DEC-465 items 1 and 3 fall away, as DEC-823 item 2 said they would.
3. Nothing here touches DNS or the Vercel project. The coordinator moves `owlhead.ai`, `www` and
   `app` onto the Worker after its first deploy.

## Founder steps this leaves

Disconnect the Vercel project from the repository (Vercel → the project → Settings → Git →
Disconnect), or delete the project. Until then, with no `vercel.json`, Vercel builds and publishes a
preview of every pushed branch, and `owlhead.ai` and `www` keep serving Vercel's last production
deploy until their DNS moves. The previews hold the same public fixture app and no secret.

## Rationale

The app is hosted on Workers alone (DEC-823). A dormant `vercel.json` would let a reconnected
Vercel project serve a second copy, and the founder asked for Vercel to go.

## Alternatives considered

- **Keep `vercel.json` disabling every branch until the project is disconnected.** It has no
  preview window, but it leaves Vercel configuration in the tree, which the founder asked to remove.
