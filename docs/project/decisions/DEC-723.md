## Decision

Proposed: **add an `info` kind to spec §3.2 for a decision the risk gate's dry run refused** (for
example `decision_refused`), with no text key. An `info` kind goes only to the pull channels and
the next brief (§3.1), so nothing more is pushed to the owner.

**The question.** E8-9 replaces the free-text `message_key` of `NotificationRef` in
`mandate-runtime` and `mandate-executor` with the closed notice kind of spec §3.2. The runtime
emits one such alert: `message_key: "decision_skipped"` (`crates/mandate-runtime/src/step.rs:538`),
after `DecisionMade` is journaled, when the gate's dry run denies a decision. Spec §10 counts it as
"one runtime key". No row of §3.2's closed catalogue has a dry-run deny as its cause, and no
decision maps it. Today the alert reaches only the paper tracer's report: no dispatcher exists yet,
so no owner receives it.

**Interim, until the founder decides (the conservative option).** The runtime keeps emitting
`decision_skipped` as it does today. E8-9 S3's tests pin neither reading: they cover the other kinds
and leave this one alert's mapping pending this decision.

## Rationale

- The proposed kind keeps the refusal visible to the owner as an attributed `info` notice, with the
  reach §3.1 gives `info`: pull channels and the brief, never a push. It removes nothing the owner
  is told today.
- It changes the closed `NoticeKind` in `mandate-notify` (33 → 34), DEC-720's `OwnerAlertSent` kind
  set, and the notifications and journal specs, each in its own spec change.
- Spec §10 names the alert and §3.2 does not catalogue it, so the code and the spec disagree. Under
  `AGENTS.md` ("if code and docs disagree, stop and ask") and DEC-176, a reading that removes an
  owner-facing alert loosens what the owner is told rather than tightening it, so the choice is the
  founder's.
- Either option adds no trading risk: the alert is a notice about a decision already refused, and
  nothing the agent may do changes.

## Alternatives considered

- **Map it to no kind.** The dry-run deny stays a journal record only: `DecisionMade` already holds
  the refusal. This needs no change to the closed kind set, and spec §10's "one runtime key"
  becomes none. The runtime stops emitting `Effect::Notify` for it, so the owner gets no notice of
  the refusal on any channel; the spec states a brief listing only for `ask_suppressed` decisions
  (DEC-195), not for dry-run denies.
- **Reuse an existing kind.** Not recommended: no row's cause is a gate refusal (`risk_limit` needs
  a `RiskLimitTriggered`).
