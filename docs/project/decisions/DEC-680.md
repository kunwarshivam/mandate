## Decision

1. **Two crates.**
   - `mandate-api` (layer 4, pure, safety-critical) holds the contract: the shapes, the problem
     document, and the idempotency rule, checked equal to the JSON Schemas under
     `schemas/workspace-api/`. It has no transport. Principals, roles, and `authorize` are
     `mandate-identity`'s (L1); the `Authenticate` trait is `mandate-api-server`'s.
   - `mandate-api-server` (claim #750), created by the story that serves the first route, holds
     the routes, middleware, and the Postgres journal client. It sits above
     `mandate-journal-pg`, is impure, and is safety-critical. It may not depend on `mandate-executor`, `mandate-runtime`, a broker
     connector, or `mandate-cli`; its `forbidden_internal` list says so (spec §1.4: no trading
     authority, the journal is the only channel).
2. **HTTP stack: `axum` on `hyper` 1 and `tokio`,** with `tower` middleware for authentication,
   CSRF, idempotency, rate limits, and problem rendering. Server-sent events (`GET /changes`, §3.1)
   use axum's SSE support.
3. **API-8's reserved path is a second listener on its own runtime.** Pause and the kill switch
   are served by their own `tokio` runtime and `sqlx` pool, sized at start and shared with no
   other route. The ordinary router cannot exhaust them, and they read no read-model table.
4. **OpenAPI 3.1 is generated, never written by hand.**
   - The shapes in `mandate-api` derive their schemas with `utoipa` (`ToSchema`). The derives sit
     behind an `openapi` cargo feature, so the pure crate's default build and its safety-critical
     dependency list do not change.
   - Scalars parsed through `try_from = "String"` declare `value_type = String` and a `pattern`.
     Decimals therefore appear as patterned strings and never as `number` (§3.1).
   - `cargo xtask openapi` writes `docs/api/openapi.json` from `mandate-api-server`'s router.
     `cargo xtask ci lint` regenerates it and fails on any difference, so the checked-in document
     is always what the code serves. The web app (L4) and audit (L5) lanes read that file.
   - A test asserts that every route in `mandate-api`'s route table appears in the document,
     with its method, path, and security scheme, and that no schema of a closed safety enum
     (§3.2) is open.

## Rationale

- **axum.** The workspace already runs `tokio` (mandate-cli, mandate-journal-pg via `sqlx`).
  `axum` is a thin layer over `hyper` with no runtime of its own, and its middleware is plain
  `tower`, so each concern of §3 (authentication, CSRF, idempotency, the reserved pool) is one
  testable layer. It is the most used Rust HTTP framework, and handlers are ordinary async
  functions over typed extractors, which keeps the safety logic in `mandate-api` rather than in
  framework code.
- **Generated OpenAPI.** §3.1 requires the document to be generated from the Rust types. A
  derive reads the same `serde` attributes the server encodes with (`rename_all`, `try_from`,
  `default`), so a renamed member or a new enum value changes the document in the same commit,
  and CI catches a document that was not regenerated.
- **The trade-off.** `utoipa` is a proc-macro dependency with a few transitive crates, and its
  output must be checked against what `serde` actually emits. A hand-written generator would add
  no dependency, but every shape would need a second, hand-kept description. That is exactly the
  drift the generated document exists to prevent, and in a safety contract it is the worse risk.
  Gating the derives behind a feature keeps the dependency out of every build that does not
  render the document.

## Alternatives considered

- **`actix-web`.** Mature and fast, but it brings its own actor runtime beside `tokio`, and its
  middleware is not `tower`, so the reserved pool and the journal client would sit on two
  concurrency models.
- **`poem` with `poem-openapi`.** OpenAPI comes built in, but the community is smaller and the
  types would carry the framework's attributes, tying the contract crate to the server framework.
- **`dropshot`.** OpenAPI-first and well suited to typed APIs, but it generates OpenAPI 3.0 through
  `schemars`, and it owns the server loop, which makes the API-8 second listener harder.
- **`warp`, or bare `hyper`.** `warp`'s filter types make middleware hard to read and review. Bare
  `hyper` would mean writing routing and extraction ourselves.
- **A hand-written OpenAPI generator** (a `Schema` trait per shape in `mandate-api`, rendered by
  xtask). No new dependency, but two descriptions of every shape. It stays the fallback if the
  founder declines the `utoipa` row; the CI drift check is the same either way.
- **gRPC at the edge.** Rejected by spec §3.1.
