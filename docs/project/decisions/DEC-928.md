# DEC-928: The shell binds the Robinhood connector over one long-lived runtime, and refuses to reconcile a Robinhood account until its account fields have a source

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-16 (UTC) |
| **Decided by** | The Claude Code builder of lane C1, under DEC-79's delegation of reversible engineering decisions and DEC-176's rule that a gap is resolved by the reading that adds no risk |
| **Story or claim** | E7-6; the first live trade brief's C1 wiring (DEC-531); the lane's claim issue and PR |

## Decision

1. **The tool seam is `mandate-mcp`'s.** The `Tools` trait (one `tools/call`, DEC-860 item 2)
   moves from `mandate-robinhood` to `mandate-mcp`, which implements it for `McpClient`: the
   client's allowlist, halt and budget refuse exactly as `McpClient::call_tool` does, and the
   answer is the server's `result` JSON byte for byte. `mandate-robinhood` re-exports it, so
   `mandate_robinhood::Tools` still names it. The implementation sits beside the client because
   only `mandate-mcp`'s own test build may dial its loopback test server over plain `http`
   (DEC-849 item 2), so only there can a test judge it.
2. **One runtime for the connector's life.** `mandate_shell::robinhood::RobinhoodBridge` holds a
   tokio runtime and the one `RobinhoodConnector`; the shell's `Connector`
   (`RobinhoodShellConnector`) drives each `BrokerConnector::call` to its end on that runtime.
   Unlike the Alpaca connector's runtime, built per call, it is not rebuilt: an MCP session's HTTP
   connections belong to the runtime they were opened on, so the client is connected on the
   bridge's runtime and every later call is made on it. `Connector::profile` is
   `robinhood_profile`, never the trait's Alpaca default.
3. **The Robinhood reconciler reads, then refuses.** `RobinhoodReconciler::snapshot` reads the
   agentic account's portfolio, positions and orders through `account_snapshot` (each read scoped
   to the recorded account, CN-8, DEC-875) and then answers `Cause::Absent` (`STATUS_UNPUBLISHED`),
   so the run stops at `Stage::Reconcile` before it opens anything. `BrokerAccount` takes the
   account's status flags, equity, last equity, maintenance margin and multiplier from the broker
   (trading spec §7.2 and §7.3), and Robinhood publishes none of them (connections spec U-R6,
   U-R7); inventing them would put figures in `AccountSnapshotRecorded` that no broker gave
   (`AGENTS.md` rule 3). A read that is refused or unreadable answers `ACCOUNT_UNREAD` instead.
   `reconcile` refuses every snapshot the same way, since none is ever handed out.
4. **The shell's simulator tests have their own harness crate,** `mandate-shell-rh-sim` (layer
   11, tests only). They cannot live in `mandate-rh-sim`: a simulator harness judges the crate at
   the top of what it drives (DEC-866), so a `mandate-shell` dev-dependency there would make the
   shell the top and drop `mandate-robinhood` from the mutants `mandate-rh-sim`'s tests judge.
   They cannot live in `mandate-shell`, which may not depend on the simulator. The harness takes
   `mandate-rh-sim`'s shared test fixtures by path rather than copying them.
5. **Left for later lanes:** the runner's ports and `connect()` choosing this pair from the
   connection record, and `mandate-shell`'s `control.rs`, are unchanged.

## For the founder

Item 3 holds every Robinhood run at its startup reconciliation, which the live run needs to
pass. How Robinhood's account is read into `BrokerAccount` is the founder's to decide, because
any answer either invents a broker fact or weakens §7.3's gate requirement that the broker report
the account active. The recommendation, for a later decision: `status` `ACTIVE` and every blocked
flag `false` exactly when `get_accounts` lists the recorded account with `agentic_allowed` true
(any other answer already refuses the read); `multiplier` 1 on the strength of DEC-529 item 11's
attestation; `cash` and `buying_power` from `get_portfolio`, with `non_marginable_buying_power`
the lower of the two (DEC-620 item 2); and `equity`, `last_equity` and `maintenance_margin`
either added to the assumed `get_portfolio` shape (DEC-902) once the founder's run shows real
fields, or set to `cash` and zero with the reconciler journaling that they were not read.

## Rationale

The seam belongs with the client it abstracts, and putting the implementation there makes it
testable without a TLS fixture or a new dependency. A runtime per call would drop the HTTP
connections an MCP session's later calls reuse. Refusing the reconciliation is the reading that
adds no risk: the run stops before any order, and nothing is journaled that the broker did not
say.

## Alternatives considered

- **`impl Tools for McpClient` in `mandate-robinhood`:** no test outside `mandate-mcp` can build
  a connected client over plain `http`, so its mutants could not be killed.
- **A runtime per call, as `AlpacaConnector` does:** breaks the MCP session's pooled
  connections.
- **Filling `BrokerAccount` with the recommendation above now:** decides a founder question
  (§7.3's status from the broker) inside an engineering lane.
- **Shell tests in `mandate-rh-sim`:** weakens the mutation coverage of `mandate-robinhood`.
