## Context

The founder wants the whole customer journey demonstrable, live trading included, and confirmed
that counsel has not signed off. Until counsel does, every customer trades paper (compliance doc,
DEC-102). The founder then decided (relayed by the coordinator, 2026-10-26) that real money is for
the founder's own workspace only, which lane LV builds under its own decision; customers stay on
Alpaca paper.

Today the workspace API refuses every request that names `live`, unconditionally, as
`live_unavailable`: creating a mandate version (`version_routes.rs`, `created`), deploying
(`deploy`), and starting a broker connect (`connect.rs`, through `plan_start`'s
`EnvironmentRefused`). That refusal is right but invisible: nothing records that a customer tried,
nothing names who may ever change it, and nothing stops a later change from opening one of the
three points and forgetting the others.

## Decision

1. **One gate, in front of every point that can leave paper.** Every workspace API route that can
   name an environment other than `paper` asks one decision, `real_money::decide`, through
   `real_money::gated`, before anything it would do with that environment, once the request is
   authenticated, authorized and well formed: creating a mandate version, deploying, starting a
   connect (after its step-up, so a caller learns nothing before it), and the owner's own request to
   move the workspace to real money (`go_live`). A request refused earlier, as malformed or
   unauthorized, leaves no `RealMoneyRefused`; a workspace whose control stream is itself not
   `paper` is refused before the gate, as today. A new route that can name another environment must
   call it.
2. **The setting is journaled, and off unless set.** The setting is the `enabled` of the latest
   `RealMoneyGateChanged` on the workspace's control stream (journal spec §9.36); a stream with
   none, or a stream that cannot be read, is off (`AGENTS.md` rule 3).
3. **Only a platform operator sets it, and no workspace route does.** `RealMoneyGateChanged` is
   written only with a `platform_operator` actor as itself (rule 273), by an operator command run
   with the deployment's own credentials, never through an HTTP route. No workspace role (owner,
   admin, operator, approver, viewer, auditor), client, service account or host CLI has any route
   that writes it. This is platform policy, not a decision for a customer: an on setting places no
   order and accepts nothing for the customer, who still confirms, accepts the disclosures and
   deploys with their own step-up, so ID-12 ("platform staff never decide for a customer") holds.
   The command is not a workspace permission and not a break-glass action: for a customer workspace
   it can only turn the gate off, which adds no risk (`AGENTS.md` rule 2), and it turns the gate on
   only for the founder's own workspace (item 6), where the platform operator and the customer are
   the same person acting on their own decision. Identity spec ID-12 notes this exception. The
   command proves no identity of its own: the operator id it records is the one given with
   `--operator`, and what makes the writer a platform operator is that it holds the deployment's
   own journal credentials, which no workspace member holds. A retry under the same key reports the
   record that key wrote, not the gate's current setting. An on
   setting cites its decision (rule 273).
4. **Off refuses, and the refusal is journaled first.** While the setting is off, the gate refuses
   the request: the API appends `RealMoneyRefused` (the action, the environment named, the
   principal, `gate_off`) and then answers `409 live_unavailable`, the code the routes answer today,
   so no client and no schema changes. If the refusal cannot be appended, the request is refused
   `journal_unavailable`: a failed record never admits. The refusal changes no other state. Its id
   is derived from the request's idempotency key (workspace API spec §3.4), so a retry under the
   same key finds it recorded and appends nothing; a new key records the new attempt.
5. **On is necessary, never sufficient.** A request the gate lets through meets every later check
   unchanged. In this decision every point in item 1 still refuses `live` as `live_unavailable`
   after the gate, so this decision alone cannot let any request reach real money. Only a decision
   of the founder's replaces that refusal, and only behind this gate: DEC-2135 (lane LV, PR #2507)
   does so for the founder's own workspace, and every customer workspace stays refused.
6. **Who may turn it on (founder-reserved).** Turning the gate on is a step toward live money, the
   founder's (DEC-79). The operator command turns it on only for the workspace the deployment
   setting `MANDATE_API_FOUNDER_WORKSPACE` names, which the founder sets in the deployment and which
   no HTTP route, workspace role or agent can write (DEC-2135 item 5). It refuses an on setting when
   the setting is absent or empty, when it names more than one workspace, and when the workspace
   differs from it. Customer workspaces therefore stay off. Turning the gate off needs no decision
   and is allowed for every workspace.
7. **Proved, not asserted.** Tests are written first:
   - a property test of `setting` and `decide` over random setting histories (none, off, on,
     toggled, unreadable, in any row order) and requested environments, against an oracle that
     walks the stream from its highest `seq`; and the journal spec's own setting streams folded by
     the API's `setting`;
   - over HTTP, every set of the five workspace roles × three setting histories × the three version
     and agent routes: never committed, and a refusal journaled exactly when the gate is off and the
     role reached it; the connect route's refusal after step-up; retries; and an append that does
     not settle (unavailable, ambiguous, conflicting) answered `journal_unavailable`;
   - a source check that only the gate (which reads it) and the operator command (which only the
     binary's `main.rs` runs) name `RealMoneyGateChanged`;
   - the operator command over every founder-setting shape item 6 names, and its draft admitted by
     `mandate-journal`'s own validator and read back by the gate.

   The diff carries 0 missed mutants, and it is reviewed independently on a different model.

## Rationale

- One decision in front of every exit from paper means a later change cannot open one point and
  forget another.
- Journaling the refusal gives the record the compliance doc asks for ("complete records of
  decisions, approvals, and configuration changes") and shows the customer, in the demo, exactly
  what stopped them.
- Making it necessary but not sufficient means the gate only ever adds a refusal: DEC-176 lets an
  agent take that reading, and no safety rule weakens.

## Alternatives considered

- **A workspace policy row a workspace admin could loosen:** rejected. Counsel's sign-off is the
  platform's, not the customer's; a customer must not be able to leave paper on their own.
- **A deployment setting read from configuration at start:** rejected. A change would leave no
  record in the customer's journal and could differ between replicas.
- **Closing `PlatformOperatorAction` with a gate action:** rejected. Its members stay open under
  DEC-261 item 9, and a dedicated record keeps the gate's two rules small.

## Consequences

- Journal spec v0.91 adds §9.36, `RealMoneyGateChanged` and `RealMoneyRefused`, with rules 273 and
  274; `mandate-journal` registers both.
- The workspace API gains `real_money::decide`, the journaled refusal at version create, deploy,
  connect start and go-live, and the operator command `mandate-api-server real-money (on --decision
  <DEC-n> | off) --operator <ULID> --key <key>`, reading `MANDATE_API_DATABASE_URL`,
  `MANDATE_API_WORKSPACE` and `MANDATE_API_FOUNDER_WORKSPACE`. No problem code, wire schema or web
  client changes.
- Each refused attempt under a new key appends one control-stream row. Only a member who holds the
  drafting, deploying or connecting row can cause one, and each is the record the compliance doc
  asks for, so no cap is set.
- Lane LV's founder-only path (DEC-2135) is item 6's one admitted on setting; it sits behind the
  same gate, calls `real_money::decide`, and adds no second route around it.
