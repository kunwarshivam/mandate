## Context

The OAuth connect's start route (`POST /v1/workspaces/{ws}/connections/oauth/start`, DEC-2623)
requires step-up for `StepUpActionKind::Connection`, bound to the digest of the workspace and the
token-breadth disclosure the owner saw. The server's only step-up port is DEC-2104's `cli_confirm`:
a code the web app shows, typed by the owner on the host, where the CLI appends `StepUpConfirmed`.
It confirms `approve` alone, and no passkey verifier exists before E9-4, so no connect can start in
any deployment: neither the founder's staging connect nor the cell's drill (E10-22).

## Decision

1. **The API.** `CliConfirm` confirms `connection` exactly as it confirms `approve`: the same nine
   checks of DEC-2104 item 6, the same challenge life and single use, the same subject-link check.
   Every other kind is still refused, `step_up_method`.
2. **The record.** `StepUpConfirmed` (journal spec §9.29) admits `action_kind` `connection`, its
   `action_digest` the start route's own connect digest, computed from the workspace and the current
   disclosure document and version; its own spec change lands first.
3. **The CLI.** The owner confirms a connect on the host with a command that computes that digest
   itself, never from the browser, in paper only, as `mandate step-up confirm` does for an approval.
4. **The interim ends** when E9-4's passkey step-up confirms `connection` (lane L1). Then `cli_confirm`
   stops confirming it, by a later decision.

Items 2 and 3 land in their own changes; item 1 is this one's.

## Rationale

The connect keeps its step-up: the browser cannot confirm it, since only the host's CLI appends the
confirmation, and the evidence is bound to the principal, the workspace and the digest of what the
owner saw, as an approval's is. Nothing is loosened beyond which action the founder's interim covers.

## Alternatives considered

- **Wait for E9-4's passkey step-up.** No connect could start, on staging or in the cell, until it
  lands.
- **A step-up exception for paper connects.** Rejected: a connect without step-up is what E10-13
  forbids.
