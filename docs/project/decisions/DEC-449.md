## Decision

1. **`RiskExitPath`'s mid-run `plan` folds the journal at request time, and everything the fold
   needs but cannot derive arrives with the call or at construction.** The run's bridge — which
   owns the stages — hands `plan` the journal's read capability, the account stream's id, and
   the step's risk clock; the adapter holds no journal, no stream, and no clock of its own, so
   no plan can be taken over a fold the run has already written past or a session the clock has
   already left. A scratch run's memory journal is readable through the same hand, which a
   journal opened by name could never be. What the adapter holds from construction, as
   `Sources` carries both, is the deciding agent — the deployment's, fixed for the run — and
   the mandate's path, for the probe's synthetic request and the universe's asset classes. At
   `plan` time it folds the journal's records into the state `mandate_risk::agent_flatten`
   reads. **The sub-ledger is attributed from the fold's own orders, not from a second pass over
   the raw records:** `mandate-executor`'s public `ExecutorState::orders()` carries each
   order's agent, and the adapter filters the deciding agent's orders and sums their signed
   filled quantities per instrument — the account-level `positions()` has no per-agent accessor
   and is never the plan's input (§5.5: other agents' and the owner's unattributed shares are
   untouched). A construction-time fold is refused: a kill switch must see the current state,
   and the adapter is constructed before the session opens, so a fold taken then is stale by
   definition.
2. **The clock is the session's only source, and it is optional.** `plan` takes
   `Option<RiskClock>`: before any clock has advanced there is no session to derive, and the
   plan is refused rather than defaulted — the fail-closed suite's own rule against defaulting
   combinators, which caught this shape's first draft. The flatten's inputs are account-stream
   records committed in earlier steps; the step's own effect batch, including the
   `KillSwitchActivated` draft, is appended after the plan is computed, so the plan never reads
   its own request. The session itself comes from the committed US-equities calendar, and a
   closed market inside the calendar's range is the **overnight** session — the equity sell
   waits for the open rather than the run halting, because risk reduction is never denied
   (AGENTS.md rule 13) and the risk crate's own derivation reads the same instant the same
   way. Only an instant the calendar cannot cover at all refuses.
3. **The mapping the adapter owes.** The risk crate's `FlattenPlan` and the runtime's are
   distinct types, and so are their working-order ids: the risk crate's are numeric, the
   runtime's requests name intents, and the journal's submissions name client orders. The
   cancels come from **the fold's working orders for the deciding agent** — `agent_flatten`
   cancels every one of the agent's open orders it is given in `open_orders` and never reads
   the request — mapped to the `md-` client order ids the journal's submissions carry. The
   request's `working_orders` is context the runtime carries, not the risk crate's input, and a
   copy of its strings would name intents the broker never saw as orders. An owner's exit
   names the one instrument it closes (mandate spec §6.1, trading-domain spec §5.5,
   DEC-257): the scope filters both the sub-ledger and the cancels to that instrument alone,
   so an exit of one instrument never sells another's sub-ledger nor lifts its protection. An
   order is working
   while its state is not terminal **and** part of its quantity rests unfilled — the
   executor's own rule that a filled quantity at or past the order's is done, whatever state
   the last journal record left it in, since a fill record does not itself transition the
   state. Beyond the ids: each sell and each deferred sell becomes a leg, a deferred one
   waiting for the regular session; the purpose carries over (`RiskExit` for a risk-limit kill
   switch, `OwnerExit` for an owner's); the request's confirmation carries over; and the
   account-wide endpoints and the mode-first flag have no runtime counterpart, because the
   runtime type cannot carry them — §5.5's unrepresentable half.
   The exit-offset tier (§5.6's table) is keyed on volume data the `plan` call cannot reach;
   the adapter passes the wider of the two equity tiers. The offset is unread on every live
   path today: a risk-initiated flatten carries no bid to bound, and an owner's confirmation
   always carries its own explicit floor, which takes precedence — so the constant prices
   nothing until a confirmation arrives without one.
4. **The broker's quantities — and every other agent's — are deliberately not the plan's
   input.** `agent_flatten` ignores `broker_positions` by design: the plan sells exactly the
   deciding agent's sub-ledger, never the broker's position (§5.5, MC-F01). A
   `BrokerPositionObserved` record is the fold's mismatch flag, and no adapter path feeds the
   broker's quantities into a plan. The same rule holds inside the account: the tests pin a
   fixture where a second agent holds five more shares of the same instrument — the account as
   a whole holds fifteen — and the plan sells the deciding agent's ten, never the account's
   total.
5. **The probe** is the task brief's ruling, unchanged: one `agent_flatten` call over a
   synthetic kill-switch request built from the mandate fixture, before anything is armed. A
   probe over a mandate it cannot read refuses; the document is load-bearing, not decorative.

## Rationale

The journal is the source of truth (AGENTS.md rule 5) and the kill switch is the one request
whose plan must reflect everything committed; handing the read capability, the stream, and the
clock with each call makes a stale plan unrepresentable rather than merely avoided, which is
the trust ladder's first rung. Keeping the runtime's port unchanged honours the earlier
ruling and leaves the poison-flag halt (PB-8) as the mid-run failure shape. The tests PR pins
the contract with the vectors' own envelope shapes, so the implementation cannot satisfy it
with records the journal's own validation would refuse.

## Alternatives considered

- **Extending `FlattenRequest` to carry the folded state** (the runtime holds it at the call
  site): it changes another stream's public type to save a fold that happens rarely, and the
  earlier ruling keeps the port as it is.
- **A construction-time fold held by the adapter**: stale for every mid-run kill switch, which
  is the only caller `plan` has.
- **The runtime planning flattens itself** (`mandate-runtime` calling `agent_flatten`
  directly): it moves the shell's stage trait out of the path the tracer's fail-closed suite
  pins, and the brief keeps the exit path a shell stage.
- **The adapter opening the journal by name**: a scratch run's memory journal has no name to
  open, and a named re-open could not see the run's own writes.
- **A defaulted clock when none has advanced**: the fail-closed suite's no-defaulting rule
  refuses it, and a wrong session would defer or hurry an equity sell — exactly the failure
  the option type makes unrepresentable.

## What it changes downstream

The tracer's risk-exit probe flip (E7-7 stream L) implements against this: the tests PR
reshapes the adapter's stub API to the agent and the mandate path and pins the contract with
seven pending tests (the probe, its unreadable-mandate refusal, the oracle, the structural
§5.5 pins, the pre-open deferral, the no-clock refusal, and determinism) over a scripted
§9.5-shaped journal that proves itself — every row parses through `mandate_journal::Draft::parse`
and the whole sequence folds through `mandate_executor::fold`, the two crates this decision
names, so the contract is never pinned on records they would refuse. The implementation PR
folds at `plan` time and deletes the markers; the fail-closed pin flips with it, from the
stub's refusal to the probe answering over the shell's fixture
(`the_production_exit_probes_over_the_shells_fixture`). The fail-closed construction repoints
at `tests/fixtures/tracer/mandate.json`, the fixture `Sources` names, and takes the agent. The
runtime's `FlattenRequest.working_orders` doc is corrected with it (intent event ids, not
client order ids — a doc fix, no port change), and so are the two `working_orders` doc
sentences in `state.rs`. The BTC/USD paper run (DEC-450, the founder's
call) rides the same path once the flips land.
