## Decision

1. **`RiskExitPath`'s mid-run `plan` folds the journal at request time, and everything the fold
   needs but cannot derive arrives with the call.** The run's bridge — which owns the stages —
   hands `plan` the journal's read capability, the account stream's id, and the step's risk
   clock; the adapter holds no journal, no stream, and no clock of its own, so no plan can be
   taken over a fold the run has already written past or a session the clock has already left.
   A scratch run's memory journal is readable through the same hand, which a journal opened by
   name could never be. What the adapter holds is the mandate's path, for the probe's synthetic
   request and the universe's asset classes. At `plan` time it folds the journal's records into
   the state `mandate_risk::agent_flatten` reads: the agent's positions and working orders from
   the account-stream fold (`mandate-executor`'s public `fold` over the journaled §9.5 records),
   and the session derived from the clock. A construction-time fold is refused: a kill switch
   must see the current state, and the adapter is constructed before the session opens, so a
   fold taken then is stale by definition.
2. **The clock is the session's only source, and it is optional.** `plan` takes
   `Option<RiskClock>`: before any clock has advanced there is no session to derive, and the
   plan is refused rather than defaulted — the fail-closed suite's own rule against defaulting
   combinators, which caught this shape's first draft. The flatten's inputs are account-stream
   records committed in earlier steps; the step's own effect batch, including the
   `KillSwitchActivated` draft, is appended after the plan is computed, so the plan never reads
   its own request.
3. **The mapping the adapter owes.** The risk crate's `FlattenPlan` and the runtime's are
   distinct types, and so are their working-order ids: the risk crate's are numeric, the
   runtime's requests name intents, and the journal's submissions name client orders. The
   mapping is journal-derived — the request's intent names resolve, through the journal's
   records, to the client order ids the cancels must carry — never a copy of the request's
   strings, which would name orders the broker never saw. Beyond the ids: each sell and each
   deferred sell becomes a leg, a deferred one waiting for the regular session; the purpose
   carries over (`RiskExit` for a risk-limit kill switch, `OwnerExit` for an owner's); the
   request's confirmation carries over; and the account-wide endpoints and the mode-first flag
   have no runtime counterpart, because the runtime type cannot carry them — §5.5's
   unrepresentable half.
4. **The broker's quantities are deliberately not the plan's input.** `agent_flatten` ignores
   `broker_positions` by design: the plan sells exactly the agent's sub-ledger, never the
   broker's position (§5.5, MC-F01). The `BrokerPositionObserved` record is the fold's mismatch
   flag — the broker's fifteen against the agent's ten is a mismatch the fold carries — and no
   adapter path feeds the broker's quantities into a plan.
5. **The probe** is the task brief's ruling, unchanged: one `agent_flatten` call over a
   synthetic kill-switch request built from the mandate fixture, before anything is armed. A
   probe over a mandate it cannot read refuses; the document is load-bearing, not decorative.

## Rationale

The journal is the source of truth (AGENTS.md rule 5) and the kill switch is the one request
whose plan must reflect everything committed; handing the read capability, the stream, and the
clock with each call makes a stale plan unrepresentable rather than merely avoided, which is
the trust ladder's first rung. Keeping the runtime's port unchanged honours the earlier
ruling and leaves the poison-flag halt (PB-8) as the mid-run failure shape. The tests PR pins
the contract with the vectors' own envelope shapes, so the implementation cannot satisfy it
with records the journal's own validation would refuse.

## Alternatives considered

- **Extending `FlattenRequest` to carry the folded state** (the runtime holds it at the call
  site): it changes another stream's public type to save a fold that happens rarely, and the
  earlier ruling keeps the port as it is.
- **A construction-time fold held by the adapter**: stale for every mid-run kill switch, which
  is the only caller `plan` has.
- **The runtime planning flattens itself** (`mandate-runtime` calling `agent_flatten`
  directly): it moves the shell's stage trait out of the path the tracer's fail-closed suite
  pins, and the brief keeps the exit path a shell stage.
- **The adapter opening the journal by name**: a scratch run's memory journal has no name to
  open, and a named re-open could not see the run's own writes.
- **A defaulted clock when none has advanced**: the fail-closed suite's no-defaulting rule
  refuses it, and a wrong session would defer or hurry an equity sell — exactly the failure
  the option type makes unrepresentable.

## What it changes downstream

The tracer's risk-exit probe flip (E7-7 stream L) implements against this: the tests PR
reshapes the adapter's stub API to the mandate path and pins the contract with seven pending
tests (the probe, its unreadable-mandate refusal, the oracle, the structural §5.5 pins, the
pre-open deferral, the no-clock refusal, and determinism); the implementation PR folds at
`plan` time and deletes the markers. The fail-closed construction repoints at
`tests/fixtures/tracer/mandate.json`, the fixture `Sources` names. The BTC/USD paper run
(DEC-450, the founder's call) rides the same path once the flips land.
