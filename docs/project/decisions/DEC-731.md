## Decision

1. **Edge middleware in place of the Node proxy.** `web/src/proxy.ts` moves to
   `web/src/middleware.ts`, and its function is renamed `middleware`. The behaviour stays the same:
   the dev preference switch, the Supabase session refresh and `authRoute`. So does the matcher,
   which still leaves out the build's assets and the push worker. OpenNext runs edge middleware but
   not Next's Node proxy, so the file imports nothing from `node:` and sets no `runtime`. Next 16
   warns that the `middleware` convention is deprecated. We accept the warning until OpenNext runs
   the proxy, and then a new decision moves back.
2. **Unoptimised images.** `next.config.ts` sets `images: { unoptimized: true }`. The app's images
   are small committed files, so serving them as they are costs nothing. The Images binding would
   add a billed service, and DEC-823 does not extend to one.
3. **The Worker's configuration** is `web/wrangler.jsonc`:
   - the Worker `owlhead-web`, with OpenNext's `.open-next/worker.js` and its assets;
   - `nodejs_compat` and `global_fetch_strictly_public`, and minification;
   - no `workers.dev` address and no preview URLs (DEC-823 item 2);
   - the `WORKER_SELF_REFERENCE` service binding OpenNext expects.

   It names no account and commits no variable or secret. The account ID and the public
   `NEXT_PUBLIC_*` variables are variables of the GitHub `production` environment, which the deploy
   job reads (DEC-1005 item 2; DEC-823 item 5). `web/open-next.config.ts` takes the adapter's defaults,
   with no incremental cache binding. `npm run cf:build` builds the Worker; it runs `npm run build`
   and its postbuild checks first. `npm run cf:preview` runs the Worker locally.
4. **The beta store in production.** A Worker keeps no file between requests, so a production build
   stores a beta request in Supabase's `beta_requests` table only. With the table missing or any
   other Supabase error, the form answers 503 unavailable and nothing is written. With Supabase
   not configured at all, the form is closed instead ([DEC-987](earlier-900-1999.md#dec-987)). The local file stays
   for development and tests only (`localFileAllowed`).
5. **Pull-request CI builds and never uploads.** The `web` workflow runs `npm run cf:build` in place
   of `npm run build`, then Wrangler's dry run, which writes the bundle it would upload and needs no
   account or token. Only `web-deploy.yml`'s deploy job uploads, from `main` ([DEC-1005](DEC-1005.md)).
   `hostingProblems` in `web/scripts/workers.mjs`, run by the unit tests, fails when:
   - any of items 1 to 4 is undone, or `vercel.json` deploys a branch other than `main`;
   - `web.yml` holds a `CLOUDFLARE_` value, reads a secret or a variable, or runs on a push;
   - any workflow or npm script but that deploy job deploys, uploads or logs in to Cloudflare, or
     any other workflow names the `production` environment (DEC-1005 items 1 and 2).
6. **The Worker's size budget** is 3 MiB gzip and 10 MiB raw, measured over every module of the
   dry run's output, leaving out source maps and Wrangler's README. The paid plan refuses a Worker
   over 10 MiB compressed; the budget holds the gzip size to the free plan's 3 MiB and the raw size
   to 10 MiB, so the bundle's growth shows long before a deploy would fail. CI fails above
   either budget, and fails a dry run that left no module to measure. On 2026-10-09 the Worker was
   7.44 MiB raw and 2.05 MiB gzip.

## Rationale

Each item is the smallest change that runs the app on Workers as DEC-823 chose. A test checks
each one, so a later change cannot quietly undo it. A new decision can reverse any of them.

## Alternatives considered

- **Keep `proxy.ts`** and wait for OpenNext to run Node middleware: the app could not move until
  it does.
- **The Images binding** (item 2): a billed service the app does not need.
- **A Workers KV or R2 store for beta requests** (item 4): new paid bindings, and a second copy of
  what the Supabase table already holds.
- **The paid plan's 10 MiB compressed limit as the budget** (item 6): CI would see growth only
  when the deploy is about to fail.
