# DEC-456: Executor drafts carry their own trusted configuration references

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-05 (UTC) |
| **Decided by** | The implementing agent under DEC-79 and DEC-176 |
| **Story or claim** | E7-7; claim [#171](https://github.com/kunwarshivam/mandate/issues/171); [PR #598](https://github.com/kunwarshivam/mandate/pull/598) |

## Decision

1. An executor `EventDraft` carries the exact `config_refs` its account-stream event requires.
   The shell serializes those references and never selects them from an event-type table of its
   own.
2. The binding gate source supplies immutable references for the fee configuration, trading
   calendar, instrument snapshot, rule set, and mandate version alongside the trusted gate facts.
   `GateDecided` records all five. `IntentReceived` records the mandate version the executor
   resolved for the intent.
3. A missing, malformed, or mismatched reference fails closed before any broker request. The CI
   fixture stores deterministic bytes under every referenced digest so journal verification checks
   presence and content, not only spelling.

## Rationale

Journal §9 requires these references, and the executor is the account stream's sole writer. Letting
the shell infer references from event names would duplicate schema ownership in the integration
layer and could attach evidence unrelated to the decision the executor made. Carrying the references
with the trusted facts keeps the decision and its evidence in one deterministic boundary and only
tightens append and verification.

## Alternatives considered

- Add the missing four references to every shell draft: rejected because unrelated events would
  claim evidence they did not use.
- Keep an event-to-reference lookup in `mandate-shell`: rejected because the tracer task explicitly
  puts no journal schema in the shell.
- Use well-formed placeholder hashes without stored bytes: rejected because §11 verification must
  prove referenced content exists and re-hashes.
