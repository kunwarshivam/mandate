# DEC-646: The membership writer is a pure function in `mandate-identity` over a control-stream port

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-09 (UTC) |
| **Decided by** | Lane L1 builder agent (E9-7), under DEC-79 and DEC-176: a reversible engineering choice of placement that only narrows what may commit a membership record |
| **Story or claim** | E9-7, claim [#760](https://github.com/kunwarshivam/mandate/issues/760); DEC-659 items 2 and 8; the backlog's *Membership writer* row |

## Decision

1. **Placement.** The one writer of `Member*` records on `ctl:{workspace_id}` is
   `mandate_identity::write_membership`, in `mandate-identity` (layer 1, pure). It reaches the
   stream only through `mandate_identity::ControlStream`, a port with two methods: `read`, which
   returns the head `seq` and the stream's records from at least its last membership record on,
   and `append`, a compare-and-append that commits a record at `expected_head + 1` only while the
   head is still `expected_head` (journal spec §5.1). The workspace store implements the port over
   the journal; the clock is handed in as a closure, as `mandate-authn` takes its clock.
2. **One attempt is one serialized append** (DEC-659 item 2): read the head and the records, take
   `last` as the last of the seven §9.12 membership records (another type is skipped), stamp
   `event_time` from the clock, build the record at `seq` head + 1, run `check_order(last, next)`,
   and append at the head read. A `HeadMoved` answer re-runs the whole attempt, re-reading `last`
   and re-stamping `event_time`, so a `last` read before a concurrent commit never admits a
   record.
3. **Refusals** (DEC-659 item 8): `WriteError::Refused(OutOfOrder)` commits nothing and is never
   clamped; `WriteError::Contended` after `ATTEMPTS` (8) attempts whose head moved each time;
   `WriteError::Store` passes a storage failure through, with no retry; `WriteError::StreamFull`
   when the head is `u64::MAX`, so no `seq` follows it (DEC-659 item 3), and nothing is written.
   The caller retries each later; nothing is granted meanwhile.
4. **`MembershipRecord` gains read accessors** (`seq`, `event_time`, `event`), which the store's
   adapter needs to map a record into a journal draft.
5. **Scope.** The writer checks order only. The state, author, step-up and independence checks of
   §9.12 stay the caller's, run before it; L2's routes (E10-x) call this writer and never append a
   `Member*` record themselves.

## Not done

Nothing. `WriteError::StreamFull` came with the implementation PR, which adds no tests (DEC-77);
`a_full_stream_takes_no_record` now reaches it, and `the_writer_makes_eight_attempts` pins item 2's
eight attempts. No existing variant fits a full stream: `Refused(OutOfOrder)` names a record against
a last membership record there may not be, and `Contended` names a moved head.

## Rationale

`mandate-identity` sits below the journal (layer 1 against layer 2), so it cannot call
`MemoryJournal::append`; `mandate-authn` and `mandate-passkey` share the journal's layer, and
`mandate-identity-testkit` is dev-only. A new store crate above the journal would be another
lane's surface and needs a new `allowed_dependents` entry on `mandate-identity-seal`, and the
journal has no §9.12 drafts to map to yet. A port keeps the safety logic (what `last` is, when to
stamp, when to re-check, never clamping) in the L1 crate that owns `check_order`, testable without
a journal, and leaves the store only a compare-and-append it already has.

## Alternatives considered

- **A new `mandate-identity-store` crate at layer 3 over `mandate-journal`.** Deferred: it is the
  workspace store, whose owner and seal entry are not decided, and the §9.12 journal schemas it
  would map to have not landed.
- **The writer in `mandate-identity-system`.** Rejected: that planned crate holds `SystemContext`,
  and only background-process bootstrap crates may depend on it (DEC-642 item 6), which L2's
  request routes are not.
- **Locking instead of compare-and-append.** Rejected for the port: the journal's protocol is an
  `expected_head` check, and a retry that re-runs the guard is equivalent to a serialized append.
