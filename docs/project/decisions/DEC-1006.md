## The founder's choice

Asked to choose between "Gate by risk (Recommended)", "Gate by risk + bigger runners" and "Make CI
optional", the founder chose **"Gate by risk (Recommended)"**, worded as: "PRs that touch
safety-critical crates (risk, executor, accounting, vault, auth, connectors, journal) keep the full
required checks and mutants. Docs, specs, web, charts and tooling PRs run only fast lint and tests;
mutants and the heavy matrix skip them. Full mutation sweep nightly on main for everything."

About seventeen builders share GitHub's free runner pool (20 concurrent jobs, 5 of them macOS), and
finished pull requests waited 30 to 60 minutes. The measurement behind this decision, from 17 recent
`ci` runs, is in the pull request that records it: per non-documentation PR the non-mutant jobs cost about 42 runner-minutes over
11 to 16 jobs. The mutation shards cost a median of 103 runner-minutes, over a median of 65 jobs
when a diff has mutants. Job waits of 8 to 20 minutes came from the pool's concurrency, not from
slow jobs.

## Decision

1. **The strict reading.** A job is skipped for a diff only when nothing in the diff can change its
   verdict. When the selection is in doubt it selects more. The mutation gate on the diff of
   safety-critical crates is unchanged (DEC-538, DEC-519, DEC-931), and so are lint, the spec guard
   and the trailer check. The founder's wording names crates by area. The build goes further: any
   crate whose code or data a diff can reach keeps every check that could fail on it, whether or not
   it is safety-critical.
2. **The affected set** (`cargo xtask ci select`, `select` in `xtask`). The selection takes:
   - the changed paths against the base `choose_base` picks (DEC-112's base, with renames as both
     sides);
   - each path's owning crate;
   - every crate whose Rust sources name the path. The scan reads every string literal piece, a
     leading `/` dropped, resolved against the file's directory, the crate's directory, `crates/`
     and the repository root. So `include_str!`, `CARGO_MANIFEST_DIR` joins, `concat!(env!(..),
     "/../..")` pieces, a sibling crate named from a computed `crates` directory, format strings
     and globs all count. It drops only a directory above the crate's own (`crates`), because `..`
     pieces in path-traversal tests would otherwise make every crate read every crate. A test
     pins the scan against an independent reading: every tracked outside path any run of path
     characters in a crate's code names, read without the tokenizer, must be one the scan covers;
   - every crate whose sources name the variable through which a test is handed another crate's
     binary (`MANDATE_RH_SIM_BIN`: `mandate-mcp`'s rehearsal tests run `mandate-rh-sim`'s
     simulator without depending on it), whenever that crate is selected;
   - every workspace member depending on one of those, directly or not, through normal, dev or
     build dependencies.

   Tests (nextest, sharded as DEC-871), doctests, pending tests (DEC-110, DEC-137), the `rh-sim`
   rehearsal runs (DEC-963) and the Postgres runs (DEC-520) cover only that set. The jobs follow it:

   | Job | Starts when |
   |---|---|
   | `fast-test`, `fast-pending` | the set is not empty. xtask's sources name `docs/`, `web/` and `crates`, so its own tests run on documentation and web changes too, which the founder's "docs… run only fast lint and tests" allows; they build only xtask |
   | `fast-python` | a path outside every crate, the documentation and `web/` changed |
   | `fast-portable` (DEC-954), `fast-rh-sim-live` (DEC-964) | the set holds the runner |
   | `full-checks` | a path outside the documentation and `web/` changed (DEC-112's classification, which a test pins to `docs-only.sh`) |
   | `schema-mutants` (DEC-688) | `schemas/`, the specs (the journal spec among them, since `check_planned.py` reads every spec), the backlog, or `reference/mandate/requirements.txt` changed |

   No workspace member turns on another member's feature or turns its defaults off, so a
   `--package` build unifies each selected crate's features as the `--workspace` build does: every
   binary containing a crate is in the set and brings its own dependencies' features. If a member
   ever does turn on another's feature, the selection takes everything.
3. **Everything.** The following select every crate and every job:
   - a change to `Cargo.lock`, any `Cargo.toml`, `rust-toolchain.toml`, `deny.toml`, `clippy.toml`,
     `.cargo/`, `.config/`, `.github/`, `xtask/` (`layers.toml` included), `.gitignore` or
     `.python-version`;
   - a path outside every crate and outside the known top-level paths;
   - a run with no diff base (main, the nightly).
4. **The required checks.** `fast` and `full` keep their names, so branch protection and the merge
   gate (DEC-175) are unchanged. Each passes only when `select` succeeded, each part it selected
   succeeded, and each part it did not select was skipped. A skip `select` did not ask for fails,
   and so does a job that ran when it should not have. A skipped job starts no runner. The
   aggregates print the selection's one-line reasons in their logs and job summaries, and `select`
   writes them to its own summary. `cancel-in-progress` already cancels a superseded run of the
   same pull request (DEC-610).
5. **The nightly on main** (`nightly.yml`, every night at 06:17 UTC; DEC-256 item 3 made it weekly
   to save private-repository minutes, and the repository is public again).
   - `dispatch-ci` dispatches `ci.yml` on main. That run has no diff base, so it selects
     everything: all tests, `schema-mutants`, and the macOS `portable` job. A local reusable
     workflow cannot be used, because the live-feature check refuses `uses: ./…` (DEC-873 item 6).
     When that run fails, `ci.yml`'s `report-main` opens an issue. A run cancelled by a newer dispatch
     opens none.
   - The nightly itself runs the Postgres tests on PostgreSQL 17, ten fuzz seeds, the reference
     implementation's seeded-bug check (`mutants.py`), and a full-history gitleaks scan.
   - It also runs the **whole-crate mutation sweep** of every safety-critical crate (`cargo xtask ci
     sweep`). The sweep is the per-PR gate over a diff that adds every source line of those crates.
     Each shard is judged by the tests of the crates its own mutants are in, plus their external and
     simulator oracles, which is what a PR touching only those crates gets.
   - Shards hold at most eight mutants, the size DEC-473 found to fit ten minutes. Each day takes
     the shards whose index is the day (days since the Unix epoch, from the runner's clock, an
     input under ES-05) modulo the rotation, at most eight at a time. The sweep runs every night
     even when main is unchanged, so no day's share is skipped.
   - The rotation is seven days and lengthens on its own once a seventh would no longer fit one
     256-job matrix.
   - Any failed or cancelled job opens an issue naming only the commit, the run's address and each
     job's verdict.

   **Why the rotation, and why it is Proposed.** The founder's words are "full mutation sweep
   nightly". The sweep lists 12,538 mutants today, and they take about 11 to 13 seconds each after
   a baseline (measured on `mandate-risk`). A full sweep every night would be roughly 45 to 50
   runner-hours, holding the whole 20-runner pool for hours, which defeats the reason for this
   decision. A seventh a night is about 1,800 mutants and some 224 shards, about 12 runner-hours,
   and about an hour and a half of wall-clock at eight in parallel. Every mutant is still tested
   once a week.

   The rotation removes nothing that runs today. On main the old nightly's `mutants` step had no
   base and so swept nothing, and the per-PR gate is unchanged. But it is weaker than the
   founder's words, so it stays Proposed. The founder can set `SWEEP_ROTATION` to 1 for a full
   nightly sweep, and `max-parallel` bounds the pool either way. The first run is expected to open
   an issue: on a local sample the sweep already found a mutant no PR diff ever selected, in
   `mandate-risk`'s `ReasonCode` `Display`.
6. **DEC-464, which DEC-473 and DEC-498 superseded, is honoured as written.** Its rule is to add
   shards rather than remove tests, baselines, mutants or safety gates. This decision removes
   nothing; it scopes per diff. A job the diff cannot affect does not start, and every job still
   runs for every diff that reaches it and for main every night. Every per-PR job keeps its
   ten-minute cap, as do the nightly's jobs. `cargo xtask check` is scoped the same way, so a
   local run judges what CI judges. With no base, on main, it runs everything.

## Rationale

The queue comes from concurrency: each job holds a runner slot, so a job that cannot change the
verdict costs another PR its turn. Scoping by the workspace graph and by what the sources read
keeps each check wherever it could fail.

Several properties are tested:

- The selection always holds every reverse dependent of a changed crate: a seeded property test
  checks it against Warshall's closure, an oracle computed another way.
- A change to a dependency alone still catches a crate it breaks: a fixture workspace's scoped run
  fails, and a changed-crates-only selector misses it.
- The verdict scripts are judged over their truth tables, as DEC-538's and DEC-871's tests do.

The scan also closes a gap DEC-112 left. Tests read `docs/specs/identity.md`, `workspace-api.md`
and `mandate.md`, so a documentation-only change could break them unseen until the next code PR.
Now it selects their crates.

Replaying the selector over 49 recent main commits:

- 14 select everything (a lock file, a manifest or CI changed).
- `schema-mutants` is skipped on 25, `fast-python` on 20, `fast-portable` and `fast-rh-sim-live` on
  6 each, and `full-checks` on 5. Tests always run, since xtask's own are selected, but on the
  other 35 they cover a subset of the 48 crates.
- Counting only whole-job skips, the non-mutant work drops from about 40.5 to 34.6 runner-minutes
  and from 11 to 9.7 jobs per PR. The lighter builds of scoped test runs come on top.

The largest lever, the mutation shards (median 65 jobs of about one minute each, mostly setup,
when a diff has mutants), is left as it is by the founder's rule. Packing several mutants a shard
would cut those slots several times over and is proposed separately.

## Alternatives considered

- **Select by crate area only** (the founder's list of safety-critical areas). Not taken: a crate
  outside the list can break one inside it through a dependency, and a spec can break a crate's
  tests. The graph and the scan decide instead.
- **Keep starting every job and let it exit early.** Not taken: the job still holds a runner slot
  for its setup, which is the queue cost this decision removes.
- **A reusable workflow for the nightly.** Refused by the live-feature check (DEC-873 item 6).
  Dispatching `ci.yml` reuses the per-PR jobs exactly.
- **A full whole-crate sweep every night.** Measured at about 45 to 50 runner-hours a night; see
  item 5.
