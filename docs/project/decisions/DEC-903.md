## Context

Mandate spec §4.2 item 4 says a delegation gives slices to the unasked figure when its
[`starts_at`, `expires_at`) "meets [*t*, the end of the risk day)": an exact interval intersection.
Delegation instants have nanosecond precision (the schema's `$defs/instant`); the risk clock *t* is
whole seconds (§5.2).

`reference/mandate/ref.py`'s `unasked_usd` compared `T(...)` of each instant, and `T` truncates to
the whole second. With `expires_at` = *t* + 0.5 s, `T(expires_at)` = *t*, so the reference dropped a
delegation that §4.2 counts, and the figure understated. §4.2 says the figure "is a bound, not an
estimate", so an understatement is a defect.

## Decision

1. **§4.2's figure compares delegation windows at full precision**, exactly as §4.2 words it. A
   delegation counts if and only if `starts_at` < the end of the risk day and *t* < `expires_at`,
   with no truncation. A window boundary that falls inside a second counts the delegation as live,
   so the figure never understates.
2. **The reference is aligned.** Every instant in `ref.py` is the 30-character
   `YYYY-MM-DDTHH:MM:SS.nnnnnnnnnZ` UTC form (`fmt` writes it; `T` and the schema's pattern assert
   it), so string order is time order, and `unasked_usd` compares the strings directly:
   `d["starts_at"] < risk_day(st["now"])["ends_at"]` and `st["now"] < d["expires_at"]`.
   `risk_day(...)["ends_at"]` is written by `fmt`, so both sides have the same form. `fuzz.py`'s
   `fuzz_unasked` checks it whatever the seed: an `expires_at` 1 ns, 0.5 s or 999,999,999 ns after
   *t*, and a `starts_at` 1 ns before the end of the risk day, each count; an `expires_at` at *t*,
   or a `starts_at` at the end of the risk day, gives nothing. `mutants.py` carries the truncating
   comparison, and a `<=` at the end of the risk day, as mutants the fuzz must catch.
3. **The Rust implementation follows.** S1a's `unasked_usd` in `crates/mandate-spec` (#1272) is
   corrected in a later tests-correction PR and fix PR (DEC-77), not with this decision.

## Finding for E8-8's owner (not decided here)

`ref.py`'s §6.2 decision, `delegation_lift`, checks
`T(d["starts_at"]) <= now and now < T(d["expires_at"])`, which truncates too:

- At a sub-second `starts_at`, it lifts an ask up to 1 s before `starts_at`, which §6.2 "Live"
  item 2 (the risk clock in [`starts_at`, `expires_at`)) does not allow. That is a loosening.
- At `expires_at` it is narrower than §6.2.

Aligning it to the exact comparison is E8-8's change, recorded in the backlog under E8-8 and on the
founder's FYI list. Once both are exact, the figure stays a bound on the decision: every instant at
which the decision can lift an ask lies in a window the figure counts.

## Rationale

§4.2 already says "meets", an exact intersection, and calls the figure a bound. Truncating the
window's end makes a delegation that is still live at *t* look expired, which can only lower the
figure below what the agent could run unasked. Comparing at full precision is the plain reading of
the spec and what the schema's nanosecond instants are for. It changes no generated reference case,
and no decision, since the figure is display only.

## Alternatives considered

- **Keep the truncation.** The figure understates for a delegation whose `expires_at` falls inside
  the risk clock's second, against §4.2's "a bound, not an estimate".
- **Round `expires_at` up to the next second.** Equivalent while *t* is whole seconds, but less
  plain: it states a rounding §4.2 does not have, and it would diverge silently if the risk clock
  ever carried sub-second precision.
