## Decision

1. **The exception.** The S1a tests PR, #794, may exceed ES-13's 400-line split threshold
   (DEC-253 item 3): 665 lines in `crates/mandate-notify/`, about 780 in all with the wiring and
   decisions outside the crate (`xtask/layers.toml`, CODEOWNERS, the workspace manifest and lock,
   `docs/dependencies.md`, the feature map, DEC-710, and this file). Of the 665, about 270 are the
   stub API, its doc comments, and the 32-kind catalogue enum; about 380 are tests and their
   fixtures.
2. **This PR only.** The exception covers #794 and nothing else. The S1a implementation PR, both
   S1b PRs (the provider interface and the canary scan), and every later `mandate-notify` slice are
   held to ES-13 as usual. DEC-77 holds: the implementation PR changes the tests only by deleting
   ignore lines, and each PR passes the mutation gate with 0 missed mutants.

## Rationale

- **Already split.** S1 measured about 1,100 lines. It was split in two (S1a the notice, S1b the
  provider interface and the canary scan), and the canary scan was moved to S1b as well, to bring
  S1a as near 600 as its content allows.
- **What the overage is.** It is tests and the declared stub API, not added logic: the catalogue
  test types out spec §3.2's 32 rows as an independent oracle, and the crate's 32-variant
  `NoticeKind` and its `ALL` list mirror them. Cutting either through the middle would separate a
  table from the test that checks it.

## Alternatives considered

- **Split S1a again** (the kinds and text keys apart from the id, payload, and link). Rejected: it
  adds two more review cycles for a stub API whose parts are reviewed together, and the payload
  tests need the text keys.
- **Leave the overage unrecorded.** Rejected. ES-13 holds by review, and an exception the review
  grants is written down so that it cannot spread unrecorded.
