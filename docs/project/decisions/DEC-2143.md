## Context

The executor process's binding-gate source answers no input for an opening once anything has
traded on the account (`Deployment::input`, `JournaledAccount::untraded`, DEC-2380 item 2), so the
opening is held until the account risk view reads it (DEC-2804). For a research agent, whose
mandate is unpinned, that view binds no instrument, so every later opening is held until a
multi-instrument risk state exists (DEC-2819 item 4). At this decision the executor process does
not yet resolve an unpinned deployment at all, so it holds every opening of a research agent,
traded or not; DEC-2819's executor slice resolves it and swaps its bare `untraded` test for the
function below. The hold is journaled nowhere: the process
raises an in-memory `opening_held` alert per intent. The workspace API's agent read serves the
agent's `mode`, so a research agent whose openings are held reads exactly like a stalled one.

## Decision

1. **One function decides the hold.** `mandate-gate-context` gains `opening_hold(account,
   pinned) -> Option<OpeningHold>`, pure, over the account stream's fold (`JournaledAccount`) and
   whether the deployed mandate pins its universe. It answers `None` while the account is
   untraded; otherwise `ResearchAgentTraded` for an unpinned mandate and `AccountTraded` for a
   pinned one. "Research agent" here is the unpinned mandate, whose working universe research
   admits (mandate spec §8, V-036). The executor process's source binds on it (lane X swaps its
   bare `untraded` test for this call in DEC-2819's slice C), and the agent read calls it, so the
   two never differ. When the account risk view reads a pinned agent's openings (R4b),
   `AccountTraded` stops being returned and nothing else changes.
2. **The agent read serves it.** `read-models/agent` gains the required `openings_held`: `null`
   exactly when the function answers `None`, else `{"reason": <code>}` with `account_traded` or
   `research_agent_traded`. A closed enum, so a reason the specs do not name is never served.
3. **Fail closed, named.** When the agent has no account stream, the read cannot read the
   deployed document to know whether it pins its universe, or any row the fold reads cannot be
   read (which makes the fold hold every opening), it serves `{"reason": "unknown"}`, never
   `null`, and the web says openings may be held and that the status is unavailable.
4. **Scope, and what `null` does not say.** Only standing holds, which last as long as the
   account's state: `null` means none of these reasons applies, not that openings run. A hold
   until a fact arrives or ages in (no risk clock, account snapshot, or mark, or a stale one), and
   a hold for one order (its quote, the session, a limit), stay the gate's verdict on each order;
   the owner's hold and a paused or stopped agent show as `mode`. No exit, protective order, or
   kill switch is ever held by these reasons (`AGENTS.md` rule 13), and the web says exits still
   run.
5. **Order.** This spec, the schema, and this decision land first, the spec's planned marker
   covering the whole member until it is served. Then the function and its tests, against an
   oracle that reads the journal rows its own way; then, once DEC-2819's executor slice binds on
   the function, the read, so the read and the gate never differ; then the web.

## Rationale

The owner must be able to tell a held research agent from a broken one, and the only honest
source is the gate's own rule. Serving the function's answer, rather than deriving the hold in the
browser or journaling a copy of it, keeps one definition; a named `unknown` keeps an unreadable
state from reading as "not held".

## Alternatives considered

- **Derive the hold in the web from the journal.** Rejected: a second copy of a gate rule, which
  would drift (the coordinator ruled it out).
- **Journal the hold as an event.** Rejected for now: the hold is a standing state of the account,
  not an event, and the executor writes nothing for a refused batch; a read of the fold says it
  exactly.
- **`null` for an unreadable state.** Rejected: it would read as "not held".
