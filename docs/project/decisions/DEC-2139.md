# DEC-2139: The account stream's `KillSwitchActivated` closes as the executor writes it

| | |
|---|---|

| **Date** | 2026-10-26 (UTC) |
| **Decided by** | `claude-code` (coordinator), on lane L1's proposal |
| **Story or claim** | The cell executor's crash on a kill switch (lane DR's finding); [journal spec](../../specs/journal.md) §9 and §9.5; [trading spec](../../specs/trading-domain.md) §5.5; [DEC-2003](DEC-2003.md) item 4; [DEC-2302](DEC-2302.md) item 2 |

## Context

The account stream's `KillSwitchActivated` was catalogued but "not yet closed" since journal spec
v0.59, so `append` refused it as `unknown_schema`. In a deployed cell every kill switch the executor
applied was refused with its batch, `[AgentModeApplied, KillSwitchActivated]`, and the executor
crash-looped: no kill switch the executor applied could be journaled (`AGENTS.md` rule 13).

## Decision

1. §9.5 closes the account stream's `KillSwitchActivated` at schema version 1 with exactly the
   members `mandate-executor`'s `kill.rs` writes: `scope` (`agent`, `account`), `subject`,
   `initiator`, `purpose` (`risk_exit`, `owner_exit`), `cancels`, `closes`, `deferred`, `floor`,
   `bid`, `bid_size`, `copied_from`, and `risk_clock`.
2. Rules, each true of the writer today: 281, the purpose is the initiator's sell purpose; 282, the
   owner's confirmation is whole or absent; 293, only the owner's switch is confirmed; 294, an
   account switch cancels through the cancel-all and defers nothing; 295, the switch is caused by
   its `AgentModeApplied`; 296, no instrument both closes and is deferred.
3. A catalogue test in `mandate-executor` asserts that every event type the executor drafts on the
   account stream is closed in `mandate-journal`, so a writer can no longer outrun the journal.
4. Rule numbers 281, 282 and 293 to 300 are the coordinator's allocation to lane L1; 297 to 300
   are left for `ExternalActivityIngested`, `RejectObserved` and `OrderAbandoned`.
