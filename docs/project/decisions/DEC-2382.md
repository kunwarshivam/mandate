## Context

DEC-2306 item 1 lets `mandate-executord` reach its in-process fixture or Alpaca's paper trading
host and nothing else, and `tests/paper_only.rs` pins it. DEC-529 allows one founder-run live
order on the founder's own Robinhood agentic account, through the paper path's deployment runner,
with the runner the only crate that may declare a `live` feature. The founder wants that order to
go through the cell's executor, the same process that places paper orders, rather than a path of
its own.

## Decision

1. **`mandate-executord` may carry the Robinhood connector beside Alpaca paper**: `mandate-robinhood`,
   its capability profile ([DEC-531](DEC-531.md)), and its MCP client with the pinned tool allowlist
   (E7-16). It may do so only for the founder's own Robinhood agentic account, whose mandate holds
   every narrowing DEC-529 sets. This replaces DEC-2306 item 1's "the fixture or Alpaca's paper
   trading host, and nothing else" for that one account; for every other connection item 1 stands.
2. **Agents build and test it only against the Robinhood simulator** (`mandate-rh-sim`, DEC-124).
   `AGENTS.md` rule 8 is unchanged: no agent places a real order, holds or reads a live
   credential, or runs the live deployment.
3. **Going live is the founder's alone.**
   - The credentials are the founder's own, in the vault.
   - The founder flips the live switch.
   - Every opening waits for the founder's grant in the approval flow, bound to the order's
     content hash (mandate spec §6.1).
   - DEC-529's cap holds: `max_order_usd` 100 USD, on one broad ETF.
4. **The executor's `live` build is a separate artifact, gated explicitly.** CI only compiles it,
   as DEC-529 item 3 has it for the runner today (as [DEC-964](DEC-964.md) narrows it). The
   `xtask/layers.toml` `live_feature` change that lets the executor declare it lands in the same
   story as the code, under this decision. The default build holds no live host.
5. **Every safety rule and every gate is unchanged.** That covers the confirmed mandate version,
   the order builder, the risk gate with the US account rules, the account ledger, journaling
   before acting, idempotency, tests first (DEC-77), an independent review on a different model,
   and zero missed mutants. DEC-529's other items stand as written, except where items 6 to 8
   change them.

## The founder's answers (2026-10-26)

The coordinator asked: "For Robinhood (DEC-2382, PR #2434), do you accept the three
recommendations? (a) A `simulated` environment for rh-sim, since Robinhood has no paper
environment. (b) The Robinhood credential kept in the vault. (c) Lifting DEC-529's 'one live order
then stop' for an always-on agent, keeping the $100 cap, one ETF and ASK on openings. Until you
answer, the cell trades on the Alpaca fixture broker only." The founder answered, verbatim:
**"Accept all three (Recommended)"**. The recommendation's own note read: "Lane LV builds the
rh-sim path, then the vault credential. Live orders still need your own run under DEC-529's other
items." Items 6 to 8 record the three answers.

6. **(a) A `simulated` environment for rh-sim.** Robinhood has no paper environment (DEC-441
   item 11, connections spec §4), and its paper stage is the simulated broker with Robinhood's
   rules (DEC-124). A connection to `mandate-rh-sim` is recorded with its own environment,
   `simulated`, beside `paper` and `live`, so nothing reads a simulator connection as live or
   as Alpaca paper. A `simulated` connection reaches only a loopback `mandate-rh-sim` and holds
   no credential. The spec and schema change that adds the value is lane LV's, tests first, with
   the spec change in a spec-only PR before the code.
7. **(b) The Robinhood credential is kept in the vault.** On the executor's path the founder's
   Robinhood credential is held in the vault, not only in one connector process's memory on the
   founder's machine (DEC-529 item 10). It still reaches no repository, log, journal, artifact,
   fixture or agent context (`AGENTS.md` rule 7). Agents design and test the vault path with
   fixture credentials only; putting the live credential in the vault is the founder's own step.
   The design is its own decision.
8. **(c) An always-on agent, not one order then stop.** DEC-529's "one order (item 1), then stop"
   (item 13), and the spent connection record that enforces it (item 3, "How the narrowings
   lapse"), are lifted for the founder's own Robinhood agentic account: the agent may keep
   running and place further orders. What stays:
   - `max_order_usd` 100 USD, on one broad ETF (DEC-529 item 2), in the confirmed mandate;
   - the mandate's autonomy rules say `ask` for every opening, so each opening waits for the
     founder's grant in the approval flow, bound to the order's content hash (mandate spec
     §6.1); exits follow `AGENTS.md` rules 2 and 13 as for every agent;
   - every other DEC-529 item, and item 3 of this decision: going live, and flipping the live
     switch, stay the founder's alone.

## What this amends

- **DEC-2306 item 1**, as item 1 above says. Its status line points here.
- **DEC-529 item 3's "only the runner may declare a `live` feature"**: the executor may declare one
  too, under item 4.
- **DEC-529 item 10's credential handling**: on the executor's path, the founder's Robinhood
  credential is held in the vault (items 3 and 7) rather than only in one connector process's
  memory on the founder's machine. It still reaches no repository, log, journal, artifact, fixture
  or agent context (`AGENTS.md` rule 7).
- **DEC-529 item 13's "One order (item 1), then stop"**, item 1's one-order reading, and item 3's
  spent connection record: lifted for an always-on agent on the founder's own account (item 8).
  The cap, the one ETF and ASK on openings stay.
- **DEC-441 item 11 and DEC-124**: unchanged. Item 6 names the simulated broker's environment;
  it adds no route to Robinhood.

## Consequences

- The code is lanes X's and LV's: the executor's connector wiring, the `live` feature and its
  `layers.toml` entry, and the change to `tests/paper_only.rs` that the feature needs. Lane LV
  builds the rh-sim path first (DEC-2386) with the `simulated` environment (item 6), then the
  vault credential's design (item 7). This decision changes no code; `tests/paper_only.rs`'s doc
  points here until that story lands.
- The founder's orders run through the production executor rather than a path of their own, and
  the agent keeps running after its first order (item 8).
