# DEC-2642: a merge that waits for no CI first passes `cargo xtask land-check`

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-26 (UTC) |
| **Decided by** | lane DR at the coordinator's request. It tightens a landing condition and adds no risk, so an agent may record it (DEC-176, DEC-79) |
| **Story or claim** | No story; process and CI. On 2026-10-26 three changes landed that only CI's checks would have refused: spec-guard violations, stale hash pins, and a duplicate OpenTofu definition. DEC-2605 row 14 lets a reviewed change merge without waiting for `fast` or `full`, so nothing ran those checks before the merge |

## Decision

1. **A merge that waits for no CI needs a passing land-check.** Under DEC-2605 row 14, a change
   lands once its independent review passed. It now also needs `cargo xtask land-check` to pass
   on the head the review saw, and a clean `git merge-tree --write-tree origin/main <head>`. The
   landing rule is: independent review PASS, a clean merge-tree, and a land-check pass. The
   founder's answer in row 14 stands: CI still does not gate the merge.
2. **What land-check runs.** It fetches `origin/main` and merges it into HEAD in a scratch
   worktree under `target/land-check/`, leaving the caller's checkout untouched. A conflict fails
   it before anything runs. On the merged tree it runs `cargo xtask ci spec-guard`, `ci lint` and
   `ci test`, with `MANDATE_BASE_REF` set to the merged base. The tests are therefore the parts
   `ci select` scopes to the change (DEC-1190). Each job runs even after an earlier one fails.
   No cell and no mutants, so it stays fast; mutants on safety-critical crates remain their own
   rule (DEC-79).
3. **One summary line.** It ends with
   `land-check summary: head=… base=…@… fetched=yes|no|skipped merged=… merge=clean|conflict spec-guard=… lint=… test=… verdict=pass|fail`,
   and exits non-zero on anything but `verdict=pass`. A lane reports from that line, as from the
   mutants summary (#2648). `fetched=no` means the base could not be fetched and the check ran
   against the last fetched `origin/main`.

## Alternatives

- **Wait for CI again (DEC-175).** Rejected: row 14 is the founder's answer, and CI's queue was
  the reason for it.
- **Run `cargo xtask check` before every merge.** Rejected: it includes the cell and the mutation
  shards, which take far longer than a landing can wait.
