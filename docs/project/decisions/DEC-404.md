## Decision

1. **Scope.** This is the tests PR (DEC-77 stage 2) for registering journal spec v0.8 §9.3's `MandateVersionApplied` and `UniverseChanged` (DEC-403). It also covers mapping them to `JournaledFact`. The pending tests carry `pending E7-10`, the story whose follow-up the backlog row is.
2. **The journal stub.**
    - **`UniverseChanged`'s catalogue entry.** It gains its §9 entry (the account stream, the `man` ref). Before this it was refused as `unknown_event_type`, because the catalogue did not list it.
    - **Routing.** `control::governs` routes both types on the account stream to §9.3.
    - **The stub.** `control::payload` refuses both as `InvalidReason::Unimplemented` at `payload`. The variant returns until the implementation PR.
    - **No outcome changes.** Both were refused before, as `unknown_event_type` or `unknown_schema`, and both are refused now.
3. **The mapping stub.**
    - **The change.** `JournaledFact::from_record` answers `SpecError::Unimplemented` for both types, where it answered `Ok(None)`.
    - **Why it is safe.** That is the stricter outcome, since the record is refused rather than skipped. No caller outside tests maps either type, and `append` refuses both, so no journal holds one.
    - **The test it replaces.** The live `a_type_section_9_2_leaves_open_maps_to_none` pinned the old answer. It becomes `a_risk_state_record_is_never_skipped`, live on the stub and on the implementation alike.
4. **What is pinned, and where.**
    - **The vectors through `Draft::parse`, inside the crate.** `control::tests::every_risk_state_draft_is_judged_as_its_vectors_say` accepts every base and valid draft, and refuses each invalid draft with its reason at its path. It is in the crate so the mutation gate judges rules 29 to 33 there.
    - **Nullability.** `control::tests::a_required_risk_state_member_is_never_null` covers the 15 non-nullable members, at every depth. The vectors pin each member's type but not its nullability. On a throwaway implementation, `universe_size_after` made nullable was caught by this test alone.
    - **The closed schemas.** `catalogue::risk_state_records_refuse_an_unlisted_member` checks that both schemas are closed. The live `risk_state_records_are_routed_to_section_9_3` checks that neither is refused for want of an entry or a schema.
    - **Through `append` and the mapping** (`mandate-refcases/tests/risk_state.rs`):
      - the vectors append as they say;
      - each base draft maps to its listed fact;
      - an unstored `new_version` is refused at `new_version`.
    - **The mapping inside `mandate-spec`.**
      - `record_tests::a_universe_change_maps_to_its_instrument_admitted_or_removed`.
      - `record_tests::a_version_maps_only_under_the_classification_its_documents_give`. Its version pairs change `max_order_usd` and `name`, rows rule 33 cannot see, and its expected verdicts are written from §9.2's rows rather than computed by `change::classify`.
5. **The blocking requirement from #470** (round 2, minor 5; DEC-403 item 5). Two pending tests require the mapping to re-derive §9.2's classification from the two stored documents and refuse a stated classification that differs, at `classification`, for applied and rejected records alike:
    - `mandate-refcases`'s `a_version_whose_classification_differs_from_its_documents_is_refused`, over every version record in the vectors;
    - `mandate-spec`'s in-crate test above.

    The implementation PR cannot pass without the check, which closes the one hole §9.3 leaves open: a risk-increasing version, through a §9.2 row rule 33 cannot see, journaled as applied, labelled `neutral`, with no step-up.
6. **The mapping's form, as the tests fix it** (the implementation decides the rest).
    - **Version records.** `old_version` and `new_version` must each name a stored document that parses and hashes to its digest. Otherwise the record is refused at that member, `old_version` first.
    - **Classification.** The stated classification must equal `change::classify`'s class.
    - **Result.** A `rejected` record yields `Ok(None)`. An `applied` one yields `AgentVersionActive` from the new document, as `AgentDeployed` does.
    - **`UniverseChanged`.** It is refused at `change` for any value but `admitted` or `removed`.

7. **#482 round 1, as ruled.**
    - **M1: the classification pairs cover the rows rule 33 cannot see.** `a_version_maps_only_under_the_classification_its_documents_give` holds 14 pairs. They cover a risk maximum in each direction, `name`, unpinning, `max_instruments`, protection off, a later `end_date`, a signal-model change, an asset class added, `behavior.research` set from null, pinning from a version with an admitting model (reducing, DEC-121) and from one without, and an autonomy `then` in each direction.
      - Each verdict is written from §9.2's table by hand. On a throwaway implementation, `change::classify` agrees with all 14.
      - A re-derivation that reads only `/capital`, `/risk` and `/name` passed all nine pending tests before. It now fails this test.
    - **M2: what the re-derivation inherits.** Strict equality stays.
      - **Coverage.** The re-derivation inherits `change::classify`'s coverage, and DEC-353's two shapes (#444, #471) are not in the Rust classifier yet. So E6-13's classifier code PR is part of closing the hole item 5 names.
      - **Order.** A change to `classify` is a journal-affecting change: a record labelled by an older classifier can become unmappable, and a context that will not build is not a hold an exit may have (`AGENTS.md` rule 13). So E6-13's classifier change lands before any path builds a context from a real journal (DEC-169's wiring). That order is a named prerequisite on both backlog rows.
    - **m6: strict equality supersedes #470 round 2's note.** That review recorded that rule 33 does not refuse a neutral or reducing record labelled `risk_increasing`, and called that harmless. The mapping now refuses it too, because §9.3 types `classification` as §9.2's verdict of the two documents, so any other value is malformed, and a malformed record is refused rather than mapped. Rule 33 stays as it is; only the mapping refuses the over-label.
    - **m1:** `a_required_risk_state_member_is_never_null` adds a rejected record that rule 33 does not read (`equity_below_exposure`), so a null `classification` there is refused by the schema alone.
    - **m2:** `a_risk_state_record_at_another_schema_version_is_an_unknown_schema` pins both types' version gate. This is the second time the gate was found unpinned, after #467's m3, so the tests PR pins it.
    - **m4:** `a_version_document_that_is_absent_or_an_impostor_is_refused` covers a missing document and an impostor stored under the other's digest, at `old_version` and at `new_version`.
    - **m3:** the backlog row for #470's minors names the 31-then-32 order.
    - **m5:** the sentence in §9.3's mapping table that the mapping refuses a mismatched classification goes with the implementation PR.

8. **The implementation.**
    - **`mandate-journal`.**
      - `control::schema` registers both schemas.
      - `control::payload` applies rules 29 to 33 after the §9.2 rules, on a well-typed payload only.
      - Both types reach their schemas through `schema`'s version gate, so the stub's early return is gone (#482 round 1, m2).
      - `InvalidReason::Unimplemented` is removed again.
    - **`mandate-spec`.**
      - `JournaledFact::from_record` maps `UniverseChanged` to its fact.
      - For `MandateVersionApplied`, it reads `old_version`'s and then `new_version`'s stored document, each parsed and re-hashed to its digest. It refuses a stated classification that is not `change::classify`'s class, and then maps an applied record to `AgentVersionActive` from the new document and a rejected one to none.
      - The stub is gone.
    - **Tests and spec.**
      - The eleven pending tests are live, with only their `#[ignore]` lines deleted.
      - The catalogue test registers both types, so the risk-clock test now requires `risk_clock` of each, with `artifact_refs` listing a payload's references.
      - §9.3's mapping-table sentence (round 1's m5) is **not** in this PR. `cargo xtask ci spec-guard` refuses a spec change alongside code (ES-22), so it goes in its own spec-only change: the mapping refuses a `MandateVersionApplied` whose `classification` is not §9.2's verdict of its two documents, applied or rejected alike. Until then the table under-states what the mapping refuses. That is the safe direction, since the code refuses more than the text says.
      - `control::tests::rule_33_refuses_nothing_that_shows_no_raise` accepts an applied decrease, a zero change, and three rejections the fold reaches without a raise, each under a reducing or neutral label. The mutation gate found that rule 33's two `&&` could become `||` with no test failing; it now catches both.
    - **#482 round 2's minors:**
      - **m1:** the classification test's doc says the mapping does not validate the stored documents, and the backlog has a line to make the six invalid pairs valid.
      - **m2:** the impostor test gains a case with neither document stored, so `old_version` before `new_version` is pinned.
      - **m3:** the risk-state backlog row names `join` over several rows, and two identical documents, as unexercised.
      - **m4:** the evidence count below is corrected.
      - **m5:** the feature map's `Run` line is rewrapped.

## Evidence

- **Throwaway implementation (not committed).** It registers both schemas and rules 29 to 33, and maps both records with the classification check. All 11 pending tests pass on it (round 1's two included), and the four crates' 1378 live tests stay green (#482 round 2, m4: 1348 was round 1's count).
- **Plants on it.** Each fails a named pending test:

| Plant | Fails |
|---|---|
| The classification check skipped | `a_version_whose_classification_differs_from_its_documents_is_refused`, `a_version_maps_only_under_the_classification_its_documents_give` |
| A rejected version mapped as applied | `each_risk_state_record_maps_to_its_journaled_fact`, `a_version_maps_only_…` |
| `admitted` inverted | `each_risk_state_record_maps_to_its_journaled_fact`, `a_universe_change_maps_…` |
| Rule 33, rule 29, or rule 32's admission clause off; `step_up` opened | `every_risk_state_draft_is_judged_as_its_vectors_say`, `the_risk_state_records_append_as_their_vectors_say` |
| `universe_size_after` nullable | `a_required_risk_state_member_is_never_null` |
| `classification` nullable (round 1, m1) | `a_required_risk_state_member_is_never_null` |
| A re-derivation reading only `/capital`, `/risk`, `/name` (round 1, M1) | `a_version_maps_only_under_the_classification_its_documents_give` |
| No re-hash check on the stored document (round 1, m4) | `a_version_document_that_is_absent_or_an_impostor_is_refused` |
| The version gate bypassed for both types (round 1, m2) | `a_risk_state_record_at_another_schema_version_is_an_unknown_schema` |

- **Do-nothing stubs.** A stub accepting every payload and mapping to none passes 0 of 11. So does one refusing every payload and mapping.

## Rationale

DEC-77 keeps the tests ahead of the code. Here, that turns the requirement #470's review raised into a test the implementation must pass, rather than a backlog line it could miss.

## Alternatives considered

- **Keep `from_record` answering `Ok(None)` until the implementation.** Rejected: the pending mapping tests would then fail on a value, not on the stub's own report, which `cargo xtask ci pending` refuses. Refusing is also the stricter answer.
- **Check the classification in `mandate-journal`.** Rejected: the journal has no mandate types, and `mandate-spec`'s mapping already opens the stored documents (DEC-403 item 5).
