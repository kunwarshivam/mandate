# DEC-2808: The executor's `ClockAdvanced` copy on the account stream is closed at schema version 1 (lane RK, E6-15 slice C)

| **Story or claim** | E6-15 slice C, lane RK's R4b; journal spec §2, §9.5 and §9.20, v0.94; [DEC-2804](DEC-2804.md) item 5, [DEC-2399](DEC-2399.md) item 5, [DEC-2307](DEC-2307.md) item 5 |

## Context

DEC-2804 item 5, after DEC-2399 item 5 and DEC-2307 item 5, has the executor journal a
`ClockAdvanced` copy on the account stream when a scheduler tick returns a risk record or crosses
New York midnight, so the account risk fold (`mandate-executor`'s `risk_state.rs`) can derive
`RiskDayStarted` from it. Journal spec §9.20 closes only the scheduler stream's records and leaves
the account-stream copies open "until the story that writes them (E7-4 slice 5) closes them".
`mandate-journal` registers no account-stream schema for the copy, so `append` refuses it as
`unknown_schema` at `payload`. Without it the risk day never rolls, and a stale day start could
miss a daily-loss breach.

The executor's own fold reads `risk_clock` from every account-stream row it folds, and refuses a
row without one or one that goes back (journal spec §2; `fold.rs`'s `risk_clock()`). It also
refuses a copied `ClockAdvanced` with no `causation_id`. The scheduler stream's `ClockAdvanced`
has only `clock`, since no scheduler-stream record is a risk input.

## Invariants first

- The copy is the tick: it never carries a clock other than the scheduler tick it copies.
- Every account-stream row the executor's fold reads carries `risk_clock`, and the stream's
  `risk_clock` never decreases (§2).
- A cross-stream fact is copied with a `causation_id` naming its original (§2).
- Closing the schema refuses nothing the executor writes under DEC-2804 item 5.

## Decision

1. **The account stream's `ClockAdvanced` is closed at `schema_version` 1** (journal spec §9.5,
   v0.94), with exactly two members, each present and never `null`: `clock`, a `risk_clock`, the
   scheduler's tick it copies; then `risk_clock`, a `risk_clock`. Any other member is `schema` at
   that member, as for §9.5's other records. `config_refs` is `{}`.
2. **Rule 301: `risk_clock` equals `clock`** (`schema` at `payload.risk_clock`). The copy is the
   tick, and the latest tick the executor had seen when it journaled the copy is that tick. With
   §2's check that `risk_clock` never decreases, a copy's tick never goes back on the account
   stream.
3. **Rule 302: `causation_id` is non-null** (`schema` at `causation_id`): the scheduler stream's
   `ClockAdvanced` the row copies (§2's copy rule; DEC-2804 item 5). `append` checks presence, not
   that the named event exists or is a scheduler tick, since there is no global order across
   streams (§2). Rule 295 does the same for the account stream's `KillSwitchActivated` (DEC-2139,
   after DEC-2003 item 4). The two rules are judged in number order, and the first that fails is
   reported.
4. **No rule binds the writer.** The executor writes the copy as a `system` actor, `executor`, as
   it writes every §9.5 record, and none of them has an actor rule: rules 281, 282, 297 and 298
   bind payloads only. Only the scheduler stream's records bind their writer (§9.20, rule 159).
5. **`TradingDayStarted`'s account-stream copy stays open** (§9.20, E7-4 slice 5): nothing writes it
   yet, and the risk fold reads the day from `ClockAdvanced` (DEC-2304 item 7). §9.20's paragraph
   on the copies says which is closed where.
6. **Rule numbers 301 and 302.** Rules 299 and 300 are not taken: DEC-2139 item 4 left them to
   DEC-2803's records, and DEC-2803 item 5 left them unused. Skipping them means no reader of either
   decision finds them on another record. No open change was seen to hold 301 or 302.
7. **Vectors.** The new `account_clock` section of `reference-cases/journal.yaml` holds a base tick
   and a midnight copy, an invalid draft for each member type and each rule, and valid drafts for
   what the rules might be misread to refuse. `reference/journal/account_clock.py` generates it,
   with an independent oracle and seeded validator and vector mutants. No other section changes,
   so the vectors stay version 3.
8. **What this amends.** [DEC-2304](DEC-2304.md) item 7 reads `clock` as "the one member the
   scheduler's record has", and [DEC-2307](DEC-2307.md) item 5 and DEC-2804 item 5 describe the copy by
   its `clock`. The account stream's copy now also carries `risk_clock`, equal to it. The risk fold
   still reads `clock`, so their readings stand for that member. The scheduler stream's record is
   unchanged.
9. **The writer journals each copy in tick order.** A copy of tick N is journaled before any
   account-stream row whose `risk_clock` is above N, which the executor meets by construction:
   every row it writes carries the latest tick it has handed, and the copy carries that tick.
   Otherwise `append`'s monotonic check (§2) would refuse the copy.
10. **The code follows separately.** In the code change after this one, `mandate-journal` registers
   the schema and judges rules 301 and 302, and `mandate-executord` writes the copy (R4b). Both
   are tested against the `account_clock` section.

## Rationale

- Copying `clock` into `risk_clock` gives every account-stream row one reading: the executor's fold
  and `append`'s monotonic check read `risk_clock` here as on every other risk input, with no
  exception for this type.
- Requiring `causation_id` makes every copy traceable to the scheduler's tick, as §2 requires of
  every copy. The writer already holds the tick it copies, so the rule costs nothing.

## Alternatives considered

- **Reuse the scheduler stream's schema (`clock` alone).** Rejected: the executor's fold refuses a
  row without `risk_clock`, so either the fold gains an exception for this type or the copy cannot
  be folded. One more member keeps the fold's reading uniform.
- **Check that `causation_id` names a scheduler tick with the same `clock`.** Rejected: `append`
  reads one stream, and there is no global order across streams (§2). The executor holds the link.
- **Close `TradingDayStarted`'s copy in the same change.** Rejected: nothing writes it yet, and its
  members and rules are for E7-4 slice 5 to decide with its writer.
- **Take rules 299 and 300.** Rejected: both decisions that allocated them name them, and a gap of
  two numbers costs nothing.
