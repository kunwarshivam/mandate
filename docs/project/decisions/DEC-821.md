## Context

The demo connects Alpaca paper by OAuth (DEC-820). The L2 lane read Alpaca's public OAuth
documentation on 2026-10-08 and found two blockers.

1. **U-A4 is not cleared.** A grant can be requested per environment (`env=paper`), but the
   documentation never says the live host refuses a paper-environment token, and the token response
   carries no environment field. DEC-441 item 21 therefore refuses every Alpaca OAuth grant, paper
   included.
2. **The code exchange runs on the live host.** It is `POST https://api.alpaca.markets/oauth/token`,
   even for paper. ES-23 and infrastructure §2 compile only paper hosts into non-production
   builds.

The coordinator offered connecting with paper API keys. Those are already allowed (connections
§5.1, DEC-441 item 3) and need no new decision. The founder chose OAuth now.

## Decision

1. **DEC-690 item 6 is accepted.** A grant requested with `env=paper` is treated as meeting U-A4
   for paper connections. The residual risk the founder accepts is that such a token might be
   honoured by Alpaca's live host.
2. **DEC-690 item 7 is accepted.** In builds that otherwise compile only paper hosts, exactly one
   call to the live host is allowed: `POST https://api.alpaca.markets/oauth/token`, made only from
   the connection's own process during the code exchange and refresh. No other path or method on
   that host is reachable. A test pins the allowlist to that single method and path. A second test
   shows every other request to the host is refused before it leaves the process.
3. **What still holds, so the residual risk cannot become an order:**
   - The workspace sends every order only to the paper trading host the connection's environment
     names (`paper-api.alpaca.markets`). No code path sends an order, or any trading or account
     call, to the live host with any token.
   - The grant requests `env=paper` and only the scopes the connections spec allows (FR-2.2, exact
     scope refusal).
   - The token stays in the vault in `SecretString` only (rule 7).
   - The connection's permission checks (§8.1) still run.
   - DEC-441 item 21 still refuses a grant that names `live` or both environments.
4. **Scope.** This decision covers paper connections only. A live Alpaca OAuth connection needs a
   new decision. The founder may still ask Alpaca in writing whether a paper-environment token is
   refused by the live host. A written "yes" retires the residual risk, and a "no" is reported at
   once.

## Rationale

The founder wants the full OAuth journey in the demo. The two narrowings are the smallest that make
it possible, and the guardrails in item 3 keep any order on the paper host whatever the token
could technically reach.

## Alternatives considered

- **Paper API keys for the demo, with OAuth deferred until Alpaca confirms in writing.** This was
  the coordinator's recommendation, and the founder did not choose it. It stays available as a
  fallback under the existing rules.
- **DEC-441 item 22.** This is the founder's earlier fallback for the case where U-A4 fails. It is
  superseded for paper by this decision.
