## Decision

1. **The format is §3.11 item 7's, written one way.** Each line is `sha256:`, 64 lowercase hex
   digits of the SHA-256 of the canonical `{"issuer","subject"}` object (journal spec §4), one
   space, the principal's ULID, and `\n`. Lines are ascending by digest, and no digest appears
   twice.
2. **The subject never leaves standard input.** The command takes `--issuer`, `--member` and
   `--links`, but no subject argument, so no process listing or shell history shows the subject.
   Neither the file, the output nor any error carries it. One trailing `\n` or `\r\n` is stripped.
   A subject that is empty, holds a control character, or is longer than 1024 bytes (the line end
   not counted) is refused, and so is an issuer that is empty or holds whitespace. The issuer is
   taken exactly, with no normalization, because the server compares the token's `iss` exactly.
3. **Idempotent, and a subject is never re-pointed.** A link already there writes nothing and
   succeeds. A digest linked to another principal is refused `subject_linked_elsewhere`.
   Removing or re-pointing a link is left to a later slice; until then, an operator edits the file.
4. **Never extend a file the server would refuse.** An existing file that is not a regular file
   (a symlink, a directory), that is group- or world-writable, or that is owned by neither this
   process's user nor root is refused `links_unsafe`. A file that does not parse as item 1 is
   refused `links_malformed`. Nothing is changed in either case.
5. **Replaced whole.** The new text goes to `<links>.writing`, created exclusively with mode `0644`.
   It is synced, renamed over the file, and the directory is synced, so the server never reads a
   partial file. A second writer at once finds the staging file and is refused `links_busy`.
   After a crash the operator removes the stale staging file. The file is `0644`, not `0600`,
   because it is not a secret (DEC-978 item 7) and the server may run as another user than the
   writer. The file is owned by whoever runs the command, and the server accepts only its own user
   or root. So the command must run as root or as the server's user: a run as any other user
   writes a file the server refuses, and every sign-in then fails closed. A line with a `\r` is
   malformed, so a file edited by hand with CRLF line ends is refused, not silently rewritten.

## Rationale

The spec fixes what the server reads. These readings fix how one writer produces exactly that, and
keep the raw subject out of every place a log or listing could show it.

## Alternatives considered

- **The subject as an argument:** refused, because process listings and shell histories would
  show it.
- **Rewrite in place:** refused, because a reader could see a half-written file.
