# DEC-776: The causal trace does not type a version-2 submission's cause, because the journal cannot record a mistyped one

|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-09 (UTC) |
| **Decided by** | The L5 lane lead (`claude-code`) under DEC-79 and DEC-176: a reading that changes no behaviour the journal can produce and adds no risk; the founder may reverse it |
| **Story or claim** | E12-1 ([#745](https://github.com/kunwarshivam/mandate/issues/745)), the follow-up named under "Not done" in [#1064](https://github.com/kunwarshivam/mandate/pull/1064); builds on [DEC-772](DEC-772.md) and [DEC-775](DEC-775.md) |

## Decision

1. **No check, because no input reaches it.** Workspace API §4.8.1's version-2 `OrderSubmitted`
   row names its `causation_id` target as an `OrderRequestRecorded`, so a cause of another type
   would read `unexpected_type`. Journal spec rule 45 makes that case impossible to record:
   `append` refuses any batch in which a version-2 `OrderSubmitted` is not immediately preceded by
   exactly one `OrderRequestRecorded` that its `causation_id` names
   (`mandate-journal`'s `control::check_batch`, run on every `append`). So the trace keeps
   following a version-2 submission's `causation_id` as #1064 left it, and adds no type check, no
   test, and no behaviour-only row for it.
2. **Why no code is added.** A type check that no recorded journal can exercise has no test that
   fails without it. In `mandate-audit`, a safety-critical crate, its mutants would survive, and
   adding it would put untested code on a read path (AGENTS.md, the trust ladder). The same
   reasoning is how DEC-772 item 9 treats link values the closed schemas cannot hold.
3. **When to revisit.** If a journal store ever serves rows that did not pass `append`'s batch
   rules, for example an import or a store that skips `check_batch`, this decision lapses. That
   store's tests PR then adds the `unexpected_type` test for a mistyped version-2 cause, with the
   check after it, in DEC-77 order.

## Rationale

The outcome the spec names can never be observed, so following the cause untyped and typing it
give the same trace for every journal that can exist. Recording the reading closes #1064's
follow-up without code that its own mutants would reject.

## Alternatives considered

- **A test-only raw insert on `MemoryJournal`, or a stub `TraceRead` store in the audit tests, to
  hold an invalid row.** This was rejected. It widens a safety-critical journal crate, or the
  audit read layer, only to exercise a state that `append` forbids.
- **Typing the cause anyway, as defence in depth, with no test.** This was rejected. Its mutants
  would survive in CI, and item 3 already covers the one case where it would matter.
