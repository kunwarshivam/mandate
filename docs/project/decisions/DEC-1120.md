# DEC-1120: The research loop calls through mandate-gateway, the call record carries the verdicts, and the recorded fake is the default

|---|---|

| **Date** | 2026-10-17 (UTC) |
| **Decided by** | An agent (Claude Code, intelligence lane I2), under DEC-79 and DEC-176 |
| **Story or claim** | E19-3, E15-6's caller side; [claim #1515](https://github.com/kunwarshivam/mandate/issues/1515); supersedes DEC-996 items 4, 5, 7 and 9 in part |

## Context

DEC-996 built the research loop against its own `ModelGateway` trait and a recorded fake, with
provisional `ModelInvocationRecorded` and `CandidateVerdictsRecorded` drafts, because the gateway
and the closed agent-stream record did not exist. Both now do. `mandate-gateway` (#1484, DEC-997,
DEC-998) is the one component that calls a model, and journal spec v0.46 §9.19 closes the
agent-stream `ModelInvocationRecorded`, with the candidates' verdicts as its `verdicts` member
(rule 151). The coordinator asked for the loop to call through the gateway's contract, with the
recorded fake as the default in tests and CI, and for a config path that uses OpenRouter when a
vaulted key exists and the recorded fake otherwise, saying which. `main` holds neither the vault's
`SecretSource` (E21-32, lane V2, Proposed) nor a hosted HTTPS `Transport` for the gateway.

## Decision

1. **The call contract is the gateway's.** `mandate-research-run`'s `ModelGateway`, `GatewayReply`,
   `CallFailure`, `ErrorKind`, and `settle` are removed. The worker builds the call as before, at the
   gateway's own clock, and sends `ResearchCall::request()`, a `mandate_gateway::CallRequest` with
   purpose `research`, key owner `platform`, the journaled observations as its retrieved context, and
   three typed inputs (`context`, `items`, `memory`), each canonical JSON. The gateway renders them
   into the pinned template's data sections, guards the prompt, reserves the cost, calls, and
   validates the output; the answer is the gateway's `CallRecord`, or a `RequestError` for a request
   it cannot make at all. `ModelPin` is the gateway's `ModelRef`. §7.3's treatments are over the
   gateway's `Outcome`.
2. **The research entry is pinned content.** `ResearchEntry` builds the registry entry: the system
   text (opinions only, data sections untrusted), the user text with the three slots, the retrieval
   plan, §6.5's output schema in the gateway's schema language, the output bounds, the deadline, the
   token bound, and the seed, all inside the content hash.
3. **Revisions fail the pinned schema.** The gateway's schema language has no optional member, so the
   pinned schema leaves `predecessor_thesis_id` out, and an output that names a predecessor is
   `schema_invalid`, with no output at all. While §8.6 item 5 allows no revision, this refuses more
   than the harness's per-candidate `revisions_not_enabled`, which stays for the day revisions are
   allowed and the language can state an optional member.
4. **What the gateway's schema cannot state, the harness's strict parse still refuses.** Ranges of
   decimal strings (conviction, confidence), blank or control-character text, and byte lengths are
   not in the schema language. An `ok` output the parse refuses, or one whose candidates the
   platform cannot fill or admission cannot decide, is judged as nothing: the call record is
   journaled with no verdicts (rule 151 permits an empty list), and no thesis record or output
   follows. **Disclosed residual:** such a call is recorded with outcome `ok` and no reason; HI-22's
   "every candidate of a judged run has a verdict" holds because the run is not judged, and the
   inference spec's schema language gaining decimal ranges and an optional member (E15-12) closes
   it.
5. **The backend selection.** `research_gateway` builds the gateway with the OpenRouter adapter
   always, and chooses its transport and key source by `select`: OpenRouter, through the cell's
   hosted transport and the vault's key, only when the vault holds the upstream's key **and** a
   hosted transport is supplied; otherwise the recorded fake, with a fixed placeholder key source so
   a hosted endpoint's call reaches the fake rather than ending `credential_invalid`. The registry,
   the routing lock, the guard, the meter and its $50 cap, and the rate caps are the same either
   way, so a recorded run shows what a hosted run would send, and the journal is identical
   (`the_demo_runs_either_way_and_says_which_gateway_it_used`). `Selection::describe` says which
   transport and why, and never names the key. A process with no hosted transport passes
   `NoHostedTransport`, an uninhabited type, so it can only select the fake. Until E21-32's vault and
   a hosted HTTPS transport land, every deployment selects the fake; `cargo xtask cell demo` says
   so. No test or CI job holds a real key or reaches a model provider (DEC-997 item 4).
6. **The call record heads the judging batch.** Rule 151 puts the verdicts in the call's own
   `ModelInvocationRecorded`, so §6.2 steps 4 and 5 are one step: an `ok` record of the run in
   flight, completed by its deadline, under the pin research still runs, is judged when it arrives,
   and the batch is the call record with its verdicts, then each judged thesis's record (caused by
   the call record) and its output. The append is atomic, and the call record precedes every record
   its output leads to (INF-10). DEC-996 item 5's wait for the record to fold back, its
   `not_pinned` verdicts, and the provisional `CandidateVerdictsRecorded` are gone: an answer under
   a pin research no longer runs, or after its deadline, is recorded with no verdicts. Verdicts use
   rule 151's results: a harness refusal's own code, `judged` for a thesis handed to admission (its
   thesis record carries admission's result), and for an invalidation `unknown_thesis` or `judged`.
   An invalidation citing evidence the run did not retrieve is `judged`, since rule 151 gives
   `unknown_evidence` to theses only; its evidence is E19-5's verdict to check, and §6.2's
   preconditions keep every run from reaching one meanwhile.
7. **The core re-checks the record, and refuses another call's.** A record whose call id, pin,
   purpose, agent, or retrieved context differs from the run's planned call is refused
   `not_interpreted` and never journaled as this run's; the run waits for its own call's record or
   its bound. A cancelled run's call is remembered until its record arrives, as before, and only that
   call's record is accepted for it. A `RequestError` ends the run with no record and disables
   research for the pin until a new version, since the same request would be refused again.
8. **The schedule counts from completion.** The last call's instant is the record's `completed_at`,
   which §9.19 carries, both when the record is handled and when it folds back, so a restart folds
   back the anchor the live process used. `called_at` and `used` are gone with the provisional
   record.
9. **The run id's correlation is a hook.** §9.19 carries the run id in the envelope's
   `correlation_id`, which a draft cannot set; the call id identifies the run's one call meanwhile.
   Setting it joins DEC-996 item 2's run-path hook, after R0.
10. **Preconditions unchanged.** `mandate-journal` does not yet register the agent-stream
    `ModelInvocationRecorded` (DEC-998's code half) or the invalidation verdict (E19-5), so
    `JournalCatalog` still registers neither and no run starts in any deployment.

## Rationale

The gateway already enforces the pin, the routing lock, the deadline, the meter, and the identity
check; calling through it removes the loop's own copy of those checks and makes the recorded fake
the same code path a hosted call takes. Every reading the swap forced is taken toward refusing more:
a revision fails the schema, an unreadable output judges nothing, a record of another call is
refused, and the hosted transport is unreachable without both a vaulted key and a transport.

## Alternatives considered

- **Add a reqwest HTTPS transport crate in this change:** it would make the OpenRouter branch
  reachable, but its network code cannot be mutation-tested without a local TLS server, and
  `.cargo/mutants.toml` exclusions are the founder's; it belongs with E21-32's vault, which
  supplies the key it needs. Offered to the coordinator as option B.
- **Keep `CandidateVerdictsRecorded` beside the closed record:** two records of one judgment, and
  rule 151 already holds the verdicts.
- **Journal the call record first and judge on the next poll:** splits the verdicts from their
  record, which §9.19 does not allow.
- **Accept a record of another call and rewrite its outcome to `identity_mismatch`:** journals a
  record the gateway never wrote.
