# DEC-2204: The research driver is its own crate, with a trigger queue and a step machine; the shell wires it in after R0

| | |
|---|---|
| **Status** | Accepted (agent; reversible engineering decisions under DEC-79, each at least as strict as the rule it implements) |
| **Date** | 2026-10-17 (UTC) |
| **Decided by** | An agent (Claude Code, intelligence lane I2), under DEC-79 |
| **Story or claim** | DEC-996 item 2's run-path hook; ADR-0005 delivery slice 5 (run triggers and the driver); [claim #1531](https://github.com/kunwarshivam/mandate/issues/1531) |

## Context

DEC-996 item 2 leaves the research loop's run-path hook for after R0. That hook is the shell's research driver. It is a task that:

- calls `handle_research`;
- stores each step's drafts before handing any request on;
- retries an unresolved append with the same input;
- runs the worker;
- builds the `ResearchContext`.

The places the shell would hook it in are R0 files, which no lane may edit until R0 closes:

- the run cycle beside `production_cycle` (DEC-968 item 6);
- `tracer.rs`'s `perform`;
- `mandate-agentd`'s host (DEC-967 item 2).

ADR-0005 makes the harness agentic. A run is one session of a loop, of one of four kinds:

| Kind | Started by |
|---|---|
| Ideation | Schedule |
| Monitoring | An event |
| Owner | A desk message |
| Explain | An ASK being raised |

The rules that go with it:

- At most one run is in flight per agent.
- Owner and explain runs go ahead of queued runs.
- Event triggers are debounced and rate-limited.
- Mode gates every start.
- A run's tools are fixed by its trigger before anything untrusted is read. Only scheduled ideation runs may propose (design §16 item 2).

## Decision

1. **A new crate, `mandate-research-driver`**, at layer 7: above `mandate-runtime`, below `mandate-shell`.
   - It is pure and safety-critical, and touches no R0 file.
   - It reads no clock and does no I/O: the shell hands it time, the journal, and the worker.
   - The shell wires it into the run path after R0 closes, as its own change: the constructor beside `production_cycle`, the host in `mandate-agentd`, and DEC-1120 item 9's `correlation_id`.
2. **The trigger queue** (`TriggerQueue`), per agent:
   - **One run in flight** (HI-8).
   - **Start order:** first the owner and explain runs, oldest first; then the oldest monitoring run the rate limit allows; then the ideation run. None interrupts the run in flight, which never holds up trading (HI-7).
   - **Debouncing:** an event is dropped within `debounce_s` of the last accepted event of the same subject and cause. A dropped event does not extend the window, so a steady drip still gets through.
   - **Coalescing:** an event joins a queued run of the same subject and cause. Schedule ticks coalesce into the one queued ideation run.
   - **Rate limit:** at most `monitoring_per_hour` monitoring runs start in any rolling hour.
   - **Bound:** at most `max_queued` ideation and monitoring runs wait. Owner and explain runs are never dropped for room.
   - **Mode:** in `paused` or `stopped` no run starts. What was queued is dropped, so nothing triggered before a pause starts after a resume, and the run in flight is cancelled at its next step.
3. **Tool classes follow from the kind and the mode alone** (`tool_classes`), never from the model:
   - **Ideation** gets read, think, risk-reducing, and proposing.
   - **Monitoring** gets read, think, and risk-reducing.
   - **Owner** and **explain** get read and think.
   - **`exits_only`:** an ideation or monitoring run gets read, think, and risk-reducing (agent harness spec §6.7, review-only).
   - **`paused` or `stopped`:** nothing.

   The tool names and schemas stay the agent harness spec's (lane AH). The driver decides only the class.
4. **The step machine** (`Driver`) runs each research input to the core through `Core`; `RuntimeCore` is `handle_research` plus the two folds. Then:
   - **Commit before use:** it appends the step's drafts as one batch and folds every stored event back into the core, in order. Only then does it hand the worker its requests in the core's order and return the other effects for the shell to run. So no request is acted on, and no notice names a record, before the record commits (`AGENTS.md` rule 5, HI-2).
   - **Unknown append:** another input is refused (`Held`) until the same input is retried. The core answers that retry with the same drafts, and the journal's idempotency settles them (journal spec §5.1).
   - **Refused append, or a committed event the core cannot fold back:** this is a defect no retry mends. The driver halts research in this process until a restart (`AGENTS.md` rule 3). Trading never waits on research, so it is untouched.
5. **Today's runtime has one run kind.** `handle_research`'s poll starts a scheduled run when its cadence is due. Monitoring, owner, and explain runs need runtime inputs that start a run of a given kind with its frozen scope (agent harness spec v0.2 §6.9, lane AH's #1540). Until those land, the queue decides which kind is next, and only ideation reaches the core.

## Rationale

A crate of its own keeps the driver clear of every R0 file without waiting for R0, and keeps it pure, so every rule above has a test. The shell's later change is then wiring alone.

The two traits (`Core`, `JournalWriter`) let the ordering rules be tested on fakes for every journal outcome. A differential test then runs one whole research run through `RuntimeCore` and the runtime's own test loop, and finds the same records, the same ids, the same order, and the same requests.

Dropping the queue on a pause is the conservative reading of "no run starts while paused". A resume then never starts a run triggered by an event from before the pause. The schedule fires again anyway.

## Alternatives considered

- **A module in `mandate-shell`.** Its `lib.rs` sits beside `production_cycle`, which DEC-968 treats as R0. Rejected until R0 closes, and then unnecessary.
- **The cadence in the queue.** Rejected: the runtime owns the research interval (HI-8) and folds it back from the journal, and two clocks of one cadence would drift.
- **Keeping queued runs across a pause.** Rejected: an event from before the pause could start a run after the resume, against a state the owner had paused.
