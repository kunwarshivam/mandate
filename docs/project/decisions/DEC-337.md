## Decision

1. The arm and its code land live. The one changed evaluation path is a stub returning
   `Unimplemented("evaluate", "E17-8")` in its own function, so the mutation gate exempts its body
   and nothing live can reach it (no live test has an empty scoreable set at a minimum of zero).
2. The pending suite is two hand cases and one property: the empty set's arm and code at the
   minimum it answers, the all-unscoreable form, the count refusal keeping the set below a positive
   minimum, the outside-window precedence, the non-empty set unchanged with the boundary pinned
   from both sides, and `no_scoreable_set_reaches_division_by_zero` over generated scenarios whose
   oracle counts the scoreable set itself. The generator varies each thesis's horizon inside and
   past the registered window, and the property asserts that each of its four expectations is
   reached by at least one scenario (#435 review minor 2).
3. Every pending test fails at the stub with the stub's own report.

## Rationale

The stub function's own body is the unit DEC-137 exempts, and the pending gate reads each failure's
stub report.

## Alternatives considered

- **Inlining the `Unimplemented` return in `evaluate`.** The string mutants would sit in a live
  function no live test reaches: missed mutants.
- **Leaving the arm out of the tests PR.** The implementation PR could not add a registry arm and
  delete only `#[ignore]` lines.
