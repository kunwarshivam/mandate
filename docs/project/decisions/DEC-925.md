# DEC-925: The CLI gestures accept a live mandate on the owner's recorded, unspent Robinhood live connection only

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-16 (UTC) |
| **Decided by** | An agent (Claude Code, the K1b builder, Lane A1), under DEC-79 and DEC-176: each reading below applies DEC-529 item 3 (founder, Accepted) and, where that item leaves a gap, takes the reading that refuses more and adds no risk |
| **Story or claim** | K1b (E7-11), [first live trade brief](../tasks/first-live-trade.md); DEC-529 item 3; mandate spec V-001; claim [#1340](https://github.com/kunwarshivam/mandate/issues/1340) |

## Context

DEC-529 item 3 narrows V-001 and DEC-530 item 2 for one founder-run live order: "a `live` mandate
is accepted only on a Robinhood connection the founder recorded through the CLI", and V-001 adds
"and has not spent", checked "when the version is confirmed and deployed". K1b's first half
(`connection record`) records that connection. Until now `version create`, `version confirm` and
`agent deploy` ran only in `paper` (DEC-530 items 1 and 2): the owner's environment was hard-coded
and every other environment refused `paper_only`. Nothing said how the owner says "live", what
"recorded through the CLI" reads as on the control stream, or which code each other combination
gets.

## Decision

1. **The owner says it.** The three gestures take `--environment`, `paper` by default and `live`
   when given; any other value is refused `environment_invalid` before any journal is opened. The
   owner's environment is the envelope `environment` of every event the gesture commits. `config
   register`, `model register`, `workspace open` and the approvals commands are unchanged and stay
   paper only (their own lanes).
2. **One check, `version::admitted`, for every gesture.** `create`, `confirm`, `deploy`, and the
   read-only `confirmation` and `deployment` call it once the document is read (for `create`,
   once it parses): an owner neither in `paper` nor in `live` is still refused `paper_only`
   before anything is read (DEC-530 item 2). Then:
   - a `paper` owner takes only a `paper` document; any other is `mandate_not_paper`. This is new
     for `confirm` and `deploy`, which could not meet a live document before: a live version
     created by a live owner cannot be confirmed or deployed in paper;
   - a `live` owner takes only a `live` document whose `connection_id` is a **recorded Robinhood
     live connection**; any other document or connection keeps `paper_only`, the existing code.
3. **"Recorded through the CLI" reads as the record `connection record` writes.** The latest
   `ConnectionEstablished` or `ConnectionRevoked` naming the mandate's `connection_id` on the
   control stream must be an establishment whose payload names broker `robinhood`, environment
   `live`, a `margin_attestation` (`cash_account` or `margin_disabled`, DEC-529 item 11),
   `step_up.method` `cli_confirm`, and `user` the owner's own id (DEC-529 item 3, "on the
   founder's own connection only"). A revoked, paper, Alpaca, Kraken, unattested, passkey or
   another user's record refuses. Each condition only refuses more.
4. **Unspent at every gesture.** V-001 checks "unspent" at confirmation and deployment; the CLI
   checks it at creation too, the tighter reading. Spent is V-001's two cases, read on the account
   stream `acct:{workspace}:{account_ref}` the record binds: an order that filled, wholly or
   partly, which is DEC-910 item 3's evidence, a `FillApplied` or `LateFillApplied`, the same the
   runner's lapse reads; and an order whose answer was lost, an order (by `client_order_id`) whose
   latest `OrderStateChanged` is `unknown`, until reconciliation moves it to another state (DEC-529
   items 1 and 4). A spent record refuses `connection_spent`, the runner's code. The runner's lapse
   reads fills alone (DEC-910 item 3); its flat check and the instrument block hold an `Unknown`
   order there, so the CLI's wider reading only refuses more. A fill or a lost answer that lands
   between the check and the commit is caught by the runner's own check at start.
5. **A re-run is refused like a fresh gesture.** The check runs before a gesture finds its earlier
   event, so a re-run after the record is revoked or spent is refused rather than answered with
   the earlier event. It commits nothing either way; an agent already deployed stays deployed.

## Rationale

The gate sits where the owner acts, before anything is stored or appended, and reads only the
journal the gestures already read. Every combination but DEC-529 item 3's one is refused with the
code it had, so the paper path and every existing test are unchanged.

## Alternatives considered

- **Derive the environment from the document.** Rejected: the owner would never state "live";
  an explicit flag that must agree with the document refuses a mistaken live file.
- **Admit any live Robinhood record.** Rejected: DEC-529 item 3 names the founder's own
  connection recorded through the CLI; the user and `cli_confirm` conditions read that literally.
- **A new code for each live refusal.** Rejected: the dispatch and DEC-530 keep `paper_only`; only
  the spent record, whose remedy differs, gets the runner's own code.
