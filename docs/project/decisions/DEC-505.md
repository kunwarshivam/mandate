## Decision

1. **The source.** The deployment input is built as [agent harness spec §5.1](../../specs/agent-harness.md)
   steps 1, 2, 4 and 6 read it, with the founder's CLI as the deployment manager ("In Phase 1 the
   founder's CLI plays that role"):
   - the latest `AgentDeployed` for the agent, with no `AgentStopped` after it, names version V;
   - the stored canonical document re-hashes to V and passes the schema and every V-rule;
   - the `MandateVersionCreated` and `MandateConfirmed` for V give the provenance and confirmed
     paths, so V-020 sees every envelope path confirmed;
   - every `ConfigSnapshotRegistered` of kind `model_version` is the V-007 registry, which is
     therefore never `None` (not checked);
   - every configuration object the input names (fee schedule, calendar, instrument snapshot,
     rule set, `policy_set`, `model_registry`) re-hashes to its reference.
   Each record maps to its fact with `JournaledFact::from_record`, and the context folds with
   `ValidationContext::from_journal`, both existing code.

   **Which registration counts.** For each configuration kind, the effective
   `ConfigSnapshotRegistered` is the latest by control-stream `seq` at the run's single read of
   the stream. Two kinds narrow first: an `instrument_snapshot` counts only if its object names the
   pinned asset id, and a `model_version` only if it registers the pinned `(model_id,
   model_version, content_hash)`. A fee schedule whose `effective_from` is after the run's trade
   date is refused, never passed over for an older one. A registration committed during a run
   applies from the next run. E19-11's tests pin each of these.
2. **Confirmation.** The founder confirms with `cli_confirm`, the step-up method allowed in a
   `paper` environment ([mandate spec §6.1](../../specs/mandate.md#61-purposes), DEC-155 item 4,
   identity spec). Its evidence is in the records `MandateConfirmed.record_ref` and
   `AgentDeployed.record_ref` name. The CLI refuses a mandate whose `environment` is `live`.
3. **Two facts no record on this path carries yet** come as explicit arguments from their owner,
   as `ContextArgs` already takes membership and instrument groups:
   - **The account equity for V-002** is the broker account read by the same run's preflight,
     the current value V-002 is defined over. `AccountSnapshotRecorded`'s registration waits on
     DEC-261 item 7.
   - **The connection's environment for V-001** is `paper`, by construction of the only trading
     transport compiled in (`AlpacaPaperHttp`, ES-23). It replaces the value the fold gives a
     connection it saw no fact about, `Some(Environment::Live)` (`mandate-spec/src/context.rs`,
     `from_journal`), **and only that value, only when the control stream holds no fact about the
     connection**. A `ConnectionRevoked`, or a `ConnectionEstablished` saying `live`, keeps the
     fold's refusing value. The CLI does not write `ConnectionEstablished`: that record says FR-2.2's
     permission check passed, and E7-12 builds the check. So V-001's other half, that the
     `connection_id` belongs to the workspace, stays unverified on this path until E7-12 writes
     `ConnectionEstablished`; the paper transport's credentials are the founder's own account,
     which is what the run reaches.
   Workspace membership is one user and one approver, the founder, passed as `Membership`.
4. **Left to E19-1.** Process states (§5.2), scheduled cycles, research (§5.1 step 5), and a
   policy overlay beyond the levels registered for the deployment.

## Rationale

DEC-502 requires a confirmed version, not a reviewed file. The records and the fold that define
one already exist; what is missing is a writer (E10-16) and a reader in the shell (E19-11). Two
facts have no record yet. Taking them from their authoritative source in the same run gives
V-001 and V-002 the values they are defined over. The environment argument is limited so that it
can never lift a refusal a journaled connection fact causes, which a plain override would.

## Alternatives considered

- **Keep the reviewed file as the mandate source** (DEC-466). Rejected: DEC-502 item 1.
- **Write `ConnectionEstablished` from the CLI without the permission check.** Rejected: the
  record would assert a check that never ran.
- **Override the fold's environment with `paper` unconditionally.** Rejected: it would lift the
  refusal a `ConnectionRevoked` causes.
- **Wait for the workspace API's confirmation and deployment (E10-11, E10-12).** Rejected: M8,
  weeks away, and not needed to confirm a paper version.
