## Context

`Artifacts::from_registered` (`crates/mandate-shell/src/paper/artifacts.rs`) refused every
mandate whose environment was not `paper` ("a paper mandate"), a lock from the paper adapter's
first slice. Since DEC-947 a live run reaches it after the live door, the login, the lapse and
`confirmed_version` with all four of DEC-924 item 1's conditions held, so the rehearsal stopped
at step 2l with nothing sent. Lifting the lock alone would let a live run bind whatever the fold
handed it, and nothing recorded which stream or environment a registration came from: the
control records the shell read carried a sequence number, a type and a payload, no more.

## Decision

1. **A live mandate only from a live admission.** `from_registered` no longer refuses a mandate
   for being `live`. A live mandate can reach it only inside a `ConfirmedVersion`, and
   `confirmed_version` is the one function that answers one: it admits a live deployment on
   `LiveAdmission::admits` alone (all four conditions; DEC-924 item 2, DEC-934 item 5).
   `checked_before_credentials` answers no version (DEC-947 item 2). A test pins that a live
   stream with the default admission, or with every condition but the door, yields no version.
2. **Every binding from the deployment's own stream, in the mandate's environment.** Each
   `ControlRecord` carries its `Origin`: the stream it was journaled on and that stream's
   environment. `Registered` keeps its record's origin, and `ConfirmedVersion::deployed_on` is
   the origin of the `AgentDeployed` it was folded from. `from_registered` refuses `Absent`
   ("every binding journaled on the deployment's own control stream") unless the deployment's
   stream is in the mandate's environment and the model, fee schedule, calendar, rule set and
   instrument snapshot were each registered on exactly that stream (same stream id, same
   environment). So a paper object in a live run, a live object in a paper run, and any object
   from another workspace refuse before the artifacts exist, which is before any cycle and any
   send. A paper run whose records all come from its own paper stream, which is every paper run
   the journal can produce (DEC-952 item 1), is unchanged.
3. **The fee schedule names the mandate's environment.** After the fee schedule is read as before
   (`paper_only_fee_config`, unchanged, still refuses any schedule naming anything but `paper`),
   its `environment` member must name the mandate's environment, or the run refuses
   `Absent` ("a fee schedule for the mandate's environment"). A paper run's refusals keep their
   order and codes. A live run therefore cannot be priced from the paper-only overestimates by
   registering a schedule that names `paper` on the live stream; and a schedule that names `live`
   is refused by `paper_only_fee_config` itself, as DEC-526 item 4 already said. A live fee
   schedule is the next blocker, R10, and its figures are the founder's (`PAPER_ONLY` is
   "Proposed (founder) as values"); this decision does not open it.
4. **Where the origin is read.** The runner's control read (`control_record`) and the grant
   fold's (`record_of`, and `journaled`'s unread rows) take the origin from the stored row's
   `stream_id` and envelope `environment` through `Origin::of`, which reads exactly `paper` or
   `live`; any other text refuses the read (`PaperError::Control`, or `GrantRefusal::Mismatched`
   for the grant fold), never a guess. The journal fixes a stream's environment at its first
   event and the runner reads only `ctl:{workspace}`, so on `main` every record of one read has
   one origin; the check holds the artifacts to that rather than assuming it.

## Rationale

DEC-952 gave a live deployment a workspace of its own so paper and live never share a stream.
Binding the artifacts to the deployment's own stream turns that into a property the artifacts
check, not one they inherit from the caller. Carrying the origin on each record keeps the check
per object, as the registrations are effective per kind. Ordering the fee check after the
existing reader keeps every paper refusal exactly as it was.

## Alternatives considered

- **Lift the paper-only lock and nothing else** (the R9 row's first proposal): rejected. It would
  let a live run bind a registration from a paper workspace or another workspace if a caller
  ever handed one, and it would let a `paper`-named fee schedule price a live account.
- **One origin for the whole read, passed beside the records:** fewer edits, but `configuration`'s
  and `confirmed_version`'s signatures would change (the runner's source-shape test pins the
  latter), and the check could not say which object came from where.
- **Check the workspace in `Artifacts::deployment` against `ctl:{workspace}`:** it adds nothing
  the runner's read does not already fix, and every caller's fixtures would need matching ids.
- **Ship a live fee schedule now (R10):** rejected here. The figures are the founder's, and
  DEC-921 asks for one PR per item.
