# DEC-842: A governed run whose store cannot resolve its policy set or model registry fails closed

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-09 (UTC) |
| **Decided by** | The founder, 2026-10-09, relayed by the coordinator |
| **Story or claim** | E7-19 slice 4 remainder (the first paper trade brief's D4d); claim #851; PR #884 |

## Decision

1. **The whole run fails closed.** A governed run's store may be unable to resolve the effective
   `policy_set` or `model_registry` that the run's version-2 records must name (DEC-484 item 2,
   journal spec §5.1 and §11 check 6). The run then fails closed, as it does in a journal outage
   (`AGENTS.md` rules 3 and 5, [DEC-534](DEC-534.md) item 5).
   - This includes a signal-driven exit. Without the objects its records name, the exit can be
     neither decided nor journaled faithfully.
   - What the shell does today is this behaviour. The run stops at `append_not_committed` at the
     first version-2 append, before any decision.
2. **What it does not touch.** None of the following reads the registry or the policy set:
   - protective orders already resting at the broker;
   - the kill switch;
   - risk exits through the executor, on the account stream.

   All three keep working while the run is refused. This is why `AGENTS.md` rule 13 still holds:
   the refusal stops only the agent's own decisions, and the paths that reduce risk without a
   decision are unaffected.
3. **The owner is alerted** when a run is refused this way. The alert is D4e's to build, under the
   same rules as DEC-534 item 4's: `OwnerAlertSent` of kind `account_state`, carrying opaque ids
   and generic text only (`AGENTS.md` rule 6).
4. **Where the case can arise.**
   - **The paper path, today:** it cannot arise there. `crates/mandate-shell/src/paper/judge.rs`
     refuses any run whose paper account holds a position or an open order.
   - **Any runtime that holds positions across cycles:** it must keep the three exit paths of
     item 2 independent of the registry and the policy set.

## Rationale

A version-2 decision record must name the policy set and registry it was decided under. The journal
refuses one whose objects the store cannot resolve. Deciding an exit anyway would mean one of two
things:
- recording the exit under a weaker form that names fewer inputs than DEC-484 requires;
- acting on the exit without a faithful record, which rule 5 forbids.

A refused run journals nothing it cannot back. The exits that matter most in an outage are the
resting protection, the kill switch and the executor's risk exits, and none of them depends on
these objects, so refusing the run removes no protection.

## Alternatives considered

- **Let exits through under a new record form**, for example a version-1 `ModelOutputRecorded` and
  `DecisionMade` naming `mandate_version` alone in a governed run. Rejected:
  - it needs a journal spec change;
  - it weakens DEC-484 item 2's binding of every production decision to its policy and registry
    snapshots;
  - the paper path cannot reach the case today.
