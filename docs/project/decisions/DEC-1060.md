## Decision

1. **Two arches, each native.** A release is built for `linux/amd64` on `ubuntu-24.04` runners
   and for `linux/arm64` on `ubuntu-24.04-arm` runners, by the same `cargo xtask release build`,
   which builds only for the arch it runs on (`x86_64-unknown-linux-musl`,
   `aarch64-unknown-linux-musl`). No cross toolchain, no emulation: each arch's build is
   DEC-972's reproducible path, with each tool's arm64 asset pinned by SHA-256 beside its amd64
   one at the same version.
2. **Each arch proves itself.** Each arch is built twice, on two runners of its own arch in two
   checkout paths, and `compare` fails unless each pair matches. Each arch's `build-a` builds
   its test-signed images and runs DEC-971's start-up drill natively.
3. **Publishing.** On a push to `main`, `publish-amd64` and `publish-arm64` each rebuild on
   their own arch, require their `build-a`'s digest, and push their images as
   `main-<commit>-<arch>`, each signed keyless and with its SBOM attested. Then `publish-index`
   reads each arch's image back from GHCR by the registry's own digest and size, pushes the OCI
   image index over them as `main-<commit>`, checks the registry reports the index's own digest,
   and signs that digest. A cell pulls `…/<binary>@sha256:<index>` on either arch.
4. **Nothing else changes.** The image layout, the start-up check and the signing keys are
   DEC-971's; an arch changes only the image config's `architecture`, so a binary's layers are
   the same bytes the arch's build produced.

## Rationale

The coordinator asked for multi-arch images from the same reproducible path, built natively on
arm64 runners rather than with a new cross toolchain. Native builds need no new dependency, and
GitHub's arm64 runners are free for public repositories. Reading each arch's manifest back from
the registry, rather than passing digests between jobs, means the index lists only what the
registry actually holds, and the workflow passes nothing the closed-world reader (DEC-873)
cannot read.

## Alternatives considered

- **Cross-compiling arm64 on amd64** (a musl cross linker, or `cross`): a new toolchain to pin,
  and an arm64 binary nobody ran before it shipped.
- **QEMU emulation:** slow, and the drill would test the emulator.
- **Separate per-arch tags only, no index:** every consumer would have to pick the arch, and a
  digest would not be portable between the founder's laptop and the cell.
