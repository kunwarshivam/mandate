## Context

Three refusals stood between the rehearsal's runner and the simulator once a live deployment
exists (R0 rehearsal record, R2 to R4):

- **R2.** `run()` handed the live door no snapshot, so every live run refused
  `lapse_evidence_not_supplied` (DEC-919). DEC-933 item 3 built the lapse's real inputs but left
  the snapshot to "the lane that connects the Robinhood connector". The snapshot is read through
  the Robinhood session, which needs the founder's login, so it cannot come before a credential
  read. FT-3 orders every check that needs no credential first, and DEC-918 item 3 put the lapse
  in front of the shell's fold.
- **R3.** `run()` handed the shell `LiveAdmission::refusing()` (DEC-934 item 4). The rehearsal
  build has `live`, so the runner pinned Robinhood's host while it dialed the simulator on
  loopback, and DEC-934 item 3's byte-for-byte equality would refuse the rehearsal for ever.
- **R4.** A logged-in Robinhood session read and sent nothing (`SESSION_UNBUILT`, DEC-937 item
  2): the MCP transport had no way to carry the login's token, and no session joined the login to
  the shell's Robinhood bridge.

## Decision

1. **The snapshot is the session's.** `Session` gains `account_snapshot`, which the Alpaca paper
   session answers with none and the Robinhood session with `RobinhoodBridge::account_snapshot`:
   `get_accounts`, `get_portfolio`, `get_equity_positions` and `get_equity_orders`, scoped to the
   recorded account, and no quote and no order. A session that reads none still refuses a live
   connection `lapse_evidence_not_supplied` (DEC-919 unchanged), and an unreadable snapshot
   refuses at `Stage::Reconcile`.
2. **The order of a live run (FT-3 amended for a live run only, under DEC-929).** In `run()`:
   1. the door's `chosen` and `account_stream`, then `acknowledge` (`--confirm-live`) and
      `harden` (core dumps off), unchanged;
   2. the dial ([`dial`](../../../crates/mandate-paper/src/robinhood.rs)): the build's endpoint
      and the account number, read from the process environment, nothing sent;
   3. the shell's new `checked_before_credentials`: the same walk, document read and fold as
      `confirmed_version`, every V-rule but V-002 included, with a live deployment admitted on
      the three of DEC-924 item 1's conditions the run holds before any credential (the `live`
      build, `--confirm-live`, and the dialed host equal to the pin). It answers no version;
   4. the one `Ports::connect`: the login, then the MCP session (item 4);
   5. the snapshot (item 1), then `lapse_read` on it and on the account stream's rows;
   6. `confirmed_version` with the door's condition now held, then everything after it as before.

   So no credential is read before every check that needs none has passed, apart from the
   configuration and artifact checks the fold's answer feeds; those still run before anything
   that can place. Between the connect and the cycle the session only reads; a refusal anywhere
   after the connect leaves it unused and sends nothing. A paper run keeps today's order exactly
   (LT-14): its lapse makes no check and its connect stays after the configuration.
3. **The admission is the run's own facts, and the rehearsal pins loopback.**
   `live_admission(built, acknowledged, door, dialed, pinned)` maps each fact to its field and
   decides nothing; the shell's `admits` judges. `built` is `Live` exactly when the runner was
   compiled with `live`. `pinned` is `pinned_host(Build::CURRENT)`: none in the default build,
   Robinhood's `MCP_HOST` in the `live` build, and `REHEARSAL_HOST`, `127.0.0.1`, the
   simulator's own address, in the `rh-sim` build. `MCP_HOST` is now compiled only under `live`
   without `rh-sim`, so the rehearsal binary holds no production host at all (the binary-bytes
   test checks it). DEC-934 item 3's exact equality is unchanged: the rehearsal admits only a dial
   of `127.0.0.1`, and the `live` build only Robinhood's host. This is DEC-922 items 1 and 2
   read into DEC-924 item 1's fourth condition: in the one build that cannot reach a broker, the
   pinned host is the simulator's.
4. **The MCP session over the login's token (O2).** `McpTransport::authorized(token)` sends the
   token as `authorization: Bearer` on every request, marked sensitive, and refuses a token no
   header can carry; the transport's printout never shows it (LT-9). The runner's Robinhood
   session is the login, then that transport pinned to the dialed endpoint, then
   `McpClient::connect` with no stored contract pin, so a server that lists a fund-movement tool
   or lacks an allowlisted one gives no client at all (connections spec §8.1's first-connection
   check), then one `RobinhoodConnector` scoped to the account number, inside the shell's
   `RobinhoodBridge` on the login's runtime (DEC-928 item 2). Its preflight is DEC-933 item 2's
   (`preflight_facts`, Alpaca's market reads, `robinhood_facts`); its cycle is the shell's new
   `robinhood_production_cycle`, whose connector is `RobinhoodShellConnector` and whose
   reconciler is `RobinhoodReconciler` around the run's executor reconciler, over the same
   bridge. Its broker ask is #1380's `BrokerAsk::robinhood` over the same bridge (DEC-945 item
   4), so the cross-check reads Robinhood's own quote at the check.
5. **Where the account number and the market keys come from.** The connector needs the agentic
   account's number (CN-8), which the founder typed and which no record carries in clear
   (journal spec §6.4). The run reads it from `MANDATE_RH_ACCOUNT_NUMBER` in the process
   environment, never prints it, and refuses `robinhood_account_unset` before anything is sent
   when it is missing or empty; the connector then refuses unless `get_accounts` lists exactly
   that number as agentic (DEC-875). The Alpaca paper keys for the market reads are read at the
   connect, from the environment, with no request; without them the session is built and its
   preflight refuses (`MARKET_UNREAD`), so a run without keys still reaches the lapse and the
   fold and stops at R5.

## Not decided here

The cycle this session builds still refuses before an order: the executor sends the mandate's
asset id as the order's symbol, which Robinhood does not accept, and `RobinhoodReconciler` reads
its snapshot past `BrokerSymbols` (DEC-938), so positions come back by ticker. Both fail closed.
Naming Robinhood's instruments by ticker on the way out and by asset id on the way back is
DEC-938 item 1's reading for a second broker, recorded as the R0 rehearsal's R8.

## For the founder

Item 2 reads your Robinhood credential (the login) before the lapse, which FT-3 did not allow.
It is the least-risk order available: the login happens only after every check the fold can make
without it, and between the login and the cycle the session only reads your account. Revert it by
a later decision if you want the login strictly after the lapse; that needs the lapse's snapshot
from somewhere other than the logged-in session, which no read offers today.

## Rationale

The snapshot exists only behind the login, so the lapse cannot come before a credential read;
moving the fold's credential-free checks in front of the login keeps FT-3's purpose, no
credential for a run that would refuse anyway, for every check that can be made. Splitting the
fold by a predicate on the same walk keeps one derivation of the deployment, so the check before
credentials can never pass where the full fold would refuse for any reason but the door. Pinning
loopback only in the build that refuses every non-loopback endpoint keeps DEC-934's exact
equality and LT-1, and removing `MCP_HOST` from that build means the rehearsal cannot hold a
production pin even by mistake. The account number from the environment fails closed and is
checked by the broker's own listing; the founder already sets the environment for the
rehearsal's endpoint.

## Alternatives considered

- **The login strictly after the shell's whole fold, the lapse after it:** the fold needs the
  door's condition, which needs the lapse, which needs the login, so the fold would have to admit
  on a door it has not checked. Rejected: that hands `DoorChecks::Passed` before the door passed
  (DEC-934 item 6).
- **Weaken the host condition to accept any loopback host in the `live` build:** rejected by
  DEC-922's alternatives and LT-1.
- **A copy of the simulator's host in the shell:** DEC-934 item 3 keeps the constant in the
  runner; the shell receives it.
- **The stored contract hash as the MCP client's pin:** no record the runner reads carries it
  yet (R1's connect check writes it). With no pin the client applies the first connection's
  check, which refuses outright where a pin would only halt openings. When R1 lands, the pin
  should come from its `ConnectionChecked`.
- **Pick the one agentic account `get_accounts` lists, with no typed number:** rejected by CN-8:
  the connector holds the number the founder typed and never adopts another account.
- **Read the Alpaca market keys lazily in the preflight:** same effect with an extra environment
  read inside the cycle's reads; reading them once at the connect is simpler to review.
