# DEC-954: The live run's core-dump hardening builds on every target, verifies what the kernel took, and refuses where it cannot

| | |
|---|---|
| **Status** | Accepted (item 5's runner label superseded by [DEC-2652](DEC-2652.md)) |
| **Date** | 2026-10-16 (UTC) |
| **Decided by** | `claude-code` (builder), under DEC-79 (reversible engineering) and DEC-176 (each reading only tightens) |
| **Story or claim** | LT-9 of the [first live trade brief](../tasks/first-live-trade.md); claim #1392 |

## Decision

1. **Builds everywhere.** `disable_core_dumps` (`crates/mandate-paper/src/harden.rs`, DEC-937
   item 4) called `prctl(PR_SET_DUMPABLE)`, which exists only on Linux, so `mandate-paper` did
   not compile on macOS, where the founder runs the paper and live CLIs. Each call is now behind
   the `cfg` of the targets that have it. The crate builds on every target, and no `unsafe` is
   added: every call still goes through `rustix`'s safe wrappers.
2. **The core-file limit on every unix target, read back.** Wherever `rustix` gives `setrlimit`
   and `getrlimit` (every `unix` target except ESP-IDF, Fuchsia, Horizon, Redox and Vita, so
   Linux and macOS both), the run sets `RLIMIT_CORE` to 0, soft and hard, then reads it back with
   `getrlimit`. Anything but zero for both limits refuses. The read-back catches a kernel or
   sandbox that returns success but does not apply the limit, which a return code alone cannot.
3. **The dumpable flag on Linux, read back.** On Linux (and Android, which shares the kernel)
   the run also sets `PR_SET_DUMPABLE` to 0, then reads it back with `PR_GET_DUMPABLE`. Only
   `NotDumpable` passes. macOS has no such flag, and nothing portable replaces it: its
   `ptrace(PT_DENY_ATTACH)` is a different guarantee that `rustix` does not wrap, and it would
   need `unsafe`. On macOS, the zero core-file limit is the whole hardening.
4. **Fails closed.** If any call fails, any read-back differs, or the target has no core-file
   limit (Windows, for example), `disable_core_dumps` returns `PaperError::Harden`. A live run
   then refuses before any credential read (LT-9, DEC-937 item 4). A paper run never calls it,
   so paper behaviour is unchanged.
5. **CI runs the runner on macOS.** A new part, `cargo xtask ci portable`, runs clippy
   `-D warnings` over all of `mandate-paper`'s targets, then its hardening tests (the read-back
   verdicts and the two kernel read-back tests in `tests/live_entry.rs`). CI runs it in a new job,
   `fast-portable`, on `macos-14`, and the required `fast` verdict needs it, so a Linux-only call
   in the runner fails a required check. Locally on Linux, `cargo xtask check` runs the same part
   on the host. A cross-check from Linux (`cargo check --target aarch64-apple-darwin`) was tried
   and cannot work: `ring`'s build script compiles C that needs the macOS SDK
   (`TargetConditionals.h`), which no Linux runner has. The job runs the default build only,
   never `live` (DEC-529 item 3).

## Rationale

The read-back makes "core dumps are off" a fact the kernel confirms rather than something
assumed from a successful return code. Refusing on a target with no limit keeps LT-9's promise
without making the crate fail to compile there. Each reading only tightens DEC-937: the Linux
behaviour is the same two calls, plus two reads that can only add refusals, so DEC-176 lets an
agent take it.

Running the runner's lint and hardening tests on macOS, rather than only type-checking it, proves
that the hardening succeeds where the founder runs it. A live run whose hardening always refused
on macOS would otherwise be found only at the first live run.

## Alternatives considered

- **`cfg`-gating the whole hardening to Linux and returning `Ok` elsewhere:** this weakens LT-9
  on macOS, since a live run would read credentials with core dumps never turned off.
- **The `libc` crate for `ptrace(PT_DENY_ATTACH)` on macOS:** this needs `unsafe`, which the
  workspace forbids, and stops a debugger rather than a core file.
- **Adding `aarch64-apple-darwin` to `rust-toolchain.toml` and cross-checking from Linux:**
  `ring` cannot build without the Apple SDK, and every job would download the target's standard
  library for nothing.
- **A raw `cargo check` step instead of an `xtask` part:** ES-12 says every CI job is one
  `cargo xtask ci <job>` command that `cargo xtask check` also runs locally.
