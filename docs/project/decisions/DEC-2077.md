# DEC-2077: A debug window into the CI runners, off by default

| | |
|---|---|
| **Status** | Proposed (founder-reserved, DEC-79: it relaxes DEC-2065 item 6's "nothing inbound", a safety rule the founder accepted). The code lands shut by default, the conservative course; opening the window is the founder's own act at each apply, and accepts this DEC |
| **Date** | 2026-10-27 (UTC) |
| **Decided by** | Proposed by an agent (Claude Code, lane RN) at the coordinator's direction; the founder decides by opening the window or not |
| **Story or claim** | E21-64; amends [DEC-2065](infrastructure.md#dec-2065) item 6 ("nothing inbound") |

## Context

On 2026-10-27 the runners registered every three minutes and never went Online. Each host's
journal holds the answer (`journalctl -u mandate-runner`), but DEC-2065 left no way in: nothing
inbound, no droplet agent, root's password locked.

## Decision

1. **`debug_ssh_key` and `debug_ssh_cidr`, empty by default.** Set together, they add one
   inbound rule, TCP 22 from that one address, and a `debug` user who may log in with that one
   key and use sudo. Empty, the plan has no port-22 rule and makes no such user
   (`the_debug_window_is_shut_by_default`).
2. **It is held tight.**
   - The address must be a single host, an IPv4 /32 or an IPv6 /128.
   - The key must be one OpenSSH public key on one line, its comment limited to letters, digits
     and `@._-`, so it cannot break out of the boot script's quoting.
   - The window takes both variables or neither.
   - sshd takes keys only, always: `PasswordAuthentication no`,
     `KbdInteractiveAuthentication no`, `PermitRootLogin no` and `AllowUsers debug`, so with the
     window shut no account can log in at all.

   Each of these refusals has a test.
3. **The founder opens it only to debug and shuts it the same day** (runbook §8). Both applies
   replace the droplets, so they run with `CI_RUNNER` unset.
4. **What the window exposes.** While it is open, the founder's key reaches root on the hosts,
   which hold the App's private key. The key is the founder's own and the port admits only their
   address.

## Rationale

A runner that cannot be inspected cannot be fixed. A window the founder opens for one address and
closes the same day costs less than the alternative, a recovery ISO and reading a raw journal from
a mounted disk.

## Alternatives considered

- **The droplet agent, or DigitalOcean's web console.** Both are always on, need a password or a
  console login, and reach every droplet in the team.
- **Shipping the runner logs off the host.** Another service, holding logs that name the
  repository's jobs.
