## Context

DEC-821 item 4 requires the token's possible breadth to be disclosed to the owner before an Alpaca
OAuth connect. DEC-2621 journals the document and version the owner confirmed with the connect's
step-up. The text is shown on the connect screen before the owner is sent to Alpaca.

## Decision (proposed)

1. **Document `alpaca_oauth_token_breadth`, version `1`:**

   > **Before you connect Alpaca paper trading**
   >
   > Alpaca's documentation does not say whether the access it grants for your paper account can
   > also be used with a live Alpaca account you hold.
   >
   > Mandate sends every order and every account request for this connection only to Alpaca's
   > paper trading service, from a process that cannot reach Alpaca's live service. The one
   > Mandate process that contacts Alpaca's live address does so only to exchange your sign-in
   > code for access, and it cannot place orders.
   >
   > You can remove Mandate's access at any time in your Alpaca account's app settings. Revoking
   > the connection in Mandate also deletes the access Mandate holds.

2. **Where it appears.** On the connect screen, before the "Connect with Alpaca" step-up, with the
   owner's confirmation being that step-up. The workspace API names the document and version; the
   web app holds the text.
3. **Until accepted.** Version `1` is served only against the fixture OAuth provider (the cell and
   tests). No real Alpaca connect starts before the founder accepts this wording and registers the
   platform's Alpaca OAuth app (DEC-441 item 18). A changed wording is version `2`, and DEC-2621's
   digest binds the version, so an owner's step-up confirms exactly the text they saw.

## Rationale

The text states the uncertainty plainly (U-A4), says what the platform does about it without
promising what Alpaca does, and tells the owner how to remove the access themselves, which
connections spec §5.4 also requires at revoke. It claims nothing about outcomes and offers no
advice.

## Alternatives considered

- **No disclosure until Alpaca answers U-A4.** DEC-821 item 4 makes the disclosure a condition of
  accepting the token; without it no paper Alpaca OAuth connect could complete.
- **A longer technical explanation** (hosts, processes, the token endpoint). Accurate, but it is the
  connections spec's, not the owner's; the short form keeps what an owner can act on.
