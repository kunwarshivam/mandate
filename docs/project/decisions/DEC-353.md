# DEC-353: A rule change that routes an order to a delegated ask is risk-increasing

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-02 (UTC) |
| **Decided by** | The stream H builder (agent), under DEC-79 and DEC-176: it only tightens a classification |
| **Story or claim** | [#444](https://github.com/kunwarshivam/mandate/issues/444), from E6-13's review ([#443](https://github.com/kunwarshivam/mandate/pull/443)); claim [#439](https://github.com/kunwarshivam/mandate/issues/439); mandate spec §9.2, MI-11, MI-29 |

## Decision

1. §9.2's autonomy row is read with the asks the new version's delegations lift. Two of its reducing
   cases become increasing when a delegation would lift what it did not lift before:
   - widening a single-comparison `ask` rule that a delegation of the new version lifts;
   - removing a rule whose `then` is not `auto` when a delegation of the new version lifts a later
     rule or the default.
2. Removing an `auto` rule stays reducing: its orders were already `auto`, so a delegation lifting
   them decides no less strictly.
3. The reference model takes the rule (`classify_autonomy`'s `lifted`), the fuzz gains
   `fuzz_delegated_rule_changes`, which compares decisions only, and `mutants.py` asserts its shared
   probe is clean on the unmutated model before any mutation. The MC-J cases pin both sides.

## Rationale

§9.2 classified rule changes with the delegations removed and delegation changes on their own, so a
change neither row saw as widening could move orders from an undelegated ask to a delegated one:
`fuzz_review_changes` found it with seed 1 (#444), which also left `mutants.py`'s shared probe failing on
the unmutated model and every one of its 122 mutants scored caught whatever it did.

## Alternatives considered

- Any rule change while delegations exist is increasing: simplest, but makes every tightening of a
  rule need step-up while a delegation stands.
- Fix the fuzz seed: hides a real MI-29 violation.
