## Context

The founder asked for staging's bootstrap to run fully automatically, in CI, after the apply. The
cluster's control plane admits only the CIDRs in `KUBE_API_ALLOWED_CIDRS` (DEC-2012 item 7), which
a GitHub runner's changing address is never among.

## Decision

The founder's answer, as relayed:

> Q: "Staging's Kubernetes control panel accepts only fixed addresses. So that setup runs fully
> automatically with no step from you, may each automated deploy run open it to just that run's
> own GitHub runner address for a few minutes, then close it again?"
> A: "Yes, per-run window (Recommended)"

Lane IAC's design, which only narrows it:

1. **One /32, validated.** Each root takes `bootstrap_runner_cidr`, default empty, which the `doks`
   module adds to the control plane's allowlist beside the founder's CIDRs. Its validation admits
   only the empty string or exactly one public IPv4 `/32`. It refuses a wider prefix, a list, IPv6,
   and the private, loopback, link-local, shared (`100.64.0.0/10`), multicast and reserved ranges.
2. **Set only by `cargo xtask infra apply`, for its own run.** No committed value or GitHub variable
   sets it. The window opens in the same saved plan the run prints and applies (DEC-2014 item 4),
   so the founder's approval of the run covers it.
3. **Closed on every path.** The same command closes the window, whether the bootstrap succeeds or
   fails, by an apply targeted at the cluster with the variable empty. `infra.yml`'s
   `if: always()` step, `cargo xtask infra close`, closes it again when the first command was
   killed. A run killed before both leaves the window open until the next run closes it; that
   residual is disclosed here.
4. **The runner's address** comes from an IP echo service and is checked by the same rule before it
   is used. A service that lied could open a different public `/32` for the run, which still needs
   the cluster's credentials to do anything.

## Alternatives considered

- **A self-hosted runner with a fixed address:** a machine to run and pay for.
- **Reaching the API through the tunnel and Access:** a second ingress path, which is lane GO's
  later hardening, not the demo's.
- **Opening a wider range (GitHub's published runner ranges):** thousands of addresses for minutes
  a run, which the founder was not asked about.
