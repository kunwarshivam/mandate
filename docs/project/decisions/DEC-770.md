# DEC-770: Journal page bounds and the not-found reading of the audit reads

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-08 (UTC) |
| **Decided by** | The lane L5 builder (`claude-code`) under DEC-79 and DEC-176: reversible engineering readings of workspace API §4.8 and API-9, API-15 that only tighten them and add no risk; the founder may reverse them |
| **Story or claim** | E12-6, slice A1; claim [#756](https://github.com/kunwarshivam/mandate/issues/756) |

## Decision

`mandate-audit`'s workspace-scoped journal reads (`JournalRead`), which the audit routes of
workspace API §4.8 serve:

1. **Page size.** `limit` is `1..=500`; a request that names none gets 100. A limit outside
   `1..=500` is refused (`LimitOutOfRange`, which the API serves as `422 invalid`), never clamped.
2. **Cursor.** A page holds the events with `seq > after_seq`, in `seq` order, as many as there are
   up to `limit`. Its cursor is the last `seq` it served, or the request's `after_seq` when it
   served none, so an `after_seq` at or past the head gives an empty page, not an error. A client
   pages until a page comes back empty.
3. **Absent.** A stream is absent until it holds an event: one whose writer took ownership but
   wrote nothing is neither listed nor served. The stream list holds the workspace's streams that
   hold an event, each with its head `seq` and hash, sorted by `stream_id` bytes, and is not paged.
4. **One not-found.** A stream or event of another workspace, an absent one, and a malformed id
   (a stream id that does not parse under journal spec §2, a workspace id that is not one
   `[A-Za-z0-9_-]+` segment) all give the same `NotFound`, which carries no detail (API-9). A
   stream belongs to the workspace whose id equals its second `:` segment whole, never by prefix.

## Rationale

- A bounded page keeps one read's cost and response size bounded whatever the stream's length; 500
  canonical bodies are a few hundred kilobytes. 100 matches the page sizes the web app's audit
  views render.
- Refusing rather than clamping means a client never believes it asked for and got 1,000 events
  when it got 500; with the cursor rule a short page is never mistaken for the end.
- An empty page past the head lets a client poll the tail of a stream with the cursor it holds,
  while a never-written stream stays indistinguishable from a foreign one.

## Alternatives considered

- **Clamp an out-of-range limit.** Silent, and API-15's client could not tell a clamped page from a
  complete one by its length alone.
- **`NotFound` for a cursor past the head.** It would tell a client polling the tail that its own
  stream had vanished.
- **List streams whose writer took ownership but wrote nothing.** Their head is seq 0, and a page
  of them is empty, which would make a never-written stream answer differently from a foreign one.
