# DEC-461: Give journal conformance vectors canonical config artifacts

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-05 (UTC) |
| **Decided by** | The implementing agent under DEC-79 and DEC-176 |
| **Story or claim** | E7-7; claim [#171](https://github.com/kunwarshivam/mandate/issues/171); [PR #598](https://github.com/kunwarshivam/mandate/pull/598) |

## Decision

1. The journal reference vectors include canonical bytes for every config reference used by their
   event chain: fee configuration, rule set, instrument snapshot, mandate version, settlement
   calendar, and trading calendar.
2. Each config reference is the SHA-256 digest reference of those canonical bytes. The chain,
   Merkle, and append vectors are recomputed from the resulting event bodies.
3. Journal conformance tests independently hash the fixture bytes, require each digest to equal
   its declared reference, and supply the verified artifacts when checking event config
   references.

## Rationale

Strict journal verification requires every referenced configuration artifact to be loadable and
to hash to its recorded digest. The prior vectors used placeholder digests without corresponding
bytes, so a conforming verifier had to reject the otherwise valid chain. Supplying deterministic
canonical artifacts closes that fixture gap and lets conformance tests exercise the same
fail-closed verification required in runtime.

This resolves the discrepancy by tightening the vectors and tests. It adds no acceptance path,
verification bypass, or weaker safety invariant, so DEC-176 delegates the decision to the
implementing agent.

## Alternatives considered

- Skip config-reference verification in conformance tests: rejected because it would make the
  tests less strict than runtime and permit missing or mismatched artifacts.
- Keep placeholder digests and special-case them in the verifier: rejected because production
  verification must not trust undeclared fixture sentinels.
- Remove config references from the vectors: rejected because the vectors must cover governed
  events that bind the exact configuration used for a decision.
