every drill green in CI on `main` for a week of merges. The 2026-10-26 demo is nine days away. The
plan also lists seven kinds of dependency (D-1 to D-7) whose `docs/dependencies.md` rows the founder
approves, one by one, as each lane first needs them. The coordinator asked the founder about both
and relayed the answers below.

## Decision

1. **D-1 to D-7 are pre-approved as kinds** (Proposed, founder). The seven kinds are those the
   plan lists: an async HTTP server crate (D-1); the OpenTelemetry metrics API and a Prometheus
   exporter (D-2); a Kubernetes API client, or plain HTTPS through the existing `reqwest` and
   `rustls` (D-3); the CI tools `k3d` or `kind`, `helm` and `kubeconform`, pinned in
   `.github/workflows/ci.yml` and `.cursor/install.sh` together (D-4); the CloudNativePG operator
   and chart, and container images for PostgreSQL 18, OpenBao, Prometheus, Alertmanager,
   `cloudflared` and k3s, each pinned by digest (D-5); the Workers adapter for Next.js and its CLI
   (D-6); and `cosign`, an SBOM generator and `cargo-auditable` (D-7). A builder adds each row in
   the PR that first uses it, with the alternatives considered and the licence. The coordinator
   checks that the row matches its kind and merges it. Anything outside these seven kinds still goes to the founder;
   so, as the recording agent's tightening (DEC-176), do a second crate for the same kind and a
   licence the registry does not already hold. `cargo xtask deps` and the `allowed_external`
   lists of `xtask/layers.toml` keep applying.
2. **Cell #1 is hosted for the demo once every drill has first passed** (Proposed, founder). The
   week of green merges in DEC-967 item 16 is dropped for cell #1's hosting. What the recording
   agent reads into it, each only tightening (DEC-176):
   - every C1 drill (E21-37) must still pass in CI on `main` at least once before anything is
     hosted;
   - the hosted cell carries paper and demo data only;
   - the founder buys H1 (the two Ashburn VMs) and H3 (R2) when the drills first pass, not after
     a week;
   - S1's check against R2 (E21-40) still runs before anything is stored there;
   - live orders from the cell (B3, E21-48) keep their own conditions unchanged: this item hosts
     nothing live.
3. **The managed-cell lanes and the demo lanes may use DEC-921's one-PR flow** (Proposed,
   founder). Every managed-cell story (backlog E21-28 to E21-50) and the demo lanes (the W2 web
   client and the identity bootstrap) may land tests and implementation in one PR: the tests
   committed first and shown failing on the stubs or on a seeded bug, then the implementation in
   the same PR. ES-22's spec-first split, the independent review on a different model, zero
   missed mutants on safety-critical crates, green `fast` and `full`, and every other
   safety-critical rule stay as they are. **Why it is not agent-accepted:** the coordinator
   relayed this item as accepted by an agent, as reversible process (DEC-79). But DEC-921 is the
   founder's, and its item 3 says "Rows off the R0 path keep DEC-77 unchanged. This decision ends
   when R0's evidence PR merges." Extending it changes a founder decision and relaxes the DEC-77
   order on safety-critical paths, so `AGENTS.md` rule 9 and DEC-79 leave it to the founder. Until
   the founder confirms it, the managed-cell lanes keep DEC-77's two-PR order.

## Rationale

Pre-approving the dependency kinds keeps the founder's say over what enters the supply chain while
removing a wait from each lane's first PR; the seven kinds are already the plan's named choices.
Hosting the cell for the demo trades a week of green merges for time, while keeping the one thing
that week was guarding: every drill has passed at least once on `main`, and nothing live is
hosted. The one-PR flow halves the review cycles per story; the safety comes from the tests
existing, failing first and being reviewed, which it keeps (DEC-921's own rationale).

## Alternatives considered

- **Approve each dependency row as it comes** (DEC-967 as written): every lane's first PR waits on
  the founder.
- **Run the demo on the DEC-822 CX22** (offered; not chosen, as relayed): the demo would show the
  single-VM path the plan now treats as a dev convenience.
- **Keep the week of green merges and host after the demo:** safest, but misses the demo.
- **Accept item 3 as an agent decision** (as relayed): not taken, for the reason in item 3.
