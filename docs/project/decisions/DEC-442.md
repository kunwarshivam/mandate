## Decision

### Accepted (agent)

1. **A closed counter list with no trading-derived unit.** Usage counters are agent-hours by
   environment, decision cycles, model calls and tokens, model cost, workspaces, seats, and data
   units (zero in v1). None reads an order, fill, intent, `DecisionMade`, position, P&L, or account
   value (design §4.1, BL-1, BL-2).
2. **The license is billing's only lever on a site.** Billing withholds renewal; it never revokes,
   pauses, stops, or flattens. While DEC-440 item 13 is Proposed, this design takes its reading:
   after grace a lapsed license refuses new deployments and new openings and never an exit,
   protective order, owner exit, risk exit, kill switch, reconciliation, or export (BL-4). That
   reading is stricter than "a billing matter, never a trading stop" (identity spec §11.2, #556)
   only for new openings, and adds no risk.
3. **The non-payment ladder.** Payment failure, dunning, renewal withheld, license `not_after`, grace,
   lapse, in that order, each preceded by a notice. Only a non-payment read from the provider's API
   moves an organization down it; an unknown payment state renews (BL-5, BL-14). The lengths are
   item 16.
4. **Enforcement before spend.** Model calls reserve their maximum cost (INF-7); a capped
   agent-hours dimension commits the hours left in the cycle at deployment; an organization's spend
   cap is split into per-workspace allotments carried in the license and enforced locally. A cap
   refuses only new spend (BL-8; design §3.4).
5. **Idempotent metering and reconciliation without estimates.** Reports de-duplicate by
   `report_id`; provider writes carry deterministic idempotency keys; a cycle line is final only
   when every chain is continuous and recounts match; a gap holds the line (BL-6, BL-7).
6. **Corrections are new records.** A sealed report is never changed; a correction report names the
   original, and a closed cycle is corrected by a traced credit or debit line on the next invoice
   (BL-11; design §4.4).
7. **Price versions are immutable and pinned per cycle.** A new version takes effect only at a
   future cycle boundary (BL-10).
8. **Webhooks are hints.** Billing acts only on state read back from the provider's API (design §5.3).
9. **`key_owner` on the metering record.** Inference spec §7.1 gains `key_owner` (`platform` or
   `customer`) so bring-your-own-key calls (DEC-432 item 16) count for quotas and are billed zero for
   tokens (BL-9).
10. **No stored value and hosted payment pages.** Mandate keeps no withdrawable balance, takes no
    payment from a trading account, and never sees card or bank numbers (BL-3).
11. **Billing's layering.** The billing crates cannot depend on the executor, connectors, the
    account ledger, or the vault (BL-3).
12. **Backlog rows E14-4 to E14-10** in the backlog's E14 epic.
13. **Decision cycles, never `DecisionMade`.** The `decisions` dimension of HLD §10 counts
    evaluation cycles, holds included, so it cannot track trading frequency (BL-2).

Until each Proposed item is decided: no provider account, no prices, no charges. The code is built
against a recorded provider fake.

## Rationale

Billing touches money but must never touch trading money or trading behaviour. Every reading here
keeps billing's reach to new activity only, so a billing defect, outage, or attacker costs revenue
or opportunity, never a liquidation or a blocked exit. Counting from journaled facts makes every
invoice line reproducible, and the closed counter list keeps the platform a software business
rather than one paid per trade or on assets.

## Alternatives considered

- **Revoking a license on non-payment.** Rejected: there is no revocation message by design (CP-8),
  and a revocation would hit hybrid sites mid-term.
- **An organization-wide spend cap checked centrally per call.** Rejected: it puts the control plane
  in the path of a model call (CP-2). Per-workspace allotments enforce the same total locally.
- **Counting `DecisionMade` as decisions.** Rejected: it is intent-level and tracks trading activity.
- **Estimating missing usage.** Rejected: an estimate is not traceable to records (BL-11).
