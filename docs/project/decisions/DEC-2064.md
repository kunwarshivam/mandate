## Context

DEC-2011 set up staging and "a small production" under a $150 monthly cap. The `production` root
it made is two nodes for one workspace, about $55 a month. Customer trading needs more: many
workspaces with isolation between them (HLD §8), a journal that survives a node's loss
(journal §5.3), a vault and backups that survive a restart, monitoring that pages when the cell is
down, and a control plane that stays up for the kill switch. The founder asked agents to design it
and bring a monthly cost, and to provision nothing until they approve the spend.

## Decision

1. **Spend (founder's).** Customer production is one managed cell, `mandate-prod-cell1`, in `sfo2`.
   It costs **$224.97 a month at demo scale** (2 workspaces) and **$515.35 at first customers**
   (10 workspaces), at the list prices read on 2026-10-26 (design §6). The founder approves a
   monthly amount, suggested at $250 or $570 with about 10% headroom, which raises DEC-2011 item
   2's $150 cap by that amount. Until then the root's `approved_monthly_usd` is 0 and every plan
   fails. Model spend stays under DEC-997's own cap.
2. **Layout.** A new root, `deploy/tofu/environments/production-cell1/`, built from the existing
   `network` module and five new ones: `cluster`, `ingress`, `archive`, `monitoring` and
   `costing`. It is not dispatchable until a follow-up PR adds it to `infra.yml` after item 1. On
   approval it replaces the small `production` root.
3. **The cluster.**
   - DOKS 1.35.9-do.1, pinned, with auto-upgrade off and the HA control plane, since the kill
     switch's Job goes through the Kubernetes API.
   - A three-node system pool.
   - A workspace pool tainted `mandate.dev/pool=workspaces`, sized `ceil(n / 2) + 1` nodes of
     `s-4vcpu-8gb`: two workspaces a node, one node spare.
   - A pool per business workspace, tainted to it.
   - No autoscaling. The control plane admits only the founder's CIDRs.
4. **Backups.** Two R2 buckets in `wnam`, each with a lock over every key for 30 days and its own
   writer token, scoped to that bucket alone:
   - the journal's WAL and base backups (DEC-973 item 6, DEC-2605 row 4);
   - the vault's Raft snapshots.
5. **Ingress.** One tunnel for the cell, and for each workspace:
   - its own host, `api-<id>.owlhead.ai`;
   - a route to its own namespace's API alone;
   - its own Access application, whose policy names only its own people.

   There is no account-members fallback. Every other host name gets a 404.
6. **Monitoring.** In the cell: Prometheus, Alertmanager and Grafana (lane GO). Outside it:
   DigitalOcean's node alerts and an uptime check on every API host, so a dead cell still pages.
7. **Egress.** The node firewall admits inbound traffic only from the VPC. Outbound it allows
   443, 53, NTP and the tunnel's 7844, and drops port 80. The `network` module's new `egress`
   variable defaults to today's list, so staging and production are unchanged. In-cluster egress
   stays DEC-2058's exact-name allow-lists.
8. **The vault's unseal in production (founder's, open in DEC-2021 item 6).** OpenBao runs three
   Raft replicas. The recommended course is a static seal key, as staging has (DEC-2605 row 10).
   The key is created at bootstrap from the `infra-production-cell1` environment and kept in the
   founder's password manager. That holds for paper only; before live money, a KMS-backed seal is
   chosen and priced. The alternative is unsealing by hand after every restart of a replica.
   Until the founder answers, DEC-2021 item 6's course holds: unseal by hand.
9. **Tenancy.**
   - A namespace, chart instance, NetworkPolicies and egress allow-list per workspace.
   - One CloudNativePG cluster per cell with three instances, a synchronous quorum of one, and a
     database per workspace.
   - An OpenBao namespace per workspace.
   - A dedicated cell for a large customer is another `production-cell<n>` root.
10. **Promotion.** Unchanged: production runs only digests that staging ran on `main`, moved by
    `cargo xtask gitops promote` in a pull request the founder approves (DEC-2016, DEC-2048).
    Infrastructure changes go only through `infra.yml` under `infra-production-cell1`, with the
    founder as its required reviewer (DEC-2014).
11. **Paper first.** The cell carries no live route. Live money for customers still needs the
    Phase 2 gate (infrastructure §1.1), the journal §6.2 cold store with its second region, and
    the M13 penetration test. Each of those is costed when the founder schedules it.

## Rationale

- Fixed counts make the estimate the bill. The `costing` module computes it at plan time from
  DigitalOcean's live size list and the cited list prices, and `tofu test` asserts both totals.
- A zero approval in code means a mistaken dispatch cannot spend: one cannot even be made today.
- Three system nodes are the fewest that keep a Raft and a three-instance journal through a
  node's loss.
- One node spare in the workspace pool is the fewest that lets a lost node's workspaces restart.
- A host and an Access policy per workspace make the tenant boundary hold at the edge, before the
  API's own checks.

## Alternatives considered

- **Grow the small `production` root in place:** it would become dispatchable with unapproved spend
  the moment it merged.
- **One shared API host for every workspace:** one Access policy would admit every customer to
  every workspace's API, leaving tenant isolation to the API alone.
- **Hosts two labels deep (`<id>.api.owlhead.ai`):** Universal SSL covers only one label, so each
  would need a paid certificate.
- **Autoscaled pools:** the bill would no longer be bounded by the estimate.
- **A managed DigitalOcean database for the journal:** ruled out by DEC-2012 item 2; the journal
  is CloudNativePG in the cell (DEC-967 item 8).
- **Without the HA control plane:** $40 a month less, but the kill switch's Job would depend on a
  single control plane.
- **Isolated workers behind a NAT gateway:** removes the nodes' public addresses. Deferred as a
  later hardening, as in DEC-2012.
