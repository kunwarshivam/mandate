# DEC-889: A connection anchor is one stream's, folded from that stream's verified prefix, and an anchored run fails closed at another stream's record

## Context

DEC-885 item 1 defines the anchor of "a range of stream `s`". The Rust fold of #1159 and #1183
went wider: an `Anchored` run judges every stream it is given, starting any stream the anchor
never saw from an empty fold, DEC-885's false-mismatch reading again. DEC-892's `bind` verifies
one stream's rows and binds them to that stream's trusted start, so no multi-stream prefix binds.

## Decision

1. **One stream per anchor.** `ConnectionAnchor::from_verified(&VerifiedPrefix)` folds one
   stream's verified prefix and gives that stream's anchor, or `ConnectionAnchorError::Broken`
   when the prefix breaks rule 66, 67, 68, or 131 (DEC-885 I5). `ConnectionStart::Anchored` holds
   that one anchor. When `bind` refuses the rows, or the fold gives `Broken`, the caller runs the
   range `ConnectionStart::Unanchored`, so it fails closed (DEC-892 item 3).
2. **Another stream fails closed.** An `Anchored` run judges only the anchor's stream. At the first
   record of any other stream that the range rules judge, it fails closed with
   `ConnectionCheck::Unanchored` (code `connection_lifecycle_mismatch`). That is the set the
   `Unanchored` arm judges (DEC-885 item 4): a request, establishment, rotation, or refusal on a
   control stream, and every connection record on an account stream, an account-stream
   `ConnectionRevoked` included ([DEC-888](DEC-888.md), #1203). A control-stream
   `ConnectionRevoked` is never judged (DEC-885 I6, `AGENTS.md` rule 13), so another stream's
   revocation never fails the run. The anchor of an empty prefix (`from_seq` 1) has no rows to name
   its stream, so its stream is that of the range's first judged record.
3. **The raw fold goes.** `ConnectionAnchor::fold(&[StoredEvent])` is deprecated in E7-17's tests
   change. The change right after E7-17's implementation deletes it with the three tests that call
   it, whose verified twins are live by then.
4. **Callers.** Lane L5's callers already run one stream at a time ([DEC-890](DEC-890.md): `mandate
   journal verify` and `verify-cold` read one stream's export, and never use `Anchored`), so
   nothing they run changes.

## Rationale

The full-chain run folds each stream on its own (§9.8: "Each holds on its own stream"), so a
per-stream anchor loses nothing a range needs. A record of another stream in an anchored run is a
caller that scoped the range wrongly. Judging it from an empty fold could report a false mismatch or a
false pass, and failing closed reports neither. A control-stream revocation is risk reduction, so
it is held by no run, scoped or not, and DEC-885 I6 is unchanged.

## Alternatives considered

- **Anchor several streams, one `VerifiedPrefix` each.** Rejected: no caller needs it (DEC-890).
- **Skip another stream's records.** Rejected: a run would pass records it never judged.
