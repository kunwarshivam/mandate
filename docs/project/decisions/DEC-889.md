## Context

DEC-885 item 1 defines the connection anchor for "a range of stream `s` with trusted start
`from_seq = n`": the fold after `s`'s records `1` to `n − 1`. The Rust fold of #1159 and #1183
went wider. `ConnectionAnchor::fold` takes the rows of several streams in commit order, and an
`Anchored` run judges every stream it is given, starting any stream the anchor never saw from an
empty fold. That is DEC-885's false-mismatch reading again for the other streams, and it lets an
anchor stand for streams whose prefixes nobody bound.

DEC-892 makes every anchor fold take a `VerifiedPrefix`. `VerifiedPrefix::bind` verifies one
stream's rows from genesis and binds them to that stream's trusted start, so a prefix of several
streams can never bind.

## Decision

1. **One stream per anchor.** `ConnectionAnchor::from_verified(&VerifiedPrefix)` folds one
   stream's verified prefix and gives that stream's anchor, or `ConnectionAnchorError::Broken`
   when the prefix breaks rule 66, 67, 68, or 131 (DEC-885 I5). `ConnectionStart::Anchored` holds
   that one anchor. When `bind` refuses the rows, or the fold gives `Broken`, the caller runs the
   range `ConnectionStart::Unanchored`, so it fails closed (DEC-892 item 3).
2. **Another stream fails closed.** An `Anchored` run judges only the anchor's stream. At the first
   connection record of any other stream, whatever its type, it fails closed with
   `ConnectionCheck::Unanchored` (code `connection_lifecycle_mismatch`). The anchor of an empty
   prefix (`from_seq` 1) has no rows to name its stream, so its stream is that of the range's first
   connection record.
3. **The raw fold goes.** `ConnectionAnchor::fold(&[StoredEvent])` is deprecated in E7-17's tests
   change. The change right after E7-17's implementation deletes it with the three tests that call
   it, whose verified twins are live by then.
4. **Callers.** Lane L5's callers already run one stream at a time ([DEC-890](DEC-890.md): `mandate
   journal verify` and `verify-cold` read one stream's export, and never use `Anchored`), so
   nothing they run changes.

## Rationale

The full-chain run folds each stream on its own (§9.8: "Each holds on its own stream"), so a
per-stream anchor loses nothing a range needs. A record of another stream in an anchored run is a
caller that mis-scoped the range. Judging it from an empty fold could report a false mismatch or a
false pass, and failing closed reports neither. DEC-885 I6 is about which records the rules judge
in a range scoped to its stream; it is unchanged.

## Alternatives considered

- **Anchor several streams, one `VerifiedPrefix` each.** Rejected: no caller needs it (DEC-890),
  and it adds an input whose streams and starts must be matched one to one.
- **Skip another stream's records.** Rejected: a run would pass records it never judged.
