# DEC-834: Route 2's rate limits never shut out a member who holds a valid key

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-08 (UTC) |
| **Decided by** | The coordinator agent, under DEC-176: the reading only adds a guarantee for the kill switch and pause (`AGENTS.md` rule 13) and loosens no refusal |
| **Story or claim** | E9-1 (claim #758); [identity spec](../../specs/identity.md) v0.3 §6.4 route 2; a minor of the independent review of PR #811 |

## Decision

1. The rate limit on `POST /v1/reduction-sessions` counts failed assertions only. An assertion that
   verifies is never refused for a rate limit, whatever the count for its address or device.
2. The rate limit on `POST /v1/reduction-sessions/challenges` counts a challenge only while it is
   outstanding: it stops counting when the challenge is redeemed by an assertion, or when it
   expires (300 s).
3. Over a limit, a failed assertion is answered with the same 401 `unauthenticated` as every other
   failure ([DEC-816](DEC-816.md) item 6), so the limit is no oracle either.
4. The test is owed to E9-1: `a_verified_assertion_is_never_refused_for_a_rate_limit`. It floods
   both routes from the member's address and device with failures, then presents a valid
   assertion, and asserts that the session opens, and that a new challenge is issued at most 300 s
   after the flood stops.

## Rationale

Route 2 is the kill switch's and pause's path during an identity-provider outage. DEC-816 item 6
rate-limits both of its routes, which is right for an unauthenticated route, but a limit that
counts every request would let an attacker on the member's network spend the member's budget and
lock them out of the kill switch while the attack lasts. Counting only failures, and counting a
challenge only while it is outstanding, keeps the limits' protection against guessing and floods
and removes that lock-out.

The residual is stated in the spec: an attacker who holds every outstanding challenge for the
member's own address and device delays a new challenge by at most a challenge's 300 s lifetime.

## Alternatives considered

- **Exempt route 2 from rate limits.** Refused: it is unauthenticated, and unlimited assertion
  verification is a cheap denial of service against the deployment.
- **Generous fixed limits only.** Refused: any fixed count of all requests can be exhausted by an
  attacker on the same address, which is the case rule 13 has to survive.
