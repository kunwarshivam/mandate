# DEC-425: One fit for a handed-on placement, and a refused protective cancel is asked again

| | |
|---|---|

| **Decided by** | The stream K builder (agent), on the coordinator's ruling on #524 (05:52Z, option (A)), under DEC-79 and DEC-176: no exit waits on a cancel that nothing asks, no sell is added, and no protection is removed that §5.4 did not already remove, so no safety rule is weakened |
| **Story or claim** | E7-4; issue [#524](https://github.com/kunwarshivam/mandate/issues/524); tests PR #559, then this fix |

## Decision

1. **No exit waits on a cancel that is neither asked nor outstanding.** Two changes keep it:
   - **One measure for a handed-on placement.** Three decisions read whether a handed-on placement (`passive_exit`) fits beside the exits still selling: whether it holds those exits back (`protection_holds`), whether it is cancelled for them (`overtaken`), and whether an arriving exit leaves it resting (`begin`). They now all read the same `fits`, which leaves out the exits the gate holds (#508's review, m1). Before this decision `protection_holds` and `begin` counted held exits and `overtaken` did not. So on #524's seed 15 the placement held two risk exits of 2 back (3 covered + 8 selling, the held 4 included, over 10) while `overtaken` asked no cancel (3 + 4 within 10). The exits waited past the bound. Now the wait and the cancel agree: the exits of 2 fit beside the placement and go.
   - **A refused protective cancel is asked again.** While a sequence that is not handed on waits on protection resting in its instrument, every protective order resting there, whoever placed it, has a cancel asked or outstanding (`cancel_resting`, shared with `overtaken`). That is §5.4's step 1, which cancels all of an instrument's protective orders. A cancel the broker refuses is queried (§5.7, `overdue`), and once the query finds the order still live with nothing pending, the cancel is asked again. Before, only `overtaken` re-asked, and only for a handed-on placement; a sequence's own cancel, refused and found live, was never asked again, and its exit waited for §5.4's bound.
   - **Asked once per refusal, never once per step** (#576's review, B1). A cancel counts as outstanding while the order is `PendingCancel`, while it is `Unknown` with a refused cancel's query out, and while the cancel was asked in a state that cannot record it, because §5.7 has no edge from there to `PendingCancel` (`orders.rs`'s `legal`): `Submitting` before the broker acknowledges, and `PendingReplace` while the broker replaces the order (the owner replacing it at the broker; the platform never asks a replace). The test is the transition table, not a list of states, so a later status with the same property is covered. Such a cancel stays outstanding until the broker reports the order in a state that can record a cancel, which asks it again once, or ends the order, which lets the sequence go on. §5.4's bound still alerts in the meantime. Each further ask needs a new refusal and a new query answer, so asks are bounded by the broker's answers, not by the clock.
2. **Rule 12 holds.** A held exit's quantity is left out only while it is held. Once released it waits, counts in `fits`, and either fits beside the placement or has it cancelled before it goes. So live protection and live sells never exceed the position; the Σ checks in the summed oracle run over seed 15 and the random properties.
3. **Rule 13's four holds are unchanged, and a held exit stays held.** It causes no cancel (#559's `a_held_exit_alone_never_causes_a_protective_cancel` and #508's `a_held_exit_beside_a_waiting_one_has_no_placement_cancelled_for_it` both pass) and it is not lost: it is evaluated again at every step and joins the fit once released.
4. **Protection is removed only where §5.4 already removes it.** The placement is cancelled only when an exit that can move does not fit beside it, as before; the re-ask repeats a cancel §5.4 had already asked.
5. **`fits` is the one fit.** The old `fits` (counting held exits) is gone, and `fits_beside_movable` is renamed `fits`. DEC-419 and DEC-421 name `fits_beside_movable`; read it as `fits`.
6. **Tests (DEC-77).** #559's three pending tests pass and lose their `#[ignore]` and `BEHAVIOUR_ONLY_TESTS` rows: `seed_15_sends_every_allowed_risk_exit_within_the_bound`, `an_exit_waiting_on_protection_always_has_its_cancel_asked` and `a_refused_protective_cancel_found_live_is_asked_again`. The last also runs every step to the bound and asserts the re-ask is made once (#576's review, minor 2). #508 m1's pin passes, so it needs no correction. #576's round 1 adds four. The first three fail on its round-1 head `a6bf5e92`; the fourth passes there, a regression pin:
   - `a_protective_cancel_that_cannot_be_recorded_is_asked_once`: the OCO `pending_replace`, a marketable exit, then four bounds of ticks. One cancel, no step journals but the bound's, and one alert.
   - `a_protective_order_back_from_pending_replace_is_cancelled_and_the_exit_goes` and `a_protective_order_that_ends_while_pending_replace_lets_the_exit_go`: both ways out of that state.
   - `an_exit_beside_two_placements_has_every_resting_one_cancelled`: item 4's all-resting cancel, as on `main` (minor 3).

## Rationale

Rule 13 counts a wait that never ends as a denial. The defect was two predicates measuring the same placement two ways, not a gate that over-allows (the gate allows 7 of 10 on seed 15). Releasing the exit that fits keeps more cover than cancelling the placement, and needs no new hold.

## Alternatives considered

- **Cancel the placement for the waiting exits instead (direction B).** Rejected: it removes protection the movable exits do not need, and measured with held exits it would cancel for an exit that cannot move, against item 3.
- **Count an allowed exit with no order in the gate's `available`.** Rejected as a fix: the gate does not over-allow here. Kept as a backlog row for a possible separate tightening.
