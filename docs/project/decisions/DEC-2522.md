# DEC-2522: §11 reports an approval request whose deferred checks differ from its decision's

| **Status** | Accepted |
| **Date** | 2026-10-26 (UTC) |
| **Decided by** | `claude-code` (lane GL), under DEC-176: a verification check that only reports, adds no risk, and weakens no rule; the coordinator assigned the task |
| **Story or claim** | Backlog `E21-30-approval-deferral-range-check` (closed when the code lands, #2717); [DEC-2515](DEC-2515.md) item 4; [journal spec](../../specs/journal.md) v0.105 §11 |

## Context

Rule 292 requires an `ApprovalRequested`'s `content.deferred_to_binding` to equal its `DecisionMade`'s,
an absent member read as empty, but `append` can judge it only when both are in one batch. The runtime
writes them together, so its own requests always agree. A writer that split them could record a request
that hides or invents a deferral. Since DEC-2519 and DEC-2521 the workspace API shows such a request as
unreadable and refuses a grant of it, but nothing in the journal itself reported it. DEC-2515 item 4
recorded that as debt.

## Decision

1. **§11 gains the agent-stream check `approval_deferral_mismatch`.** An `ApprovalRequested` fails when:
   - it names no `causation_id`;
   - its cause is an earlier event on the stream that is not a `DecisionMade`;
   - on a full chain, no earlier event is its cause, which covers a request before its decision and one
     naming no event;
   - its `content.deferred_to_binding` differs from the decision's `payload.deferred_to_binding`, each
     side's absent list read as empty, and each list compared as `append` admitted it, in order.
   It is reported at the request.
2. **Only earlier events are in hand:** a cause before a later range's start is left unchecked there, as
   §11's other per-range checks leave references outside the range; the weekly full-chain run judges it.
3. **§9.13 lists the code at both `VerificationRun` versions**, and rule 111 classes it as reported at an
   event. This follows v0.29's reading for codes added to §11, which only tightens (DEC-176).
4. **No record or rule changes**, so the test vectors stay version 3. The `approval_deferrals` section
   gains `ranges`: a case for each clause and for each kind of range, with the reference's four range
   mutants each caught, and an independent oracle that reads each range by sets.
5. **Implementation:** `mandate-journal`'s `verify_agent_stream` and the reference's
   `approval_deferrals.range_mismatches`; `mandate journal verify` runs it with the agent stream's other
   checks.

## Rationale

The journal is the record. A request that names other checks than its decision did is a fact about the
journal, so `verify` reports it, whatever a reader does with it. The rule is rule 292's, the one the API
applies at the read and the grant. A missing or non-decision cause fails, because ambiguity resolves to a
report rather than a pass (non-negotiable 3).

## Alternatives considered

- **Look a cause up anywhere in the range, as `intent_action_mismatch` does.** Refused: a request before
  its decision is itself the disagreement this check exists for, and earlier-only keeps the reference and
  the crate on one reading.
- **Leave a request without a cause unchecked.** Refused: the runtime always names its decision, so a
  request without one cannot be shown to agree.
