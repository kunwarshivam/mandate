# DEC-2806: The agent runtime folds the executor's account-wide restriction

| | |
|---|---|
| **Status** | Accepted (agent: a reversible engineering decision under DEC-79 and DEC-176. It only tightens: the runtime now also holds itself in a restriction the executor already enforces on it, and nothing it folds can lift a restriction it held before) |
| **Date** | 2026-10-26 (UTC) |
| **Decided by** | an agent, under DEC-79 (`claude-code`, lane D1) |
| **Story or claim** | E21-54 (lane DR's follow-up to [#2579](https://github.com/kunwarshivam/mandate/pull/2579)); trading spec §7.3; journal spec §9.6 |

## Context

The executor writes `AgentModeApplied` with `agent` `*` (`EVERY_AGENT`) for:
- an account kill switch;
- an order status it cannot map;
- a fee-step pause;
- a reconciliation mismatch that no order names.

Every agent of the account is then held in it: the executor's `effective_mode` for an agent is the
strictest of the account's mode, `*`'s, and the agent's own. The runtime's `addressed_here` read a
`*` as addressed to no one, so a runtime went on proposing what the executor would refuse. Lane DR
found this in the cell while fixing #2579.

## Decision

1. **A slot of its own.** `RuntimeState` folds a `*` record into `every_mode`, beside
   `copied_mode`, this agent's own. The effective mode, and the re-hand mode a restart uses, take
   the strictest of the two with the lifecycle, the startup hold and the kill switch's final mode,
   as the executor's does.
2. **Neither lifts the other.** An account-wide `normal` replaces only `every_mode`, never this
   agent's restriction. This agent's `normal` never lifts the account's. A sibling's record moves
   neither.
3. **Only the slot moves.** A `*` record never confirms or retires this agent's kill switch
   (`retired`), so it cannot lift a switch.
4. **Copies:** a tightening is journaled as any account-stream mode change is: an
   `AgentModeChanged` citing the `*` record, and every pending approval cancelled
   (`mode_tightened`).
5. **`FOLD_VERSION` 3.** A journal holding a `*` record folds to a stricter mode than before, so
   the fold version moves and the golden journal pins one such record (ADR-0001 ES-21).

## Rationale

The runtime must never be looser than the account stream (`AGENTS.md` rules 1 and 3), and keeping
the executor's own slots means each record lifts only what it set.

## Alternatives considered

- **Read `*` as this agent's.** Simpler, but one slot would let an account-wide `normal` lift this
  agent's own restriction, which adds risk.
