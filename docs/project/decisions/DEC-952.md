# DEC-952: Paper and live never share a stream: a live workspace of its own (R0 blocker R1b)

| | |
|---|---|
| **Status** | Accepted (agent, under DEC-929): the coordinator's call on how a live workspace is opened, taking the reading that keeps the journal's one-environment-per-stream rule and refuses more; the builder's readings of it under DEC-79 and DEC-176 |
| **Date** | 2026-10-16 (UTC) |
| **Decided by** | The coordinator (Claude Code), under DEC-929; items 3 to 6 by the R1b builder (Claude Code) under DEC-79 and DEC-176 |
| **Story or claim** | E7-11; the [R0 rehearsal](../tasks/r0-rehearsal.md)'s blocker R1b; [first live trade brief](../tasks/first-live-trade.md) steps 2 and 3; claim #1387 |

`mandate workspace open` opened `ctl:{workspace}` in `paper` only, and the journal fixes a
stream's environment at its first event (`environment_mismatch`), so the live
`ConnectionEstablished`, and every live version, confirmation, deployment and grant after it,
could never be appended to the workspace's control stream. The rehearsal stopped there (step 2f).

## Decision

1. **Paper and live never share a stream** (the coordinator, under DEC-929). A live deployment
   gets its own workspace, whose control stream is opened in `live` at its first event; a paper
   workspace stays exactly as it was. The journal's rule that a stream has one environment is
   kept, not narrowed.
2. **Opening.** `mandate workspace open --workspace … --environment live` opens the control
   stream in `live`; `--environment` defaults to `paper`, so every existing paper command line is
   unchanged, and any other value is refused `environment_invalid` before the journal is opened.
   An id whose control stream holds any event is refused `workspace_already_open` in either
   environment, so a live workspace can never be opened over a paper one or the other way round.
3. **Every owner command states its environment.** The owner flags every control command takes
   (`--workspace`, `--user`) gain `--environment`, `paper` by default, as the gestures already had
   (DEC-925): the registrations (`config register`, `model register`), `approvals list`, `show`,
   `approve` and `skip`, and the gestures (`version create`, `version confirm`, `agent deploy`).
   `connection record` keeps its own required `--environment`. Explicit rather than read from the
   stream: each environment needs its own acknowledgement, as the runner's `--confirm-live`
   (DEC-937 item 3), so a paper command line can never act in a live workspace.
4. **A command in the other environment is refused before it writes.** An owner's event is
   appended only to a control stream whose first event is in the owner's environment; otherwise
   it is refused `workspace_environment`, with nothing stored, minted or appended, rather than
   left to the journal's raw `environment_mismatch`. The check sits where each command first
   could write: in `commit` (answers and agent commands) and `commit_caused` (`connection
   record`) before any step-up evidence is minted; in the registrations before they store their
   object; and in `version::admitted`, which every version gesture (create, confirm, deploy and
   their show-code steps) passes before it stores or mints anything, after the paper and live
   document checks, so `mandate_not_paper` and `paper_only` keep their precedence. A show-code
   step that finds its version passes the same check, so it is refused too. A stream with no
   event is the journal's to refuse (`not_stream_opened`), as before.
5. **Registrations in a live workspace.** `config register` and `model register` were paper only
   (DEC-526, DEC-527). A live workspace needs its own registered configuration, since the runner
   reads the configuration from the workspace's control stream, so a `live` owner may register in
   a live workspace; by item 4, only there. A registration places nothing: the version that
   names it is still created, confirmed and deployed through DEC-529 item 3's live admission. An
   owner neither in `paper` nor in `live` is still refused `paper_only`.
6. **Tests that modelled a mixed stream.** The CLI's test journal does not enforce the
   journal's environment rule, and some fixtures seeded a live connection or live gestures on a
   control stream whose first rows were paper, or pinned `--environment` as an unknown argument
   of the registration, approval and `workspace open` commands. Those fixtures now seed one
   environment per control stream, and the parse tests accept `--environment`, as this decision
   requires; what each test asserts about its own command is unchanged.
7. **The founder's steps and the rehearsal.** The first live trade brief's steps 2 and 3, and
   `scripts/r0-rehearsal.sh`, open the live workspace with `--environment live` and pass it to
   every owner command. With it, the rehearsal passes every configuration and gesture step (2b to
   2k) and stops at the first run (2l), on R2's lapse evidence.

## Rationale

Keeping one environment per stream keeps every reader simple and every replay unambiguous: a
control stream's environment is its first event's, and nothing on it can say otherwise. A live
workspace of its own also separates the founder's live records from every paper experiment in
the journal, which is what DEC-529's narrowings assume. Refusing a mismatched command before it
writes turns the journal's generic refusal into one the owner can act on, and puts it ahead of
any stored object or minted step-up.

## Alternatives considered

- **Let the control stream carry both environments** (each event's own environment in its
  payload): rejected by the coordinator; it changes the journal's stream rule, every reader of
  the control stream, and the replay, to save the founder one `workspace open`.
- **Read the environment from the stream instead of `--environment`**: rejected; a paper
  command line would then act in a live workspace without saying so (item 3).
- **Check only at the journal**: rejected; the refusal would come after the object was stored
  and the step-up minted, and would name no code the CLI documents.
