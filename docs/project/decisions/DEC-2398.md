# DEC-2398: The account's day-trading facts are journaled on `AccountSnapshotRecorded` version 2

| | |
|---|---|
| **Status** | Accepted (agent, under DEC-79 and DEC-176: journaling two broker facts the gate already reads adds no risk and loosens no check; a reader without them holds; number assigned by the coordinator) |
| **Date** | 2026-10-26 (UTC) |
| **Decided by** | `claude-code` (lane XF, split from lane X's G2b), under DEC-79 |
| **Story or claim** | E21-30 (the cell's trade loop); product-flow map X4 and X5; [DEC-2378](DEC-2378.md) item 11 condition 2 (lane D1's ask); trading spec §7.2, §9.2; journal spec v0.88 §9.35 |

## Context

The cell's runtime's advisory dry run reads only the journal (DEC-2378 item 11). It defers the
day-trade budget (trading spec §9.2) because nothing journals the two broker figures that check
reads, and nothing journals the regime that says which of them applies:

- **The prior-close equity** that `legacy_pdt` compares with its threshold: the broker's
  `last_equity` under either regime (DEC-840 item 5).
- **The maintenance excess** that `intraday_margin`, Alpaca's regime, checks: `equity` less the
  broker's `maintenance_margin`, signed (DEC-524 item 2).

The executor already reads both on every account snapshot (`BrokerAccount`). DEC-524 item 3 kept
them out of the journal because `AccountSnapshotRecorded` was closed at version 1 and nothing then
needed them replayed. DEC-2378 item 11 condition 2 now needs them: the day-trade budget turns on in
the dry run "once the executor journals ... the account's regime and `last_equity`". The regime and
the account type are the connector's declaration (DEC-840 item 1), which no record carries: the
broker profile registered as configuration (DEC-531, DEC-630) holds order cells only. Lane D1 asked
for both figures, required, with version 1 read as unknown, and asked which record carries the
regime.

## Decision

1. **`AccountSnapshotRecorded` gains version 2** (journal spec v0.88, §9.35): version 1's account
   members, then `account_type` (`cash` | `margin` | `null`), `day_trading_regime`
   (`intraday_margin` | `legacy_pdt` | `null`), and `last_equity` and `maintenance_margin`, both
   required `decimal`, then version 1's cash comparison and `risk_clock`. Version 1 stays
   registered and is never edited (§8).
2. **The declaration is the connector's; both figures are the broker's, as it reported them.** A
   `null` declaration means the connector declares none, never a default. Nothing is derived, rounded, floored, or
   substituted. A deficit and a negative figure are well formed, so no consistency rule is added: a
   rule that refused a broker's odd figure would refuse the reconciliation batch that carries the
   snapshot, and with it the pauses and alerts the batch journals (DEC-402's reasoning for the fee
   step). Rule 24 applies to both versions. Rules 287 to 290, which the coordinator reserved for
   this slice on 2026-10-26, are released unused.
3. **How a reader takes them.** The latest snapshot on the stream counts, whatever its version. A
   version 1 has no figures and no declaration, a `null` declaration is unavailable, and a reader that needs them holds what
   depends on them: it never reads them as zero or as `equity` (`AGENTS.md` rule 3). A version 2's
   prior-close equity is `last_equity`; its maintenance excess is `equity` less
   `maintenance_margin`, signed. A negative `maintenance_margin` gives no excess, as DEC-524 item 2
   refuses it, and a reader holds as on a version 1. Under `legacy_pdt` §9.2 also reads the
   broker's pattern-day-trader flag and the trailing day-trade count, which no record journals: a
   reader that cannot see one holds or defers the budget, never reads the flag as unset or the count
   as zero (the independent review of #2542). No exit, protective order, or kill switch reads
   any of the four (`AGENTS.md` rule 13).
4. **The executor writes version 2 for every snapshot**, the cash step's and the fee step's, from
   the change that builds it, after `mandate-journal` registers it, with its connector's declared
   account rules. A writer that has not read a figure writes version 1. `AccountStateObserved` is unchanged.
5. **Slices.** This spec change (the spec guard keeps it apart from code); then `mandate-journal`
   validates version 2; then the executor writes it and its readers accept it. The dry run's read of
   the figures is lane D1's.
6. **This supersedes DEC-524 item 3 for `AccountSnapshotRecorded` only.**

## Rationale

The journal is the one thing the runtime and the executor share, so a fact the dry run must see has
to be journaled (DEC-2378's rationale). Recording the figures in the same snapshot as the equity they
are compared with keeps the excess consistent with one broker read. Two figures, not `last_equity`
alone, because Alpaca's regime is `intraday_margin`, whose check reads the maintenance excess; with
`last_equity` alone the dry run would still have to defer Alpaca's budget.

## Alternatives considered

- **The regime in the broker profile.** Rejected for now: the profile is a registered
  configuration object read by order construction, and changing its canonical form re-registers
  every profile; the snapshot already carries the figures the regime is read with.

- **`last_equity` alone, as asked.** Rejected: it serves only `legacy_pdt`, and the demo's broker is
  Alpaca (`intraday_margin`).
- **Journal the derived maintenance excess.** Rejected: the journal records what the broker said;
  a reader derives, and DEC-524 item 2's rules for the derivation stay in one place.
- **Nullable figures, `null` when unread.** Rejected: version 1 already means "no figures", and a
  required member keeps a writer from journaling an unread figure as present.
- **A consistency rule refusing a negative `maintenance_margin`.** Rejected (item 2).
- **Add the figures to `AccountStateObserved` too.** Not needed by any reader yet; left for a later
  version if one does.
