## Context

Journal spec §9 catalogues `BacktestRunRecorded` on the workspace control stream ("data snapshot,
code build, configuration, results, paper/live/backtest marker") but closes no payload, and the
workspace API spec names `GET /backtests/{id}` with no shape. Lane A1 builds the server and lane
W2 the web client from that shape, so it has to exist before either can serve or show a report.
E4-2's report (`report_version` 1) covers the baseline strategy only.

## Decision

1. **The report is an artifact.** A run's report is one canonical JSON object (journal spec §4),
   stored under `sha256:` of its canonical bytes (journal spec §6.3). The digest is the run's
   identity: the same inputs give the same bytes and so the same reference (DEC-1000 item 9).
2. **The schema, `report_version` 2.** `kind: "backtest_report"`, `subject: "mandate_version"`,
   and these members, every decimal a canonical string, every instant a journal timestamp:
   - `mandate_version` (ref), `instrument` (asset id), `research_agent` (boolean);
   - `inputs`: the digests `bars` (the data snapshot), `model_outputs`, `theses`, `config`;
   - `strategy` and `benchmark` (buy-and-hold of the same instrument, from the same cash, through
     the same fill model and fees): E4-2's metric block, unchanged;
   - `excess_total_return`;
   - `decisions`: `count`, `outcomes` (every outcome code with its count, zeros included),
     `gate_reasons` and `hold_reasons` (each code that occurred, with its count), and `rows`, one
     per decision instant in time order: `at`, `date`, `purpose` (or `null` for a hold),
     `outcome`, `reason` (or `null`), `decided_by` (or `null`), `qty` and `limit` (or `null`),
     and `outputs_used`;
   - `risk`: `limits_latched` (the limit names that latched, in order), `risk_exits` (count), and
     `most_restrictive_mode`;
   - `equity`: the strategy's and the benchmark's closing equity per period, `{date, equity}`;
   - `limitations`: fixed codes for what the run does not know or does not model, every one that
     applies: `no_lookahead_by_receive_time`, `recorded_model_outputs_only`,
     `admissions_replayed_not_rejudged`, `fills_within_bar_range`, `spread_from_fill_model`,
     `single_instrument`, `daily_decisions`, `asks_unanswered_skip`,
     `participation_from_bar_volume`, `marks_at_bar_close` (the risk state and the protection see
     each bar at its close, not intrabar), `trading_status_assumed` (no halt or trading-status
     data: the instrument is taken as active and tradable), and for a research-agent
     version `mechanics_not_thesis_quality` (DEC-99);
   - `disclosures`: the named placeholders DEC-1003 lists. No drafted wording is carried.
   The outcome codes are `submitted`, `builder_hold`, `builder_refused`, `gate_deny`,
   `gate_defer`, `gate_hold`, `autonomy_deny`, `ask_unanswered`, and `order_working`. A report
   with another code, or a member missing, does not validate. A change to any member's meaning
   raises `report_version`; `report_version` 1 stays E4-2's baseline report.
3. **No thesis-quality figure in a backtest.** The report carries no per-thesis outcome, hit rate,
   or score, for any version (DEC-99, DEC-111 item 1; product brief B2). Thesis quality is the
   forward-paper evaluator's alone (DEC-1002).
4. **The record.** `BacktestRunRecorded` (workspace control stream, journal spec §9.18 at
   `schema_version` 1) carries exactly: `backtest_id`; `mandate_version`; `data_snapshot` (the
   bars digest, or the data plane's manifest digest once DP-14 lands, which then replaces it);
   `model_outputs` and `theses` (digests); `configuration` (the config digest); `code_build` (the
   runner's build digest, journal spec §6.3); `report` (the artifact ref); `report_version`;
   `marker`, always `backtest`; and `result`, `completed` or `refused`, with `refusal` (the run's
   stable reason code) when refused. Its required refs are `rule` and `man`. The report artifact is
   stored before the record is appended (journal before acting, rule 5). Registration in
   `mandate-journal`, with its vectors, is E4-5's.
5. **The read shape.** `GET /backtests/{id}` answers `read-models/backtest`: the envelope, and
   `backtest: {backtest_id, mandate_version, state, refusal, report_ref, report}`. `state` is
   `running` until the record commits, then `completed` or `refused`; `report` is the artifact's
   object for `completed` and `null` otherwise. The read is the workspace's own: a backtest is the
   owner's own strategy's history, never another workspace's, and never aggregated (API-2).
6. **Disclosures by name.** The read carries `disclosures` as DEC-1003's names; the web client
   shows each named placeholder until counsel's text exists (DEC-79's reserved legal text; the
   product brief's compliance-text row).

## Rationale

A stable, schema-checked shape lets A1 serve and W2 render a report before either is built, and
the digest identity is what FR-4.5's reproducibility means in practice: the record names bytes,
and the bytes recompute. Carrying every decision row lets the owner see why each order did or did
not go out, which is the point of backtesting the version's own path. Fixed limitation codes, not
prose, keep wording out of the record and leave it to counsel.

## Alternatives considered

- **Put the report inline in the event.** Rejected: rows over years exceed what a payload should
  hold, and journal spec §6.3 already says reports are artifacts.
- **Summary only, rows behind a second route.** Kept as an option for later: the report is one
  artifact either way, and a paged rows route can be added as an optional member without a
  version change.
