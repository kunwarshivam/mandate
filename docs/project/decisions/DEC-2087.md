## Context

DEC-2065 moved the cell jobs onto three self-hosted DigitalOcean runners, named by the repository
variable `CI_RUNNER`. Each job runs k3d inside a Sysbox container with its own Docker daemon.

On those runners the cell's NetworkPolicy is not enforced, and the cell jobs have failed on every
pull request since:
- Every workspace pod's `egress-gate` init container refuses to start, with "egress still open after
  a minute: refusing to start". The gate probes an address its policy must deny, and fails closed
  while that address still answers (AGENTS.md rule 3).
- `helm upgrade --install workspace … --wait` ends with nine deployments at `Available: 0/1`
  (`main`'s run 40837985477, `cell-demo-web`).
- The ten-minute cell jobs run out their time before printing anything.

Three runners take one job each, so one pull request's eighteen cell jobs held all three for about
three and a half hours (#3013's run 40978034914). Every other pull request's cell jobs queued behind
them.

The merge workflow merges only a pull request whose latest `ci` run succeeded (`merge-approved.sh`).
A timed-out cell job leaves the run `cancelled`, so no pull request that selects the cell could
merge, however green its required checks.

## Decision

1. **The runner guard also requires `CI_RUNNER_POLICY_ENFORCED` to be `true`.** `select`'s
   `runner` output names `CI_RUNNER` only for a pull request from this repository or a push or
   dispatch on `main` (DEC-2075), and now only while that variable is set. Otherwise it is
   `ubuntu-24.04`. Today it is unset, so the cell jobs run on GitHub's runners again, where k3s's
   network-policy controller enforces the policies and the egress gate passes.
2. **Moving back needs no code change.** The founder sets `CI_RUNNER_POLICY_ENFORCED` to `true` once
   a cell job on a self-hosted runner gets past the workspace release, for example a
   `runner-smoke` dispatch or a pull request run with the variable set for its duration.
   `CI_RUNNER`, the runners themselves and their cost cap are unchanged.
3. **Still one guard.** The guard is still the only expression that names a self-hosted runner, and
   `only_the_event_guards_reach_the_self_hosted_runners` pins it with the new condition.

## Rationale

- The egress gate is right to fail closed, and loosening it to suit the runners is not on the
  table.
- A cell job that cannot pass where it runs is worse than one that waits for a GitHub runner.
- Unsetting `CI_RUNNER` would do the same, but it is the founder's setting. This change lives in
  the repository, can be reverted with a commit, and leaves `CI_RUNNER` ready for when the runners
  are fixed.

## Alternatives considered

- **Unset `CI_RUNNER`.** The same effect, but it needs the founder's console, and moving back later
  repeats the step.
- **A fail-fast network-policy probe before the workspace release.** It would shorten each doomed
  job but leave every cell job red. It is still worth adding, so that a runner's controller state
  can be read from CI.
- **Raise the cell jobs' ten-minute limit.** No: DEC-464, and the jobs would still fail.
