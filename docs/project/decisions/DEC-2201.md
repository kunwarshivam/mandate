## Context

Agent harness spec v0.1 made a research run one model call over a context that deterministic code
assembled: the model named no read (HI-4) and the gateway offered no tools (INF-5). §13 item 6 left
multi-call runs open, because letting the model choose its inputs needed its own spec change. The
founder has now closed that question:

> "it has to be agentic harness, as what we are selling/the product is agent harness for trading."

The trading side does not change. The model still writes opinions, never orders (`AGENTS.md` rule 4);
the order builder, the gate, the autonomy rules, and the envelope are untouched (rule 11).

## Decision

1. **The research run is an agent loop (the founder, 2026-10-17).** A run is a bounded sequence of
   model turns. In each turn the model either asks for reads through the research entry's pinned
   tools or gives its final answer. The answer is the same candidate theses and invalidations as
   before, judged by the core exactly as before.
2. **The core owns the loop; the worker does the I/O.** Each turn is one gateway call. The core
   journals every turn's `ModelInvocationRecorded`, dispatches its tool calls only after that record
   commits, journals every item a tool returned as `ObservationRecorded` and every tool call as
   `ToolCallRecorded`, and only then emits the next turn. The loop's state and bounds are a pure fold
   of the run's journaled records (`mandate-research-run`), so a replay recomputes them. The worker
   still never appends (HI-16).
3. **The mode is pinned content.** The research entry gains `mode` (`single_call` or `agentic`), its
   tool declarations, and its loop bounds, all inside the content hash. Moving an agent from one
   mode to the other is a new signal-model version that the owner confirms (§8.4, rule 11). Mandate
   spec §8.1's definition of the content hash, which inference spec §4.1 says is the same, names
   them too: the hash covers more, which only tightens (DEC-176).
4. **Tools read, and only from the store.** v0.2's tools are `news`, `filings`, `filing_text`,
   `bars`, and `quote`. Each takes typed arguments: data-universe symbols, bounded windows and
   counts, an item id this run already received, and for `news` and `filings` at most five search
   terms. Each reads the workspace data service's point-in-time store (data-plane spec §4.6) at the
   run's cut-off, from the allowlist version in effect. A tool call never causes a fetch from a
   source, so no text the model wrote leaves the deployment except in its own gateway call (HI-26).
   No tool places, cancels, approves, appends, changes a mandate, policy, allowlist, or universe,
   reads the vault, or reaches another host (HI-4).
5. **No fundamentals tool and no note tool yet.** The data plane serves no XBRL facts (E2-9's rest),
   so `fundamentals` is declared later, as a new research entry. A scratch note tool adds nothing the
   journaled turns do not already hold, and it would be one more write surface, so v0.2 has none.
6. **The gateway returns tool calls as data and runs none.** INF-5 becomes: the gateway offers the
   model only the read-only tool declarations pinned in its entry, and executes nothing. A reply is
   either a final output valid against the output schema or one to four tool calls, each naming a
   tool offered in that turn with arguments valid against its pinned schema. Anything else is
   `schema_invalid`, so the error kinds and the journal's `outcome` set stay as they are. Provider
   plugins, web search, code execution, and `transforms` stay off.
7. **The last turn offers no tools.** The request for turn `max_turns` declares no tool, so the model
   must answer; a tool call there is `schema_invalid`. The model is told its remaining turns and
   tool calls in every turn.
8. **Every bound ends the run with no output (rule 3).** Defaults, engineering values inside the
   content hash (DEC-431 item 7's rule): 6 turns, 12 tool calls per run, 4 per turn, 20 items and
   24,000 bytes per tool result, 96,000 result bytes per run, a run cost ceiling of $0.25, and a run
   deadline of 900 s on the risk clock. A turn whose tool calls exceed the run's remaining calls runs
   none of them; each is recorded refused `call_budget`, and the run ends. A turn the ceiling cannot
   cover ends `budget_exhausted`. The deadline cancels the run. Byte caps truncate a result, oldest
   items first, and the record says so: the model cannot know a result's size before it asks, so a
   size cap trims rather than ends.
9. **The run's spend ceiling is a cap the gateway checks.** The request carries
   `spend_ceiling_usd`, the run's ceiling less the cost of the run's earlier turns as the core folds
   them from their records. The gateway admits the turn only if its reservation fits under it and
   under every other cap (inference spec §7.3). It only refuses: the founder's caps (DEC-997 item 3,
   DEC-431 item 15) still bind, unchanged.
10. **A tool call has one record.** Journal spec v0.48 §9.21 closes `ToolCallRecorded` on the agent
    stream with rules 165 to 170: the turn that asked, its index, the tool, the arguments and the
    result as artifacts, the result's outcome and reason, its byte length, whether it was truncated,
    and the `ObservationRecorded` ids it returned. `ModelInvocationRecorded` is unchanged: a
    tool-call turn has an `ok` outcome and no verdicts, and only the final turn's record carries
    verdicts.
11. **A run replays from the journal, and re-runs from its recorded responses.** Replay never calls a
    model (HI-3). Driving the loop again with the recorded fake keyed by each turn's
    `request_digest`, over the same store snapshot, reproduces every record of the run byte for byte
    (HI-25). That is what CI and the demo run on.
12. **A crash ends the run.** Turns already recorded stay; reservations stay counted; no turn is
    re-sent under its old call id; a run with no judged final turn is never resumed or judged. The
    next run waits for `next_proposal_at`, counted from the last reservation of any turn.
13. **The single call stays, with no runtime fallback.** `single_call` entries stay registered and
    pinnable. A failed agentic run is missing; it is never retried as a single call, because a second
    try until something answers would select outputs (DEC-432 item 3). The internal paper and demo
    agents may pin an agentic entry once E19-6's adversarial bench and a §8.3 regression evaluation
    pass on it; users' agents also need its own DEC-99 forward evaluation (DEC-431 item 16).

## Rationale

The founder's item 1 is the product. Items 2 to 13 are how to take it without moving any risk
boundary: the model gains a choice of what to read, inside the data universe, the allowlist, the
cut-off, and a budget, and nothing else. A fooled model can therefore read more allowlisted data and
spend up to the run's ceiling; it still produces at most a thesis, which §8.5 and the autonomy rules
admit or not (HI-10). Every new step is journaled before it is used, so INF-10 and DP-3 hold per
turn as they held per run.

## Alternatives considered

- **Tools as a tagged union in the output schema** (the model writes `{"reads": [...]}` and the
  harness runs them): no provider tool support needed, but weaker models fill it poorly, and it is
  still tool use under another name. Native tool calls with gateway-side validation keep the same
  boundary and are what providers train for.
- **Execute tools inside the gateway:** the gateway would need data-plane access and a reader per
  tool, and it would stop being the one place that only brokers calls. Tool calls as data keep
  execution in the harness, behind its read-only ports.
- **Let the model fetch URLs or search the web:** breaks DP-9 and DEC-101, and opens exfiltration
  through query strings. Refused.
- **Truncate on every bound instead of ending the run:** keeps going after the model asked for more
  than it was allowed, which the founder's brief rules out; only result size, which the model cannot
  know in advance, trims.
- **Fall back to a single call when the loop fails:** a second sample after a failure selects
  outputs, and doubles spend. Refused.
- **A new `MeterReserved` member for the run:** the per-run ceiling then folds on the meter stream,
  but it changes a closed schema that two lanes are registering; the caller's own records already
  hold every earlier turn's cost.
