| | |
|---|---|
| **Status** | Proposed (reserved for the founder: it changes the mandate spec, which needs the founder's approval, DEC-79) |
| **Date** | 2026-10-09 (UTC) |
| **Decided by** | Recommended by the lane L2 builder (agent); the founder decides |
| **Story or claim** | E10-7 slice S0 (the backlog row "The unasked-dollars figure (DEC-189): its formula in mandate spec §4.2"); claim [#755](https://github.com/kunwarshivam/mandate/issues/755) |

## Decision

1. **What DEC-189 fixes.** The figure is "the order value the agent could still submit today without
   an ask, bounded by the `auto` paths, each live delegation's remaining caps, `max_orders_per_day`,
   `max_order_usd`, and gross-exposure headroom, computed from the mandate and the journal", display
   only. It names the bounds but not how they combine, what "today" and "live" mean against the risk
   clock, how far a rule's condition counts, what an unknown input shows, or the rounding. DEC-189
   put the formula in the product brief; the backlog moved it to mandate spec §4.2 beside the
   confirmation screen's other dollar figures, with a reference-model function the web figure is
   tested against. This decision states it there.
2. **The formula** (mandate spec §4.2, `unasked_usd` in `reference/mandate/ref.py`). An upper bound
   on the order value of opening and increasing orders the agent could have decided `auto` from the
   risk clock *t* to the end of its risk day, before an exit, a new risk day, or a version raises it.
   Each `auto` path is a set of slices: an `auto` default or `auto` rules give one unlimited slice of
   the largest per-order size they allow (`max_order_usd`, narrowed by an `order_usd` bound in the
   rule's condition); each delegation whose window meets the rest of the risk day gives slices of its
   per-order cap until its remaining orders or remaining total run out. The `max_orders_per_day`
   still left picks the largest slices; the sum is capped by the gross headroom
   min(`max_gross_exposure_usd`, E) − G, floored at 0, and rounded up to the cent. Exact decimals
   throughout.
3. **Unknown is never 0.** A missing journal input (the risk clock, agent equity, gross exposure,
   today's order count, or delegation usage) makes the figure unknown, shown as "not known"
   (`AGENTS.md` rule 3). It is a known 0 only when the review date has passed (§6.2 step 5b), the
   version is `policy_nonconforming`, or the effective `auto_allowed` is false (step 5c). A policy
   that is not known reads as allowing `auto`, the larger figure.
4. **Conservative readings taken in the interim, each the larger figure,** so the owner is never
   shown less than can run without them:
   1. "Today" is from *t* to the end of the risk day, so a delegation starting later today counts
      now; DEC-189's "right now" would leave it out.
   2. The agent's mode and delegation suspension (§6.5 condition 5) do not lower the figure; the
      state is shown beside it. A suspension can lift within the day without the owner.
   3. Only `order_usd` bounds narrow a condition. Other fields (`bought_today_usd`,
      `gross_usd_after`, `purpose`, instrument, session), rule order, the admission and client
      ceilings, and the position cap are left out; each only lowers what runs unasked.
5. **Workspace API §5.3's `unasked_usd_after`** is the same figure for the preview's version at the
   agent's current state, a decimal string or `null` when unknown.
6. **The loss answer** (DEC-182: it maps only to `capital.max_loss_from_allocation`,
   `risk.max_drawdown`, and `risk.max_daily_loss`; mandate spec §7, `loss_answer_fields`). A fraction,
   or a dollar amount divided by the allocation, is rounded down to whole basis points to give F; F
   of 0, or 1 or more, is asked again. `max_loss_from_allocation` is F (`user_stated`);
   `max_drawdown` is 0.8 × F and `max_daily_loss` is 0.2 × F, both `platform_proposed` and inactive
   until confirmed (V-020, MI-12). These are the base mandates' ratios (0.1, 0.08, 0.02); V-014
   holds, and the flatten rung's `at` follows `max_drawdown` by V-011, not by a further mapping.
7. **Questions for the founder**, each with the interim this change takes:
   1. Should the figure be a snapshot of "right now" (drop to 0 while delegations are suspended or
      the agent is not in `normal` mode, and leave out delegations not yet started), or the rest of
      the risk day as written? Interim: the rest of the day, the larger figure.
   2. Should more of a rule's condition narrow it (`bought_today_usd` as a day total, the position
      cap per instrument)? Interim: `order_usd` bounds only.
   3. Are 0.8 and 0.2 of the loss answer the right proposed drawdown and daily loss, or should the
      drafted drawdown leave a wider gap below the floor for gaps and exit pricing? Interim: 0.8 and
      0.2, the base mandates' ratios, both shown as proposed and confirmed by the owner.
8. **Interim while Proposed.** The formula and the mapping live in the spec text and the reference
   model only; no reference case, fixture, Rust code, or web figure depends on them, and nothing in
   the gate or the autonomy decision reads them.

## Rationale

DEC-189 makes autonomy a dollar amount; a figure the web and the reference disagree on, or one that
shows 0 when it does not know, would mislead the owner exactly where they decide how much to hand
over. An upper bound computed from the same inputs §6.2 decides on can be checked: the reference
fuzz runs the real autonomy decision over adversarial days and asserts that nothing runs unasked
beyond the figure, and that a greedy day reaches it exactly where the formula claims to be exact;
twenty seeded bugs in `reference/mandate/mutants.py` are each caught. The loss mapping keeps the
owner's one essential answer as the floor and proposes the two tighter limits beneath it.

## Alternatives considered

- A snapshot "right now" (question 1): smaller, but would read 0 during a short suspension and
  understate a delegation that starts in an hour.
- The exact maximum over every condition field: needs a solver over the §6.3 language, and a model
  that cannot be checked independently.
- Showing only the dial's label (DEC-189 rejected it).
- Loss answer to `max_loss_from_allocation` only, with the other two left for the owner to enter:
  three questions would become five.
