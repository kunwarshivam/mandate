# DEC-983: Workspace control services judge each control-plane instruction per workspace, journal it, then apply it

| | |
|---|---|
| **Status** | Accepted (agent: reversible engineering readings under DEC-79, taken under DEC-176; each refuses or records, and none adds an effect) |
| **Date** | 2026-10-17 (UTC) |
| **Decided by** | `claude-code` (builder, managed-cells lane G0), under DEC-79, DEC-176, DEC-981 and DEC-982 |
| **Story or claim** | E20-3; plan DEC-967 lane G0; claim [#1436](https://github.com/kunwarshivam/mandate/issues/1436) |

`cp-agent` verifies and hands over ([DEC-982](earlier-900-1999.md#dec-982)); workspace control services, the
control stream's single writer, judge CP-9, journal the §9.17 record, and only then apply it
(design CP-5 (b), CP-9; journal spec §9.17, [DEC-981](DEC-981.md)). `mandate-cp-site` is that
side. These are its readings.

## Decision

1. **Two ports, no journal crate.** `Site` implements `cp-agent`'s `InstructionSink` over a port
   of its own, `ControlStreams` (the hosted workspaces with their organizations, a workspace's
   committed records, and an append at the head under the writer's epoch), and an `Effects` port.
   It takes event IDs and the clock as functions, so it reads no clock and holds no randomness, and
   it depends on no journal crate outside its tests: whichever process hosts workspace control
   services supplies the writer.
2. **Which workspaces an instruction covers.** A license covers the hosted workspaces of its
   `org_id`; every other instruction, and every refusal, covers every hosted workspace (DEC-981
   item 2). A license whose organization has no workspace here is refused `not_addressed` on
   every hosted workspace, since `cp-agent` judges only the deployment (DEC-982 item 4).
3. **CP-9, per workspace and per kind.** The kinds are: the license; the release; a catalog
   entry per its `kind`; a data bundle per `dataset`; and a withdrawal per `release_id`. A record's
   identity is its digest member (`document_digest`, `manifest_digest`, `content_hash`,
   `bundle_digest`; for a catalog entry, its `entry_id` with its `content_hash`, since two entries
   may share content) with its sequence. An instruction whose identity is that of the latest record of
   its kind is already applied: nothing is journaled and nothing applied. Otherwise one whose
   sequence is not above the highest of its kind is refused `replayed`. Otherwise it is new.
4. **Journal, then apply.** A new instruction is appended to that workspace's stream, and the
   effect runs for that workspace only after the append committed. No instruction has an effect
   beyond its record in this slice: licenses, releases, catalog entries and bundles act in E20-4,
   E20-6, E20-9 and E2's data stories. A process that dies between an append and its effect
   finds the instruction in effect on retry and does not apply it again; the story that adds the
   first effect makes it recover from the journal at start (a constraint on E20-4 and later). `LicenseStateChanged` is written by E20-4, and
   `ControlPlaneEnrolled` by lane G1's enrollment.
5. **A refusal once per digest.** A refusal is journaled on a workspace unless a refusal with the
   same `document_digest` is already there (DEC-981 item 5). With DEC-982 item 1's canonical form,
   one document has one digest, so a repeated bad message never fills the stream.
6. **One answer for a fan-out.** `Unavailable` if any covered workspace could not be read or
   written, or none was covered at all (a deployment hosting no workspace journals nothing, so it
   never acknowledges), so `cp-agent` keeps the message and retries; the retry finds the workspaces already
   written in effect and journals no duplicate. Otherwise `AlreadyApplied` if nothing new was
   journaled anywhere (including a replay whose refusal is already on every stream),
   `Refused(replayed)` if any workspace newly refused it as a replay, and `Journaled` otherwise.
7. **Nothing on the kill-switch path.** `cp-agent` calls into `Site`, never the reverse, and the
   `ControlStreams` port takes and releases its writer per call, so a hand-over that hangs (in
   `cp-agent` or in an effect) holds nothing an owner command needs (CP-3); a test commits a kill
   switch while an effect hangs.

## Rationale

Judging per workspace keeps every check inside one stream, the same scope `append` and §11 use,
and keeps tenancy where it is. Identifying a record by its digest and sequence makes a re-pull of
the instruction in effect a no-op while a lower or conflicting sequence is still a replay.

## Alternatives considered

- **One deployment-wide highest sequence.** Simpler to state, but it would read across tenants'
  streams. Rejected with DEC-981's per-workspace placement.
- **Journal through `mandate-journal` directly.** Couples the handler to one store; the port lets
  the Postgres writer, the memory journal of the tests, and a later process share it.
