# DEC-909: The welcome page spends nothing on what nobody sees: the owl rests, the cue measures only when something moves, and loops out of view or under the page hold still

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-10 (UTC) |
| **Decided by** | The founder, who asked for a review of the site with the Framer agent's skills and then said "fix" to its four findings: the flying owl's frame loop never rested, the Scroll cue measured every frame forever, the sea's and the lock screen's loops ran out of view, and parts of the page sat outside any landmark. The agent chose the details under DEC-79; every item is reversible engineering and changes nothing a visitor sees |
| **Story or claim** | Landing page (DEC-907, DEC-908), PR #1290 |

## Decision

1. **The flying owl rests.** Once its springs have stayed still for 12 frames and it is neither
   peeking, glancing about nor blinking, it stops asking for frames and stands (`data-owl` is
   `perched`). Its bob is a CSS animation (`owl-bob`, its height `--owl-bob`), so a standing owl
   runs no script; a blink is two timed paints. It wakes when the window scrolls or resizes, the
   pointer moves, the cue moves, a transition starts or ends on the page, the theme changes or the
   page changes size, and at its next glance. Peeking over the cue it sways, so there it keeps
   flying. Each frame turns each of its parts once rather than once per corner (`voxel-owl.ts`).
   The owl still bobs at rest and blinks, as DEC-907 item 5 says.
2. **The Scroll cue measures in bursts.** After anything that can move the browser window's status
   bar (a change to the window holding it, an animation or transition there, a resize, a scroll on
   the first screen, fonts loading) it measures for 30 frames and stops, and tells the owl when it
   moved (`cue-moved`).
3. **Pictures out of view hold still.** The sea's waves, foam, glints and gulls and the lock
   screen's stars pause while their picture is more than 200px outside the window (`ambient.tsx`,
   `data-ambient`). The moon's rise follows the scroll and is never held.
4. **The desktop holds still once the page covers it.** When the page has risen 200px past covering
   the desktop, every animation on it and in the app in its browser window pauses, and plays again
   before it shows. `Ambient` marks the desktop and the root of each app document `data-ambient`,
   and one rule in each document (`scroll.module.css`, `globals.css`) holds every animation with
   `!important`, since each loop's `animation` shorthand would otherwise set it running again. The
   desktop stays drawn, so its landmarks and the live app stay in the accessibility tree.
5. **Every part of the welcome page sits in a landmark.** The desktop is a region named Desktop and
   the long page's bar is a `header`, so axe's `region` rule passes in light and dark, at 1440px and
   390px.

## Rationale

The site is a landing page left open in a tab. Before, it kept Chromium's main thread busy
about 450ms of every second while idle at 1440px, wherever the visitor stopped: the owl and the cue
asked for every frame, and every loop ran whether or not it could be seen. Measured the same way
after (idle, 1440px, main-thread busy per second; `idle-before.log` and `idle-after.log` on the PR):

| Where the visitor stopped | Before | After |
|---|---|---|
| The first screen, the owl peeking | 447ms | about 340ms |
| The opening, the sea in view | 465ms | about 260ms |
| The bottom of the page | 459ms | about 170ms |
| Any of these, motion reduced | 0 | 0 |

What remains on the first screen is the owl's peek, which sways by design, and the desktop's own
loops, which are in view there. Nothing a visitor sees moves differently: the owl flies, glances,
blinks and bobs as before (`owl-flight.test.tsx`, `e2e/long-page.spec.ts`).

## Alternatives considered

- **Skip drawing the covered desktop (`content-visibility: hidden`).** Measured about 40ms a second
  cheaper than pausing at the bottom of the page. Rejected: it takes the desktop, its landmarks and
  the live app out of the accessibility tree, and axe then finds no `main` landmark.
- **Watch the desktop with an IntersectionObserver.** It does not work: the desktop is sticky, so it
  stays in the window, covered rather than scrolled away. The page's scroll position says when it is
  covered.
- **Ask the app in the frame to pause by message.** Rejected: a new message to the demo for what one
  attribute on its root and one rule in the stylesheet it already loads can do.
- **Batch the owl's faces by colour.** Measured no better than turning each part once a frame, so it
  was not kept.
