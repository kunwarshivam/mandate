## Decision

1. **No cross toolchain.** Only a linux/x86_64 host can link the cell's static `mandate` binary
   (DEC-993 item 9). Building it on macOS arm64 would need a cross linker or a Rust builder image,
   and neither is among DEC-990's seven dependency kinds, so the coordinator chose to add none.
2. **Another host pulls a pinned image.** On any other host, `cargo xtask cell up` and `cell demo`
   take the `mandate` image from `MANDATE_CELL_IMAGE`, which must name a 64-digit SHA-256 digest in
   the form the workspace chart's schema takes: lane R2's signed multi-arch image (E21-35). The
   cell checks the digest, not the signature; checking R2's signature joins with R2. They skip the build and the import, and k3d pulls
   the image. Without the variable they stop and say that R2 has not published it yet. A pinned
   image wins on linux/x86_64 too, so R2's image can be proven in CI before a laptop needs it. A
   tag without a digest is refused.
3. **darwin-arm64 tool pins.** k3d 5.9.0, helm 4.3.0 and kubeconform 0.8.0 for darwin-arm64 are
   pinned by SHA-256 in `deploy/cell/README.md`, from the same publishers as the Linux pins. They
   are not downloaded by `.cursor/install.sh`, which installs x86_64 Linux builds only.
4. **The cgroup v1 kubelet argument is Linux-only.** On macOS, Docker Desktop's VM runs cgroup v2,
   and the host's `/sys/fs/cgroup` says nothing about it.
5. **Restart drill.** A control stream is written; the journal's CloudNativePG primary pod is
   deleted; once the pod and the cluster are Ready again, the stream exports and verifies by
   journal spec §11. Seeded, it verifies a stream id the restart never held, which must fail as
   `export_stream_empty`, so a drill that verified nothing cannot read as held. That seed proves the
   drill sees a lost stream; it does not plant a loss caused by the restart itself, which would
   need deleting the cluster's volume, and the restore drill (OPS-8) covers that case.
6. **A drill can be skipped, by name.** `kill-switch` (OPS-4) reports `skipped` with the lanes it
   waits on (P1's runtime and executor images, O4's `mandate agent kill`), never `held`, until
   those are on `main`.

## Alternatives considered

- `cross` or `cargo-zigbuild`, or a Rust builder image (`rust:…`) to build inside docker: a new
  dependency kind, outside D-1 to D-7.
- Running the cell on macOS through an x86_64 k3s image under emulation: needs the same x86_64
  binary, which cannot be built there.
- Faking the kill-switch drill with a mock process: it would read as held while proving nothing.
