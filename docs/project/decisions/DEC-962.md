## Context

R12, observed at the rehearsal's 2l on Saturday 2026-10-17 (DEC-961's run): the shell's judge
refuses `a run clock inside the regular session` (`crates/mandate-shell/src/paper/judge.rs:95`),
correctly, because the run's clock is the system's and the market is shut. The founder decided to
finish the rehearsal this weekend by overriding the run clock in the rehearsal build only.

## Decision

1. **The runner's clock (`mandate-paper`).** `RunClock`, a type alias chosen by `cfg(feature =
   "rh-sim")` as DEC-961's `Market` is, is `SystemClock` in every build without `rh-sim`, the
   `live` one included, and `SimClock` in the rehearsal's. `SimClock` reads the instant
   `MANDATE_RH_SIM_CLOCK` names (RFC 3339, any zone) when the process starts and moves exactly as
   the system clock moves from then on, so the run's elapsed time, pauses and deadlines are real;
   unset, it is the system clock. It is every clock read the run makes: `Production`'s
   `Ports::Pause` (the judge, the preflight, the wake, the grant wait, the watch and every journal
   stamp), the connect check's `now`, and the fixture market's quote stamps (`SimMarket` is opened
   on it). A set value that is not an instant refuses the process before anything is read
   (`PaperError::SimClock`); the run never falls back to the system clock for a clock it was given.
   `SimClock`, the variable and `PaperError::SimClock` compile only with `rh-sim` (and in the
   crate's unit tests), so `tests/sim_clock.rs` shows the runner built without `rh-sim` (default
   and `live`) holds no byte of the variable's name and ignores it, and the `rh-sim` one holds and
   reads it, each case the other's seeded bug. As for DEC-961's fixture, CI runs the absence
   cases in the default build only (DEC-529 item 3 lets CI only compile `live`, and `cargo xtask ci
   test-rh-sim` builds only `mandate-mcp` with the feature); the builder ran the `rh-sim` and
   `live` cases, and the override has no function body that only `rh-sim` compiles, so every
   mutant of it is judged by the default build's unit tests.
2. **The owner's clock (`mandate-cli`, a new `rh-sim` feature).** The founder's grant is judged by
   the runtime at its effective time, the later of its `submitted_at` and the folded clock
   (DEC-156), and its step-up evidence must be at most 300 s older than that
   (`mandate_approval::stepup`), and the CLI stamps every gesture and answer with its own clock.
   A CLI on the system clock would stamp them on Saturday while the run's clock is Monday, so
   every one would be stale. The CLI therefore gets a feature of its own, `rh-sim`, which only the
   rehearsal script turns on, and with it the moment the owner ran a command is
   `MANDATE_RH_SIM_CLOCK`'s instant when set (one read per command, as before). The founder's CLI
   is built with no feature and holds neither the variable nor the module (`tests/sim_clock.rs`).
   This tightens nothing and loosens nothing in the founder's build; DEC-922 item 1's reading
   (only an explicit rehearsal feature reaches the simulator's world) is extended to the CLI.
3. **The simulator's broker clock (`mandate-rh-sim`).** The script takes an optional `clock`
   member, an RFC 3339 instant read strictly like every other member: the core's clock when the
   script's core is built, and on the rehearsal server the clock each `tools/call` sets on the core
   before it acts, moved by the time the server has served. So the orders it records are stamped on
   the rehearsal's timeline, and the restart's `created_at_gte` listing (DEC-941) finds them.
   Without the member nothing changes: the core has no clock and its orders no creation time.
4. **One timeline (`scripts/r0-rehearsal.sh --sim-clock INSTANT`).** The script reads INSTANT when
   it starts and, for each process it starts, hands it the instant moved by the time since
   (`sim_now`): every CLI and runner process gets `MANDATE_RH_SIM_CLOCK`, the simulator its
   `clock`, the daily-bars writer its `<at>` (the example now takes an optional fourth argument, so
   the stored closes run through the last session completed at the run clock), and the instrument
   snapshot's `etp_classified_at` the run clock's date. With `--sim-clock` the CLI is built with
   `--features mandate-cli/rh-sim`; without it nothing changes and the system clock runs
   everything. The registered calendar has no holiday, so any weekday's 09:30 to 15:50 New York
   time is inside a regular session outside the close window; the agent's run used
   `2026-10-19T15:00:00Z` (a Monday, 11:00 New York time).
5. **What the override does not do.** It changes no rule: the session, age, skew, collar and
   cross-check rules all run unchanged against the instant. It reaches nothing new: the `rh-sim`
   build still dials only loopback (DEC-937 item 2) and reads no key (DEC-961). The live order is
   still made by the `live` build without `rh-sim`, on the system clock, inside a real session.

## Rationale

The rehearsal must run the code R0 runs. Moving the clock under every rule, rather than relaxing
the session rule, keeps every rule in the path, and the type alias and features keep the override
out of every build that can reach a broker or that the founder runs. A clock that moves from the
instant, rather than a frozen one, keeps every age, timeout and deadline real.

## Alternatives considered

- **Relax the session check in the rehearsal build.** Rejected: it removes a rule from the path the
  rehearsal exists to exercise, and every other rule would still read Saturday.
- **A frozen clock at the instant.** Rejected: the grant wait, the watch and every quote age would
  never move, so timeouts could never fire and the rehearsal would not be the live run's shape.
- **Override only the runner.** Rejected: the owner's grant and gesture codes would be judged
  against the runner's Monday and refused stale (item 2).
- **One offset shared through the variable.** Rejected: the founder named the variable an instant;
  the script computes each process's instant on one timeline instead, to within milliseconds.
