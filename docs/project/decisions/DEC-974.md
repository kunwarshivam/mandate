# DEC-974: The cold store and every other journal spec §6.2 object go to Backblaze B2 with compliance-mode Object Lock, not to R2

| | |
|---|---|
| **Status** | Proposed (spending is the founder's, DEC-79) |
| **Date** | 2026-10-17 (UTC) |
| **Decided by** | Proposed by the agent; the founder decides |
| **Story or claim** | E21-40, claim [#1434](https://github.com/kunwarshivam/mandate/issues/1434); the plan's H3b and L-2 |

## Decision (proposed)

1. Because [DEC-973](DEC-973.md) item 5 finds Cloudflare R2's locks weaker than §6.2, the objects
   §6.2 lists (cold segments and manifests, artifacts, configuration objects, timestamp tokens,
   verifier releases) go to **Backblaze B2**, in a bucket with Object Lock enabled at creation,
   versioning on, and a default rule in compliance mode of at least six years, written through
   B2's S3-compatible endpoint by a writer key that holds neither `bypassGovernance` nor the
   capability to write the bucket's lock configuration. This is the plan's fallback H3b, about $0
   to $1 a month at cell #1's scale.
2. R2 stays cell #1's endpoint for the journal Postgres's WAL archive and base backups (DEC-973
   item 6, H3 as approved).
3. The second-region copy §6.2 requires before live capital (L-2) is a second B2 bucket in another
   region under the same rules.

## Until the founder decides

The conservative option holds: nothing §6.2 lists is written to any hosted store. The lock check
refuses R2 for those objects, so the cold exporter and the artifact writer cannot start against it;
on the local and CI cells they run against the S3 test store, whose compliance mode the check
accepts. No B2 account is opened and nothing is spent.

## Rationale

B2 documents standard S3 Object Lock in compliance mode, whose settings "cannot be removed by any
user, but their retention dates can be extended" (Backblaze's Object Lock page), which is what §6.2
names. The same check and conformance suite run against it unchanged (DEC-973 item 7).

## Alternatives considered

- **AWS S3 with Object Lock in compliance mode.** Meets §6.2; costs egress, and is a second large
  cloud account for one bucket.
- **Wait for R2 to add per-object Object Lock.** Leaves the cold store with no write-once store
  before live capital; revisit if R2 ships it (the R2 run would then accept it).
- **Accept R2's bucket lock rules.** Loosens §6.2; refused in DEC-973.
