# DEC-2280: The news reader polls the tickers of the workspace's registered instrument snapshots, and keeps no raw response

| | |
|---|---|
| **Status** | Accepted (agent, a reversible engineering decision under DEC-79 and DEC-176: it resolves gaps in DEC-2278 by the readings that add no risk. The reader polls only instruments the owner registered, and keeps less, not more, of a licensed vendor's bytes) |
| **Date** | 2026-10-26 (UTC) |
| **Decided by** | an agent, under DEC-79 (`claude-code`, lane NE) |
| **Story or claim** | E2-10; amends DEC-2278 items 2 and 3; journal spec v0.103 §9.37 |

## Context

Building the news reader of DEC-2278 found four gaps.

1. **No stream names a ticker.** DEC-2278 item 2 has the reader read "the symbols of the agent's
   active theses and held instruments" from the agent and account streams. Those streams name an
   instrument only by its asset id (journal spec §9.4). The vendor is asked by ticker. The runtime
   gets tickers from its data plane's instrument facts, which no stream journals.
2. **The parser drops the vendor's tickers.** `NewsItemStored.symbols` is "the vendor's tickers for
   the item" (§9.37). `mandate-sources`' news parser reads them only to resolve tags, and its
   `Draft` keeps none.
3. **The item id's form.** `mandate-sources` ids an item `<source>/<vendor id>@<vendor version>`.
   That form breaks §9.37's grammar, which allows neither `/` nor `@`.
4. **No raw-bytes store.** §9.37 step 1 and DEC-2278 item 3 have the reader store the raw response
   in the data plane's store. No persistent store exists. Only `mandate-sources`' in-memory
   `ItemStore` does. For a licensed vendor, the raw response holds licensed text whose retention
   is open with counsel (data-plane spec §4.5, DEC-433 item 20).

## Decision

1. **Tickers from the registered instrument snapshots.** The reader also reads the workspace's
   control stream, and only reads it. An asset id's ticker is the `symbol` in the artifact of the
   latest `ConfigSnapshotRegistered` of kind `instrument_snapshot` on the control stream whose
   artifact names that `instrument_id` (DEC-523). The event carries only the kind and the
   artifact's hash, so the reader also reads those artifacts from the artifact store. This is the
   same lookup the gate's inputs make (`mandate-gate-inputs`).
   - **What it reads, and no more.** Of the control stream, the reader's code reads only
     `ConfigSnapshotRegistered` rows of kind `instrument_snapshot`, and of the artifact store only
     their artifacts. Its Postgres role can read the whole control stream, which holds no
     credential, but no mandate text, membership, or approval reaches the reader's output or its
     one egress host. That is a wider read than DEC-2278 item 1 gave the reader. It is disclosed
     here, and narrowing the role to those rows is a later hardening (backlog).
   - **The symbol is parsed.** A symbol that does not parse as a ticker, or a snapshot artifact
     that is missing, corrupt, or malformed, counts as no snapshot.
   - **A renamed instrument.** A later registration with a new `symbol` wins, as it does for the
     gate. The next poll asks about the new ticker, and items already stored keep the tickers the
     vendor gave them. The reader does no point-in-time ticker resolution (data-plane spec §4.3); it
     asks the vendor only about the tickers the snapshots name today.
   - The reader polls the tickers of the active theses' instruments and of the held instruments.
   - An instrument with no registered snapshot is not polled. It is counted by asset id in the
     reader's metrics, never silently. Missing news adds no risk: news only ever leads to an
     opinion, and every protective exit runs without it.
   - The workspace registers each instrument the agent trades, through its control services
     (`config register`), so this asks the vendor about nothing the workspace has not already
     named.
   - The tickers polled are the active theses' and held instruments', at most `max_instruments`
     plus the held positions. Each poll is paced by the allowlist (DEC-1130), so a large registered
     set cannot widen a poll beyond those.
2. **The vendor's tickers kept.** `mandate-sources`' parsed news item keeps the vendor's tickers,
   as parsed. `NewsItemStored.symbols` is that set, sorted and unique. The tags it resolves are
   unchanged.
3. **The journal's item id.** `item_id` is `<vendor id>:<vendor version>`, the version written as a
   journal timestamp, for example `12345:2026-10-26T14:00:00.000000000Z`. It fits §9.37's
   grammar. A vendor's update is a new version, and so a new id, as data-plane spec §4.4 says.
   `source` names the source.
4. **No raw response kept, until a store and counsel allow it.** The reader keeps the raw response
   only in memory, while it parses the item. It stores the item's typed record alone, which holds
   no licensed text. §9.37 step 1 becomes this. A durable raw store waits on the data plane's store
   and on DEC-433 item 20. This keeps less than DEC-2278 did, never more.
5. **`knowledge_at`.** It is the later of the parsed item's knowledge time (its receipt, its
   publication, and its update, data-plane spec §5.2) and the stream's last `knowledge_at`, as
   §9.37 says.
6. **Readiness with a reason.** The process lifecycle's probe has no slot for a reason. The reader
   reports not ready on the probe, and writes the reason's code on its standard error: `no_key`,
   `vault_unavailable`, or the refusal's own code, `NewsKeyRefusal::code()` (`not_paper`,
   `news_key_malformed`). That is the code alone, never a value of the key.

## Consequences

- **Journal spec v0.103** amends §9.37 step 1, the `item_id` row, and what the writer owes. The
  record and its rules are unchanged.
- **Data-plane spec** §4.2 and §4.5 gain the news reader's interim of item 4. A news record's
  raw-bytes digest cannot be re-verified until the durable store exists.
- **A correction to v0.97, found in #2688's review:** §9.13's `stream_id` type (which §9.14's anchor
  leaves reuse) and §9.15's `stream_id` row did not name the news stream, so no anchor, export, verification range, or notice
  cause could name it. v0.103 adds `news:{workspace_id}` there, making the stream types eight, as
  v0.46 did for the meter stream. #2688's code and vectors follow.
- **The reader's PR** includes the `mandate-sources` change of item 2, with its tests.
- **Backlog** gains a row for the durable raw store, behind DEC-433 item 20.
- **Adversaries:** registering an instrument the agent neither holds nor has a thesis on widens
  nothing: the reader polls only active theses' and held instruments. A registered snapshot only
  names their tickers. Every query is still read-only news, under the allowlist and its pace.
- **Backlog** also gains a row to narrow the reader's Postgres role to the snapshot rows.
