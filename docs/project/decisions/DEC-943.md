# DEC-943: The run journals its own IEX quote reads as marks, and the binding gate judges a fresh quote at the grant

| | |
|---|---|
| **Status** | Accepted (agent: reversible engineering readings under DEC-79, each one under DEC-176 — no bound moves, and every reading refuses where the code before it refused or sent nothing) |
| **Date** | 2026-10-16 (UTC) |
| **Decided by** | `claude-code` (builder), under DEC-79, DEC-176 and DEC-921 |
| **Story or claim** | E7-26; DEC-940 item 6, gaps 1 and 3; claim [#1375](https://github.com/kunwarshivam/mandate/issues/1375); DEC-156 item 3, DEC-920, DEC-935, DEC-936 |

DEC-940 item 6 named three gaps between an `ask` opening and its grant, each failing closed.
This decision closes gaps 1 and 3. Gap 2, the granted intent's execution policy, is claim #1374's.

1. **No mark reached the runtime.** No production code journaled `MarkUpdated`. The request
   recorded `reference_mark: null`, and re-validation skipped every grant as `drift`.
2. **The binding gate judged the preflight's quote.** `TrustedPaperContext` rechecked the
   preflight quote's age at the gate's clock. A grant answered more than `iex_quote_max_age_s`
   (10 s) after the preflight was refused there.

## Decision

1. **The run journals its own quote reads as marks.**
   - The shell writes `MarkUpdated` on the account stream at the registered version 1:
     `instrument_id` (the pinned asset id), `price`, `source` `quote`, `feed` `iex`, and
     `risk_clock`.
   - The price is the quote's bid, a long's risk mark (trading-domain spec §8.2).
   - The envelope's `event_time` is the quote's own stamp. The `risk_clock` is the session's
     second (mandate spec §5.2: `event_time` is never used for risk timing).
   - The record is written as the executor's, the account stream's one writer. Its id is
     derived from the stream's head, as the executor derives its own.
   - Two writes, both before the runtime reads the mark:
     - **At the cycle's open**, from the preflight's IEX quote. It is written after the
       control stream's tail and before the observation and the output, so a request records
       it as its `reference_mark`.
     - **At each wake of an asked opening's wait**, from that wake's fresh quote (item 2). It
       is written before the control stream's answers reach the runtime, so the re-validation
       that wake may run compares the request's reference with that mark.
   - Only `run_observed_asked_watched` writes marks. That is the one door `mandate-paper`'s
     `run()` uses, for an `auto` cycle too. The older doors (`run`, `run_observed`,
     `run_observed_watched`) write none.
2. **Each wake reads a fresh IEX quote, and the binding gate judges it.**
   - Before each wake that hands the runtime anything, the runner (`granted_opening`) reads
     `Session::fresh_quote`. That is `mandate_shell::paper::fresh_quote`: the preflight's own
     `DataClient::latest_quote`, with the same `iex_quote_max_age_s` bound and DEC-936's 250 ms
     skew tolerance at the read. Then come the shell judge's checks: the reviewed symbol, the
     IEX feed, and a bid not above the ask.
   - The read is handed to the binding gate's `GateQuote`. From then on every binding request
     judges that quote, as the market quote and by its age at the gate's own clock. The gate's
     recheck is unchanged (DEC-935 item 2, DEC-936 item 4): ten seconds, and a stamp after the
     gate's clock refuses.
   - The read's bid is journaled as that wake's mark (item 1).
   - A read that fails, is stale, or is out of tolerance stops the wait before the runtime is
     handed anything (`market_data_untrusted`, "a current, uncrossed IEX quote at the wake"),
     and nothing is sent. The bound is never relaxed for a grant.
   - A wake at or past the ask's deadline reads no quote; DEC-940 item 7's denial is unchanged.
   - A Robinhood session refuses the fresh read until its session is built (O2), as its
     preflight does.
   - Exits and protective orders are never held (`AGENTS.md` rule 13). The fresh read is the
     asked opening's wait alone. A `GateQuote` only ever receives a quote the run just read
     and judged current, so no exit is judged on an older quote than before.
3. **The runtime's fold reads the registered member.** The journal's registered `MarkUpdated`
   version 1 names its instrument `instrument_id`. The runtime's fold read `instrument`, which
   no record the journal accepts carries, so a real mark would have refused the fold. The fold
   now reads `instrument_id` and refuses a record without it (`non_canonical`). The runtime's
   fixtures, its golden journal and the reference-case harness move with it. No production
   journal holds a `MarkUpdated`, because none was ever written.
4. **`Session::cycle` borrows the session.** The wait reads its fresh quote through the same
   session after the cycle is built, so `cycle` takes `&self`. The Alpaca session clones its
   transport, as it already did for the preflight.

## Rationale

The runtime decides drift from its own folded marks (mandate spec §6.4 check 12), so the only
way to hand it the run's quotes is the record the spec names: `MarkUpdated`, journaled before
the step that reads it (`AGENTS.md` rule 5's order). A fresh read per wake keeps the binding
gate's existing ten-second bound meaningful for a grant that arrives minutes later, without
widening it. The wake that releases the opening is the one whose quote was read immediately
before the gate judges it.

Refusing on any failed fresh read, not only the releasing wake's, is the conservative reading:
the wait cannot know in advance which wake the runtime will act on. A refusal sends nothing,
and the approval stays pending for the runtime's own fold.

Every reading here refuses or holds where the code before it refused. Today the
`role:approver` reference is not yet resolved to a user (see Not covered), and gap 2 is still
open, so a grant still cannot open a position in a production build. The end-to-end tests
reach the order through the two test doubles that name those gaps.

## Alternatives considered

- **Widen the binding gate's quote bound to the ask's timeout.** Rejected: it loosens a bound
  (DEC-79 reserves that), and a ten-minute-old quote says nothing about the price the order
  meets.
- **Read the fresh quote only at the wake that releases.** Rejected: the release is the
  runtime's, inside the wake. The runner learns it only after the binding gate has judged, so
  the quote must be handed before every wake.
- **Have the executor write `MarkUpdated` from `Input::Market`.** Rejected for this lane: it
  changes the executor's step and its journaled batches, a larger safety-critical change. The
  shell already writes the account stream's `StreamOpened` as the executor's.
- **Accept both `instrument` and `instrument_id` in the runtime's fold.** Rejected: two
  spellings of one member is the drift the registered schema exists to prevent. The journal
  accepts only `instrument_id`.

## Not covered

- **The approver set is unresolved.** `runtime_view` hands the runtime the mandate's approver
  references as written (`role:approver`), and admission check 3 matches the responder's user
  id against that set. So no grant is admitted in a production build. This fails closed, and
  belongs to the approvals lane. The end-to-end tests resolve the role to the founder in a
  mandate-stage double, as the shell's grant probes already do.
- **Gap 2** (the granted intent's execution policy) is claim #1374's. The tests here keep a
  policy-supplying sink double.
- **The advisory gate's dry run** (re-validation check 11) still reads the preflight's
  snapshot at the preflight's clock. It is advisory; the binding gate decides.
