# DEC-643: The refusal codes of the authorization step

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-08 (UTC) |
| **Decided by** | The lane L1 builder agent, under DEC-79 and DEC-176: it names refusals the spec already makes and adds none that grants |
| **Story or claim** | E9-2 (claim #757); [identity spec](../../specs/identity.md) v0.2 §4.5 |

## Decision

The authorization step and the role-change check return exactly these refusals, each with a
stable code. Each code's HTTP status is stated once, in workspace API §3.5's table: under its own
code, except `no_membership`, sent as `not_found` (API-9), and `forbidden` and
`inactive_permission`, sent as `forbidden`.

The refusals:

- `no_membership`: no membership reaching the scope, a non-member principal outside its column's
  scope, or a principal kind with no column;
- `forbidden`: the scope is reached, but no effective role or column grants the row;
- `inactive_permission`: the row is inactive (DEC-641 item 4);
- `reduction_only`: a reduction-only session asks for a row other than pause or a kill switch's
  engage (§6.4);
- `membership_unavailable`: the membership lookup cannot answer on a row that is not risk-reducing, so nothing is granted; never on a risk-reducing row (DEC-642 item 10);
- `own_roles`: a change grants or removes a role of its own author (ID-13);
- `owner_role_reserved`: someone other than an org owner grants or removes the org owner role;
- `last_owner`, `last_admin`: the change leaves no `active` org owner or workspace admin (§5.2).

ID-13 is read tightly: a principal neither grants nor removes its own roles. It leaves through the
leave row (DEC-641 item 5), which the last-owner and last-admin rules still check. Deactivating
another member who holds the org owner role counts as removing that role.

## Rationale

The API and the web app need one code per refusal to render it, and the tests need to assert
which refusal fired, so a refusal for the wrong reason is caught.

## Alternatives considered

- **A single `forbidden`.** Hides why, and a test could not tell a last-admin refusal from a missing role.
