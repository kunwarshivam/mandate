## Decision

Journal spec v0.21 adds §9.9, with rules 69 to 80, and the vectors' generated `workspace_api`
section. E10-15 is split into three spec changes so that each can be reviewed in one sitting:
this one (owner and mandate records), DEC-671 (the `client` actor, `ConnectionRevoked`'s reason,
and the client records, v0.22), and DEC-672 (the `hold_openings` and `lift_hold` commands and their
agent-stream copies, v0.23). The client actor comes first because the identity and audit lanes'
records reference it.

1. **`MandateDraftSaved`** (control stream, schema version 1) records one explicit save of a
   draft (DEC-436 item 11). Its members are `draft_id`, the stored `draft`, its `origin`
   (`description`, `goal_answers`, `template`, `version`, `edit`, `compile`), `base_draft`, the
   save it replaces, and `base_version`, the version a draft of origin `version` starts from. The
   draft is an artifact, because it holds free text and provenance and may fail validation
   (rule 69 ties the two nullable members to the origin).
2. **The compiler's `ModelInvocationRecorded` is on the control stream.** This answers inference
   spec §13 question 1 (DEC-432 item 19): the compiler acts for a user and has no agent, and the
   control stream's single writer, the workspace services, is what calls the gateway for it.
   A new stream type was the alternative, but it would add a stream owner for a record that
   changes no state. The record is closed there with DEC-432 item 11's members, typed from
   inference spec §3.1 to §3.5. The inference spec had left this question to E15-8; this item
   settles it there, and E15-8 keeps the meter stream. Until `mandate-journal` registers the
   control-stream record, the compiler still makes no gateway call (inference §3.6, INF-10). The
   agent-stream record stays open for E15-8, which should adopt
   the same members and add the agent harness's.
3. **A refused or cached call sent and spent nothing, and an `ok` was in time** (rules 72 to 75).
   These turn inference spec §3.3 to §3.5 into checks on the record: the six refusals have no
   response, provider request, attempt, token, or cost; a cache hit only on `ok`, with no attempt,
   no provider request, and no cost; any other call made at least one attempt; and an `ok`
   completed no later than its deadline (INF-3). Rule 71 binds the model the call names to
   `config_refs.model_version`, as rule 38 does for a thesis.
4. **`MandateConfirmed` version 2** adds `agent_id` and `base_version` after version 1's members.
   Version 1 is never edited (§8) and stays registered, so the CLI's confirm (E10-16) keeps
   working. Rule 77: the two are `null` together (a new mandate), and a base is never the version
   confirmed. So every confirmation for a deployed agent records the version it replaced, and
   API-19's "every version's recorded base is its real predecessor" can be checked from the journal.
5. **`OwnerRequestSubmitted`** (schema version 1): `agent_id`, `instrument_id` (an `asset_id`),
   `side`, an optional positive `quantity`, `requested_by`, and `client_id`. It has no limit price
   or purpose: the order builder sizes, prices, and classifies the request as any proposal
   (rule 4), and the gate assigns the purpose (mandate spec §6.1). The runtime's `DecisionMade` for
   it names the request as `causation_id` (§2). The link crosses streams, so `append` does not
   check it.
6. **The actor rules.** v0.21 is the first version whose rules read `actor.kind`. Only a `user`
   confirms version 2 (rule 78). Only a `system` writes the compiler's record (rule 76). A draft
   is a `user`'s, or a `client`'s created from a base version (rule 70). `requested_by` and
   `client_id` follow the actor, never the body (rule 79; workspace API API-6, DEC-185 item 2).
   The `client` kind is not admitted until DEC-671 adds it to §3, so until then these rules admit
   users only. Their client branches are written now so that DEC-671 changes no rule text.

### Invariants

- **INV-1. Nothing here changes the envelope** (`AGENTS.md` rule 11). A draft, a compile, and a
  request are not versions. A version is still created by `MandateVersionCreated` and confirmed by
  a user's `MandateConfirmed` (rules 70, 78).
- **INV-2. Model text is never a member** (rule 4, API-18). The prompt and the response are
  artifacts. The record carries only identities, counts, and outcomes.
- **INV-3. A confirmation for an agent names its real base** (API-19; rule 77).
- **INV-4. Who asked is the authenticated principal** (rule 79).
- **INV-5. Records written before v0.21 are unchanged.** No member or rule of an existing record
  version changes, and `MandateConfirmed` version 1 is accepted exactly as before.

Every invariant has vectors: an invalid draft for each rule, and valid drafts for each reading a
rule might be misread to refuse. The generator checks them with three oracles of its own:

- the drafts' lineage: the compiled save follows the call that read its base;
- what a call that made no attempt can show, computed from inference §3.2 to §3.5 rather than from
  the rules' outcome lists;
- the human behind each confirmation and owner request.

All 87 validator mutants and 6 vector mutants are caught. The actor rules (70, 76, 78, 79) each
have an invalid draft for every actor kind they refuse, including `agent`, `broker`, and
`platform_operator`, so a rule misread as "not the system" or "not a user" is caught.

### Lifecycle walk

- **Draft.** A creating save (`base_draft` null), then edits and compiled saves, each naming the
  save it replaces. A draft never ends in the journal; an abandoned one is simply not saved again.
  Turning a draft into a version is `MandateVersionCreated`, which leaves the draft open for further
  edits. Restart: the latest save per `draft_id` is the one no other save names as its base. Two
  saves naming the same base are a fork. The API's `If-Match` refuses the second (API-19), and the
  journal records both bases, so a fork that got through is visible.
- **Compile.** A call record, then on `ok` a save of origin `compile` whose `causation_id` is the
  call (rule 69). On any other outcome there is no save, and the description is kept (A2). A crash
  between the two leaves a call with no save: the owner compiles again under a new `call_id`
  (inference §3.4).
- **Confirm.** Version 2 is committed, and the executor's `MandateVersionApplied` applies or
  rejects it as before. A stale base is the API's `stale_base`, refused before anything is
  committed.
- **Request.** Committed, then copied by the runtime to its builder, then `DecisionMade` and what
  follows. A request the builder can size to nothing still needs a runtime record so that command
  status can reach `refused`. That is the runtime's story, flagged for E10-12's tests.

### Adversary

- **A careless user:** a stale draft overwritten. The API refuses it, and the journal records both
  bases.
- **A bad model:** it returns an action or a delegation. The output is an artifact, and the saved
  draft must still pass validation and be confirmed by a user (V-022, V-038).
- **A malicious insider:** confirms through the services account. Rule 78 refuses it.
- **A forged body:** a request claiming `requested_by: client` from a user, or `owner` from a
  client. Rule 79 refuses both.
- **A bad tick:** none of these records reads market data.

## Rationale

DEC-436 item 14 says these records must exist in the journal spec before the operations that write
them ship. Each member comes from the workspace API spec, the inference spec, or DEC-432 item 11,
and no member is inferred where none of them names it. Every rule refuses more than an open schema
would, so DEC-176 lets an agent accept this.

## Alternatives considered

- **One PR for all of E10-15:** over 1,000 hand-written lines, which is too big to review in one
  sitting.
- **Close all of `OwnerCommandIssued` with the hold commands:** the members of pause, kill switch,
  and owner exit belong to M7's agent-commands slice. DEC-672 closes only what the hold needs.
- **`MandateConfirmed`'s agent link in place at version 1:** this edits a closed schema, which §8
  forbids, and it would refuse the CLI's existing records.
- **A stateful `append` check that `base_draft` is the latest save of the draft:** this would make
  the journal the authority for API-19. Deferred: the API's `If-Match` is the authority, and the
  recorded bases make a fork detectable.
- **A `card_digest` member on `OwnerRequestSubmitted`** (DEC-192's chat card): no clause says
  whether the card is stored, so it waits for the chat story rather than being guessed.
