## Context

`mandate-backtest` runs a baseline moving-average crossover through the fill model. That proves the
loop (E4-2), but it is not the owner's mandate: the strategy sizes itself, there is no gate, no
autonomy, and no risk state. FR-4.1 asks for a backtest of a **mandate version**, and the go-live
record (mandate spec §10, `AgentDeployed`) names the backtest that was shown. A backtest that runs
other code than the live agent tests nothing the owner deploys.

The live agent's decision lives in four pure crates: `mandate-spec`'s risk state
(`risk::RiskState`), `mandate-builder` (`propose`, `classify`), `mandate-risk` (`evaluate`,
`trim_proposals`, `agent_flatten`), and the executor's protection prices
(`mandate_executor::equity_bracket_prices`). The shell only wires them; it holds no trading logic
(DEC-138 item 3). A backtest can call the same four, in the same order, with the run's own state
in place of the broker's.

## Decision

1. **The decision path.** At each decision instant `t` the run does mandate spec §6.2's steps with
   the live crates, in this order:
   1. the risk state is stepped (`RiskState::step`) over every input since the last instant, in
      time order: the risk day's start at 00:00 New York, each bar's close as a sane mark (a
      regular-session or continuous bar only, trading spec §8.2), and each fill;
   2. **risk exits first** (§6.2 step 1): when the effective mode is `paused` or `stopped` with a
      position held, the agent-scoped flatten plan (`agent_flatten`, initiator `risk_limit`) sells
      the whole sub-ledger position; otherwise `trim_proposals` proposes any `trim_to_target` sell.
      Either goes to the gate with origin `risk_engine` or `trim_to_target`, and no builder call is
      made at that instant;
   3. otherwise the order builder (`propose`) sizes from the recorded outputs that are fresh at `t`;
   4. the gate's dry run (`evaluate`, pass `before_submission`, so every rule applies in full)
      judges the proposal against the run's account, agent, instrument, market and conduct state;
   5. for a buy, autonomy (`classify` on the builder's action) decides AUTO, ASK, or DENY, and a
      nonconforming policy denies an opening (DEC-536). An exit is built-in AUTO;
   6. an allowed order goes to the fill model as a limit order at the gate's quantity and price
      (its pacing, when it paces), eligible from `t` plus the configured decision latency;
   7. after an opening's fill, the executor's protection (`equity_bracket_prices` from the fill
      price and the mandate's distances) rests as one GTC OCO leg pair, or a stop-limit when the
      mandate has no take-profit, exactly as the executor places it on a position.
2. **An ASK has no one to answer it.** A backtest has no owner at the screen. An ASK resolves as
   an approval that times out does: `skip`, no order (`AGENTS.md` rule 3, journal spec §9.7's
   `on_timeout: skip`). The report counts it as `ask_unanswered`. Assuming an approval would
   report trades the owner never approved.
3. **No look-ahead, enforced by receive times.** The information set at `t` is the bars whose
   close is before `t`, and the recorded outputs and theses whose **receive time** (the instant
   the record was journaled) is at or before `t`. A record whose `as_of` is after its receive time
   cannot exist and refuses the run (`record_before_its_data`). The fill model already refuses a
   fill before an order's eligibility (trading spec §6.4 rule 1), and `t` is the next bar's start,
   so nothing decided at `t` fills in a bar that closed before it. What the rule cannot rule out is
   stated in the report (DEC-1001 item 2's `limitations`): a model may have been trained on what
   happened after `as_of` (DEC-99, R-27), so an LLM agent's backtest tests mechanics, never thesis
   quality.
4. **Recorded inputs only.** The run takes model outputs and theses as typed records. It has no
   model port: there is no trait, callback or client through which it could call a model, so a
   live call is unrepresentable rather than merely untested. An instant with no fresh output holds
   (`no_fresh_outputs`), as live.
5. **Theses and the universe.** For a research-agent version the working universe at `t` is every
   instrument with a recorded admitted thesis that was received at or before `t` and has not
   expired or been invalidated at `t`. Admission verdicts are replayed as journaled, never
   re-judged: the backtest holds none of the sources an admission read. A pinned universe
   (bring-your-own strategy) is the version's own list, and theses play no part.
6. **Inputs are checked, never trusted.** A recorded output not pinned by the version (model id,
   version and content hash) refuses the run (`output_not_pinned`), as the shell refuses it live;
   a thesis or output for another instrument than the run's refuses it
   (`record_other_instrument`), so nothing is silently dropped.
7. **Quotes.** Bars carry no quote. The bid and the ask at a decision are the last close moved by
   the fill model's own `half_spread_bps`, each rounded against the agent onto the tick (the bid
   down, the ask up), so the spread is the one the fills already charge. The risk mark is the bid
   (trading spec §8.2, long only).
8. **Slice 1's scope, refused outside it.** One instrument per run; long only (v1); decisions at
   each period's closing bar (the last regular-session bar of a trade date, or a crypto UTC day's
   last bar), as the E4-2 loop already defines periods. A version whose universe needs more than
   one instrument at once, and a mandate whose protection the run cannot place, refuse with a
   named code rather than run a different strategy. Corporate actions inside the bar range are
   refused (`corporate_action_in_range`) until the accounting fold's corporate-action inputs are
   wired (E4-4 slice 2); a report that silently ignored a split would be wrong by the split.
9. **Purity.** The run is a pure function of its inputs: no clock, no file, no randomness,
   ordered collections only (ES-21). The same inputs give the same report bytes.
10. **The oracle.** The property tests check, with an accumulator of their own: the same inputs give
    byte-identical report bytes; every fill price lies inside its bar's `[low, high]`; no order is
    eligible before the receive time of any output it used; no ASK ever fills; the risk-exit and
    protection rules of `AGENTS.md` rule 13 hold (an exit is never denied by the gate in the run).
    Each oracle is shown to fail on a seeded bug before it is trusted.

## Adversaries

- **A careless owner** backtests a version and reads the report as a forecast. The report holds
  figures and fixed codes only, under the hypothetical legend (DEC-1003), and its `limitations`
  say what it cannot know.
- **A bad model** whose recorded outputs were produced after the fact, with an `as_of` earlier than
  what they saw: receive time, not `as_of`, gates visibility, and a record whose `as_of` is after its
  receive time is refused. Hindsight through training data cannot be ruled out by any record; the
  research-agent report says so (`mechanics_not_thesis_quality`).
- **A malicious insider** edits the recorded outputs, theses, or bars to flatter a run: each is
  digested into the report and the record (DEC-1001), so a changed input is a different report.
- **A bad tick** inside the bars: the fill model fills only inside a bar's own range and the gate
  judges the collar against the last close, exactly as live; the run never fills at a price it did
  not see.

## Rationale

The point of a backtest before going live is that it runs what will run. Calling the live crates
rather than re-implementing their rules means a fix to the gate or the builder reaches the
backtest by construction, and a backtest can never be more permissive than the agent. Every
reading here refuses more than the alternative (an unanswered ask, a record out of order, an
unpinned output, a split in range), so DEC-176 lets an agent take each.

## Alternatives considered

- **Run `mandate_runtime::handle` with simulated ports.** The most faithful in principle, but the
  runtime's ports are the shell's (layer 8), and the backtest sits at layer 7. Its decide step calls
  exactly the four crates above, so calling them directly is the same decision without the journal
  effects. Recorded as debt: when the shell's mapping from a mandate document to the gate's
  mandate moves into a shared crate, the backtest and the shell call one mapping (backlog E4-4).
- **Assume approvals are granted.** Rejected: it reports trades nobody approved.
- **Call the model gateway in a backtest.** Rejected: not reproducible, and it would score a model
  on a period it may have read about (DEC-99).
