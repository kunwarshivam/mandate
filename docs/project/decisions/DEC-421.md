# DEC-421: Protection is sized net of fills the broker reported and the executor has not applied

|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-02 (UTC) |
| **Decided by** | The stream K builder (agent), under DEC-79 and DEC-176: it takes the reading that never covers more than the broker holds, and adds no risk |
| **Story or claim** | E7-4; [#515](https://github.com/kunwarshivam/mandate/issues/515); #468's round-3 review; the coordinator's ruling on #468 (18:42Z) |

## Decision

1. **The rule.** When the executor re-places protection after an exit ends, it sizes from the
   position less every fill the broker has reported on an order and the fold has not yet applied.
   That quantity is `OrderDetail.reported_filled` beyond the order's applied `filled_qty`.
   `bracket` already does this; the sequence's `replace` now does too, and so does #468's
   `re_place` once #468 merges `main`.
2. **Tests first (DEC-77).** The pending test
   `sequence_tests::an_exit_ended_with_a_fill_not_yet_applied_is_re_protected_for_what_the_broker_holds`
   pins #515's first script on `main`. It fails on the size it asserts (an OCO for 10 against 7
   held), not at a stub, so it is a `BEHAVIOUR_ONLY_TESTS` row until the fix deletes it.
3. **The oracle.** The rule-13 property's Σ check reads the fold's position today. It gets an arm
   that reads the broker's reported fills instead, so that it does not trust the fold here. The
   arm extends the Σ check #496 brings to `main`, so it is added once #496 has merged, in this
   tests PR if it is still open, otherwise in the fix PR before the fix.
4. **#468's route.** The top-up (`re_cover`) reaches the same sizing. Its script, #515's second,
   is pinned in #468 when it merges `main` with this fix.
5. **Lifecycle.** The correction lasts only until the fill is applied: the reconciliation that the
   report asks for applies it, and the unapplied part then reads zero. A restart folds
   `reported_filled` from the journaled `OrderStateChanged`, so it sizes the same way.

## Rationale

Rule 12 and §5.4: the sum of protective sells never exceeds the position. Waiting for the
reconciliation before re-placing would leave the remaining shares unprotected for an unbounded
time. Sizing on the broker's own report covers exactly what it holds, at once.

## Alternatives considered

- **Hold the re-placement until the reconciliation applies the fill.** Rejected: it opens a gap
  with no bound of its own.
- **Apply the reported fill in the fold at once.** Rejected: an order report carries no fill price
  or fees (`BrokerOrder`), so the fold would book a fill it cannot value. The fill update or the
  reconciliation's activities carry them.
