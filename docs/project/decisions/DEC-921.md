# DEC-921: Live-arm rows land as one PR carrying both tests and implementation, with every merge gate kept

| | |
|---|---|
| **Status** | Accepted (founder) |
| **Date** | 2026-10-16 (UTC) |
| **Decided by** | The founder (kunwarshivam), DEC-79, answering the coordinator's decision batch of 2026-10-16 |
| **Story or claim** | R0 live-arm rows of the [first live trade brief](../tasks/first-live-trade.md); DEC-77 |

## Decision

1. For the rows on the path to the first live order (R0), a builder may land the tests and the
   implementation in one PR, instead of the DEC-77 order (a tests PR with pending pins, then an
   implementation PR that only deletes them).
2. Every other gate is kept: the tests are written first in the PR's own history and shown to
   fail on the stub or on a seeded bug before the implementation commit; the PR gets an
   independent review by an agent on a different model; every mutant on the diff of a
   safety-critical crate is killed; CI `fast` and `full` are green on the merged head.
3. Rows off the R0 path keep DEC-77 unchanged. This decision ends when R0's evidence PR merges.

## Rationale

The founder has about a week. The tests-then-implementation order doubles the review and CI
cycles per row. The safety comes from the tests existing, failing first, and being reviewed;
keeping all of that and dropping the second PR saves one cycle per row.

## Alternatives considered

- Keep DEC-77: about twice the cycles; code-complete moves well past 10/29.
- Drop review or mutants for speed: refused; that weakens a safety rule.
