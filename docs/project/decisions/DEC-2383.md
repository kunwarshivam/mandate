## Context

The deployed runtime, `mandate-daemon`, decides only on a risk-clock tick. The order builder sizes
only from the model outputs it has folded, which the core journals only when it is handed
`Input::ModelOutput`. Nothing in the daemon handed one, so no deployed agent could propose,
whatever its ports (lane DR's product-flow map, X2). The model host, `mandate-modelhost`, has
existed since E15-13, but only the founder's paper run, `mandate-paper`, composed it.

## Invariants first

1. A model output reaches the core only from the pinned model's host, and every refusal is no
   output (DEC-503 item 3, MI-10).
2. An output's inputs are journaled before it: the closes as an artifact, then
   `ObservationRecorded`, then `ModelOutputRecorded`, before the tick that decides (DEC-503 items 5
   and 6).
3. Each output is journaled once, whatever the tick rate, and across restarts.
4. Replay reads the records and never runs the host (INF-10). Exits, protective orders, kill
   switches and reconciliation never ask it (INF-13).
5. `mandate-daemon` keeps its layer and its forbidden list: it never runs a model itself.

## Decision

1. **A port, not the host.** `mandate-daemon::models::Models` answers every pinned quant model's
   evaluation at a tick: the host's `ModelOutput`, the canonical bytes of the closes it read, and
   their source. An empty answer is a refusal. `Wiring::models` is `None` unless a composer wires
   it.
2. **Asked once per tick, before the tick.** On a pass whose clock stream has a tick this process
   has not evaluated at, the process asks the port, keeps the evaluations the agent stream holds
   no `ModelOutputRecorded` for (`fresh`: same model id, version, instrument and `as_of`), and,
   for each one, stores its closes through the `ArtifactSink`. It then hands `Input::Observation`
   (the source, the instrument, the output's `as_of`, the closes' digest) and `Input::ModelOutput`,
   and only then `Input::Tick`.
3. **Once per output.** With a tick every second (the scheduler, #2439), a daily output is
   recorded once. A restart asks again and records nothing new. An `ObservationRecorded` left
   without its output, by a pass that stopped between the two, does not count as the output.
4. **Fail closed, for openings only; the tick always runs.** An agent stream that cannot be read,
   or whose outputs do not read, gives no new output for that pass (MI-10). Closes the sink cannot
   store are no output, and so is an evaluation either of whose two inputs the core would refuse
   (an empty source, or an `as_of`, `expires_at` or `horizon_s` a payload cannot write): the
   process hands each input to a copy of the core's state first, and hands neither unless both are
   taken, so a bad answer never stops the process. Either way the tick is still handed, so its
   expiries, exits and protective orders never wait on a model (rule 13). Only a hand that did not
   commit, because its append is in doubt (DEC-131 item 6) or the process stopped, skips the tick
   for that pass. The in-doubt input is handed again first, then the inputs queued after it in that
   pass, then the tick; nothing new is evaluated while inputs are still queued, so an observation
   in doubt is still followed by its output; a restart in between drops the queue, and the next
   tick records the output (item 3). The same output twice in one answer is recorded once. The
   control stream, and so the kill switch, is handed before the clock pass, so nothing here holds
   it.
5. **Only the clock pass asks the port, and it must answer at once.** Nothing else in the
   process calls it. The call is synchronous on the clock pass, ahead of the tick, so the
   composer (item 7) must answer from data already held (stored daily closes), with no network
   call and no unbounded work; a port that blocks would delay the tick. S3's review checks this.
6. **The configuration references.** `ModelOutputRecorded` version 2 needs `model_registry`
   beside `mandate_version` (DEC-484). The production `Refs`, which lane D1 is wiring under
   DEC-2378, supplies them; the composer (item 7) supplies nothing to the journal.
7. **The composer (S3).** The port is implemented over `mandate_modelhost::evaluate`, as
   `mandate-paper` does it (`lib.rs:664-690`), with the confirmed mandate's pin, the
   `model_registry` snapshot, `ExchangeCalendar::us_equities()` and the daily closes from lane SC's
   data process, in a thin layer-9 crate the daemon binary links. That is an `xtask/layers.toml`
   and `CODEOWNERS` change, and DEC-503 item 2 puts it to the founder.
