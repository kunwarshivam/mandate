## Context

DEC-928 item 3 made `RobinhoodReconciler` read the agentic account and then refuse every
Robinhood run at `Stage::Reconcile`, because `BrokerAccount` takes a status, flags, equity, last
equity, maintenance margin and multiplier from the broker and Robinhood publishes none of them
(connections spec U-R6, U-R7). Its note left the mapping to the founder; DEC-929 says such a
question is decided by the option that adds the least risk and recorded for the founder to
revert. The runner's live door, meanwhile, called the lapse with an empty read and zero counts
(DEC-919's "trap").

## Decision

1. **The account mapping** (`mandate_shell::robinhood::robinhood_account`). From the agentic
   account's `AccountSnapshot`:
   - `cash` is `get_portfolio`'s, as reported; `buying_power` and `non_marginable_buying_power`
     are the lower of `get_portfolio`'s cash and buying power (DEC-620 item 2), so no buying
     power figure the gate or the executor reads ever exceeds cash;
   - `status` is `ACTIVE` and `trading_blocked`, `account_blocked` and
     `trade_suspended_by_user` are `false`: a snapshot exists only when each of its reads found
     the recorded account listed by `get_accounts` with `agentic_allowed` (DEC-875), and any
     other answer refuses the read (DEC-928's recommendation);
   - every figure Robinhood does not publish takes the value that adds no buying power and
     lifts no limit: `crypto_status` `INACTIVE` (no crypto opening), `multiplier` 1 (DEC-529
     item 11's attestation), `equity` the cash alone (a long-only account's equity is never
     less), `last_equity` zero (below every equity threshold: the gate reads §9.2's `legacy_pdt`
     budget only for a margin account, so under the declared cash account it decides nothing
     today, and were the type ever margin the budget would always apply),
     `maintenance_margin` the whole equity (no maintenance excess), `accrued_fees` zero;
   - the account rules are a cash account under `legacy_pdt` (trading spec §7.2's Robinhood
     row; `robinhood_account_rules`).

   `RobinhoodReconciler` now hands that snapshot, with the broker's positions and working
   orders, to the executor's own reconciliation, as Alpaca's is. Robinhood publishes no account
   activity, so the snapshot carries no fill and leaves the executor's cursor where it was; the
   live run starts only on a flat, unspent account (DEC-529 item 3), so no fill is outstanding.
   `STATUS_UNPUBLISHED` is removed; a refused or unreadable read still answers
   `ACCOUNT_UNREAD`.
2. **The preflight facts of a Robinhood connection** (`mandate_shell::paper::robinhood_facts`).
   The account, positions and working orders are `mandate-robinhood`'s preflight (read through
   `RobinhoodBridge::preflight_facts` on the bridge's runtime); the asset record, the latest IEX
   quote and the minute bars are Alpaca's market reads (`market_facts`, the reads `preflight`
   already made, split out unchanged). The gate's quote stays the IEX quote: it is the one whose
   age the run can judge (DEC-902 item 7: Robinhood's quote has no time field). The Robinhood
   quote must name the same instrument, or the facts refuse. The runner's
   `robinhood_cross_check` then compares Robinhood's ask (the broker's) with the IEX ask (the
   independent one) through `cross_check_the_opening`, inside the registered collar's own `x`
   for the instrument's 20-day median dollar volume (DEC-529 item 12, DEC-912 item 2); quotes of
   two instruments refuse `quote_absent`.
3. **The live door's real inputs** (`mandate_paper::lapse_read`). `the_live_door` takes the
   agentic account's snapshot and calls `lapse_read`, which for a live connection counts `Held`
   from that snapshot (every position record, a zero quantity included, and every working order;
   DEC-470 item 1) and reads the rows of the account stream `account_stream` names from the run's
   own journal, ungated by `--place-one-order` (DEC-918 item 2); a journalless run reads none.
   A Postgres-backed test appends a `FillApplied` to the account stream and sees the record
   spent. A live connection with no snapshot refuses `lapse_evidence_not_supplied` through
   DEC-919's `unsupplied`, before any read; one whose account stream cannot be read refuses at
   `Stage::Reconcile`. A paper connection makes no check and reads nothing (LT-14). The empty-read
   literal is gone. `run()` hands no snapshot until the runner's ports connect the Robinhood
   connector (DEC-928 item 5, another lane), so a live connection refuses at the door until then.
4. **Unchanged:** the Alpaca paper run (its preflight makes the same reads in the same order;
   the door makes no check on a paper connection), `control.rs`'s live refusal, and the runner's
   `Ports` and `connect()`.

## For the founder

Item 1 answers the question DEC-928 left for you, by the reading that adds the least risk. It
journals `AccountSnapshotRecorded` figures Robinhood did not state (`equity` as the cash, zero
`last_equity`), each the value that can only tighten a limit; replace it with a later decision if
the founder's run shows real fields (DEC-902).

## Rationale

Each unpublished figure is set where an error can only refuse more: understated equity tightens
every fraction-of-equity limit, zero prior-close equity keeps the day-trade budget on, no
maintenance excess and no crypto status open nothing, and 1× with the lower of cash and buying
power spends no margin. The cash account type, and so the settled-cash rule that binds in place
of the day-trade budget, rests on the founder's attestation (DEC-529 item 11). Keeping the IEX quote as the gate's, with Robinhood's checked against it
before anything runs, keeps the freshness check the opening already requires. Counting `Held`
from the broker's own snapshot type, and reading the rows from the journal, gives the lapse
evidence no literal can stand in for.

## Alternatives considered

- **Keep refusing (DEC-928 item 3):** the live run could never pass startup reconciliation.
- **`equity` and `last_equity` zero:** zero equity refuses every opening, so the live order could
  never be placed; the cash is the least equity a long-only account can have.
- **Robinhood's quote as the gate's quote:** it carries no time, so the opening's age check could
  not be made; DEC-529 item 12's agreement is kept by the cross-check instead.
- **A `Ports` method for the account stream and the snapshot:** the runner's ports belong to the
  lane that connects the Robinhood connector (DEC-928 item 5); `lapse_read` reads the journal from
  the run's own DSN and takes the snapshot as an argument, so that lane only hands it in.
