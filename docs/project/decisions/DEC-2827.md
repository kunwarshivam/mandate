## Context

The deployed runtime's model composer (`mandate-runtime-models`, DEC-2383 item 7) pins each
`quant.` model of the confirmed mandate on the mandate's `universe.pinned_instruments`, once at
start. A research mandate pins none (`universe.pinned` false): its instruments come at runtime, from
the research agent's admitted theses (DEC-97, mandate spec §8.5). So the composer pinned nothing for
the cell's research agent. Its admitted SPY was never evaluated, no quant output reached the core,
and the agent never decided. A faketime replay of the cell showed this (lane GW). The executor side
was sound: it reconciled clean and marked SPY throughout.

DEC-2819 already has the executor read a research agent's working universe from the agent stream's
thesis records through `mandate_research::replay_theses`. It opens only on the one instrument a
surviving thesis holds, and maps a held position's exits to any instrument a record ever admitted.
It resolves each instrument through its own registered snapshot (`admitted_configuration`).

## Decision

1. **The port reads the streams.** `Models::evaluate` takes the tick and the streams the process
   read for it: the workspace's control rows, `None` when they do not read, and the deployment's
   agent rows. The process already reads the agent rows for `fresh`. A pinned mandate's composer
   reads neither, so its answers are unchanged.
2. **The working universe, read as the executor reads it.** For an unpinned mandate, the composer
   reads the working universe at each tick from the agent stream's thesis records:
   - **Instruments evaluated.** Each `quant.` model is evaluated on every instrument a
     `ThesisProposed` or `ThesisRevised` admitted, in instrument order. The admitting model is the
     mandate's one model that admits instruments (V-036).
   - **Symbol.** Each instrument takes its symbol, which names its daily dataset, from the latest
     snapshot registered on the control stream that names it, as DEC-523 and DEC-2819 item 3 read
     it. An instrument with no such snapshot, or whose latest one names no symbol, is not
     evaluated. A snapshot registration whose object does not read, or names no instrument, gives
     no output at all, as the executor then resolves no instrument; it is never passed over for an
     earlier one.
   - **No second gate.** The snapshot's other DEC-523 members stay the executor's to check before
     any opening. The composer may not reach `mandate-gate-inputs`, which is built on the executor
     (`xtask/layers.toml`, DEC-525), and an output can only shrink a buy (MI-10).
3. **A `Long` only where the executor would open.** A `Long` output is kept only on the
   instrument `replay_theses` at the tick finds the one surviving thesis holding. None is kept when:
   - two or more theses survive, or none does;
   - a thesis record does not replay;
   - any control row does not read as the executor reads one (a payload, of the paper or the live
     environment).

   These are the cases in which the executor holds the opening.
4. **An exit wherever a position may be held.** An exit output (`quant.ma_crossover` 1.1.0's
   conviction −1, DEC-2390) is kept on every instrument a record admitted, whatever any other
   record says, as the executor maps exits. A thesis record that does not read takes no instrument
   from an exit (`AGENTS.md` rule 13). Control rows that do not read at all give no output,
   because no instrument can be resolved to its symbol.
5. **Pinned mandates are unchanged.** A pinned mandate is never read as a working universe, and the
   working reading refuses one. The wiring takes the working reading for an unpinned mandate and the
   pinned one otherwise.

## Rationale

The composer and the executor must agree on the universe. A `Long` on an instrument the executor
would hold is noise in the record. Missing a `Long` on the one it would open leaves the agent idle,
which is the defect here. Reading the same records with the same replay and the same resolution
makes them agree by construction. A property test checks the outcome against an oracle that replays
the records its own way.

## Alternatives considered

- **Pin at start from the theses then admitted.** Rejected: theses are admitted and end while the
  process runs, so the pins would go stale.
- **Evaluate `Long`s on every admitted instrument and leave the filtering to the core and the
  executor.** Rejected: the record would carry outputs on instruments the agent may not open in,
  and the composer would read the universe differently from the executor.
