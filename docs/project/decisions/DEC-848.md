## Decision

1. **The waiver.** X1's step 3b may add about 470 lines to `xtask/src/main.rs`, above the 400-line
   limit for an implementation PR. The step reads commands fail closed wherever a word may
   execute.
2. **Readability comes first.** The code is not squeezed to fit.
3. **No further growth.** Any later change to 3b that would add lines splits instead, after a tests
   correction that splits its test.
4. **What 3b may change in tests.** The pins for the five branches the planted bugs left untested
   land first, in X1 tests correction 7. In test files, 3b changes only its `#[ignore = "pending
   E7-26"]` lines and its behaviour-only rows ([DEC-845](DEC-845.md)).

## Rationale

- A split would need a tests correction first, because 3b's pending test,
  `commands_are_read_fail_closed_where_a_word_may_execute`, is one function.
- `xtask` is not a safety-critical crate.
- The parts are tightly coupled: the lexer, the pipeline judging, the known non-executing
  commands and the text lines (here-doc bodies, single-quoted strings that span lines) only make
  sense together.

## Alternatives considered

- **Split 3b into 3b-1 and 3b-2.** 3b-1 would hold the lexer, the pipeline, the known commands and
  rule 3, about 360 lines. 3b-2 would hold the text lines, about 110 lines. This costs another tests
  correction and splits code that is reviewed best as one piece.
- **Compress the code to 400 lines.** Rejected, because readability comes first.
