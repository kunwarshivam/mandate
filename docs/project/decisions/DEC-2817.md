# DEC-2817: An unattributed fill in an instrument with no instrument snapshot is booked

## Context

DEC-2812 booked an unattributed fill as `FillApplied` version 2, but only in an instrument the
platform holds a snapshot of. A fill needs the four `config_refs` §9 names for `FillApplied` (fee,
calendars, instrument snapshot), and the executor's instrument port answers them only for an
instrument a deployment holds. An owner trading another symbol by hand, the likeliest external fill,
had none. The journal refused the batch, DEC-2805's hold stood in, and the activity cursor never
passed the fill, so every later reconciliation was refused too and the hold never ended.

## Decision

1. **Rule 300** (journal spec §9.5, v0.96). `FillApplied` version 2 requires the fee configuration
   and both calendars of every fill, and the instrument snapshot only of a fill that names an order
   (`client_order_id` non-null): refused `missing_config_ref` at `config_refs.instrument_snapshot`
   otherwise. A fill of an order of ours is in an instrument its order was gated on, so it always
   has one. An unattributed fill may name one or not. Version 1 and `LateFillApplied` still require
   all four.
2. **The account's fill configuration.** The executor's instrument port gains `account_fill_refs`:
   the fee configuration and calendar, which do not depend on the instrument. The deployed port
   answers the one every followed deployment of the account names alike. It answers none when no
   deployment reads or when two differ, since the executor cannot then say which is the account's.
   A stopped agent's last deployment counts as one, so after a fee configuration changes, a stale
   deployment that still names the old one makes the account's none until it is no longer followed.
   That fails closed: the fill is refused, and DEC-2805's hold stands in.
   The paper contexts answer their registered fee configuration and calendar.
3. **The executor** journals an unattributed fill in an instrument with no snapshot under the
   account's fill configuration and no instrument snapshot. Everything else is DEC-2812's: the batch
   is `ExternalActivityIngested`, the fill, every agent's `exits_only` under
   `reconciliation:external_activity`, and the owner's alert; the fill moves the account's position
   and cash and no agent's; the activity cursor passes it; the owner's acknowledgment of
   `external_activity` lifts the hold. With no account fill configuration either, the journal
   refuses the fill as before and DEC-2805's hold stands in.

## Rationale

- The fee configuration and calendars that §9 binds a fill to are the account's, not the
  instrument's. The instrument snapshot binds what an order was gated on, which an unattributed fill
  never was.
- Refusing the record did not stop the trade, which had happened at the broker. It only left the
  executor's books wrong and every agent's openings held until the process was rebuilt.

## Alternatives considered

- **Register every broker asset's snapshot.** Rejected for now: it needs a snapshot source for
  the whole broker universe and its review, for records no agent trades.
- **A placeholder instrument snapshot.** Rejected: it would name configuration the fill was not
  accounted under.
- **Pick the first deployment's configuration when deployments differ.** Rejected: which one is the
  account's is then a guess, and a refusal is the reading that adds no risk (DEC-2805's hold).
