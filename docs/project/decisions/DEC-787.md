# DEC-787: The inputs of a requested verification run

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-09 (UTC) |
| **Decided by** | An agent (Claude Code, lane L5's spec author) under DEC-79 and DEC-176: each item refuses or fails more than §4.8.1 said, closes a gap by the reading that cannot produce a false pass, and adds no risk |
| **Story or claim** | E12-3 ([#748](https://github.com/kunwarshivam/mandate/issues/748)); workspace API spec §4.8.1; journal spec v0.36 §9.14, §11 |

## Context

Workspace API §4.8.1 said the run reads its range "in one snapshot", but not what else it reads in
that snapshot, where anchors and manifests may come from, whether the trusted-start record is
itself checked, how far the trusted-start manifest is checked, or what two in-range manifests that
overlap or leave a gap mean. Journal spec §11 gives `held_mismatch` and
`connection_lifecycle_mismatch` an anchor folded from the stored chain, without saying when.

## Decision

1. **One snapshot.** The range's events, the control-stream records the run reads, the
   trusted-start record, and the hold and connection anchors are all read in one database
   snapshot, taken at start.
2. **Anchors and manifests come only from the workspace's own `ctl:{ws}`, up to its head in that
   snapshot**: the trusted-start record and every `AnchorComputed` and `SegmentExported` the
   checks read. Nothing appended after the snapshot, and nothing of another workspace, is read.
3. **The trusted-start record is itself checked.** Its own `ctl:{ws}` row must pass journal spec
   §11 checks 1, 2, and 4, and a `SegmentExported` must also satisfy rule 117. Otherwise the start
   is 422 `trusted_start` and nothing is recorded.
4. **The trusted-start manifest is checked over its whole segment** (`segment_manifest_mismatch`),
   including any rows past `to_seq`; those rows are not counted in `checked`, which counts the
   range's events only (rule 132).
5. **A manifest start is read from the cold store** (sub-question 2 of [DEC-789](DEC-789.md)). Its
   manifest and segment file are read from the cold store (journal spec §6.2); a start that only
   the hot store's `SegmentExported` vouches for, because the cold store cannot be read, is not a
   trusted start: 422 `trusted_start`, nothing recorded. Journal spec §9.14 says so.
6. **Consecutive in-range manifests that overlap or leave a gap fail `segment_gap`,** the
   trusted-start manifest included: each next manifest's `first_seq` must be the previous one's
   `last_seq + 1`.
7. **The hold anchor (an agent stream) and the connection anchor (a control or account stream)
   are folded from the stored chain, `seq` 1 to `from_seq − 1`, in the same snapshot** as the
   range, never from a read model. A range from `seq` 1 is anchored on nothing before it.

8. **An obligation on the run, which no record rule can hold.** A `VerificationRun` lists no
   anchors, so journal spec rule 132 cannot see that a `genesis` or `manifest` range holds an
   anchor's leaf. The run must never record `pass` for a range that holds a leaf of an anchor,
   stamped or with a `null` token ([DEC-789](DEC-789.md) items 5 and 7); it records `incomplete`
   or a failure. The implementation PR must test it, as part of AU-8's tests: a genesis range and
   a manifest range, each holding a stamped anchor's leaf and, separately, a `null`-token anchor's
   leaf, each recorded `incomplete`, never `pass`.

## Rationale

A verification that reads its inputs at different moments can judge a range against an anchor or
a fold that describes another moment, and report a false pass or a false SEV-1. A trusted-start
record that does not re-hash vouches for nothing, and a `SegmentExported` whose manifest hash is
not its own fields' would let a rewritten hot store supply its own start; checking the record
before using it costs one row. The cold store is what an attacker with the hot store cannot
rewrite (object lock, §6.2), so a manifest start only the hot store vouches for is DEC-115 item
5's refused case, a start the journal vouches for alone, exactly as an anchor without a token is.
Refusing it adds no risk: nothing changes state, and the caller can retry when the cold store is
readable. Overlap and gap between manifests both mean the segments do not tile the range, which is
what `segment_gap` names.

## Alternatives considered

- **Record `segment_manifest_mismatch` when the cold store cannot be read.** Rejected: an outage is
  not tampering, and a false SEV-1 freezes the control stream for nothing.
- **Record `incomplete` for an unreadable cold store.** Rejected: [DEC-789](DEC-789.md)'s outcome
  is for a check that cannot be proven by anyone yet; an outage is a retryable refusal, and
  refusing records nothing a reader could misread.
- **Fold the anchors from a read model.** Rejected: §11 forbids it, and a read model can lag.
- **Check the trusted-start manifest only up to `to_seq`.** Rejected: a manifest hashes its whole
  file, so the check cannot stop part way.
