#1308's "Not done": "The G1a door in `run()`. Per this dispatch, `connection()`/`lapse()` are

The readings the frames and the coming implementation are bound by:

## Decision

1. **The frames the run calls the door through.** Three, over the merged seams, each adding
   the run's own derivation and nothing else:
   - **`chosen(records, mandate, account_ref)`** — the connection the run uses. `records` are
     the run's own single control-stream read, handed **verbatim and in the journal's order**,
     never a re-read behind a second query (DEC-910 item 2: "The runner reads the control
     stream for the confirmed mandate's connection"); `mandate` is the deployment's own
     document; `account_ref` is the run's own (`--account-ref`), the stream every record of
     the mandate's connection must bind or refuse `connection_account` (DEC-910 item 2). Every
     refusal reaches the run as `PaperError::Connection` — the transparent variant #1297
     merged — so the run's report (`stderr_line`) carries the door's own message and code
     verbatim (ES-09; R0 step 4: "the exact refusal"). The implementation is the seam's call:
     `connection(records, mandate, account_ref).map_err(PaperError::Connection)`.
   - **`account_stream(workspace, account_ref)`** — journal spec §2's
     `acct:{workspace_id}:{account_ref}`, derived from the run's own names, never a constant
     where the run's own belong (the derivation discipline DEC-914 item 6 gave the export
     names). A form §2 cannot hold (segments the journal's stream ids refuse) is no stream a
     run could read, so the naming fails closed — `Cause::Absent` for
     "the account stream the connection binds", at `Stage::Reconcile`, where the run
     reconciles the account's own truth — never a fallback onto another stream the id could be
     mashed into (rule 3).
   - **`unspent(connection, rows, held)`** — DEC-529 item 3's lapse wrapped for the run:
     `lapse(connection, rows, held).map_err(PaperError::Lapse)`. `rows` are the journal's own
     read of the account stream `account_stream` names; `held` counts what the connector's
     snapshot listed (DEC-470 item 1), handed by the live arm's preflight and re-derived by
     nothing — a second fold of the account-stream rows beside the executor's own is
     precisely the two-admissions drift DEC-914 item 4's alternative rejects.
2. **The account stream is ungated by `--place-one-order`, and a journalless run has none.**
   The account stream is read "through the same journal it reads the control stream from"
   (DEC-910 item 3), so the read holds the run's arguments' journal without the placing filter
   the evidence keeps (DEC-157 item 6: the run appended to nothing when it did not place) —
   DEC-529 item 3's lapse refuses "to start", before anything runs, R0 step 4's dry run
   included: a run without `--place-one-order` makes no place call and still cannot start on
   a spent record. No separate refusal is invented for a journalless run: its own
   control-stream read already refused one (the door's `records` come from that journal too,
   in the binary's ports and any faithful one), and the default build's `connector_not_built`
   stands in front of the live arm's read anyway.
3. **The door is ahead of the shell's own answers in the run; the shell's fold keeps them
   all.** DEC-910 item 2: "These checks refuse before anything runs, ahead of the shell's own
   `DeploymentRefusal::Live`, which stays for the shell's fold." The shell's phase-1 fold names
   three of the door's cases with less exact answers — a revoked or live-environment record
   reaches its V-001, and a live deployment its unconditional `DeploymentRefusal::Live` — so a
   door placed behind `confirmed_version` (whose mandate the door needs) would report the
   less exact refusal DEC-910's own alternative rejected ("it answers `live` and names
   neither the record, the environment mismatch nor the missing connector, and R0 step 4 asks
   the run to report the exact refusal"). Reading: `run()` calls `chosen` with the deployment's
   own mandate document ahead of the shell's fold — the run holds the same records and the
   same artifact store phase-1 folds, and how it reads the deployed document ahead of the fold
   is the implementation PR's to write and its review to judge, bounded by: the door performs
   **no validation of its own**, never answers where the shell refuses, and only ever adds a
   refusal in front of the shell's (a document the two disagree on still answers at the
   shell's fold behind the door, so the reading can only over-refuse, the DEC-176-safe side).
   Within that, the call-site order the pins cannot bind (DEC-914 item 7's precedent) is the
   implementation's to write and the review's to judge: `chosen` before every credential read
   (FT-3; #1297's approved inventory "wiring the seams into run() ahead of every credential
   read"), `unspent` before anything runs, a live connection's snapshot handed after the
   founder's `--features live` build serves the choice the default build refuses
   (`connector_not_built`; DEC-910 item 3: "the default-build refusal stands in front of it").
4. **The pins drive the frames, never `run()`.** A pending test that drove `run()` would fail
   on the run's answer rather than at the row's stub, which the pending gate refuses
   (DEC-137; DEC-914's alternative, settled by #1311's review). The pins therefore bind the
   values the frames take and what each refusal reports; the frames' signatures are final —
   `run()` calls them under the feature with no re-shaping, and the implementation PR's diff
   is exactly the stub bodies and the `run()` call sites.
5. **What this row does not touch.** The G1b frames' call sites inside the cycle stay stream
   L / M7's remainder's; the shell watch's own loop stays the shell row's; the live arm's Robin
   hood connector, preflight and the account-stream journal read stay the door implementation's
   to write under these signatures (the `Ports` growth #1297's inventory named with the live
   arm); `connection.rs`'s seam semantics, `ROBINHOOD_LINKED`, and the `live` feature's
   declaration and compile-only discipline (X1, E7-28, DEC-529 item 3) are exactly as merged.
   No pin, stub or doc of this row reaches a host, a credential, a broker or a real order
   (LT-1, rules 7 and 8), and the default build's paper path is unchanged except by refusing
   (LT-14: an unrecorded or agreeing paper connection keeps today's run exactly).

## Rationale

Each reading refuses more or names a stop more exactly. Reading the revocation, the
environment and the build refusals through the door ahead of the shell's V-rule answers gives
R0 step 4 what it asks for — "the exact refusal" — where the shell's fold answers a violation
code instead; the alternative keeps both refusals in the shell and merely orders them, which
is what "stays for the shell's fold" says the shell's own answers do behind the door. Reading
the account stream ungated by placing is the only reading under which a dry run cannot start
on a spent record, the refuse-more side of DEC-529 item 3's "refuses to start". Deriving the
stream id from the run's own names (and refusing when §2 cannot hold the result) keeps the
same property the evidence's names hold: no other run's stream is read by a wrongly-derived
constant, and no read at all happens where no stream exists. Wrapping the seams in frames keeps
the merged refusal vocabularies the single answer surface (`PaperError::Connection`,
`PaperError::Lapse`, both transparent) and adds no reason code a review has not already read.

## Alternatives considered

- **Place the door behind `confirmed_version`** (which yields the mandate): rejected — it
  reports `DeploymentRefusal::Live` or a V-rule where DEC-910 reads the door's exact refusal
  ahead of it, losing three of the seven names (revoked, environment, and the live-mandate
  half of `connector_not_built`) at the run level, and only default-build cases the shell
  passes today would be observable at all.
- **Catch the shell's `DeploymentRefusal::Live` and re-derive the door's refusal from it:**
  rejected — the shell's answer would be the first the run reports, and the catch-and-reread
  re-derives after the fact what the door owns before anything runs.
- **A live-tolerating parameter on the shell's phase-1 fold:** rejected — a `mandate-shell`
  edit, which this row may not make (the shell row and stream L own shell changes); the
  shell's fold keeps every refusal it makes today and the door only adds in front.
- **Gate the account-stream read on `--place-one-order`** like the evidence's journal filter:
  rejected — DEC-529 item 3's lapse is not a placing-only check; R0 step 4's dry run makes no
  place call and must still refuse a spent record.
- **Pin the call sites by driving `run()` with pending tests:** rejected — the pending gate
  requires each failure at the row's stub (DEC-137), and a driven `run()` fails on its own
  answer first; the binding lands with the frames the implementation calls, and the review of
  that implementation reads the call order (DEC-914 item 7, the #1311/#1313 precedent).
- **A `Ports` method stub for the account-stream read in the tests PR:** rejected for this PR —
  the port is a call-site shape the pins do not bind; the frames take the rows the journal's
  own read hands, and the implementation adds the read (its review judging the growth #1297's
  inventory named), so no signature is frozen where the journal read belongs.
