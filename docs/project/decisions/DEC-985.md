## Decision (proposed)

1. **Default, holding now: cell #1's VMs, apart.** The control plane runs on cell #1's VMs (DEC-995)
   as its own Helm release in its own namespace, with its own Postgres database and role, its own
   keys and secrets, and its own egress policy. Nothing is shared with the cell's releases but the
   nodes; a test renders it beside a cell release and finds no shared secret (E21-43). It adds no
   cost.
2. **The alternative: its own small VM**, about $8 to $20 a month, which gives the separate
   accounts and keys DEC-440 item 16 recommends and keeps a cell's node failure from also taking
   the plane down.
3. **Moving later is a values change**: the release, its database and its keys move together; the
   cell reaches the plane only outbound through `cp-agent`, so only the plane's address changes.

## Rationale

Speed for the 2026-10-26 demo and no new spend. The plane holds IDs and versions only and is never
in the path of a trade (CP-2, CP-3), so sharing the nodes risks only its availability, which no
trading depends on. The separation that matters for security (namespace, database, keys, egress)
holds either way.

## Alternatives considered

- **Inside the cell's own release.** Rejected: E21-43 asks for its own deployment, and sharing a
  release would share secrets.
