## Decision

1. The `schema-mutants` matrix runs twenty shards, `0/20` to `19/20`, `fail-fast: false`, in place
   of DEC-2637's ten. Everything else in DEC-688, DEC-1004 and DEC-2637 stands: each shard runs the
   three checkers on the unmutated tree first, the required `full` verdict passes only when every
   shard succeeded, and `cargo xtask check` and the nightly run the sweep unsharded.
2. The xtask test that pins the job's lines pins the twenty shards.

## Rationale

On #3014's run 41009478811, shards 0, 1, 6 and 9 were cancelled at the ten-minute job timeout
(shard 6 ran from 05:38:26 to 05:48:37). The sweep is now 1,802 mutants, where DEC-2637 sized ten
shards for about 1,369, and each mutant runs the three checkers at about 3.4 seconds. Twenty shards
hold about 90 mutants each, about five minutes on the slowest runner.

A pull request that only touches `schemas/` can cut each mutant's cost instead, but the spec guard
(ES-22) keeps that change out of a pull request that changes code, so it cannot land beside the CI
fixes it would otherwise wait on. More shards need no protected path.

## Alternatives considered

- **A larger timeout.** Rejected: DEC-464's bound is per job.
- **Fewer examples or mutants.** Rejected: DEC-464 forbids removing tests or safety gates to meet
  the bound.
- **Only the faster checker run.** Still worth landing on its own, and it would let the shard
  count come back down; it does not unblock this pull request.
