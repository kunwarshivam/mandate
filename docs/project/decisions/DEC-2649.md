| **Date** | 2026-10-29 (UTC) |

| **Story or claim** | no story; CI throughput and the self-hosted runners. Amends [DEC-2609](DEC-2609.md); generalises [DEC-2634](DEC-2634.md); reads against [DEC-1190](DEC-1190.md), [DEC-993](DEC-993.md) item 10, [DEC-464](DEC-464.md), [DEC-2065](DEC-2065.md), [DEC-2610](DEC-2610.md) |

## Context

A pull request whose diff reaches the cell starts eleven cell jobs on the three self-hosted
DigitalOcean runners the founder keeps (DEC-2065, DEC-2075): `cell`, `cell-kill-switch`,
`cell-seeded`, `cell-upgrade`, `cell-demo`, `cell-demo-web`, `cell-journal`, `cell-failover`,
`cell-executor`, `cell-vault` and `cell-exchange`. Each brings up its own k3d cell, so such a pull
request holds the pool for roughly thirty runner-minutes, and a few opened together queue for
hours. The founder's ruling of 2026-10-29 was "remove process overhead", and he declined to pay
for more runners; GitHub-hosted runners are blocked from the cell (DEC-2065: a fork brings its own
workflow, and the runners' job-started hook is part of what stops forks).

`cell-demo-web` already left the per-PR path (DEC-2634): `selection()` clears `cell_web` when
`GITHUB_EVENT_NAME` is `pull_request`, so the job reads `skipped`, and `main`'s own runs and the
nightly's dispatch — which have no diff base and select everything — keep it. This decision
applies the same mechanism to eight more jobs.

## Decision

1. **A pull request runs only `cell` and `cell-kill-switch`.** They cover what the cell *is* on a
   pull request: the chart, its invariants, the built image, the drills, and the kill switch — the
   one control `AGENTS.md` rule 13 never lets depend on model state.
2. **Eight jobs move to post-merge:** `cell-demo`, `cell-journal`, `cell-failover`,
   `cell-executor`, `cell-vault`, `cell-exchange`, `cell-seeded` and `cell-upgrade` start only on
   `main`'s own runs and the nightly's dispatch. `select` prints a new output, `cell_post_merge`,
   computed exactly as `cell` — the selection stays pure, DEC-2609's inputs unchanged — and
   `selection()` clears it on `pull_request`, alongside the `cell_web` clearing DEC-2634 added
   (`withhold_post_merge_jobs`). The jobs' `if:` reads `cell_post_merge` instead of `cell`; their
   steps, drills and ten-minute bounds (DEC-464) are untouched. No diff base selects everything,
   so `main` and the nightly run all eleven exactly as before.
3. **Nothing about what any job checks changes.** Every drill, every seeded-bug variant, the
   demo, the upgrade and the web gesture still run before `main` can rest green; only the set of
   events that starts them on a pull request narrows.
4. **`report-main` follows every cell job.** It needed only `fast` and `full`, so a cell job
   failing on `main` opened no issue even before this change. It now needs all thirteen verdicts
   and opens its issue when any of them fails, naming each verdict, still never a log line.

## Rationale

The eight moved jobs re-run the same cell the per-PR pair already proves, in narrower variants:
each drill family on its own cell, the drills again with their bugs planted, an in-place upgrade,
the demo. That depth is a `main`-branch signal — it catches what slipped past review — not a
per-pull-request one. The merge path requires `fast` and `full` (DEC-993 item 10 keeps the cell
jobs out of both), so a pull request's coverage of the cell is what `cell` and `cell-kill-switch`
give it, and that pair already runs the chart's invariant tests (`fast-python`) and the cell's own
drills. The founder pays for three runners; spending thirty runner-minutes per pull request on
the eight, while pull requests queue for hours, is the process overhead he told the repository to
remove.

DEC-2634 proved the mechanism: an output cleared by event, a job that then reads `skipped`, and
`main` keeping full depth. This is the same shape, so its risks are the same ones that decision
already accepted.

## Alternatives considered

- **Add runners.** The founder refused (2026-10-29): the pool is three DigitalOcean runners.
- **Move the eight into the nightly only, dropping the post-merge run.** Refused: `main`'s own
  push run already exists (DEC-2610) and selects everything; using it costs nothing new and finds
  a break the night it merges rather than up to a day later.
- **Drop the eight jobs entirely.** Refused: no test or drill is removed (the founder's mandate,
  2026-10-29); they move, not disappear.
- **Edit `merge-approved.sh` instead.** Out of scope and out of shape: DEC-175 governs the merge
  gate, and nothing here needs it — the moved jobs were never required checks.

## Consequences

- A pull request whose diff reaches the cell starts two cell jobs instead of eleven (ten before
  DEC-2634 withheld the web demo per PR): its demand on the self-hosted pool drops by roughly
  twenty-five runner-minutes.
- A regression the eight would have caught on a pull request is caught after the merge, on
  `main`, where `report-main` now opens an issue naming the verdicts; the next pull request that
  reaches the cell re-runs `cell` and `cell-kill-switch` immediately.
- `select` prints one more output, `cell_post_merge`, and its reasons line names the split;
  `fast` and `full` accept the skips exactly as they accepted `cell_web`'s (the cell jobs are in
  neither aggregate's `needs`).
- No journal event: this changes no runtime state.
