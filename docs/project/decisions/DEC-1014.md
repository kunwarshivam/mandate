# DEC-1014: The runtime process folds the account stream its connection's establishment names

| | |
|---|---|
| **Status** | Accepted (agent: a reversible engineering decision under DEC-79 and DEC-176; it lets the runtime process take the account stream's facts the shell already folds, and every reading it takes is the stricter one) |
| **Date** | 2026-10-17 (UTC) |
| **Decided by** | `claude-code` (builder of lane P3 of the managed-cells plan, DEC-967, DEC-990), under DEC-79 and DEC-176 |
| **Story or claim** | E21-30 slice 1; trading spec §11 (the startup hold); journal spec §2, §9.8; DEC-131 items 13 and 22; DEC-914 item 2; DEC-1012 |

## Context

`mandate-daemon`'s runtime process (DEC-1012) read the control and clock streams and never the
account stream. The core's startup hold lifts only on a clean `ReconciliationRun` folded from the
account stream (DEC-131 item 13), so its effective mode stayed `paused` for good: no research run
could start and no proposal could be made. The executor's `AgentModeApplied`, and every other
account-stream fact the shell's copy fold takes, never reached it either.

The account stream is `acct:{workspace}:{account_ref}`, and `account_ref` is not the connection id:
an account stream belongs to the connection whose version-2 `ConnectionEstablished` on the control
stream names its `account_ref` (journal spec §9.8).

## Decision

1. **Each pass folds the account stream after the control stream and before the clock stream.**
   The rows past the core's head for that stream are folded with `mandate_runtime::fold`, as the
   shell folds them, so a row is folded once and the core's own sequence check refuses a gap. The
   next input the core takes (each pass's tick) settles the startup hold and journals the mode
   change. The owner's kill switch is still read first (ES-06).
2. **The start folds it too, before `Input::Started`.** So the hold is taken on the whole fold, as
   the shell's open replays the account stream before the start, rather than lifted later by the
   looser test that settles it.
3. **The account is the one the latest version-2 `ConnectionEstablished` of the deployment's
   connection names.** Another connection's establishment, and a version-1 record, name nothing.
   Until one names it, the process follows no account, and the hold stays.
4. **It fails closed.**
   - A start that cannot read the control stream, or the account stream it names, is never ready.
   - A pass that cannot read the account stream hands no tick, so nothing is decided on a mode that
     may be stale. The control stream, and the owner's kill switch on it, are still handed.
   - A record the core cannot fold stops the process (DEC-85), as an unfoldable control or agent
     row already does.
   - A running process never changes the account it follows. A later establishment that names
     another account stops it, and the next process follows the new account from its start.
5. **The runtime only reads the account stream.** It never takes ownership of it or writes it. The
   account's executor stays its single writer (journal spec §2).

## Rationale

The shell's in-process run already folds the account stream beside the agent stream. The runtime
process is the same core on the journal alone (DEC-1012), so it takes the same facts the same way.
Folding before the start keeps the hold's stricter test, which also wants nothing outstanding;
folding only after it would lift the hold on the looser one.

## Alternatives considered

- **A `--account` flag.** One more thing to keep in step with the journal, and a wrong value would
  let another account's reconciliation lift this agent's hold.
- **Hand the account rows as `Input::Journal`, as the control rows are.** The core folds account
  facts rather than taking them as input, and refuses a row it has already folded, so handing the
  stream whole each pass would stop the process.
- **Follow a new account without a restart.** The core keeps one reconciliation state, so an old
  account's reconciliation could lift the hold for the new one.

## Consequences

- In the cell nothing changes yet. The demo deployment's connection has no establishment and no
  executor writes its account stream, so its runtime stays held until the executor lands (E21-30
  slice 2).
- Research (lane I2) and trading can run in the process once the executor reconciles.
