## Context

DEC-1010 closes the scheduler stream's records and the rules a writer holds. This decision records
how the `mandate-scheduler` process writes them, where the spec leaves the choice to the writer.

## Decision

1. **A new safety-critical crate, `mandate-scheduler`, at layer 7.** It uses `mandate-journal`,
   `mandate-journal-pg`, `mandate-process` and `mandate-time`, with `tokio` (`rt`, `signal`) its
   only external dependency, which adds no crate to the lockfile. Its `forbidden_internal` list
   keeps it from the runner, the shell, the CLI, the runtime, the executor and every broker
   connector: it holds nothing secret and places nothing.
2. **The time servers are asked over SNTP (RFC 4330) by the crate itself.** It sends one 48-byte
   request per configured server over `std::net::UdpSocket` and waits one second for each reply.
   A reply counts only when all of these hold:
   - it is a server reply (mode 4);
   - its originate time is the request's transmit time;
   - its leap indicator is not "unsynchronized";
   - its times read.

   No time-protocol crate is added. The host clock is read only at the binary's edge and handed
   in, as ES-05 requires. The servers are configuration (`--servers`); with none, every
   measurement is out of tolerance (DEC-1010 item 3), which withholds openings and nothing else.
3. **Ticks are paced by the process's monotonic clock.** The binary steps once per elapsed
   monotonic second. Each tick is DEC-1010 item 7's later of the last tick plus a second and the
   host clock's second. A slow step catches up on the next tick's value rather than writing a
   burst.
4. **The measurement schedule.** The scheduler measures:
   - at its own start, before its first tick's measurement is due;
   - once in the 15 minutes before each trading day's regular session (`ExchangeCalendar`);
   - every five minutes, half §5.4's ten-minute bound, so one lost measurement stays inside the
     executor's 15-minute window (DEC-1010 item 5).
5. **Paper only.** `Scheduler::start` refuses any environment but paper before it takes the
   stream, as `mandate-agentd` does (DEC-968 item 1). The scheduler writes no order, but it writes
   the environment into every record, and a live workspace's scheduler belongs with the live
   decisions (DEC-967 item 15, E21-48).
6. **One writer epoch, and a batch in doubt is retried as the same bytes.**
   - **Start.** The scheduler takes a newer epoch at start, fencing every earlier one, and replays
     the stream. It writes `StreamOpened` only to an empty stream.
   - **Event ids.** They are derived from the epoch, the head and the ordinal in the scheduler's
     own id space (`2`, after the agent's `0` and the account's `1`).
   - **`Unavailable` or `Ambiguous`.** The batch is kept and appended again unchanged before
     anything new, so the journal answers `AlreadyCommitted` rather than writing twice.
   - **`Fenced`.** The scheduler exits `fenced` before it writes anything more.
   - **Any other refusal.** It exits `cycle_failed`, and the restart replays.
7. **Lifecycle and probes come from `mandate-process`.**
   - **Kind.** The scheduler is a `Writer`: ready once it holds the epoch and has replayed to the
     head.
   - **Probes.** The binary publishes the lifecycle's snapshot to the probe socket after every
     step, and its `probe livez|readyz` subcommand is the `exec` probe (DEC-994 item 5).
   - **Drain.** SIGTERM drains: the scheduler writes nothing new, tries a batch in doubt once
     more, then exits `drained`, or `drain_incomplete` if the batch is still in doubt.
8. **A trading date the calendar cannot answer starts no day.** The previous day's limits then
   stay in force rather than being reset on a guess (`AGENTS.md` rule 3).

## Rationale

The scheduler's one duty is a risk clock that never stops and a record of how good the host clock
was. Keeping the time protocol and the clock reads at the edges keeps everything else pure and
testable with an injected clock and a shared in-memory journal. That includes fencing, restarts,
steps back and a batch in doubt, as `mandate-agentd`'s tests do.

## Alternatives considered

- **Read the offset from the host's NTP daemon (chrony or `adjtimex`).** Rejected: it needs a
  daemon in an image built on an empty base, or `unsafe` system calls the workspace forbids.
- **An SNTP or NTP crate.** Rejected: outside DEC-990's pre-approved kinds, and the 48-byte
  exchange is small enough to own and test.
- **Pace ticks by the host wall clock.** Rejected: a host clock that steps back would stall the
  loop itself.
- **Run on any environment.** Deferred to the live decisions with a refusal now.
