| **Story or claim** | E12-6 ([#756](https://github.com/kunwarshivam/mandate/issues/756)); E12-1 (#745), E12-2 (#747), E12-3 (#748); workspace API spec §4.8.1 |

## Decision

1. **Page bounds.** `limit` is 1 to 1,000, default 100; `after_seq` is 0 to 2^53 − 1, default 0.
   Out of range is 422 `invalid`, never clamped.
2. **Cursor and head.** The cursor is the last returned `seq`. The page and the stream head it
   carries are read in one database snapshot. An `after_seq` at or past the head returns `200`
   with no events, `at_head: true`, and the head.
3. **Body encoding.** Each event carries its stored canonical body as standard base64 with padding
   (RFC 4648 §4), plus `hash`, `prev_hash`, `seq`, `event_id`, `event_type`, and `recorded_at`.
4. **One 404.** A `stream_id` or `event_id` that is absent, malformed, or in another workspace is
   resolved by the same scoped lookup (a malformed id is looked up, not rejected early) and returns
   the same `not_found` problem document, byte for byte, with no id echoed: the `Problem` of
   `schemas/workspace-api/envelope.schema.json` (#788, planned) with `type`
   `https://mandate.dev/problems/not_found`, `status` 404, `code` `not_found`, `title` `Not found`,
   `effect` `none`, `event_id` `null`, `retryable` `false`, and `violations` `[]`.
5. **Role before id.** The role check runs before any id is resolved, so a principal without the
   "Read records" row gets 403 for every id, present or not. Non-id query members are validated
   before ids too.
6. **Stream list.** Ascending `stream_id` bytes, each with its head `{seq, hash, recorded_at}`,
   paged like events by `after` and `limit`, with the event page's `limit` bounds (1 to 1,000,
   default 100, 422 outside). Each page is one snapshot; a listing of several pages is best effort
   while streams are being created, and a stream created behind an earlier page's last id appears
   in a fresh listing.

## Rationale

API-15 and API-9 named the properties and left the numbers. Rejecting rather than clamping keeps a
client from believing it read a range it did not. A 200 past the head reveals nothing, since the
stream is in the caller's workspace, while a 404 there would make "behind the head" look like
"absent". Checking the role first means existence never leaks through 403 versus 404.

## Alternatives considered

- **Clamp `limit`.** Rejected: a silent clamp hides a client bug and makes page-size fuzzing
  ambiguous.
- **422 for a malformed id.** Rejected: a distinct answer for "malformed" lets a prober learn the id
  grammar of other workspaces' streams; one body for all three is simpler to test.
