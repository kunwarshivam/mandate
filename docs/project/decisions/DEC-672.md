## Decision

1. **`OwnerCommandIssued` is closed for `hold_openings` and `lift_hold` only.** Its members are
   the ones the CLI already writes for every owner command (`agent::issued`), in its order:
   `agent`, `command`, `scope` (`agent`), `subject` (the agent, rule 91), `release`,
   `warning_shown`, `bid`, `bid_size`, `floor` (all `null` for these two commands), `user`,
   `submitted_at`, and `step_up`. Matching the writer means M7 closes the other commands without
   renaming a member. Times are integer risk-clock
   seconds, as §9.7's approval answer's are (DEC-533 item 2), because the same writers produce
   both. The other commands' members stay with M7's agent-commands slice. Closing them here would
   mean guessing at pause, kill switch, and owner exit.
2. **Every other command stays open, and is never refused for its members.** `append` catalogues
   `OwnerCommandIssued`, reads its `command`, and refuses a client's (rule 90); a pause or a kill
   switch from any other principal, the host CLI's `system` actor included, is recorded whatever
   its other members (`AGENTS.md` rule 13). Today `mandate-journal` does not catalogue the record
   at all, so this records more than before, never less, and lets rule 84's batch find a kill
   switch. Found while tracing rule 84 (#792): a rule 90 limited to users would have refused the
   host CLI's kill switch.
3. **Who may issue them** (rule 90). A `user` may issue either. A `client` may issue
   `hold_openings` only (DEC-191, workspace API §3.8). Rule 83 now admits a client's
   `OwnerCommandIssued`, and rule 90 confines it. `user` is the actor's human (rule 91).
4. **A hold carries no step-up** (rule 92). It only reduces risk (`AGENTS.md` rule 2, identity
   ID-5), and a client never presents step-up (ID-11).
5. **The hold is recorded on the agent stream as owner state beside the lifecycle.**
   `AgentModeChanged` version 2 adds the reasons `owner_hold` and `owner_lift_hold` and the member
   `held`. This is needed for the same reason version 1 records `lifecycle`: a hold taken while a
   stricter state held the agent would otherwise be lost when that state lifts, on replay. Rule 93
   ties `held` to the two reasons. Rule 94 replaces rule 11 at version 2: `to` is at least the
   lifecycle's mode, and at least `exits_only` while held. Rule 95 extends rule 16's copy link to
   the new reasons. Version 1 is never edited. The coordinator's review added §11's per-range
   check `held_mismatch`: `held` changes only on a hold or a lift, every other version-2 copy
   carries the last one's, and no version-1 record follows a version-2 one, so a stray
   `held: false` cannot drop the hold on replay. The check anchors on the stored chain before a
   range, never on the range's own first record, which a second review found could launder a
   dropped hold; without the chain before it, a later range's first version-2 copy fails closed.
6. **A lift that does not count is refused like a resume.** `OwnerCommandRefused` version 2 adds the
   command `lift_hold`. It is registered on the agent stream only (rule 26), and is never
   `not_independent` (rule 28).
7. **Mandate spec §6.1 gains two rows:**
   - Hold: no step-up, always applies, and a client may issue it.
   - Lift: step-up required and judged when the runtime processes it. It is refused without valid
     step-up, is the owner's alone, and lifts only the hold.

   Both carry DEC-191. MI-3 already said a resume never lifts a hold.

### Invariants

- **INV-1. A hold never adds risk.** It only moves the agent to `exits_only` or keeps it stricter,
  and every exit keeps running (rule 94; mandate §6.1).
- **INV-2. Only the owner lifts, with step-up** (rules 90 and 92, mandate §6.1).
- **INV-3. A lift lifts only the hold, and a resume only the pause.** Neither clears the other or a
  latched limit (rule 94, MI-3).
- **INV-4. Each command has one copy** (rule 95, as rule 16).
- **INV-5. Nothing recorded before v0.23 changes.**

The vectors' `hold` section has an invalid draft for every rule and valid drafts for the readings
a rule might be misread to refuse:

- a lift while a limit is latched;
- a resume while held;
- a hold while paused;
- a hold after a Stop;
- a restriction lifting under a hold.

Three oracles of the generator's own are checked:

- the strictest mode each copy may leave, ranked independently;
- one copy per command;
- that a hold is a person's and a lift a user's.

All 37 validator mutants, 10 range mutants, and 8 vector mutants are caught. DEC-673 records the anchor and the expected-hold reading.

### Lifecycle walk

- **Entered** by `hold_openings` from the owner or a client, at any mode. On a paused or stopped
  agent the copy records `held` with the mode unchanged.
- **Blocks** openings and increases (`exits_only`). Never an exit, a protective order, or the kill
  switch.
- **Ends** only by the owner's `lift_hold` with valid step-up. Without it, the lift is refused as
  `OwnerCommandRefused`.
- **Session close, midnight, version change:** the hold persists. Restriction changes and limits
  neither set nor clear it.
- **Restart:** the runtime folds `held` from the last `AgentModeChanged`.
- **Repeats:** a second hold, or a lift with no hold standing, is copied with `held` as it already
  stood. Command status still reaches `applied`.

### Adversary

- **An injected client:** its worst case is a hold, which costs missed openings only. It cannot
  lift (rule 90), pause, or stop (rule 83 with rule 90).
- **A careless owner resuming:** the hold still stands (rule 94).
- **A malicious insider forging a lift:** it needs the owner's step-up, judged by the runtime.

## Rationale

DEC-436 item 14 requires the commands in the journal spec before the API offers them. The
agent-stream copies are what make "lifts only the hold" and "a resume never clears a hold" true
on replay.

## Alternatives considered

- **Close all of `OwnerCommandIssued`:** this belongs to M7's slice, and guessing other commands'
  members is what DEC-261 forbids.
- **Record the hold as a separate event, not a member of `AgentModeChanged`:** this would give
  replay two records to fold for one mode, and leave `to` unexplained by its own record.
- **Let a hold carry optional step-up:** it buys nothing, and a client could then present
  evidence, which ID-11 forbids.
