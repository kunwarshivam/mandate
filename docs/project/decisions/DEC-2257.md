## Context

DEC-997 is Accepted, so live model calls through OpenRouter may run on staging, within its
routing lock and its $50 a month cap. The pieces exist but nothing joins them:
- `mandate-gateway-http::HttpsTransport` exists, and no crate depends on it (DEC-2200 item 2);
- the cell's research worker names only the recorded fake (DEC-2210 item 3);
- the cell's meter is in memory (DEC-2249 item 3);
- staging's vault has a path for the provider's key and no step writes it (DEC-2020);
- the workspace chart declares a `model-gateway` service, `built: false`, with the only
  `model-providers` egress, and that target allows nothing.

## Decision

1. **One live path: the model-gateway service.** Live calls are made only by the chart's
   `model-gateway` process: a service of its own, running `mandate-gateway` over `HttpsTransport`,
   the journaled meter and the system clock. The runtime has no model egress (inference §8.2) and
   reaches a model only by calling that service.
2. **No live call before the journaled meter.** The service refuses to start live unless its meter
   store is the journaled `meter:{workspace_id}` stream (E21-61, DEC-998 item 8). A test pins
   this. E21-61 merges before staging ever sets the live flag.
3. **The key.** The service reads `platform/model-provider-key` once at start, as `ModelGateway`,
   and holds it only in memory (DEC-2020 item 3). It never logs the key or sends it anywhere but
   the provider's `Authorization` header.
   - Only `SecretImport` writes the key, through `mandate vault import` reading stdin. Staging's
     infra run pipes the `infra-staging` environment secret `OPENROUTER_API_KEY` into it (lane V2).
   - The key is never an argument, an environment variable of a workload, a file in the
     repository, or chat text.
4. **The probe.** The service registers an endpoint only after inference §4.3's identity probe
   matches the pin, on real calls metered under the caps. A mismatch registers nothing, so
   research gets no answer, the safe default.
5. **Egress.** Port 443 to OpenRouter's host is opened for the model-gateway pod alone, by an
   FQDN network policy where the cluster supports one (lane GO). An address-range allowlist does
   not fit a provider behind anycast.
6. **Recorded everywhere else.** Tests and CI use recorded responses only (DEC-997 item 4). A runtime
   started without the gateway service's address keeps the recorded fake, deny-all by default. On
   staging, research reads the recorded bundle's news, bars and filings for the demo; live data is
   a later story.
7. **The registry entry is the founder's.** The live entry (model slug, single upstream, dated
   snapshot, prices) is proposed in its own decision, with a recommendation, for the founder to
   choose. Until then the service registers no hosted entry.

## Rationale

The chart already declares the process, its role and its egress, so building it is the permanent
shape. A gateway inside the runtime pod would give the runtime model egress, which §8.2 forbids,
and would be thrown away. The journaled meter is what keeps the cap true across a crash or a
restart.

## Alternatives considered

- **The gateway in the runtime process, with egress on the runtime pod.** Rejected: §8.2 and
  E15-6, and throwaway.
- **The key in a Kubernetes Secret.** Rejected by DEC-2020: readable by whoever reads the
  namespace's Secrets.
- **The founder writes the key into OpenBao by hand.** Rejected: it needs an operator token and
  cluster access on a laptop. An environment secret is one form, and rotation is the same form
  again.
