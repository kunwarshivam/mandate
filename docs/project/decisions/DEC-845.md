# DEC-845: An implementation PR that turns a pending test's stub failure into a behaviour failure adds that test's behaviour-only row

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-09 (UTC) |
| **Decided by** | The coordinator, as a reversible process decision agents may take (DEC-79, DEC-176) |
| **Story or claim** | E7-26 (X1), claim #857; PR #738, after tests correction 5 (#914) |

## Decision

1. **Who adds the row.** Sometimes an implementation PR replaces a stub but leaves some of the
   pending tests on that path failing on behaviour rather than at the stub, because a later
   implementation step will make them pass. That implementation PR adds an `xtask/behaviour-only`
   row for each such test, in the same change.
2. **Rows are not test files.** [DEC-77](../04-decision-log.md) item 2 limits what an
   implementation PR may change in test files: it may only delete the `#[ignore = "pending
   <story>"]` lines. A behaviour-only row is not a test file. Adding one changes no assertion, and
   `cargo xtask ci pending` still runs the test and requires it to fail (DEC-110, DEC-137).
3. **Each step deletes its own rows.** Each later implementation step deletes the rows of the
   tests it un-ignores, in the same change as their `#[ignore]` lines.
4. **First use.** X1 is split into steps 1, 3a, 3b and 3c. Step 1 (#738) adds the rows of three
   tests:
   - `the_backstop_and_the_feature_value_rules_refuse_ci_bypasses`, which step 3a deletes;
   - `commands_are_read_fail_closed_where_a_word_may_execute`, which step 3b deletes;
   - `array_expansions_are_read_through_their_definitions`, which step 3c deletes.

   Step 3a also deletes the row of `ci_files_reads_every_file_that_decides_a_build`, and step 3c
   the row of `ci_files_reads_the_build_files_anywhere_in_the_repository`.

## Rationale

A tests-correction PR cannot carry these rows. On `main` the tests still fail at the stub, and
`cargo xtask ci pending` refuses a row whose test stops at a stub (DEC-137). So the row has to
arrive with the change that moves the failure off the stub. The rows stay as narrow as the
README of `xtask/behaviour-only` requires, because each one is deleted when its test is
un-ignored.

## Alternatives considered

- **Have the tests correction add the rows.** Refused by the pending gate, as above.
- **Land the whole implementation in one PR.** About 1,150 lines of shell-parsing logic would be
  too much to review in one sitting (the coordinator's ruling on #738).
- **Keep the stub until the last step.** A stub would leave the word scan unshipped and the eight
  tests that already pass still pending.
