# DEC-1012: The runtime runs as its own process on the journal alone, reads the kill switch first, and waits for the post-R0 hook for production ports

## Context

E21-30 asks for the agent runtime and the account executor as long-running processes. The R0
rehearsal holds the paper runner, the shell's run path, the CLI's live entry, and the rehearsal
script until it closes, and the production-cycle constructor (DEC-968 item 6) is the post-R0 hook.
The shell's production ports (its `Bridge`) are private to it. This decision records what slice 1
builds without them and where it stops.

## Decision

1. **Two new safety-critical crates, and two moves that change no behaviour.**
   - `mandate-store` (layer 7): the journal port a long-running process writes through (`Store`,
     over `MemoryJournal` and Postgres), and the shared envelope that turns a draft into the bytes
     the journal hashes. It moves out of `mandate-scheduler`, which now uses it.
   - `mandate-daemon` (layer 8, process group `agent_process`): `RuntimeProcess` and its binary.
     Its `forbidden_internal` list keeps it from the shell, the executor, every broker connector,
     the MCP server, the paper runner, the CLI, and the broker simulator: the runtime has no
     broker credential and no route to a broker by construction (`AGENTS.md` rule 12).
   - The control-stream tail moves from `mandate-shell` into `mandate-runtime` as
     `mandate_runtime::tailed`, and the shell's `tailed` delegates to it with its own error, so the
     shell's tests pass unchanged.
2. **Slice 1 is the runtime process; the executor process is slice 2.** The executor's process,
   whose readiness also waits for reconciliation, is where a not-ready process hands only the kill
   switch and risk exits. It needs the executor's public items and its broker fixture, and lands
   as its own change.
3. **The journal is the only channel; a wake hint only shortens a wait.** `Wake::wait` returns
   early on a hint, and every pass reads the journal whether or not one came, so a lost, late or
   repeated hint costs latency and never changes an outcome (DEC-17, ES-20). The Postgres journal
   has no `NOTIFY` today. Adding one is a migration of the journal schema and lands as its own
   change. Until then the binary waits one second between passes (`Sleep`).
4. **Each pass reads the control stream first.** The control stream is read before anything else,
   so the owner's kill switch is never queued behind a tick (ES-06, design §3.6).
   - **The control stream.** It is handed whole each time its head grows. The core's copy fold
     makes a row handed again inert (DEC-914 item 2, EI-3).
   - **The clock stream.** Its latest `ClockAdvanced` is handed on every pass as the core's risk
     clock. The core evaluates each risk-clock second once and takes a tick it has seen as no input.
   - **A clock stream that cannot be read** hands no tick and holds nothing else.
5. **The runtime process has no readiness gate of its own.** It is not ready in two cases:
   - before its `Input::Started` batch commits;
   - while a batch is in doubt.

   In both, the core accepts only that same input, so there is nothing for a gate to hold back.
6. **Production ports wait for the post-R0 hook (DEC-968 item 6, lane P5).** `RuntimeProcess`
   takes a `Wiring`: the core's ports plus `Refs`, the schema version and configuration references
   each draft is journaled with. A draft the wiring has no references for stops the process
   (`cycle_failed`) rather than being written without them.
   - **The binary today.** It runs only `fixture::wiring`, over an in-memory journal: a gate that
     denies every proposal, a plan that proposes nothing, a flatten planner with nothing held, and
     one fixed mandate version.
   - **Without `--fixture`.** The binary refuses with `deployment_ports_not_wired`. [DEC-1013](DEC-1013.md)
     item 1 supersedes this sub-item: without `--fixture` it runs on the journal
     `MANDATE_JOURNAL_DSN` names, still on the fixture wiring.
7. **One writer epoch, and a batch in doubt is offered as the same bytes.**
   - **Start.** The process takes a newer epoch on the agent stream, fencing every earlier one,
     folds the stream, and writes `StreamOpened` only to an empty stream. A `StreamOpened` whose
     append is in doubt exits `cycle_failed` before the core starts; the restart replays and finds
     it.
   - **`Unavailable` or `Ambiguous`.** The input is kept with the event time its drafts were first
     written at, and handed again before anything else. The journal then answers
     `AlreadyCommitted` rather than writing twice.
   - **`Fenced`.** The process exits `fenced` before it writes anything more.
   - **Any other refusal.** It exits `cycle_failed`, and the restart replays.
   - **SIGTERM.** It drains: nothing new is handed, a batch in doubt is tried once more, and the
     process exits `drained`, or `drain_incomplete`.
8. **Intents and timers do not leave the runtime process.**
   - **Intents.** They reach the executor only through the journal (design §3.1).
   - **Deadlines.** A deadline is folded state that the next tick acts on.
   - **Owner alerts.** They are returned only after the drafts they name commit, as a fixed key
     and an opaque event id (`AGENTS.md` rule 6). Delivering them is the notifier's.
9. **An owner's kill switch with no bid shown records its bid members as `null`, and records its
   owner.** Before this change, the core wrote `OwnerExitRequested` with empty text for `bid`,
   `bid_size`, `floor` and `user` when the control-stream kill switch carried no bid. The journal
   refuses that under journal spec §9 rule 12, so the process stopped instead of acting on the
   switch. The copy now records `null` for the bid members and the issuing owner as `user`, as rule
   12 requires. This tightens the core to the spec and changes no outcome a correct writer could
   reach.
10. **Paper only.** `RuntimeProcess::start` refuses any environment but paper before it takes the
    stream, as `mandate-agentd` and the scheduler do (DEC-968 item 1, DEC-1011 item 5).

## Rationale

Slice 1 is the part of E21-30 that holds without touching the R0 path:
- the process shell;
- the journal tailing with the kill switch first;
- the fencing and in-doubt retry;
- the lifecycle and probes.

Every outcome is tested on the real in-memory journal, which validates each draft the process
writes. That is how item 9's defect surfaced. Production ports then plug into the `Wiring` without
changing the loop.

## Alternatives considered

- **Host the shell's production cycle from `mandate-daemon`.** Rejected for now: its ports are
  private, and opening them edits the R0 path, which is the post-R0 hook's to do.
- **A readiness gate in the runtime process.** Rejected: item 5's windows are exactly when the core
  takes only one input, so a gate would hold nothing and add a path to get wrong.
- **Tail only the rows after the last one handed.** Rejected: DEC-914 item 2 hands the control
  stream whole, and the copy fold makes that safe.
