# DEC-423: A trim that sells everything left to sell is never withheld for the minimum order size

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-02 (UTC) |
| **Decided by** | the coordinator's ruling on [#504](https://github.com/kunwarshivam/mandate/pull/504), recorded by the stream G builder (claim [#123](https://github.com/kunwarshivam/mandate/issues/123)) under DEC-79 and DEC-176. It only lets a risk exit go that is held today, and reducing risk needs no approval (`AGENTS.md` rule 2) |
| **Story or claim** | E6-4, the full-close exemption to the trim's minimum (#504 review, M1); this tests PR is DEC-77 stage 1 |

## Decision

1. **The exemption.** A `trim_to_target` trim whose quantity equals what is left to sell (the
   quantity held less the agent's own non-protective resting sells, DEC-399 item 7) is proposed
   even below the instrument's `min_order_size`. Trading spec §5.3 rule 2 exempts a sell closing
   the full position. `account_rules.rs` and `conduct.rs` already call such a sell always valid.
   Withholding it would hold a risk exit for a venue minimum the broker does not apply, which
   `AGENTS.md` rule 13 forbids.
2. **What stays.** A trim below `min_order_size` that leaves part of the position unsold is still
   withheld (DEC-399 item 5). That order is one the broker would refuse for size. §5.3 rule 2 is
   not the ground: in the gate, its minimum applies to openings only.
3. **The tests PR (DEC-77 stage 1).** `trim::proposals` calls `exempt_full_close` for a trim that
   is below the minimum and equals the unsold quantity. Until the implementation PR, the stub
   refuses the whole call as `GateError::Unimplemented("the full-close trim", "E6-4")`.
   - On `main` that trim was withheld silently.
   - No production caller reaches `trim_proposals` yet, so the stricter refusal reaches no order.
   - The family-B harness's cases never reach it: every trim there is 3 shares of 10.

   The pending test `hand::a_trim_that_sells_everything_left_is_never_withheld_for_the_minimum`
   states four rows:
   - an equity full close of 1 share at a 2-share minimum;
   - a full close of the 1 share not already on sale;
   - a crypto full close of 0.0002 at a 0.001 minimum;
   - a 3-share trim of 10 at a 4-share minimum, which is still withheld.
4. **The implementation PR** makes `exempt_full_close` return `Ok(())` and deletes the
   `#[ignore]` line.
5. **Then the spec and the reference (ES-22).**
   - §5.5 gains the exemption.
   - `reference/mandate/ref.py`'s `below_minimum_order` guard skips a trim equal to the position.
   - A new family-B case states the full-close trim.
   - The harness's `trim_guards` moves in step, as #498 did.

## Rationale

The #504 review's case is 0.0002 BTC at a 600,000 bid (120 dollars), with a cap of 100, a
confirmed factor of 0.5, a 0.0001 increment and a 0.001 `min_order_size`. The trim is the whole
position, and it was withheld at every evaluation. The exemption is rule 2's own, so the gate
sends nothing the broker refuses.

## Alternatives considered

- **Keep withholding and document it.** That holds a risk exit for a minimum the broker does not
  apply to a full close, which rule 13 forbids.
- **Exempt every sub-minimum trim.** A partial sell below the venue minimum is refused by the
  broker, so the order would only fail later. Withholding it until the excess grows is the same
  answer, and it is visible.
- **Compare with the quantity held rather than the unsold quantity.** With a sell already resting,
  the remainder closes the position, but it never equals the quantity held. So that reading
  withholds the last piece of the exit.
