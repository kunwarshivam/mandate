## Decision

Proposed, as relayed; binding only once the founder confirms. Items 6 to 11 follow items 1 to 3 because they were answered after them; items 4 and 5 are the recording agent's readings.

1. **The first hosted version after R0 is a managed cell** (infrastructure §1.1, §3.2: a
   Kubernetes cell running one or more workspace deployments, every process its own pod), not one
   always-on VM under systemd (item 6 says how small it starts). It runs **paper and venue demo environments only**. Live stays out of every cell
   until the Phase 2 gate, counsel's sign-off and the M13 penetration test, as infrastructure §1.1
   and OPS-5 already require, **except** the founder's own Robinhood account, which item 15 makes
   live.
2. **The cell's service pieces are built now, in parallel lanes, in crates off R0's path.** No lane
   edits `crates/mandate-paper/src/lib.rs`, `crates/mandate-shell/src/control.rs`,
   `crates/mandate-shell/src/adapters.rs` or anything under `crates/mandate-shell/src/paper/` until
   R0 closes. A lane uses `mandate-shell` and `mandate-paper` only through what they already make
   public. The lanes, their order and the crates each needs are the
   [managed-cells plan](../tasks/managed-cells.md).
3. **The only spend approved is Cloudflare Workers for `web/`.** No VM, Kubernetes cluster, managed
   database, object store, key management service, container registry, paging tool or paid CI
   runner is approved. Everything the cell needs is built and tested first on a **local and CI
   cell** (kind or k3d on the CI runner and on a developer machine), with no hosting spend. Each
   hosting cost the cell will need is listed in the plan as a decision for the founder, with a
   rough cost.

6. **One architecture, small first.** The same Helm-packaged cell runs on k3s at small scale (one
   or two nodes), grows by adding nodes and then cells, and moves to managed Kubernetes later
   without changing the application or the chart. No work item may assume a host-specific feature
   that would force a rewrite, and nothing that matters only at large scale goes in the first
   slices. The single-VM systemd path in `deploy/` (DEC-822) becomes a dev and demo convenience,
   not the production path.
7. **Cell #1's compute is k3s on one or two Hetzner VMs in Ashburn, VA** (near the brokers, market
   data and US users), with server types confirmed as offered there at order time. The VMs are
   still spend the founder approves with their cost (the plan's H1).
8. **The journal's Postgres runs in the cell, managed by the CloudNativePG operator**: a
   synchronous standby, WAL archived to object storage, point-in-time recovery. This answers
   DEC-434 item 15 (self-run) for cell #1.
9. **Object storage is Cloudflare R2** (location hint eastern North America), off the Hetzner VMs,
   so backups sit in a separate failure domain. Its first story checks that R2 gives the
   write-once retention and the start-up lock check journal spec §6.2 requires: per-object S3
   Object Lock, or R2's bucket lock rules. If only bucket-level, either the start-up check reads
   R2's bucket-lock rule and accepts nothing weaker, or the cold store alone goes to a provider with
   standard S3 Object Lock in compliance mode (for example Backblaze B2), recorded as a decision.
   Storage sits behind a plain S3 endpoint and a lock-check interface, so providers swap by
   configuration. R2 is spend the founder approves with its cost (the plan's H3).
10. **MinIO only as an optional in-cell cache**, never the only copy and never the backup. Using it
    at all puts its AGPL-3.0 licence to the founder and counsel first (DEC-434 item 16).

11. **Three API surfaces, each a lane:** the workspace services API (first, since the web app, the
    CLI and the owner's MCP adapter use it), a minimal first slice of the global control plane
    (directory, cell routing, fleet health; licensing, billing and the relay later), and the data
    plane (market-data ingest and serving, and the internal interfaces between workspace services
    and the agent processes). The plan says for each which spec it implements, what exists, the
    first slice, and how it runs in cell #1 without rework.

Readings the recording agent would accept under DEC-176 once items 1 to 11 are confirmed (each only

4. **DEC-822 is untouched.** The demo's API host (DEC-822, founder-accepted spend for the

5. **The local and CI cell is not staging.** DEC-434 item 19's minimal staging cell needs hosting

   results, never as staging's. A drill the design says must run in staging (infrastructure §6.4)
   is not counted as passed by a local-cell run.

**Until the founder confirms:** lanes may write tests, pure crates, charts and CI jobs that spend
nothing (the conservative reading of items 2 and 3 together), and nothing is bought. If the
founder confirms different answers, this file is rewritten before any lane builds on it.

## Rationale

Going straight to managed cells means the processes, probes, drain and hand-over, vault, packaging
and observability are built once, the way the product ships them, instead of first for a VM under
systemd and again for Kubernetes. Building them now, off R0's files, keeps the first live trade's
path free of merge conflicts. Holding all hosting spend until a local cell passes its drills means
the first money spent runs software already proven against the same chart.

## Alternatives considered

- **One VM, paper, always-on** (offered; not chosen, as relayed). Faster to a hosted paper agent,
  but the supervisor, probes and packaging would be rebuilt for the cell.
- **Wait for R0 before starting the service pieces.** Not chosen, as relayed.
- **Managed GKE or EKS for cell #1, or deciding later** (offered for item 7; not chosen, as
  relayed). The chart keeps managed Kubernetes open (item 6).
- **MinIO as the object store** (asked about; item 10 keeps it to an optional cache): it would put
  the backups on the same VMs as the journal, and bundling it is a licensing question.
- **Treat the local cell as staging** (item 5). Rejected: staging is a hosted environment the
  founder pays for and DEC-434 item 19 names; calling a CI cluster staging would overstate what has
  been drilled.
