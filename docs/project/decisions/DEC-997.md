The coordinating session asked the founder to choose the provider for hosted model calls between
"Claude, direct API" (recommended), "Keep OpenRouter", and "Both". The founder chose **"Keep
OpenRouter"**, and set a spend cap of **$50 a month** for paper and demo. DEC-432 item 14 (the
founder, 2026-10-03) already chose "an aggregator for every call, with provider routing locked per
pinned model" over that decision's recommendation of direct provider APIs. This decision names the
aggregator, fixes how the routing lock is set, and replaces item 14's "no new paid service" spend
guard with a metered cap.

## Decision

1. **The aggregator is OpenRouter.** Every hosted model call, for the platform's own workspaces and
   for users' agents alike, goes through the model gateway to OpenRouter. Direct provider APIs are not
   built in v1. Self-hosted open weights remain the local path after v1 (DEC-432 item 14).
2. **The routing lock, conservatively** (INF-1, INF-2, DEC-432 item 10). Each registry entry pins:
   - **one model id** (OpenRouter's model slug), with no fallback list (`models`), no automatic
     router, no variant suffix (`:nitro`, `:floor`, `:online`, `:free`, or any other), and no floating
     alias (`latest`, `auto`); the entry's `snapshot` names the upstream's dated snapshot the slug
     serves, or the entry is refused at registration;
   - **one upstream provider**: the request sets `provider.order` and `provider.only` to that one
     provider and `provider.allow_fallbacks` to `false`, and `provider.require_parameters` to `true`,
     so a provider that would ignore a pinned parameter is never chosen;
   - **no training and zero retention**: `provider.data_collection` is `deny` and `provider.zdr` is
     `true`, so only zero-data-retention endpoints serve the call (DEC-432 item 15). Both
     OpenRouter's terms and the upstream's must meet this before an endpoint is registered (§4.3's
     data-terms check);
   - **no capabilities**: the request carries no `tools`, `tool_choice`, `functions`, `plugins`
     (OpenRouter's web search among them), or `transforms` (INF-5).

   The response's reported `model` and `provider` are both compared with the pin by exact string
   equality. Any difference, or either one missing, ends the call `identity_mismatch`: no output,
   metered, the endpoint marked unhealthy, the operator alerted (inference §9).
3. **The cap.** Model spend is capped at **$50.00 a month per workspace** for paper and demo,
   enforced by the gateway's meter (E15-9) before any byte leaves: a call is admitted only if the
   month's spend (journal spec §9.18's fold, open reservations at their maximum) plus the call's
   maximum cost is at most $50.00. Per-agent monthly caps sit under it, each at most the workspace
   cap, and the research agent's daily cap (`behavior.research.cost_cap_usd_per_day`) still applies.
   A call past any cap is refused `budget_exhausted`, which is the safe default: no output, so no
   proposal and no order (INF-4, INF-7). The month is the calendar month of the call's risk day. The
   cap is never raised by a restart, a redeploy, or a new month's carry-over; raising it is a new
   founder decision.
4. **The key.** The OpenRouter key lives only in the vault (`SecretSource`, E21-32) or the GitHub
   `production` environment, and only the gateway's real-cell adapter reads it. No builder, agent
   runtime, test, or CI job sees it. CI and every test use recorded responses only, with no network
   to any model provider (rule 8, INF-14).
5. **What it supersedes.** DEC-432 item 14's "Meanwhile: no new paid service beyond the spike key"
   is replaced by item 3's metered cap. Everything else in DEC-432 item 14 stands.

## Rationale

The founder chose to keep the aggregator the spike already uses, which keeps one key and one
adapter. The cost of an aggregator is that it may route one name to several hosts; items 2's lock
and reported-identity check are what keep DEC-67 (no substitution) whole on that path. A monthly
cap is the founder's budget unit; folding it from the meter stream means a crash, a retry, or a
replica hand-over can only count more, never less.

## Alternatives considered

- **Claude through the direct API** (the coordinator's recommendation), and **both**. Not chosen by
  the founder.
- **A daily cap only.** The inference spec's caps are per risk day; a monthly budget is what the
  founder set. Both apply: the daily research cap and the monthly workspace cap.
- **Allow OpenRouter's provider fallbacks within the same model.** Rejected: a fallback may serve a
  different quantization or region, which INF-2 counts as a different model.

## Residual risk, disclosed

OpenRouter's model slug is not itself a dated snapshot. The registry records the upstream snapshot
the slug serves, and the reported model and provider are checked on every response, but a change
behind the slug that reports the same names is not detectable from one response. Inference spec
§10's canary probes are the mitigation, and owners are told this is a limit of hosted models.
