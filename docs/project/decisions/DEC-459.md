# DEC-459: Close the order-state transition journal schema

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-05 (UTC) |
| **Decided by** | The implementing agent under DEC-79 and DEC-176 |
| **Story or claim** | E7-7 and E7-2 integration; claim [#171](https://github.com/kunwarshivam/mandate/issues/171); [PR #598](https://github.com/kunwarshivam/mandate/pull/598) |

## Decision

1. `OrderStateChanged` schema version 1 is a closed transition record with required
   `client_order_id`, `state`, and `risk_clock`, plus always-present nullable transition evidence:
   `attempted`, `broker_status`, `filled_qty`, `reject_code`, `replaces`, `replaced_by`,
   `replaced_by_broker_order_id`, and `lookup`; and always-present booleans `ignored`,
   `cancel_requested`, `cancel_confirmed`, `cancel_overdue`, `adopted`, and `ladder_step`.
2. `state` and `attempted` use the executor's complete `OrderState` vocabulary. `lookup`, when
   present, is `absent`. Quantities remain canonical decimals. Opaque broker status, reject, and
   broker-order values are non-empty text.
3. Every executor writer uses one constructor that fills absent evidence with `null` and false.
   `ladder_step` preserves DEC-408's governed ladder-cancellation marker. The fold remains tolerant
   of historical sparse records, while new appends are exact.

## Rationale

The event and its lifecycle are already specified, and the executor already emits and folds every
member listed here. The missing registration prevented the first broker acknowledgment from being
journaled. Closing the union of existing writer and fold fields makes replay deterministic without
inventing a new transition or loosening validation. One constructor prevents different transition
branches from drifting into incompatible payloads.

## Alternatives considered

- Register only the happy-path acknowledgment fields: rejected because unknown, cancel,
  replacement, adoption, and illegal-transition records use the same event type.
- Leave optional members absent: rejected because journal §4.2 and §9 closed records require every
  member, using `null` for absent values.
- Accept an open object: rejected because the fold could silently begin reading ungoverned fields.
