## Context

DEC-924 item 1 replaces `mandate-shell`'s unconditional `DeploymentRefusal::Live` with an
admission that needs four conditions: the binary is built with `live`; the run passed
`--confirm-live`; the live door's connection and unspent checks passed on real inputs; and the MCP
host is the pinned Robinhood host constant. Item 2: any one missing still refuses `Live` before a
credential is read. None of the four exists on `main` in a form the shell can read: the shell may
not declare `live` (`xtask/layers.toml` gives it to the runner alone), and the flag, the host
constant and the door's real lapse inputs are being built by other lanes (#1354, #1356).

## Decision

1. **Where the inputs go.** `RunFacts`, "what the run supplies beside the stream", gains a
   required field `live: LiveAdmission`. `confirmed_version`'s signature is unchanged, and no
   caller can build `RunFacts` without saying what it supplies, because the field has no default.
2. **One type per condition.** `LiveAdmission { build: Build, confirmation: Confirmation, door:
   DoorChecks, host: McpHost }`. `Build` is `Default` or `Live`; `Confirmation` is `Absent` or
   `ConfirmLive`; `DoorChecks` is `NotPassed` or `Passed`; `McpHost` holds the host the run dials
   (`Option<String>`) and the pinned constant (`Option<&'static str>`). Two-variant enums rather
   than `bool`s, so a call site names which condition it sets.
3. **The host condition.** It holds only when both are present, the pin is not empty, and the
   dialed host equals the pin byte for byte: no case folding, no trailing-dot or other
   normalization. The shell does not hold a copy of the constant: DEC-924 item 3 puts it in one
   place behind `live`, which is the runner (#1354's `PINNED_HOST`), so the runner hands it in. A
   build that pins no host hands `None` and is refused.
4. **The refusing value.** `LiveAdmission::refusing()` has all four conditions missing. Every
   current caller passes it: `mandate-paper`'s `run()` and the shell's own tests. A live
   deployment therefore refuses `Live` exactly as before this decision, in every build, until the
   lanes building `--confirm-live`, the host constant and the door's real inputs replace it in
   `run()`. That includes the build condition, although the runner could state its build today:
   one admission value per call site, replaced as a whole by the lane that wires the live arm, is
   easier to review than four values arriving in four PRs.
5. **Where it is checked.** In phase 1, at the same line the unconditional refusal stood:
   after the document is read and parsed, before the fold and before anything reads a credential
   (phase 1 takes none). A live deployment that is admitted goes on to the fold unchanged, so
   every V-rule still applies to it, V-001 on its connection included. A paper deployment never
   reads the admission.
6. **What the door condition means.** The shell cannot tell a real read from a placeholder. The
   runner may hand `DoorChecks::Passed` only after `chosen` and `unspent` both returned `Ok` on
   the run's own control-stream records, its journal read of the account stream and its snapshot's
   held counts (DEC-918 item 1, DEC-919 item 2). `unsupplied`'s refusal already stops a live
   connection at the door before the shell is reached, so today's runner could not reach the
   shell with a live connection even if it passed `Passed`. The review of the PR that passes it
   judges that the inputs are real.

## Rationale

Each reading refuses at least as much as DEC-924 item 1. Typed inputs on `RunFacts` make the
admission explicit at every call site without changing `confirmed_version`'s signature, which
the runner's source-shape test pins. Exact host equality refuses any variant of the pinned name.
Passing the refusing value everywhere means this PR admits nothing on its own: the founder's lock
opens only when the four inputs are wired, each by a reviewed PR.

## Alternatives considered

- **Add a fourth parameter to `confirmed_version`:** rejected. It would change every call site and
  the runner's source-shape pin for no gain over a required field on the struct that already
  carries the run's facts.
- **A copy of the host constant in the shell:** rejected. DEC-924 item 3 says one place, and two
  copies can drift.
- **Pass the runner's real build (`cfg!(feature = "live")`) now:** rejected for this PR, see
  item 4. It would change no outcome, since the other three conditions still refuse.
- **`bool` fields:** rejected. `LiveAdmission { true, false, true, .. }` does not say which
  condition is which.
- **Normalize the host (lower-case, strip a trailing dot) before comparing:** rejected. It admits
  more names than the constant; the runner dials the constant itself, so exact equality costs
  nothing.
