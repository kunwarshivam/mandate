# DEC-2133: a passkey deployment that rule 201 refuses is refused, never committed without its assertion

| | |
|---|---|
| **Status** | Accepted (agent: a reversible engineering reading under DEC-79 and DEC-176; it only refuses a deployment the manager would never start, and weakens no rule) |
| **Date** | 2026-10-26 (UTC) |
| **Decided by** | `claude-code` (lane L1) |
| **Story or claim** | E9-4 S5; claim #759; [DEC-2131](DEC-2131.md) items 2 and 3; [journal spec](../../specs/journal.md) v0.84 §9.24 and §9.32 rule 253 |

## Context

[DEC-2131](DEC-2131.md) item 2 makes `AgentDeployed` version 3 version 2's members plus `step_up`,
and item 3 has the workspace API write it exactly when it commits a deployment under passkey
step-up. Version 2, and so version 3, is written only when §9.24's rule 201 holds (the connection
established on the control stream at version 2 and not since revoked); otherwise the API writes
version 1, which names no connection and which the deployment manager starts nothing for. Version
1 has no `step_up`, so §9.32's rule 253 refuses a `StepUpAsserted` after it. DEC-2131 does not say
what the API does with a passkey deployment for which rule 201 does not hold.

## Decision

1. A deployment under **passkey** step-up for which rule 201 does not hold is refused, and the API
   appends nothing. Its problem code is the deploy slice's (DEC-2128) to name; it must not be
   `journal_unavailable`, since a retry cannot pass.
2. The API never commits a passkey deployment without the `StepUpAsserted` that records its
   assertion: an assertion left unjournaled leaves its counter out of rule 254's fold and its
   challenge reusable.
3. Under any other step-up, or none, the API writes version 1 or version 2 as today.

## Rationale

- The refused deployment is one the manager would never start (§9.24), so refusing it removes no
  running agent and adds no risk; the owner records the connection and deploys again.
- Writing it at version 1 without the assertion would commit a step-up nothing can audit or count,
  which loosens rule 254's one-use guarantee.
