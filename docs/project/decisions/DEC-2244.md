## Context

`mandate-evaluation` scores the internal paper workspaces' thesis records (DEC-1002), and
`mandate-journal` registers `EvaluationRunRecorded` (DEC-1141). `GET /evaluations/{id}` serves
one (DEC-1143). But nothing calls `mandate_evaluation::evaluate` outside tests, and nothing
journals the record. So E17-8's "reproducible from the journal" and E15-3's scorecards are never
produced. A second gap: the report names its `theses`, `closes` and `cost_model` by digest, but
the crate exposes only the digests, not the objects they hash. A caller therefore cannot store
what the record's references must resolve to (§6.3, §11 check 6).

DEC-1144 split the backtest in two because the run links the executor, which `mandate-cli` may not
reach (DEC-986). The evaluation links no executor: `mandate-evaluation` is a pure layer-6 crate in
neither process group, over `mandate-research`, `mandate-spec` and `mandate-accounting`. The
thesis records it reads are on the same journal the record is appended to.

## Decision

1. **One step, in `mandate-cli`.** The command is `mandate evaluation run --workspace <id>
   --inputs <dir> --evaluation-id <id> --cut-off <instant> --journal <dsn> [--store <dir>]`.
   It reads the records from the journal, evaluates, stores, and appends. No separate binary and
   no hand-carried export: the records scored are the ones the journal holds, at the heads the
   payload names.
2. **The records read.** The workspace's agents are the `agent_id`s of the control stream's
   `AgentDeployed` records, deduplicated and sorted. For each agent stream, in that order, the
   command reads every `ThesisProposed` and `ThesisRevised` record. Each becomes a `ThesisRecord`:
   its stream, `seq`, `hash`, `config_refs.mandate_version` and payload. A thesis record with no
   `mandate_version` refuses `record_unbound`. The mandate documents `check_thesis_record` reads
   come from the store by version; one the store lacks is `None`, so that record refuses as the
   check refuses it. An agent stream with no thesis record is not read. No record at all refuses
   `no_theses`, since rule 145 requires one entry or more.
3. **The inputs.** `--inputs` holds four JSON files that `mandate-canon` parses, strict as
   DEC-1144 item 3 is: every member required, none unknown, decimals as strings, instants in
   RFC 3339 UTC.
   - `decision.json`: `{decision_id, window: {from, to}, minimum_scoreable, z}`. This is the
     registered DEC-122 decision.
   - `closes.json`: `{series: [{instrument, closes: [{at, price}]}]}`, each series oldest first.
   - `cost.json`: `{slippage_per_leg_bps, reference_notional, increment, fees}`, with `fees` in
     the shape the configuration digest spells.
   - `baselines.json`: `{basket: [instrument], index: instrument}`.

   An unreadable input refuses `input_invalid` and names the file.
4. **Internal paper only.** The command refuses `not_internal_paper` before reading any agent
   stream unless both hold:
   - `MANDATE_INTERNAL_PAPER_WORKSPACE` is exactly `true`, read as DEC-1143 item 1 reads the
     API's setting (absent, empty or `false` is off; any other value refuses
     `internal_paper_setting`);
   - every row of the control stream is `paper`.

   `--environment` is not taken: an evaluation is never live. The journal cannot say whether a
   workspace is internal (DEC-1141 item 2), so the operator's setting carries it, as in the API,
   and the stream's environment is checked rather than trusted.
5. **What is stored, then appended.** In order, the command stores:
   - its build text (`mandate-cli/<version>`, digest `code_build`);
   - the three input objects whose digests the report names;
   - the canonical report;
   - last, the payload `evaluation_run_recorded` builds.

   Before appending, it re-reads each stored object by its digest and re-hashes it, refusing
   `artifact_corrupt` on a mismatch. It then appends the payload exactly, as the `system`
   `evaluator` (DEC-1141 item 1). The `artifact_refs` are the payload's references, sorted;
   `theses_head` is not among them (DEC-1142). An evaluation id another record already holds
   refuses `evaluation_id_taken`. A re-run with the same inputs finds the record it committed
   (DEC-290). An evaluation the scorer refuses as a whole (`evaluate`'s `Err`) stores nothing,
   appends nothing, and prints its code. A group's own refusal is part of the report, as DEC-1002
   item 4 says.
6. **`mandate-evaluation` exposes its input objects.** `mandate_evaluation::input_objects(request)`
   returns the canonical `theses`, `closes` and `cost_model` objects whose digests the report's
   `inputs` hold, so a caller stores exactly what the record names. Its tests check each object's
   shape from the request itself, and that its digest is the one `evaluate`'s report names.
7. **Slices.** `mandate-evaluation` and `mandate-cli` are both safety-critical in
   `xtask/layers.toml`, so each slice is a DEC-77 pair (tests PR, then implementation PR), with
   zero missed mutants:
   - (a) item 6;
   - (b) item 3's input parsing;
   - (c) items 1, 2, 4 and 5, the command.

## Rationale

The evaluation's inputs that matter most are the journal's own records. Reading them in the same
process that appends the record, at the heads it names, leaves no gap for a stale or edited export
to fill. The split DEC-1144 needed exists only because of the executor, which this run does not
link. Item 4 mirrors the API's reading, so a record can be written only where the route would
serve it.

## Alternatives considered

- **An evaluator binary that writes artifacts, then `mandate evaluation record`** (DEC-1144's
  shape). It adds a crate and an export format for thesis records, and the record step would have
  to re-read the journal anyway to check `theses_head`. Nothing requires the split here.
- **Read the thesis records from a `mandate journal export`.** An export is verifiable, but it is
  a copy. The command already holds the journal and appends to it.
- **Trust the operator's flag without the paper check, or the paper check without the flag.**
  Either alone is weaker than DEC-1143's reading. Both are cheap.
