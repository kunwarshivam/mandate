## Decision

1. **The exception.** In a workspace of fewer than two active users under
   `independent_approval_required`, V-047 does not refuse a new version of a running agent that
   mandate spec §9.2 classifies as **risk-reducing** against its previous version. Everything else
   V-047 refused is still refused: a **neutral** version, a risk-increasing one, a first version (a
   deployment, which has no previous version), and the high-water-mark reset and the tripwire lift,
   which are not versions. It holds at validation and again when the version is applied.
2. **One classifier.** The exemption reads §9.2's own result for the two documents, as change
   classification (E10-3) computes it, with no second reading of "reducing". §9.2 makes a version
   risk-increasing if any path is, so a version that lowers one limit and raises another is
   risk-increasing and refused (MC-V74). V-047 uses plain `classify(previous, new)`, deliberately
   stricter than V-042's reading, which removes the delegations from both versions and gives the old
   one the new review date (DEC-353 item 4): a version risk-increasing only by what its own
   delegations lift is reducing for V-042 and increasing for V-047, so V-047 refuses it. It must not
   be aligned toward V-042 (#570 round 1).
3. **The previous version is the agent's current version, matched by hash.** The exemption reads the
   document whose canonical hash (§9.1) equals the agent's current `mandate_version`, which the
   platform supplies from the journal and the requester never does. A document validation cannot
   match to that hash is not a previous version for this purpose, and the version is refused: no
   previous version (a deployment), only its identity (environment and connection), part of a
   document, a whole document with a value the schema refuses, a whole document with no current
   version beside it, and a whole schema-valid document that hashes to anything else (MC-V75 to
   MC-V77). The member test (every top-level member present) is what lets the reference classify at
   all; the schema test is what refuses a whole document with a bad value. This replaces the first reading of this item, "a
   whole document, valid against the mandate schema", which #570's round-1 review showed fails open:
   a forged predecessor with a larger cap makes a real increase classify as reducing. V-047 is the
   first rule where a wrong predecessor fails open; for V-042 the same input only refuses more
   (DEC-420 item 4). The tighter reading follows the founder's decision, which exempts a reducing
   version of a *running agent*, so it is taken under DEC-176 (the coordinator's ruling on #570).
   **For E10-1's code:** `PreviousVersion` carries no digest today, so the Rust side cannot match a
   document to the agent's version and refuses every version under V-047 until the type can (the
   same gap DEC-420 item 4 records for V-042). When it can, the digest and the document are read
   from the same agent's journal record, keyed by the agent and never by the connection, so the pair
   is never assembled per request: a sibling agent's current document on the same connection hashes
   to its own `mandate_version` and must not stand in for this agent's (#570 round 2, minor 2).
   **Which version is current** (§9.1, §2.2; walked through each state):
   - *While a new version is pending confirmation or waiting for its safe point:* the version in
     force, the latest `AgentDeployed` or applied `MandateVersionApplied`. A version validated or
     confirmed but not applied is never current.
   - *After a version is rejected at application:* still the version in force; a rejected
     `MandateVersionApplied` changes nothing (§2.2).
   - *After a restart:* the latest applied version in the journal, folded on start; never a version
     held in memory.
   - *Two versions proposed against the same current one:* each is validated against that version.
     §2.2 does not say what happens when the first applies before the second, so this takes the
     reading that refuses: at application the recheck reads the then-current version again, and a
     version validated against a predecessor that is no longer current is refused by V-047 rather
     than classified against the new one.
4. **What it changes downstream.** A lone workspace under the policy can now tighten a running
   agent, including §4.3's conforming version after a `PolicyChanged` when that version classifies
   as reducing. §5.7's loosening of a latched lifetime floor raises `max_loss_from_allocation`, which
   §9.2 rates increasing, so it stays refused there. The rest of DEC-411 item 6 is unchanged and
   still the founder's: whether removing the second user should be refused, or flag the agents
   `policy_nonconforming`.
5. **Records.** DEC-411's status line points here (DEC-344: a decision file is edited only in its
   status); its item 6 reads with this item 1. Spec V-047, §4's input list, and the change history;
   `ref.py`'s V-047 (`reduces_previous`, which takes the current `mandate_version` beside the
   document); MC-V72 to MC-V77; `fuzz_independence_floor`; and nine seeded V-047 bugs in
   `mutants.py`, three from DEC-411 (a stated policy read by its presence, one user counted as
   enough, an unknown count read as two) and six for this exception: a neutral version exempted;
   every version of a running agent exempted; a version exempted when no current version is
   supplied; a document that is not the agent's current version exempted (the hash check dropped);
   and a version whose previous document validation does not have exempted (a partial document that
   matches its own hash), restored in #570 round 2 with the validity test first so it never reaches
   `classify`; and the schema test dropped (a whole document above a schema bound that matches its own
   hash, MC-V77). The reference models validation; item 3's rule at application is spec text that
   E10-1's recheck carries.

## Rationale

Rule 2: reducing risk never needs approval. Refusing a risk-reducing version in a lone workspace
kept the owner from tightening an agent that could not be lifted out of a latch either; exempting
it adds no risk because the classifier says the new version reduces every path it changes. A
neutral version stays refused because it reduces nothing, so nothing is lost by refusing it, and
the founder chose that boundary.

## Alternatives considered

- **Keep refusing every version** (DEC-428 item 6's interim reading). Rejected by the founder.
- **Exempt reducing and neutral versions.** Rejected by the founder.
- **A second, narrower notion of "reducing" for V-047.** Rejected (item 2): two classifiers could
  disagree, and the one §9.2 defines is the one owners see when they confirm.
- **Any schema-valid document as the previous version** (this decision's first reading of item 3).
  Rejected in #570 round 1: it fails open on a forged predecessor.
