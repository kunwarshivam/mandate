## Decision

1. **The exception.** In a workspace of fewer than two active users under
   `independent_approval_required`, V-047 does not refuse a new version of a running agent that
   mandate spec §9.2 classifies as **risk-reducing** against its previous version. Everything else
   V-047 refused is still refused: a **neutral** version, a risk-increasing one, a first version (a
   deployment, which has no previous version), and the high-water-mark reset and the tripwire lift,
   which are not versions. It holds at validation and again when the version is applied.
2. **One classifier.** The exemption reads §9.2's own result for the two documents, as change
   classification (E10-3) computes it, with no second reading of "reducing". §9.2 makes a version
   risk-increasing if any path is, so a version that lowers one limit and raises another is
   risk-increasing and refused (MC-V74).
3. **The previous document must be in hand.** Validation exempts a version only when it holds the
   previous version's whole document and can classify against it. With no previous version, or only
   its identity (environment and connection, as `PreviousVersion` carries when the caller withholds
   the document), it refuses (rule 3, as V-042 refuses a carried delegation it cannot classify;
   DEC-420). The reference reads "whole" as "valid against the mandate schema" (MC-V75).
4. **What it changes downstream.** A lone workspace under the policy can now tighten a running
   agent, including §4.3's conforming version after a `PolicyChanged` when that version classifies
   as reducing. §5.7's loosening of a latched lifetime floor raises `max_loss_from_allocation`, which
   §9.2 rates increasing, so it stays refused there. The rest of DEC-411 item 6 is unchanged and
   still the founder's: whether removing the second user should be refused, or flag the agents
   `policy_nonconforming`.
5. **Records.** DEC-411's status line points here (DEC-344: a decision file is edited only in its
   status); its item 6 reads with this item 1. Spec V-047 and its change history, `ref.py`'s V-047
   (`reduces_previous`), MC-V72 to MC-V75, `fuzz_independence_floor`, and three seeded bugs in
   `mutants.py` (a neutral version exempted, every version of a running agent exempted, a version
   whose previous document validation lacks exempted) carry it.

## Rationale

Rule 2: reducing risk never needs approval. Refusing a risk-reducing version in a lone workspace
kept the owner from tightening an agent that could not be lifted out of a latch either; exempting
it adds no risk because the classifier says the new version reduces every path it changes. A
neutral version stays refused because it reduces nothing, so nothing is lost by refusing it, and
the founder chose that boundary.

## Alternatives considered

- **Keep refusing every version** (DEC-428 item 6's interim reading). Rejected by the founder.
- **Exempt reducing and neutral versions.** Rejected by the founder.
- **A second, narrower notion of "reducing" for V-047.** Rejected (item 2): two classifiers could
  disagree, and the one §9.2 defines is the one owners see when they confirm.
