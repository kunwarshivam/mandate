# DEC-2136: An agent's position read serves its sub-ledger's cost basis, its latest risk mark, and the instrument's protection, each from the journal by one shared reading

## Context

Workspace API spec §4.7 names, for `GET /agents/{id}/positions`, "cost basis, risk mark and its age,
protection and unprotected intervals". DEC-2111 item 5 serves `cost_basis`, `risk_mark`, and
`protection` as `null` until each lands as a decision that types it, and refuses a cost basis
computed in the API by a second reading of the accounting rules. The product flow (step 4: the
agent monitors its position, and the owner sees real risk numbers) needs all three. Every record
they need is already journaled: the agent's own `FillApplied` and `LateFillApplied` (§9.5), the
executor's `MarkUpdated` at version 2 (§9.30, DEC-2305, written since DEC-2380 item 3), and
`ProtectionChanged` (§9.5).

## Invariants first

- The API serves only what the journal records, under names that say what it is; what it cannot
  read is `null`, never zero and never guessed (DEC-2111 item 5).
- One reading per figure: the API, the cell's runtime, and the executor read a figure through the
  same code, so the owner never sees a figure the gate does not use (DEC-2111's refused
  alternative; `mandate-gate-context`'s purpose, DEC-2378 S1).
- Money and quantities are fixed-point decimals; no figure is rounded except as §8.1 rounds it.
- A read never changes the journal, an order, a limit, or a mode.

## Decision

1. **`cost_basis` is the agent sub-ledger's position** (mandate spec §5.1: the account ledger
   filtered to the agent's orders): an object `{qty, basis}`, the signed quantity Q and signed cost
   basis B of trading spec §8.1, folded from the agent's own `FillApplied` and `LateFillApplied`
   records in `seq` order through
   `mandate-accounting`'s own §8.1 rule, never re-derived, at each fill's `qty_gross` and `price`.
   Average cost is not served (§8.1: derived, never stored). It is `null` for an instrument in which
   the agent released any quantity (`PositionReleased`, mandate spec §3.1), to which a
   `CorporateActionApplied` applies, or in which a fill of the agent's charges a fee in an asset
   other than USD (a crypto buy's asset fee, which reduces the quantity received, §8.3): how a
   release, an action, or an asset fee moves a sub-ledger is the accounting fold's, which no read
   serves yet, so the read says "not reported" rather than guess. A release of 0 (a goal's release
   of a flat position) moves nothing and leaves the basis served.

   **The agent's orders** are the executor's: those whose `OrderRequestRecorded` names the agent
   (DEC-2111 item 3), else, with no companion, an `OrderSubmitted` naming it; the order an
   `OrderStateChanged` says replaces or succeeds one of them; and a protective leg the broker created
   whose id names one of them as its entry (DEC-160's first rule, trading spec §2.3). `filled_qty`
   (DEC-2111 item 4) is read over the same orders by the same fold, so it never disagrees with
   `cost_basis.qty` except by what a release took. A fill of a leg whose id names no known entry,
   in an instrument the agent holds, may be the agent's under DEC-160's single-holder rule, which
   needs every agent's lots; the read refuses it (`journal_unavailable`) rather than guess.
2. **`risk_mark` is the instrument's latest version-2 `MarkUpdated` from a session that counts**
   (`regular`, or `crypto`; mandate spec §5.2: an equity's extended-hours quote never moves E), as
   `mandate-gate-context` reads marks for the gate: `{bid, sane, session, marked_at}`, where `bid`
   is the record's bid when it is sane and `null` when it is not, `sane` its verdict, `session` its
   session, and `marked_at` its
   `risk_clock`. The mark's age is `served_at` less `marked_at`. A version-1 mark carries no verdict
   and is not a risk mark (DEC-2305 item 3), so an instrument with none is `null`. A mark that is
   not sane is served with `sane` false, never hidden, and never priced.
3. **`market_value` and `unrealized_pnl` join the position** (trading spec §8.2: market value =
   Q × mark; unrealized = Q × mark − B), computed from item 1's Q and B at item 2's bid, exactly,
   with no rounding. Each is `null` unless `cost_basis` is served, its `qty` is not negative, and the
   latest mark is sane: a short is marked at the ask (§8.2), which a risk mark does not carry. They
   are the risk mark's figures, not the reporting mark's.
4. **`protection` is the account's protective orders in the instrument**, folded from
   `ProtectionChanged` by the rules the executor's own fold applies (`mandate-executor`'s `fold`):
   `{orders, covered_qty, stop, take_profit, unprotected_since}`. `orders` are the protective orders
   resting: named by a `placed` and since neither named by a `cancelled` nor ended by a terminal
   `OrderStateChanged`. `covered_qty` adds each `placed`'s `qty`, and takes away a `cancelled`'s
   `qty` where it is journaled and each ended order's quantity, never below 0. `stop` and
   `take_profit` are the prices of the latest `placed` that names them, `null` once no order rests.
   `unprotected_since` is the earliest start (`risk_clock`) of an unprotected interval still open:
   opened by `unprotected_start`, ended as the executor's fold ends it (an `unprotected_end` awaiting
   no cancel and not uncovered, or acknowledged, or a later start that replaces it), `null` when
   none is open. An order named twice is served once, with the executor's covered sum. It is the
   account's, like `account_positions`, since a protective leg the broker
   created may have no `OrderRequestRecorded`; with no record it is the empty object
   (`orders` `[]`, `covered_qty` `0`, the rest `null`): unprotected, which is what the journal says.
5. **One reading, in `mandate-gate-context`.** The sub-ledger's basis and the protection fold are
   their own folds in `mandate-gate-context`, beside `Journaled`, and the latest mark is read by the
   one function `Journaled` already reads marks with; the API calls them. They are separate folds
   because `Journaled` refuses a corporate action outright, which would make every position read
   unavailable; these mark only the instrument `null`. `mandate-accounting` exposes the §8.1 fill
   rule it already applies (`Position::after_fill`) rather than anything re-deriving it. A property
   test in `mandate-executor` (a dev-dependency only) drives random account streams through both
   the executor's fold and the protection fold and asserts the same resting orders, covered
   quantity, prices, and open intervals: the executor's fold is the oracle.
6. **Unreadable is refused, never partial.** A row the reading reads that does not parse makes the
   whole read `journal_unavailable` (DEC-2112 item 1), as an own fill that cannot be read already
   does. So is an `OrderStateChanged` naming, or replacing, an order the journal never submitted or
   placed, which the executor's fold refuses too, and a protective order id that is empty or longer
   than 200 characters. Another agent's fill stays passed over unread (DEC-2112 item 2), unless it
   is a fill of a protective order, which item 4's account-wide protection reads.

## Consequences

- `read-models/positions` types the three members and adds `market_value` and `unrealized_pnl`;
  the spec PR closes the schema with valid and invalid examples, and the code PR follows.
- The agent's own risk figures (E, H, drawdown, E₀, the latched limits and the mode) are the
  account risk fold's (E6-15). They are served once the executor journals that fold's records in
  the cell, as a separate read.

## Alternatives considered

- **Compute the basis in the API from fill prices.** Refused, as DEC-2111 refused it: a second
  reading of §8.1 would drift from the accounting fold.
- **Serve the latest sane mark only.** Refused: an instrument whose latest quote failed its checks
  would show a fresh-looking old price; `sane` false says what the gate sees.
- **Serve protection as the agent's own orders only.** Refused for now: a bracket's legs the broker
  created carry no `OrderRequestRecorded`, so filtering by owner would hide real protection.
