## Decision

The [agent harness spec](../../specs/agent-harness.md) v0.1 is the draft contract for how a confirmed
mandate version becomes a running agent process, and for the research loop inside it. It is the
caller side of the [inference spec](../../specs/inference.md) ([DEC-432](DEC-432.md)) and assumes its
INF-1 to INF-16. It restates DEC-04, DEC-08, DEC-16, DEC-67, DEC-97, DEC-99, DEC-101, DEC-120, and
DEC-131, and adds these readings.

**Accepted (agent):**

1. **Two loops, one writer.** The research worker runs on its own task and never appends to the
   journal. It hands every result to the runtime core as an input, and the core journals it. Journal
   spec §1 principle 3 (one writer per stream) and HI-7, HI-16.
2. **Thesis records are appended by the runtime core.** `mandate-research`'s doc comments say "the
   executor journals them" for `ThesisProposed`, `ThesisRevised`, and `UniverseChanged` alike. Journal
   spec §2 makes the agent runtime the agent stream's only writer and the executor the account
   stream's, so the core appends the thesis records and the executor copies `UniverseChanged` with a
   `causation_id`. The spec wins over a doc comment; the comment is corrected in E19-9. No behaviour
   changes: the crate appends nothing.
3. **Construction** (spec §5.1). The process re-checks the mandate's hash, schema, and document-only
   V-rules; loads the policy with unreadable keys at their strictest value; loads every pinned
   model, treating a withdrawn or unloadable one as missing; and takes the writer only after that.
   A failure in research-only configuration disables research rather than the agent, so exits and
   quant models keep running.
4. **The description is guarded at construction.** If `behavior.description` fails the gateway's
   prompt guard (inference spec §8.3), research is disabled for that version and the owner is
   alerted with opaque text, since every call would end `input_rejected`. It only restricts.
5. **The research entry's content hash covers the retrieval plan and the validation bounds**, not
   only the template (spec §1.3, §10.1 item 1). What the model is shown is then pinned by the owner
   under rule 11, and a change to it is a new signal-model version (mandate spec §9.2's signal-model
   row). Harness code is a platform build named by `actor.build`, not a mandate version. The
   inference spec's next revision is asked to add the plan to its registry entry.
6. **One call per run, and the model chooses no reads** (spec §6.2). This matches INF-5 and inference
   spec §8.3: retrieval happens before the call, in deterministic code. A multi-call run is an open
   question (spec §13 item 6).
7. **Default bounds** (spec §6.3, §6.5, §7.1): one run in flight; 20 daily bars per instrument; 50
   news items over 48 hours at 2,000 bytes each; 20 filing excerpts over 7 days at 4,000 bytes each;
   50 instruments per screen; 50 theses of memory; at most 4 theses per output; horizon at most 30
   days; a 60 s retrieval timeout. They are engineering values inside the content hash, so a change
   is a new version the owner confirms. Spending is bounded separately, in dollars, by the owner's
   cap and the gateway (items 15 and DEC-432 item 4).
8. **The run schedule counts from the last call or reservation**, whichever is later, so a crash loop
   cannot call faster than `behavior.research.interval_s`. Event sources never bring a run forward.
   The harness never retries a call within a run; the gateway's transport retries are the only ones
   (DEC-432 item 3). After a restart, a run whose record committed but whose judging batch did not
   is not judged: it ends there, and the next run waits for its due time.
9. **Mode gates research** (HI-15): `normal` runs in full; `exits_only` runs review-only, so only
   invalidations count; `paused`, `stopped`, and Holding make no call. A run in flight is cancelled
   on a pause, a Stop, a kill switch, or a version that changes or removes the research agent. This
   saves spend and adds no risk.
10. **The version in effect judges** (HI-17). A run that started under one version and finishes under
    another is judged under the version in effect, and its output is ignored as `not_pinned` if the
    research agent's pin changed. This reads mandate spec §8.2's "must equal the pinned values" at the
    moment of judging, the stricter of the two moments.
11. **What a model is never shown** (spec §6.4): besides INF-8's list, no dollar figure of the agent
    or account (allocation, limits, equity, P&L), no autonomy rules, delegations, tripwires, or
    review date, and no approval content. Positions are shown as instruments held, without
    quantities. This only narrows INF-8.
12. **The platform fills the facts** (HI-18, spec §6.5): ids, lineage, revision, `as_of`,
    `expires_at`, asset class, sources, corroboration, and the pins. The harness's own checks
    (`unknown_instrument`, `unknown_evidence`, `duplicate_instrument`, `forbidden_language`,
    `revisions_not_enabled`, `unknown_thesis`) refuse before admission and are journaled as candidate
    verdicts, never as mandate spec §8.5 reasons. `forbidden_language` refuses price targets and
    statements of likely profit (DEC-126) and never "buy" alone, since the research agent may be
    directional (§8.1).
13. **Invalidation verdicts come from the model's output and only remove** (spec §6.7). They are
    taken without corroboration or approval, because removal is exits-only and adds no risk (MI-19,
    rule 2). The journal has no event for the verdict yet, so until E19-5 adds one (journal spec
    first), the harness removes nothing by invalidation and theses end at their horizon. Research
    leaves the internal thin slice only after E19-5.
14. **Backlog epic E19, Agent harness**, with stories E19-1 to E19-9. E18 is the enterprise harness
    (DEC-149), E21 is taken by the infrastructure design (DEC-434, in review), and E19 was left to
    this spec. Existing stories (E6-1, E15-1, E15-3, E15-6 to E15-10, E17-2, E17-5, E17-7, E17-8)
    keep their scope.

**Proposed (founder):**

15. **The thin slice's dollar budgets.** `behavior.research.cost_cap_usd_per_day` for the internal
    research agents, and the internal workspaces' daily model-spend quota. **Recommendation:** 5 USD
    per agent per risk day and 20 USD per workspace per day, revisited after two weeks of spike paper
    runs show the real cost per run. **Meanwhile:** no product research runs until set; the spike
    keeps its own one-call-per-day bound.
16. **A DEC-99 pass belongs to one content hash.** Should any change to the research entry (template,
    retrieval plan, bounds, or model) need its own forward paper evaluation before users' agents may
    pin it? **Recommendation: yes.** A pass on one entry says nothing about another, and an
    unevaluated entry reaching users would be the platform's idea without evidence. It costs a new
    three-month window per change, so changes should be batched. **Meanwhile:** yes.
17. **Retaining licensed source text.** Retrieved news and filing text is kept as artifacts for the
    retention period (journal spec §6.3, six years), which audit and replay need. Some news licences
    may forbid that. **Recommendation:** allowlist only sources whose terms permit retention, and
    ask counsel to confirm. **Meanwhile:** the allowlist admits only such sources (data-plane spec,
    in draft).

## Rationale

The HLD draws the agent runtime as boxes, and the code has a pure runtime core and a pure research
contract with no process and no model between them. That gap is the data plane's critical path: a
research agent cannot run until something gathers data, calls the gateway, records the result,
checks it, and hands it to admission. Each reading picks the option that adds no risk: one writer,
no model-chosen reads, a missing output wherever anything is unclear, research off whenever the mode
is not `normal`, and every behaviour the owner relies on inside the hash the owner pins. Items 15 to
17 involve spending, a gate on what reaches users, and licence terms, which DEC-79 reserves.

## Alternatives considered

- **A tool-using research loop** in which the model asks for reads. Rejected for v0.1: it lets
  injected text steer which inputs the model sees next, and the inference spec gives models no tools
  (INF-5). Kept as an open question.
- **A research worker that appends its own records.** Rejected: two writers on the agent stream
  break journal spec §1 principle 3.
- **Redacting the description before each call.** Rejected: it silently changes the owner's text.
  Disabling research and telling the owner keeps the text the owner confirmed.
- **Judging a run under the version it started with.** Rejected: an output from a model the owner
  has just unpinned would still be admitted.
- **Waiting for an invalidation event before any research run.** Rejected: theses already end at
  their horizon, so holding them to it adds no risk inside the internal thin slice, where every
  admission is `ask`.
- **Showing the model the agent's dollar figures.** Rejected: sizing is deterministic (rule 4), and a
  model that sees the account invites outputs about size.
