# DEC-937: The runner's ports name a broker session, a live run needs `--confirm-live` and turns core dumps off, and the Robinhood login dials one endpoint per build

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-16 (UTC) |
| **Decided by** | `claude-code` (builder), under DEC-79 (reversible engineering), DEC-176 (each reading only tightens) and DEC-929 |
| **Story or claim** | G1a, LT-1, LT-9 of the [first live trade brief](../tasks/first-live-trade.md); claim #1352 |

## Decision

1. **Broker-neutral ports.** `Ports::Transport`, which only an Alpaca transport could fill, is
   replaced by `Ports::Session: Session`. A `Session` gives the run its preflight
   (`BrokerFacts`) and its production cycle; every `TradingTransport + DataTransport` is one, so
   the Alpaca paper run calls exactly the code it called before. `Ports::connect` takes the
   `Connection` the live door chose from the connection record and the confirmed mandate, so the
   ports build the broker that record names. The door now returns that connection; a run whose
   door read no deployment but whose fold passed has no connection and refuses
   (`Cause::Absent`, "the connection the deployment names") rather than guess one. The fold
   refuses every such case first, so this only closes a gap.
2. **The Robinhood login and its endpoint.** `Production::connect` on a Robinhood connection
   runs O1b's login (`AuthServer::discover`, `CallbackListener::bind`, `register`, `begin`, one
   callback within `LOGIN_LIFETIME`, `exchange`) on a current-thread runtime that the session
   keeps for its MCP client (DEC-928 item 2). The authorization URL is printed on stderr for the
   founder to open; the token is never printed and stays in memory (LT-9). Which endpoint it
   dials depends on the build, and `robinhood::endpoint` decides it:
   - the default build holds no Robinhood host and refuses `robinhood_not_built` (LT-1);
   - the `live` build dials `https://agent.robinhood.com/mcp/trading`. `MCP_HOST`,
     `agent.robinhood.com`, is the host Robinhood's support article publishes (decision log
     OD-12), written once and compiled only behind `live` (DEC-924 item 3). If
     `MANDATE_RH_SIM_ENDPOINT` is set in this build, it refuses rather than ignoring it;
   - the `rh-sim` build dials only the endpoint `MANDATE_RH_SIM_ENDPOINT` names, and only when it
     is exactly `http://<IPv4 loopback>:<port 1–65535><path>` with no credentials, query or
     fragment. Anything else refuses `rehearsal_off_loopback`, and an unset variable refuses
     `rehearsal_endpoint_unset` (DEC-922 items 1 and 2). When both features are on, `rh-sim`
     wins, so such a build dials loopback only.

   The login accepts one authorization host, the endpoint's own. Robinhood has not published
   where its authorization server lives. If it is on another host, discovery refuses that host,
   and the host is added in a reviewed PR (DEC-847 item 2). The runner's `rh-sim` feature does
   not turn on `mandate-mcp`'s (DEC-926 item 2), so the rehearsal build passes both flags
   explicitly. Until the MCP session carries the token (O2), a logged-in Robinhood session
   (`Linked`) reads and sends nothing: its preflight and cycle answer `Cause::Absent` with
   `SESSION_UNBUILT`, so a Robinhood run stops after the login and before any broker read.
3. **`--confirm-live`.** The runner takes exactly one acknowledgement, `--confirm-paper` or
   `--confirm-live` (`Args::acknowledged`). Giving both is a usage error. Giving neither is the
   same usage error as before ("--confirm-paper is required"). Right after the door chooses the
   connection, and so before the shell's fold and every credential read, `acknowledge` refuses
   a live connection without `--confirm-live` (`LiveUnconfirmed`) and a paper connection given
   `--confirm-live` (`PaperUnconfirmed`). Each environment needs its own acknowledgement, so a
   paper flag can never stand in for a live one. A paper run with `--confirm-paper` is
   unchanged.
4. **Core dumps off.** `acknowledge` then calls `Ports::harden` for a live connection only,
   before `connect`. `Production::harden` is `disable_core_dumps`: `setrlimit(RLIMIT_CORE, 0)`
   for both the soft and the hard limit, and `PR_SET_DUMPABLE` 0. Clearing the dumpable flag
   also stops a core-dump pipe handler, which a zero limit does not always stop, and a
   same-user `ptrace` from reading the token. If either call fails, the run refuses
   (`PaperError::Harden`) before any credential is read. Both calls go through `rustix`'s safe
   wrappers, its first direct use, because the workspace forbids `unsafe`.
5. **Unchanged, and left for later lanes.** The shell's `DeploymentRefusal::Live` (DEC-924,
   `control.rs`) still refuses every live deployment at the fold. That fold runs after
   `acknowledge` and before `connect`, so no build reaches the login yet. In front of both, the
   door's `unsupplied` (DEC-919) refuses every live connection until the live arm hands it the
   lapse evidence, so `acknowledge` sees a live connection only after that arm lands. DEC-935's
   clock read still follows the session's preflight. The Robinhood
   preflight, the MCP session (O2), the shell constructor for a Robinhood cycle, and
   `mandate-mcp`'s `rh-sim` build (#1349) are other lanes.

## Rationale

The record already chooses the broker (G1a), so the ports have to build whichever broker it
chooses rather than an Alpaca transport by type. A blanket `Session` impl for Alpaca transports
keeps the paper path's code and every existing test double unchanged.

The acknowledgement is checked where the run first knows its environment, so a missing
`--confirm-live` refuses before anything else can happen. Requiring the matching flag, rather
than allowing both flags, means `--confirm-paper` can never stand in for a live run.

Choosing the endpoint per build in one pure function puts LT-1 and DEC-922 item 2 into code that
CI tests: the default build's answer, the rehearsal's loopback-only reading, and the `live`
build's answer in a local build. The binary-bytes test checks that the default binary contains
no Robinhood host.

## Alternatives considered

- **An associated `Ports::Transport` per broker:** a generic run cannot name a Robinhood type
  in a build without `live`, and the shell's cycle constructor takes Alpaca transports only.
- **Accepting `--confirm-live` beside `--confirm-paper`, or either flag for either
  environment:** this lets a paper acknowledgement stand in for a live one.
- **Checking `--confirm-live` before the door:** this reorders the door's exact refusals, which
  `src/tests.rs` pins (DEC-918 item 3), and the door already refuses before any credential.
- **Writing `/proc/self/coredump_filter`, or `libc`:** the first still writes a core file and
  leaves `ptrace` open; the second needs `unsafe`.
- **Several authorization hosts, or a guessed Robinhood OAuth host:** this adds a live host
  that nobody has reviewed. One host fails closed.
- **Turning on `mandate-mcp/rh-sim` from the runner's `rh-sim`:** DEC-926 item 2 forbids it, so
  that no workspace build links the rehearsal transport.
