## Context

R5, observed at the rehearsal's 2l on `main` at `1b9fbb4`: a Robinhood run's preflight takes the
asset record, the latest IEX quote and the trailing window's IEX minute bars from Alpaca (DEC-933
item 2), and the asked opening's wake and cross-check read the IEX quote again (DEC-943, DEC-945).
`Linked::session` built the Alpaca client from the environment's paper keys, so an agent's run,
which reads no key (rule 8), stopped at `MARKET_UNREAD`. The `--bars` directory must also hold the
pinned ticker's trusted IEX daily bars, which only `mandate download` writes, from Alpaca, and
which cannot exist for the rehearsal's made-up `RHETF`.

## Decision

1. **The `rh-sim` build's market source is a fixture, and only that build has one.** A
   `SessionMarket` trait (mandate-paper) says where a Robinhood session's market reads go;
   `Market`, a type alias chosen by `cfg(feature = "rh-sim")`, is `SimMarket` in the rehearsal
   build and `AlpacaPaperHttp` in every other build, the `live` one included. `SimMarket` and its
   variable `MANDATE_RH_SIM_MARKET` are compiled only with `rh-sim` (and in the crate's own unit
   tests); `dial` reads the variable through `Market::FIXTURE_VAR`, which is `None` for Alpaca, so
   a build without `rh-sim` never holds the variable's name. The rehearsal build no longer reads
   Alpaca keys for a Robinhood session at all, which only tightens DEC-922 item 2 (it now reaches
   no Alpaca host either). `tests/market_fixture.rs` reads the runner binary it is built with:
   without `rh-sim` (default and `live`) the variable's bytes must be absent, with `rh-sim`
   present, each case the other's seeded bug; the `rh-sim` case failed on the tests-first commit.
   CI runs the absence case in the default build only (DEC-529 item 3 lets it only compile
   `live`), and the `live`-without-`rh-sim` runner is held by the same `cfg`, which that compile
   checks; the builder ran the absence case with `--features live` too.
2. **The fixture answers below `mandate-alpaca`'s clients, with Alpaca's own bodies.** `SimMarket`
   implements `TradingTransport` and `DataTransport` over `<dir>/market.json` (strict JSON, every
   member decimal or plain text: `symbol`, `asset_id`, `exchange`, `bid`, `ask`, `bid_size`,
   `ask_size`, `minute_volume`). It answers only `GET /v2/assets/{symbol}` (an active, tradable,
   whole-share US equity with no attribute), the latest IEX quote of its symbol, stamped with its
   clock as the request is answered, as a live feed stamps it, and the bars request of its symbol,
   one bar at the bid with the fixture's volume for every minute from the request's first start
   to its last. Anything else is `RefusedPath` with nothing answered. So `DataClient`'s age bound
   (the rule set's `iex_quote_max_age_s`), DEC-936's 250 ms skew, the symbol, the feed, the bars'
   grid, window and page checks, the shell's liquidity and gate checks, and DEC-945's cross-check
   of Robinhood's ask against the IEX ask within the collar all apply unchanged; the unit tests
   show the stale (10.001 s), skewed (251 ms) and wrong-symbol cases refused by the clients
   themselves, with the fixture's clock offset from the reader's. In the rehearsal both clocks are
   the system's, so a stale or skewed quote cannot occur there end to end; those refusals are
   shown by the unit tests only. A fixture that is missing or unreadable gives no market, and the
   preflight refuses `MARKET_UNREAD` as before.
3. **The stored daily bars come from a dev-only example.** `examples/rehearsal_bars.rs`
   (mandate-paper, built from its dev-dependencies, so no product binary holds it) writes the
   ticker's IEX daily-bars dataset with `mandate-marketdata`'s own `Store`: the last 30 regular
   sessions through the last one completed at the system clock, closes rising by 0.1 to the given
   close, 50,000,000 shares a session. The shell trusts it by the same `inspect` rules as a
   download (coverage through the last completed session, no gap, no split).
4. **The rehearsal's numbers.** `market.json` scripts the IEX quote at 84.99 / 85.01 beside the
   simulator's Robinhood ask of 85, inside DEC-529 item 12's collar (`collar_liquid_x` 0.01 for a
   median dollar volume above 50,000,000), 20,000 shares a minute, and the daily closes rise to 85.
   `scripts/r0-rehearsal.sh` builds the example (step 1c), writes both (2a0) and hands the runner
   `MANDATE_RH_SIM_MARKET` and `--bars`.

## Rationale

The rehearsal must run the same code the live order runs. Answering at the transport, with
Alpaca's wire format, keeps every client, shell, gate and cross-check rule in the path, and the
type alias keeps the fixture out of every build that can reach a broker. No key is read and no
host is dialed (rules 7 and 8).

## Alternatives considered

- **Serve the Alpaca endpoints from `mandate-rh-sim` over loopback.** Rejected: the Alpaca clients
  pin `https` to Alpaca's two hosts (ES-23), so the runner would need a loopback Alpaca transport
  anyway, and the simulator (a pure crate) would need HTTP routes for a second broker.
- **A fixture quote with a scripted fixed timestamp.** Rejected: a quote must be at most 10 s old
  at the preflight, the wake and the check, which a file written before the run cannot be.
- **A fixture mode in `mandate download`.** Rejected: the founder's CLI would then be able to
  write trusted market data from a file.
- **Keep reading Alpaca keys in the rehearsal build when they are set.** Rejected: the rehearsal
  would then read real market data with real keys, which the fixture makes unnecessary.
