## Context

Alpaca's `FILL` activity names the broker's own order id and no `client_order_id`. The executor's
fill path (`mandate-executor` `orders.rs` `fill`, reached from reconciliation's step 2 and from
broker answers) attributes a fill by `client_order_id` alone. Every such fill is applied
unattributed, as external activity: the agent's order reads `Filled` with nothing applied to it, its
sub-ledger is empty, and its kill switch (trading-domain spec §5.5) sells none of its shares. DEC-955
item 3 matches by the broker's id only in `mandate-paper`'s own-fill pass. Journal spec §9.16
(DEC-869) journals the broker's id on `OrderStateChanged` version 2, but says the executor's fold
does not read it.

## Invariants first

1. A fill the broker reports for one of the agent's orders, by either id, is applied to that order,
   so the agent's kill switch sells exactly its filled lots (rule 13).
2. Nothing is attributed by guess: a fill reaches an order only through an id that order's own
   journaled records carry, once, and only when the instrument, side, and quantity checks pass.
3. A fill that cannot be attributed stays external activity: applied to accounting, every agent
   `exits_only`, the owner alerted (§7.1), and no agent's switch sells those shares.
4. The attribution is folded from the journal, never held only in memory, so a restarted executor
   attributes the same fills.

## Decision

1. **The fold reads `broker_order_id`.** For each order it keeps the `broker_order_id` its
   version-2 `OrderStateChanged` records carry. Two different ids on one order leave it with none.
   Journal spec v0.80 §9.16 says so; no record, member, rule, or vector changes.
2. **A fill with no `client_order_id`** and a `broker_order_id` is the order's whose records carry
   that id, when exactly one order's do, and is then judged as a fill that named that order: the
   same instrument, side, and no more than the order has left. Any check that fails leaves it
   unattributed, as today.
3. **Everything else is unchanged.** A fill that names a `client_order_id` is judged by it alone. An
   unattributed fill is still applied to accounting, every agent goes `exits_only`, and the owner is
   alerted. Replay of journaled fills is unchanged: a `FillApplied` keeps the attribution it records.

## Consequences

- `mandate-executor`'s fold keeps the broker id per order, and `fill` falls back to it.
- The tests PR pins: a reconciled fill naming only the broker id is applied to the agent's order;
  the agent's kill switch then sells exactly those lots; a fill whose broker id matches no order, or
  one of two orders', stays external and every agent goes `exits_only`; the attribution survives a
  restart; and DEC-2347's `holds_lots` agrees.
- DEC-2347 item 9's gap closes.

## Alternatives considered

- **Ask the broker for the order's id at each fill** (DEC-955 item 3's lookup). Rejected for the
  executor: the id is already journaled, and a read per fill adds a call that can fail.
- **Attribute by instrument and side alone.** Rejected: it guesses, and could hand an owner's fill
  to an agent.
