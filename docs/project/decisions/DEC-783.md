# DEC-783: Close the anchor and segment records (journal spec v0.27 §9.14)

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-08 (UTC) |
| **Decided by** | An agent (Claude Code, lane L5's builder) under DEC-79 and DEC-176, on the coordinator's assignment and the L5 lead's rulings on items 6 and 7. Closing two records from the shapes the code already reads refuses unknown members and adds no risk |
| **Story or claim** | E12-3; claim [#748](https://github.com/kunwarshivam/mandate/issues/748) |

## Context

Workspace API §4.8.1 and DEC-767 take a verification's trusted start from a `SegmentExported`
manifest or an `AnchorComputed` event in the journal, never from the request. Neither record had a
closed payload: journal spec §9 listed their members in prose ("leaves, root, timestamp token";
"manifest hash, range"), and `mandate-journal` catalogues both without a schema. The shapes did
exist in code: the verification command reads an anchor file "as `AnchorComputed` records it"
(`crates/mandate-cli/src/journal.rs`, DEC-115 item 6), `mandate_journal::Anchor` holds the leaves
and root, and `mandate-journal-cold`'s `SegmentManifest` holds DEC-263's six fields and their hash.
So `mandate-audit` could resolve only a genesis start (DEC-782 item 2).

## Decision

1. **Journal spec v0.27 adds §9.14**, which closes `AnchorComputed` and `SegmentExported` on the
   control stream at schema version 1, with rules 113 to 118.
2. **No new shapes.** `AnchorComputed` is `{leaves: [{hash, seq, stream_id}], root, token}`: the
   anchor file of DEC-115 item 6, member for member, plus the token §9's row names.
   `SegmentExported` is DEC-263's six manifest fields, with `stream` spelled `stream_id` as every
   other record spells it, and the manifest's hash.
3. **Every hash is a `digest`, not a `ref`.** Leaf hashes and the root are event hashes, and the
   manifest and its file live in the cold store, not the journal's artifact store. A `ref` would fail
   §11 check 6 on the control stream. The token is a `ref`, because §10 stores it as an artifact.
4. **What can be recomputed is recomputed at append.** The root over the leaves (rule 114) and the
   manifest hash over the six fields (rule 117) are checked when the record is appended, so a record
   whose members contradict its own hash is refused, never stored.
5. **Tenant isolation, order and the anchor's own leaf.** Every stream named is in the control
   stream's own workspace, as §9.13's rule 107. Leaves are strictly ascending by `stream_id` bytes,
   so no stream has two, and one leaf names the anchor's own control stream (rule 113): a control
   stream always holds its `StreamOpened` before an anchor, so omitting that leaf would dodge
   `anchor_self_mismatch`. A segment's bounds and genesis are rule 107's (rule 116).
6. **The control stream's own leaf is a §11 per-range check, not an append rule** (the lead's
   ruling): the leaf must name the event just before the anchor, `seq` one less than its own, and an
   append rule cannot see the `seq` the journal assigns. The check is `anchor_self_mismatch`,
   reported at the `AnchorComputed`, and §9.13's `VerificationRun` admits the new code (rule 111
   reports it at an event). It only adds a check.
7. **`SegmentEvicted` stays open** (the lead's ruling): a backlog row under "Spec follow-ups".
8. **A null token is allowed, and such an anchor is not a trusted start** (the reviewer's major,
   the conservative reading). §10 says only that timestamping outages are queued, retried and
   journaled as gaps; it does not say what an unstamped anchor proves. This decision reads it as
   proving nothing outside the journal: an anchor that only the journal vouches for is the
   self-vouching start DEC-115 item 5 refused. So `token` may be `null` at append, so the anchor
   and its gap are recorded, but a verifier never takes a start from it; a range is entered from
   genesis, a `SegmentExported`, or a stamped anchor. The later record that supplies the token is
   the anchor stamp record, `AnchorStamped` (backlog): it backfills an outage's token and re-stamps
   before expiry, and makes the anchor a start once it is journaled.
9. **Only a `system` actor writes either** (rules 115 and 118): the anchoring job and the cold-store
   exporter are workspace services.

## Rationale

These two records are the trusted starts §11 reads. Closing them in the shapes the verification
command, `mandate-journal` and `mandate-journal-cold` already use makes one definition of each. The
append-time recomputation means the journal never holds an anchor or a segment record that
contradicts itself, which is what lets a verifier trust it as a start.

## Alternatives considered

- **`ref`s for the manifest and the root.** Rejected for item 3's reason.
- **A `range` member as §9.13's.** Rejected: DEC-263's manifest already names the same bounds, and a
  second spelling would let the two disagree.
- **The control-stream leaf as an append rule.** Rejected by the lead (item 6).
- **Closing `SegmentEvicted` too.** Deferred by the lead (item 7).
