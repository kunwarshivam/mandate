# DEC-2088: Admission reads release.yml's signature as the bundle's cosign-sign attestation

| | |
|---|---|
| **Status** | Accepted (agent: a reversible engineering decision under DEC-79 that keeps DEC-2016's check, the same identity over the same digest, and loosens nothing) |
| **Date** | 2026-10-31 (UTC) |
| **Decided by** | An agent (Claude Code), on the founder's instruction to get staging ready |
| **Story or claim** | Staging's infra applies on 2026-10-31 (runs 41149569495, 41150795629); [DEC-2016](DEC-2016.md) items 1 and 4; #2973 |

## Decision

1. The admission policy `mandate-release-signed` keeps its images, identity (release.yml on main,
   GitHub's issuer), Fulcio and Rekor, and `signatureFormat: bundle`. It now also lists one
   attestation, `release-signature`, of predicate type `https://sigstore.dev/cosign/sign/v1`.
2. `deploy/tests/test_gitops.py` pins that authority and seeds the attestation's removal and a
   wrong predicate type.

## Rationale

Both staging applies on 2026-10-31 stopped at the workspace HelmRelease: the webhook denied its pods
on their signatures. policy-controller's own tester, v0.13.1, the version staging runs, gives the
cause for every image of release 0d659695: "bundle support for image signatures is not yet
implemented". #2973 set `signatureFormat: bundle` because cosign 3 writes no legacy `.sig` tag, but
this policy-controller reads a bundle only as an attestation. In a Sigstore bundle, `cosign sign`'s
signature is an in-toto statement of predicate type `https://sigstore.dev/cosign/sign/v1` whose
subject is the image digest. Requiring that attestation from the same identity checks the same
thing DEC-2016 asks: release.yml on main signed this digest, logged in Rekor.

With the tester, against the policy as written here:
- all fourteen images of release 0d659695 pass;
- the same image fails under any other identity;
- an image outside `ghcr.io/kunwarshivam/mandate/**` stays uncovered, as before.

## Alternatives considered

- **Sign with cosign's legacy format again** (`--new-bundle-format=false`), and drop
  `signatureFormat: bundle`. Rejected for now: it needs a new release before staging can admit
  anything, and it reverses #2973's reading of cosign 3.
- **Attest the SBOM and require that.** Rejected: release.yml attests the SBOM on each
  architecture's image, not on the index a chart deploys, so the index has none.
