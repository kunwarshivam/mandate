# DEC-761: The causal trace follows a closed table of links, not causation_id alone

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-08 (UTC) |
| **Decided by** | The agent in lane L5, under DEC-79 and DEC-176: a reading of an unclosed API contract that adds a bound or a refusal and loosens no rule |
| **Story or claim** | E12-6 ([#756](https://github.com/kunwarshivam/mandate/issues/756)); E12-1 (#745), E12-2 (#747), E12-3 (#748); workspace API spec §4.8.1 |

## Decision

1. The trace follows the envelope's `causation_id` on every event and the payload link members of
   workspace API spec §4.8.1's table: `client_order_id` (fill to its submissions), `intent_id`
   (order request, intent, gate decision, abandonment, protection to the intent and its
   `IntentProposed`), `approval` (re-validation to its request), `outputs_used` (decision to its
   outputs), `evidence` and `thesis_id` (output to its evidence and thesis). Nothing else.
2. Each target is looked up by the row's rule, only among the workspace's streams, and on the
   stream the row names; `causation_id` and `evidence` may name any stream of the workspace.
3. A version-1 `OrderSubmitted` has no link and reads `not_recorded`; a null `intent_id` is no link.

## Rationale

The executor journals `IntentReceived`, `GateDecided`, and `FillApplied` with a null
`causation_id`, and the journal spec links them by `intent_id` and `client_order_id` (§2, §9.5).
A walk on `causation_id` alone would stop at the fill, which is exactly the hop FR-7.2 needs. A
closed table is testable: an oracle builds the expected graph from the same table independently.

## Alternatives considered

- **`causation_id` only.** Rejected: the trace from a fill would be empty.
- **Set `causation_id` on the executor's records.** Out of this lane (the executor is
  safety-critical and another lane's), and the payload links already carry the facts. Recorded as
  workspace API spec §12 question 7 for the links that are still missing.
