## Decision

1. The trace follows the envelope's `causation_id` on every event, whatever its type, and the
   payload link members of workspace API spec §4.8.1's table. Those are:
   - `client_order_id`: a fill to its submissions;
   - `intent_id`: an order request, intent, gate decision, or protection to the intent and its
     `IntentProposed`;
   - `approval`: a re-validation to its request;
   - `content.evidence.outputs[].event_id`: an approval request to the outputs it cites;
   - `outputs_used`: a decision to its outputs;
   - `evidence` and `thesis_id`: an output to its evidence and thesis.

   Nothing else is followed. `OrderAbandoned` has no closed schema, so no payload member of it is a
   link. A `causation_id` that cannot be resolved is `not_recorded`; one of a type the row does not
   name is `unexpected_type`.
2. Each target is looked up by the row's rule, only among the workspace's streams, and on the
   stream the row names; `causation_id` and `evidence` may name any stream of the workspace.
3. A version-1 `OrderSubmitted` has no link and reads `not_recorded`; a null `intent_id` is no link.

## Rationale

The journal spec requires a `causation_id` only on copies of cross-stream facts, `IntentProposed`
(rule 10), `OrderSubmitted` version 2 (rule 45), and `ApprovalResponded` (rule 50). It links fills,
intents, and gate decisions by the closed payload members `client_order_id` and `intent_id` (§9.5).
A walk that depended on any other `causation_id` would hang on what a writer happened to record.
The table uses only members the closed schemas define. The one hop a writer records today and the
spec does not require, `ApprovalRequested` to `DecisionMade`, is shown only when present, and is
workspace API spec §12 question 7. A
closed table is testable: an oracle builds the expected graph from the same table independently.

## Alternatives considered

- **`causation_id` only.** Rejected: the trace from a fill would be empty.
- **Set `causation_id` on the executor's records.** Out of this lane (the executor is
  safety-critical and another lane's), and the payload links already carry the facts. Recorded as
  workspace API spec §12 question 7 for the links that are still missing.
