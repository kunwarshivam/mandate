## Context

The founder asks for the best model for each problem. Two readings of "semantic router" exist:

- **A router that picks a model freely at call time**: OpenRouter's `openrouter/auto`, or an
  embedding classifier choosing among providers. This breaks four accepted rules:
  - DEC-997: one zero-retention upstream, no fallbacks, and a pinned dated snapshot.
  - INF-1 and DEC-432 item 10: the reported identity must equal the pin, or the call is
    `identity_mismatch`.
  - Replay: the journal must say exactly which model gave each opinion.
  - The meter: a call's maximum cost is reserved from the pinned entry's price before it is sent
    (inference spec §7.2). An unknown model has no price to reserve.
- **A fixed route from each kind of problem to a pinned model.** This keeps all four.

**The problems the harness has today** are its run kinds (agent harness spec §6.9 and §15). The core
picks the run kind deterministically before anything untrusted is read:

| Run kind | What it does | Output |
|---|---|---|
| `ideate` | Finds and argues a new thesis: read, think, propose | Theses and invalidations |
| `monitor` | Re-checks held instruments and active theses, on the schedule or on a news trigger | Risk-reducing output only: invalidations, and once declared, exit requests |
| `owner`, `explain` | The desk: answers a question, explains an ask (§15, not yet live) | An answer, never an order or a thesis |

There is no "summarise" or "classify" class. Today a run is one model for all its turns.

**What holds today without a spec change:**
- The registry holds many entries, each with its own identity, endpoints, evaluation gate and
  price table (inference spec §4.1 to §4.3, §7.2).
- The identity probe runs per endpoint.
- The meter reserves per call at that call's entry's price. All caps fold over every call
  (§7.3), so two live entries share the $50 workspace and deployment caps unchanged.

**What does not hold:**
- A registry entry pins exactly one `identity`.
- The mandate pins exactly one research entry: the one model that admits instruments (V-036). Every
  research call carries that entry as its `model` (agent harness spec §10.1).

So routing by run kind needs a spec change. That is item 2.

## Decision

1. **Route by run kind only, deterministically.** The route table maps each run kind to one
   pinned registry entry. Nothing picks a model at call time:
   - no `openrouter/auto`;
   - no model fallback;
   - no classifier that can name a model.

   If a finer split is wanted later, a new run kind is added through the harness spec, with its
   menu, output schema and route, as any run kind is.
2. **The route table is part of the research entry's pinned content.** Its new member `routes` maps
   each run kind to a registry entry: `model_id`, `version`, `content_hash`. It is inside the
   research entry's content hash, so the owner's one pin of the research agent covers every routed
   model (rule 11, V-007). A routed model changes only through a new research entry version that the
   owner confirms. Each routed entry is a full registry entry in its own right, with:
   - its own identity, a dated snapshot on one zero-retention upstream, with `allow_fallbacks`
     false;
   - its own §4.3 evaluation gate and identity probe;
   - its own price table.

   Every turn of a run calls its run kind's entry, so a transcript never mixes models.
3. **The record says which model answered.**
   - Each call's `model` is the routed entry.
   - `ModelInvocationRecorded` already records the called entry's id, version and hash and the
     reported identity (journal spec §9.19).
   - Rule 146 still holds per call: the record's `config_refs.model_version` names the routed entry.
     So each routed entry is registered on the control stream like any model (`model register`), and
     a call to an unregistered one is refused.
   - `RunStarted` already names the run kind. The run is under the research entry the mandate pins,
     whose hash covers the table. Replay therefore resolves the same entry for the same run.
4. **The meter.** Each call reserves the maximum cost at its routed entry's price, under every
   existing cap. No cap changes:
   - the $50 workspace and deployment caps (DEC-997 item 3, DEC-2396);
   - the research cost cap per day;
   - the run ceiling.
5. **The proposed table.** All entries go through OpenRouter, `provider.only: ["google-vertex/global"]`,
   zero data retention, `allow_fallbacks: false`, at the prices DEC-2396 read on 2026-10-26.

   | Run kind | Entry | Why |
   |---|---|---|
   | `ideate` | Claude Sonnet 5.5 (DEC-2396 A), 2 / 10 per million | Writes the thesis an owner reads and is asked about; the stronger model where a thesis can open a position |
   | `monitor` | Claude Haiku 5.5 (DEC-2396 B), 0.10 / 0.50 per million, pinned at its highest tier | Checks whether held theses still stand. Its output can only reduce risk: an invalidation leads to an exit, never an opening |
   | `owner`, `explain` | Claude Sonnet 5.5 | Owner-facing wording; routed only once §15 lands |

   Both are Anthropic models on the same upstream, so one terms file and one zero-retention check
   cover both.
6. **The spec changes this needs** (one spec PR after acceptance; code only after that):
   - inference spec §4.1: the `routes` member, and the registry's check that every routed entry
     exists and is `offered`;
   - agent harness spec §6.9 and §10.1: a call's `model` is its run kind's route;
   - mandate spec §8.1: the pin covers the routes through the hash.

   The journal spec is unchanged.

## Cost

These use DEC-2396's run of 8 turns, each 20k tokens in and 2k out, with no cache: **$0.48** a run on
Sonnet and **$0.024** on Haiku.

The demo's research envelope:
- runs at most hourly (`interval_s` 3600), and up to 4 event runs a day;
- has `max_instruments` 1;
- caps research at $5 a day.

So once its one slot holds a thesis, almost every run is `monitor`.

| A day of 2 `ideate` and 20 `monitor` runs | All Sonnet | Routed |
|---|---|---|
| Cost a day | $10.56: the $5 daily cap stops it after about 10 runs | $0.96 + $0.48 = **$1.44** |
| A month at that rate | Past the $50 cap in under 5 days | about **$43**, inside $50 |
| Runs $50 buys | about 104 | about 750 at this mix |

At DEC-2396's own pace of 3 runs a day, routing changes little. Its value is that the agent can watch
its thesis hourly, and on news, inside the same cap.

## Risks

- **A weaker monitor.**
  - A missed invalidation leaves a position open longer. The position stays bounded by its stop,
    the risk limits and the kill switch, none of which use a model (rule 13).
  - A false invalidation causes an exit that wasn't needed. That reduces risk, and costs fees and
    the thesis.
  - Both are measured before `offered`: the §4.3 gate per entry, and a §8.3 regression of
    `monitor` on Haiku against Sonnet on the same recorded runs.
- **Haiku's tiered price.** A pinned price below the real one would make the meter reserve too
  little. The entry pins Anthropic's highest listed tier, and the price is re-read before the entry
  is mounted (DEC-2396 item 3).
- **Two entries to keep pinned.** Each has its own snapshot, probe, deprecation date and evaluation.
  Deprecating either one deprecates the research entry that routes to it (inference spec §4.4).
- **Founder-facing wording.** Calling this "semantic routing" could suggest the platform chooses
  models by meaning at call time. It does not: the run kind is the platform's fixed classification
  of the task, and the owner confirms every model it can reach.

## Rejected

- **`openrouter/auto`, or a free embedding router.** It breaks DEC-997, INF-1, replay and the meter,
  as Context says.
- **A classifier that picks among the fixed run kinds.** The core already picks the run kind
  deterministically, from the mode, the working universe and the trigger. A classifier would add an
  untrusted input to that choice, for nothing.
- **Routing per turn inside a run.** It would mix models in one transcript, and the run's
  coherence and its ceiling would rest on two models' behaviour at once.
