## Decision

1. `web/wrangler.jsonc` commits the three public variables that point the app at a workspace
   ([DEC-975](DEC-975.md)): `OWLHEAD_DATA_SOURCE` `api`, `OWLHEAD_API_ORIGIN`
   `https://api-staging.owlhead.ai`, and `OWLHEAD_WORKSPACE_ID` `01KDEM0000000000000000000W`.
   The deploy from main sets them; the founder no longer sets them in the dashboard.
2. `vars` may name only those three. `web/scripts/workers.mjs` refuses any other name, and its
   secret check now reads the variables too. `keep_vars` stays `true`, so any other variable set in
   the dashboard survives a deploy.
3. Everything else in DEC-823 and DEC-1005 stands: no account, route, build command or credential
   in the file, and the deploy step still reads only the token and the account ID.

## Rationale

The founder asked for the remaining setup to be done rather than handed back. The three values are
public by DEC-975 (each is served to the browser or names a public host), so committing them adds
no credential. It also makes them reviewable and keeps a redeploy from depending on a dashboard
entry.

## Consequences

- app.owlhead.ai reads staging's workspace from the first web-deploy after this merges: the push to
  main runs it while the repository variable `WEB_DEPLOY_ENABLED` is `true`, and nothing changes in
  the Worker until it runs.
- To show the fixtures again, set `OWLHEAD_DATA_SOURCE` to `fixtures` here and merge.
- Section P's other steps are unchanged: the Supabase redirect URL is a setting in the Supabase
  dashboard, which no repository credential reaches.
