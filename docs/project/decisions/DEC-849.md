# DEC-849: The simulated Robinhood server binds loopback with the standard library, and its tests speak the transport's wire format (S2)

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-09 (UTC) |
| **Decided by** | The E7-25 lane, under DEC-176: items 1 to 3 keep each rule as tight as it is or tighten it, and add no risk. Item 4 is a question left open |
| **Story or claim** | E7-25 (the first live trade brief's S2); the S2 tests PRs |

## Decision

1. **Standard library, loopback only.** `SimServer` listens with `std::net` on `127.0.0.1:0` and
   nothing else. `mandate-rh-sim` stays `pure = true`, so no `tokio` and no HTTP server crate.
   `serde_json`, already in the workspace, joins its `allowed_external` list.
2. **The tests speak the transport's wire format.** `mandate-mcp`'s production build refuses plain
   `http`, even to loopback (`crates/mandate-mcp/tests/production.rs`). Another crate's tests link
   that build, so they cannot drive `McpClient`. They use a client that sends what
   `McpTransport::post` sends: the same headers and the same handshake. They take `ALLOWLIST` and
   `PROTOCOL_VERSION` from `mandate-mcp`. The production refusal is not loosened. A live test
   (`tests/wire.rs`) guards the mirror. `mandate-mcp` keeps `USER_AGENT` private and exports no
   version, so the guard pins `mandate-mcp/0.0.0` and `clientInfo`'s `0.0.0` as literals; a
   version bump there fails it until the pin follows. The client's own `connection: close` is the
   one header the transport does not send.
3. **Readings where the protocol leaves a choice.** Every request and notification after
   `initialize` must carry the session the server assigned. Without one the answer is `400`.
   With one it never assigned, the answer is `404`, which the transport reads as an expired
   session. An `mcp-protocol-version` other than the transport's revision is `400`, the strict
   reading of the MCP transport's version header. Answers are `application/json`. The tool
   answers' shapes are assumed, and S2 part 2's tests name them:
   - a refusal by the core is a tool result with `isError: true`;
   - an order answer carries the order as `structuredContent`, with its `id` and its contract
     `state` text; `get_equity_orders` carries `orders[]`, newest first;
   - `review_equity_order` carries `alerts`, named `buying_power`, `pattern_day_trading` and `halt`;
   - a tool the server does not list is JSON-RPC error `-32602`, an unknown method `-32601`.
4. **Open: TLS for C1 and the rehearsal.** The live build's client dials only `https` with a
   verified certificate (connections spec §6.2 rule 1). It cannot reach this server. C1's
   end-to-end tests through `McpClient` and R0's rehearsal need one of two things: the server
   behind TLS with a trust root the client accepts, or a test seam in `mandate-mcp`. Both touch a
   safety-critical rule, so it waits on the founder, and S2's binary waits on it.
5. **What `contract/tools.json` leaves out or assumes.** The contract publishes inputs as
   parameter descriptions, not schemas. `place_equity_order`'s `tax_lots` ("sell only") is
   published with no shape, so it is left out. The input schemas of `get_accounts`,
   `get_portfolio`, `get_equity_positions`, `get_equity_quotes` and `get_equity_tradability` are
   assumed, since the contract names no parameters for them. The contract publishes no output
   schemas, so none is listed. The real server's hash will differ: the founder's login-and-reads
   run (R0 step 4) gives the pin a connector stores.

## Rationale

Item 1 is the narrowest server that works, and its loopback bind is LT-1's. Item 2 keeps the
transport's guard as it is, and still pins what the live connector sends, header for header.
Item 3 takes the strict reading of the MCP transport's session and version rules. Item 5 says
where the pinned file is the simulator's guess, so no one reads it as Robinhood's own schema.

## Alternatives considered

- **Accept plain `http` to loopback in `mandate-mcp`'s production build.** Rejected. It loosens
  §6.2 rule 1, which only the founder may do.
- **A `tokio` and `hyper` server.** Rejected. It makes the crate impure for a few lines of HTTP.
