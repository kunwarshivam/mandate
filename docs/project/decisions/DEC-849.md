# DEC-849: The simulated Robinhood server binds loopback with the standard library, and its tests speak the transport's wire format (S2)

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-09 (UTC) |
| **Decided by** | The E7-25 lane, under DEC-176: items 1 to 3 keep each rule as tight as it is or tighten it, and add no risk. Item 4 is a question left open |
| **Story or claim** | E7-25 (the first live trade brief's S2); the S2 tests PRs |

## Decision

1. **Standard library, loopback only.** `SimServer` listens with `std::net` on `127.0.0.1:0` and
   nothing else. `mandate-rh-sim` stays `pure = true`, so no `tokio` and no HTTP server crate.
   `serde_json`, already in the workspace, joins its `allowed_external` list.
2. **The tests speak the transport's wire format.** `mandate-mcp`'s production build refuses plain
   `http`, even to loopback (`crates/mandate-mcp/tests/production.rs`). Another crate's tests link
   that build, so they cannot drive `McpClient`. They use a client that sends what
   `McpTransport::post` sends: the same headers and the same handshake. They take `ALLOWLIST` and
   `PROTOCOL_VERSION` from `mandate-mcp`. The production refusal is not loosened.
3. **Readings where the protocol leaves a choice.** Every request after `initialize` must carry the
   session the server assigned. Without one the answer is `400`. With one it never assigned, the
   answer is `404`, which the transport reads as an expired session. Answers are
   `application/json`. The contract publishes no output schemas, so none is listed. The tool
   answers' shapes are assumed, and S2 part 2's tests name them.
4. **Open: TLS for C1 and the rehearsal.** The live build's client dials only `https` with a
   verified certificate (connections spec §6.2 rule 1). It cannot reach this server. C1's
   end-to-end tests through `McpClient` and R0's rehearsal need one of two things: the server
   behind TLS with a trust root the client accepts, or a test seam in `mandate-mcp`. Both touch a
   safety-critical rule, so the question goes to the coordinator before S2's binary. It goes to the
   founder if the answer loosens rule 1.

## Rationale

Item 1 is the narrowest server that works, and its loopback bind is LT-1's. Item 2 keeps the
transport's guard as it is, and still pins what the live connector sends, header for header.
Item 3 takes the strict reading of the MCP transport's session rule.

## Alternatives considered

- **Accept plain `http` to loopback in `mandate-mcp`'s production build.** Rejected. It loosens
  §6.2 rule 1, which only the founder may do.
- **A `tokio` and `hyper` server.** Rejected. It makes the crate impure for a few lines of HTTP.
