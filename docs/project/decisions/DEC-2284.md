## Context

DEC-2283 item 9.1 lets customers' workspaces read IEX bars fetched with the platform's data-only
paper key (the founder's F1). Item 9.2 asked how the bars would reach them. One way was a
`bars-reader` vault role in every customer cell, which would put the key in each one. The other was
one platform-side fetcher writing each workspace's generations, which keeps the key in one place.

## Decision

1. **One central fetcher (founder).** The founder chose "One central fetcher." over a vault role in
   every customer cell. The agent reads that choice as follows:
   - The platform key stays in one fetcher on the platform side. The fetcher writes each tenant's
     generations into that tenant's store, in the layout data-plane spec §3.8 gives.
   - The key never enters a customer cell. No customer namespace gets the `bars-reader` role or the
     key's AppRole Secret, and DEC-2277 item 6's binding to the founder's workspace stands.
2. **The interim (agent).** Until the central fetcher lands, the founder's workspace's own data
   process is the only `bars-reader`, and only the founder's workspace has stored IEX bars.
   Customers' workspaces have none, so their agents get no signal and open nothing on bars. That is
   DEC-2283 item 9.2's default, now settled rather than Proposed.
3. **The work (agent).** Backlog row E2-21 builds the central fetcher:
   - it writes into each tenant's store with an identity scoped to that store's bars root alone;
   - it reads only the instrument registrations each workspace's §3.8 set needs, with an identity
     scoped to those reads;
   - it settles what becomes of the per-workspace data process's own fetching and of DEC-2283
     items 1, 2 and 5's per-workspace cost model;
   - it keeps §3.8's cap, batching, pacing, generations and invariants DP-15 to DP-17.

   It is needed before customers get bars.

## Consequences

- The key's blast radius stays one platform namespace. Rotating the key restarts one fetcher, not
  every cell's data process.
- Writing into tenants' stores is a new cross-tenant write path. E2-21 must show, in its own design,
  that the writer reaches no tenant datum but that tenant's bars root (DP-10).
- Data-plane spec §3.8 and HLD §12 risk 3 name this decision in place of the open question.
