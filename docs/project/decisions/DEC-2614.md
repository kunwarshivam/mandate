## Context

GitHub-hosted Actions gives this account one pool of 40 concurrent jobs, served first come, first
served, with no priority between workflows. On 2026-10-19 the founder's `infra` staging plan
(run 39216480244) waited behind about 233 queued or running jobs (190 `ci`, 29 CodeQL, 14
`release`, 5 `merge`), the third such wait that day. No workflow setting reorders that queue:
cancelling superseded runs (DEC-2606, DEC-2610, DEC-2611), skipping drafts (DEC-2604), scoping
jobs to the diff (DEC-1190, DEC-2609) and skipping documentation-only CodeQL (DEC-2613) all shorten
it, but none can guarantee that an `infra` job starts at once.

## Decision (proposed)

1. **One runner is reserved for `infra.yml`.** The founder registers a self-hosted runner on the
   repository with the label `mandate-infra` and sets the repository variable `INFRA_RUNNER` to
   that label. `infra.yml`'s one job runs on `${{ vars.INFRA_RUNNER || 'ubuntu-24.04' }}`, so it
   takes the reserved runner when the variable is set and GitHub's hosted runner when it is not.
   A self-hosted runner does not count against the hosted pool, so `infra` never queues behind CI.
2. **No other job can ask for it.** A repository's self-hosted runner takes any job whose
   `runs-on` matches its labels, a pull request's included, and GitHub cannot restrict a
   repository-level runner to one workflow. So `cargo xtask lint` (`runner_problems`) refuses, in
   every workflow:
   - a `runs-on:` that is not one of the listed hosted runners, exactly, `infra.yml`'s own aside;
   - a matrix `runner:` that is not a listed hosted runner;
   - and any line outside `infra.yml` naming `mandate-infra`, `self-hosted` or `INFRA_RUNNER`.

   This is a check, not a wall: a pull request that also changed xtask could pass its own check,
   so it holds against mistakes and is backed by review, as DEC-2014's guard is.
3. **The runner's shape** (for the founder to accept or change):
   - **Ephemeral:** one job per registration (`--ephemeral`), re-registered by a supervisor after
     each job, so no state, credential or tool survives a run.
   - **Dedicated:** it runs nothing else, has no inbound access, and holds no credential of its own.
     The environment `infra-<environment>` still hands the job its secrets after the founder's
     approval (DEC-2014), exactly as on a hosted runner.
   - **Equipped like the hosted image:** Ubuntu 24.04 x86_64 with `curl`, `sudo`, `git`,
     `rustup` and the tools `infra.yml` installs itself.
4. **Cost and ownership** are the founder's: a small always-on VM (or a machine the founder already
   runs), and its patching.

## Alternatives considered

- **Larger GitHub-hosted runners in their own group.** Ephemeral and managed, with a concurrency
  pool of their own, but billed per minute and, as of this writing, offered to organizations
  rather than to a personal account's repository; it would mean moving the repository.
- **Throttle CI further** (fewer shards, PR runs only when approved). Declined here: it reduces
  testing (AGENTS.md, DEC-464), and still cannot guarantee a free slot.
- **Run `infra` from the founder's own machine.** Possible today without CI changes, but it
  leaves the reviewed-commit binding (DEC-2042) and the environment's approval to discipline
  instead of the workflow.
