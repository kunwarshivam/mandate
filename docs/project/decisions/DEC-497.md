# DEC-497: every reference suite declares the packages it judges, and a mutation run uses the ones that judge what it mutates

| **Story or claim** | E7-19 follow-up to [#644](https://github.com/kunwarshivam/mandate/pull/644), round 2 finding 1; [#652](https://github.com/kunwarshivam/mandate/pull/652) review, major 1; ES-11's mutation gate, DEC-137, DEC-139, DEC-253, DEC-464's ten-minute budget |

## Decision

1. **Every reference suite declares the packages it judges**, in `crates/mandate-refcases/oracles.toml`:
   one entry per `crates/mandate-refcases/tests/<name>.rs`, naming the workspace packages a change
   to which that suite can fail on. An entry is a claim, so a package is named whenever the suite
   reaches it, indirectly included; `refcases`, the case runner, names every package the corpus
   exercises.
2. **A mutation run executes the suites that judge the packages it mutates.**
   `cargo xtask ci mutants` reads the table, takes the union of the suites naming any mutated
   package, adds `--test-package=mandate-refcases` and the nextest filter
   `package(<mutated>) | … | binary(<suite>) | …`, and so runs every test the mutated packages own
   plus exactly those suites. With no suite naming any of them the run is what it was.
3. **A suite the change edits runs whatever it declares**, so a new or reworked suite judges the
   mutants of the change that writes it, before its entry has been through a review.
4. **A suite the change deleted names no binary.** Only paths that still exist are collected: a
   deleted suite would contribute a `binary(<name>)` term matching nothing, and could leave a
   filter that selects no test at all, which DEC-139 then reports as a mutated package no live
   test judges.
5. **`cargo xtask oracles`, in the lint job, holds the table to the suites**: every suite file has
   an entry, every entry names a suite that exists and workspace packages that exist, and no entry
   is empty. A suite cannot join the harness without saying what it judges.
6. **The rule is `external_oracles` in `xtask/src/main.rs`,** a pure function with its own unit
   test, `the_external_oracle_runs_for_the_suites_that_judge_the_mutated_packages`, beside
   `every_reference_suite_declares_the_packages_it_judges`, which reads the real table.

## Rationale

A mutant is judged only by the tests cargo-mutants runs, and cargo-mutants runs the tests of the
mutated package. Several crates' oracles are not there: they live in `mandate-refcases`, a package
the mutated crate does not depend on, so nothing discovers them. E7-19 showed the hole directly —
`validate_config_artifacts` replaced by `Ok(())` was caught only by two `production_config_refs`
cases, and the gate as it stood never ran them.

The first fix for that, and this decision's first shape, keyed the choice on the diff: run a suite
when the change edits it. #652's review refused it, rightly. DEC-77 lands the tests and the
implementation of a story in two PRs, so an implementation PR legitimately changes only
`crates/mandate-journal/src` and edits no suite; under the diff rule its mutants were judged
without the one oracle that could catch them, which is the DEC-79 zero-missed-mutants assurance
quietly not holding on a safety-critical path. "The paved path usually edits the suite too" is not
an assurance.

What a run needs follows from what it mutates, so that is what the gate now reads. The table makes
the relation explicit and reviewable where the dependency graph cannot carry it: the harness
depends on the core, never the reverse, so nothing in Cargo's graph says which suite covers which
crate. `cargo xtask oracles` keeps it from rotting on the side that silently loses coverage — a
suite with no entry is an error, so a new suite must declare itself.

Naming the whole of `mandate-refcases` instead would be sound with no table at all, and was tried:
it makes every mutant of every PR pay the whole harness. Measured at `d8b99df`, on this four-core
box with two test threads, the suite is 62 seconds per mutant, and it is concentrated in three of
the twelve: `mandate_harness` 19.7s, `mandate_lifecycle_harness` 13.5s, `refcases` 10.7s, against
`production_config_refs` 0.34s, `risk_state` 0.32s, `control_stream` 0.36s. A `mandate-journal`
change now pays `refcases` and the five journal suites, about 13 seconds a mutant, and never the
two mandate harnesses that judge nothing of it. On CI's two-core runners that difference is the
one between fitting DEC-464's ten minutes and the shard timeouts the first shape hit.

The residual risk is an under-named entry: a suite that would catch a mutant of a package it does
not list. It is visible in one file, it is reviewed with the suite, and the cost of naming one
more package is bounded by that suite's own run time, so the table is written to over-name rather
than under-name.

## Alternatives considered

- **Key the suites on the change's diff** (this decision's first shape). Cheap and wrong: an
  implementation PR that edits no suite runs no external oracle, which DEC-77 makes an ordinary
  case rather than an edge one.
- **Name `mandate-refcases` on every mutation run.** Sound and needs no table, but it charges every
  mutant of every PR the three harness suites that are most of the run time and none of most
  changes' oracle, and it timed the CI shards out.
- **Derive the mapping from the suites' source, by the crate names each file mentions.** Automatic,
  but unsound in the direction that matters: a suite that reaches a crate only through
  `mandate_refcases`'s own harness mentions it nowhere, so the derivation would quietly drop
  exactly the indirect coverage the table exists to record.
- **Make the mutated crates depend on `mandate-refcases` so cargo-mutants finds the oracles.**
  Refused: it inverts the layering (`xtask/layers.toml` puts the harness above the core) and would
  put a test harness in the dependency graph of shipped crates.
- **Move the oracles into each crate's own tests.** The reference cases are one approved corpus
  read by one harness (DEC-253); splitting it per crate would duplicate the corpus and lose the
  single place that proves every case is covered.
