# DEC-497: the mutation gate runs an external reference-case suite only when the change touches it

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-07 (UTC) |
| **Decided by** | The merge coordinator (agent), under DEC-79: a reversible engineering decision about the gate's own cost, which the founder may overturn |
| **Story or claim** | E7-19 follow-up to [#644](https://github.com/kunwarshivam/mandate/pull/644), round 2 finding 1; ES-11's mutation gate, DEC-137, DEC-139, DEC-253, DEC-464's ten-minute budget |

## Decision

1. **A mutation run names `mandate-refcases` as a test package, and filters to it, only when the
   change touches one of its suites.** `cargo xtask ci mutants` collects the
   `crates/mandate-refcases/tests/<name>.rs` files the diff changes. With none, the run is what it
   was: the mutated packages and their own tests. With one or more, the run adds
   `--test-package=mandate-refcases` and the nextest filter
   `package(<mutated>) | … | binary(<name>) | …`, so it executes every test the mutated packages
   own plus only the reference suites the change touched.
2. **A suite the change deleted names no binary.** Only paths that still exist are collected. A
   deleted suite would contribute a `binary(<name>)` term matching nothing, and on a change that
   deleted its only suite the filter would select no test at all, which DEC-139 then reports as a
   mutated package no live test judges.
3. **The rule is `external_oracles` in `xtask/src/main.rs`,** a pure function with its own unit
   test, `the_external_oracle_runs_only_for_the_reference_suites_a_change_touches`, which pins all
   four cases: no suite touched, one of several touched, the reference package already mutated,
   and a suite deleted.

## Rationale

A mutant is judged only by the tests cargo-mutants runs, and cargo-mutants runs the tests of the
mutated package. Several crates' oracles are not there: they live in `mandate-refcases`, a package
the mutated crate does not depend on, so nothing discovers them. E7-19 showed the hole directly —
`validate_config_artifacts` replaced by `Ok(())` was caught only by two `production_config_refs`
cases, and the gate as it stood never ran them.

Naming `mandate-refcases` on every run closes the hole and is what #644 first did, but it makes
every mutant of every PR pay the whole harness suite. Measured at `142baaf`: the unmutated suite is
52 seconds of test time on four cores, and on CI's two-core runner with `--jobs 2` that exceeded a
120-second `--minimum-test-timeout`, so shards 4, 5 and 13 died on timeouts before the catching
tests reported. Raising the cap to about 360 seconds was the alternative; it keeps one regime but
charges every safety-critical PR for a suite almost none of them need, and it spends most of
DEC-464's ten minutes on scheduling rather than on mutants.

Conditioning on the diff keeps the cost where the benefit is. The risk the condition carries is
real and worth naming: a PR that changes only `crates/mandate-journal/src` still does not run the
external oracle, so a mutant only a reference case would catch is missed there. That is no worse
than the gate before #644, and the paved path already prevents it, because DEC-77 lands the
reference suite and the implementation in two PRs of one story, and the tests PR is what changes
the suite. A PR that revisits an implementation long after its suite landed is the gap; it is the
founder's to close by widening this rule if it ever bites.

## Alternatives considered

- **Name `mandate-refcases` on every mutation run.** The first shape, reverted: correct but it
  timed the CI shards out, and the fix is a cap that charges every PR for a suite it does not need.
- **Raise `--minimum-test-timeout` to about 360 seconds and keep one regime.** Simpler to explain
  and it has no diff-shaped gap, but it spends most of the ten-minute budget on a suite that
  judges nothing for most changes, and a timeout cap tuned to one suite's size is a number that
  silently rots as the suite grows.
- **Make the mutated crates depend on `mandate-refcases` so cargo-mutants finds the oracles.**
  Refused: it inverts the layering (`xtask/layers.toml` puts the harness above the core) and would
  put a test harness in the dependency graph of shipped crates.
- **Move the oracles into each crate's own tests.** The reference cases are one approved corpus
  read by one harness (DEC-253); splitting it per crate would duplicate the corpus and lose the
  single place that proves every case is covered.
