# DEC-2413: The web app gets a Portfolio page beside the agents' chat

| | |
|---|---|
| **Status** | Accepted (the founder) |
| **Date** | 2026-10-30 (UTC) |
| **Decided by** | the founder; recorded by `claude-code`; number taken from the web range (2400s) |
| **Story or claim** | The chat-first web app; amends [DEC-2293](DEC-2293.md) item 15 ("The web") |

## Context

[DEC-2293](DEC-2293.md) item 15 made the agent's chat thread the app's main surface: two screens
(Home and an agent's thread, with its Details drawer) and one settings page. The change that built
it (#3003) deleted the account and portfolio screens with the rest: the account equity chart, the
positions screen, the dashboard's breakdowns and the backtest report.

On 2026-10-30 the founder ruled: "We need a portfolio page. Agent page is main, but not having a
place to see the chart as we had before, and see portfolio and breakdowns etc would not be helpful."

## Decision

1. **A Portfolio page.** `/portfolio` is a top-level screen, in the navigation as Home · Portfolio ·
   Settings: on the desktop dock after Home, and on the phone as a tab after Home. The agent's chat
   stays the main surface; Portfolio is where the owner sees the account as a whole.
2. **What it shows.** The account's value, its cash and what is invested, today's change and the
   total P&L; the account's equity over time with its ranges; every holding with its quantity,
   average cost, last price, market value, unrealized P&L and the agent holding it; and the
   breakdowns of what is invested by agent, by instrument and by asset class, and of the account
   into cash and invested. Each agent row and each holding links to that agent's page. The page
   shows the environment, paper or live, beside the money.
3. **Only the reads that exist.** Over the workspace API the page reads only routes the API
   already serves (`GET /agents`, `GET /agents/{id}`, `GET /agents/{id}/positions`,
   `GET /instruments`). A figure no served read gives, such as the account's value or its equity
   history, is shown as not reported, never computed in its place or drawn from the fixtures. The
   reads it lacks are follow-ups for the workspace API, each a spec change of its own.
4. **Read only.** The page places, asks for and changes nothing. An owner's exit stays in the
   agent's Details drawer, and every action stays in the agent's thread.
5. **What this amends.** DEC-2293 item 15's "two screens and one settings page" becomes three
   screens and one settings page. Everything else in DEC-2293 stands.

## Consequences

- `web/src/lib/screens.ts` lists the screen, so the dock, the phone's tabs, the command palette and
  the route-coverage tests reach it.
- The account equity chart that #3003 deleted is restored for the page, drawn from the fixtures
  until the API serves an equity history.
- The `/demo` example workspace renders the page from the fixtures, like every other screen.
