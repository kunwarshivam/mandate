## Context

A resume and a Stop (`POST /agents/{id}/resume`, `/stop`) are recorded as `OwnerCommandIssued` with
the step-up evidence the server's port verified, or `null`, which the runtime refuses (DEC-2102
item 4). Their bodies could not carry the passkey assertion the port judges, so a web resume or Stop
under passkey step-up was recorded with `null` and refused by the runtime. DEC-2128 item 6 left
them to their own slice.

## Decision

1. **The wire, as DEC-2128 item 1.** `ResumeRequest` and `StopRequest` each gain an optional
   `step_up_assertion`, read as `null` when absent, carried only beside `passkey` evidence: one
   beside `cli_confirm` or `null` evidence is `invalid` at `/step_up_assertion`, and nothing is
   recorded.
2. **The judgment, as DEC-2128 item 2.** Evidence with an assertion beside it is judged by the
   port's `asserted`, against the action the route already binds (DEC-2102's object for `resume`,
   `stop` or `stop_release` at the control head).
3. **The record, as DEC-2128 item 3 and DEC-2102 item 4 together.** A verified passkey step-up
   records the command with its evidence and appends its `StepUpAsserted` right after it in one
   batch (journal spec §9.32, rule 253: `OwnerCommandIssued` carries `payload.step_up`), its id
   §3.4's under `resume_step_up_asserted` or `stop_step_up_asserted`. Anything the port does not
   verify, passkey evidence with no assertion included, is still recorded with `null` evidence,
   which the runtime refuses: unlike a confirmation, these brakes are never refused at the API.
4. **Order, as DEC-2128 item 5.** The types and routes land first, the schemas naming the member
   ahead of the shapes' check (`members_ahead`); the workspace API spec and the two request
   schemas follow in their own change, which empties that list.
5. **Lifting a hold is not in this decision.** The API serves no lift-hold route yet; when it does,
   it takes the same member (backlog E9-4a).

## Rationale

The readings are DEC-2128's on two more routes that commit one control-stream event, the shape
rule 253 names. Item 3 keeps DEC-2102 item 4: a resume or Stop the owner sent is never lost to its
step-up, and the runtime, not the API, refuses a command without valid evidence.

## Alternatives considered

- **Refusing passkey evidence without an assertion as `step_up_missing`, as a confirmation does.**
  Rejected: DEC-2102 item 4 records these commands with `null` so the runtime's refusal is journaled,
  and changing that is not this slice.
