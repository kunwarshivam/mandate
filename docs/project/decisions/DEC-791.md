# DEC-791: An ES-13 exception for slice S8a's tests PR (mandate-webpush)

## Decision

1. **The exception.** The S8a tests PR may exceed ES-13's 400-line limit for safety-critical
   crates: it adds about 730 lines in `crates/mandate-webpush` (the stubbed API 270, the closed
   payload 57, the tests 405). The implementation PR stays within the limit (about 190 lines
   changed in the crate).
2. **Why.** More than half the lines are tests, and of those most are the RFC 8291 and RFC 8188
   vectors, an independent receiver-side decrypt oracle, and an ES256 check of the VAPID token.
   Splitting by topic (encryption, then VAPID and the envelope) leaves the first PR at about 600
   lines, so a split costs a third PR and a second review without making either one reviewable in
   a sitting.
3. **ADR-0001 is unchanged**, as for DEC-366 and DEC-537: its ES-13 row lists only per-file
   exceptions.

## Rationale

ES-13's limit keeps a review to one sitting. The tests here are mostly fixed vectors and oracles
that are read once against the RFCs; the code under review, the implementation, is within the
limit.

## Alternatives considered

- **Two stacked tests PRs.** Rejected unless the lead prefers it: about 600 and 130 lines, with the
  first still over the limit.
- **Fewer tests.** Rejected: each test pins an RFC requirement or an invariant (NT-1, the 512-octet
  cap), and none can go without leaving a requirement unchecked.
