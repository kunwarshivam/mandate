## Decision

1. **The exception.** Only #800 may exceed ES-13's 400-line limit for safety-critical crates.
2. **Sizes.** 855 lines inside `crates/mandate-webpush`:
   - the stubbed API and its doc comments in `src/lib.rs` (279);
   - the closed payload in `src/payload.rs` (57);
   - the test logic in `src/tests.rs` (385): the receiver-side decrypt checks, the ES256 check of the
     VAPID token, the refusal tables, the size cap, the properties, and the guard that keeps the
     vectors out of product code;
   - the published vectors and their fixtures in `tests/vectors/mod.rs` (112; DEC-794);
   - `Cargo.toml` (22).

   Outside the crate there are about 185 non-generated lines of wiring and decisions (the workspace
   `Cargo.toml`, `xtask/layers.toml`, `CODEOWNERS`, `_typos.toml`, `.github/codeql/codeql-config.yml`,
   `docs/dependencies.md`, the feature map, DEC-790, DEC-794 and this file), and 300 generated lines
   of `Cargo.lock`.
3. **Why.** The overage is the stub API with its doc comments, the closed payload, and the test
   logic. The RFC vector values themselves are about 15 lines. A topic split would leave the first
   PR at about 600 lines, so it would add a PR and a review without making either fit one sitting.
4. **The implementation PR is held to ES-13.** It changes about 190 lines in the crate, and its
   tests change only by deleted ignore lines.
5. **ADR-0001 is unchanged**, as for DEC-366 and DEC-537: its ES-13 row lists only per-file
   exceptions.

## Rationale

ES-13's limit keeps a review to one sitting. Here the code under review is the implementation, and
it is within the limit. The tests PR is signatures, a closed payload type, and tests that each pin
an RFC requirement or an invariant.

## Alternatives considered

- **Two stacked tests PRs.** Rejected: they would be about 600 and 130 lines, with the first still
  over the limit.
- **Fewer tests.** Rejected: each test pins an RFC requirement or an invariant (NT-1, NT-2, the
  512-octet cap).
