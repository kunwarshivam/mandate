## Decision

1. **The exception.** Only #800 may exceed ES-13's 400-line limit for safety-critical crates.
2. **Sizes.**
   - **Inside the crate:** 762 lines in `crates/mandate-webpush`. They are the stubbed API in
     `src/lib.rs` (271), the closed payload in `src/payload.rs` (57), the tests in `src/tests.rs`
     (412) and `Cargo.toml` (22).
   - **Outside the crate:** about 135 non-generated lines of wiring and decisions. They are the
     workspace `Cargo.toml`, `xtask/layers.toml`, `CODEOWNERS`, `_typos.toml`,
     `docs/dependencies.md`, the feature map, DEC-790 and this file.
   - **Generated:** 300 lines of `Cargo.lock`.
3. **Why.** Most of the overage is the RFC vectors with their oracles and the stub API:
   - the RFC 8291 and RFC 8188 vectors, byte-exact;
   - an independent receiver-side decrypt;
   - an ES256 check of the VAPID token;
   - the API's signatures and doc comments.

   These are read once against the RFCs. A topic split would leave the first PR at about 600 lines,
   so it would add a PR and a review without making either fit one sitting.
4. **The implementation PR is held to ES-13.** It changes about 190 lines in the crate, and its
   tests change only by deleted ignore lines.
5. **ADR-0001 is unchanged**, as for DEC-366 and DEC-537: its ES-13 row lists only per-file
   exceptions.

## Rationale

ES-13's limit keeps a review to one sitting. Here the code under review is the implementation,
and it is within the limit. The tests PR is fixed vectors, oracles and signatures.

## Alternatives considered

- **Two stacked tests PRs.** Rejected: they would be about 600 and 130 lines, with the first still
  over the limit.
- **Fewer tests.** Rejected: each test pins an RFC requirement or an invariant (NT-1, NT-2, the
  512-octet cap).
