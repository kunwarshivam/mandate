## Context

The cell's API server (DEC-1024) refuses every sign-in, because the cell has no
issuer and no subject links. [DEC-2100](DEC-2100.md) gives a dev or CI cell a stub issuer:
- it runs on loopback with a key made at each start;
- it is compiled only with debug assertions;
- a `dev` or `ci` cell runs it once E21-53 is on `main`.

This decision settles how the cell runs the stub and links a demo owner.

## Decision

1. **A native sidecar of the API pod, on its loopback.**
   - The stub runs as an init container with `restartPolicy: Always`, as `--bind 127.0.0.1:8090`, in the server's own network namespace. No other pod, node or host reaches it.
   - The tier it is given is the server's `api.tier`.
   - The API server's settings name it exactly: issuer `http://127.0.0.1:8090` and key set `http://127.0.0.1:8090/jwks.json`.
2. **The server starts only once the stub answers.** A second init container waits, up to a minute, until `127.0.0.1:8090` accepts a connection, and otherwise fails.
   - The server fetches the stub's key set at its own start and only every five minutes after. A server started first would refuse every sign-in until its next fetch.
   - The stub's image has no shell, so the wait runs in the postgres image, as the egress gate already does.
3. **It cannot run in a hosted deployment.** Three separate checks enforce this, each shown by a test:
   - The schema allows `images.stub-issuer` only as a local `mandate.local/` build.
   - The chart allows a local build only under `localImages`, which only the local cell's values set.
   - The chart refuses the stub when `api.tier` is not `dev` or `ci`.

   E21-53 also makes the server itself refuse the stub's `http` key set outside `dev` and `ci`.
4. **It runs only when both pieces are in the checkout.** `cargo xtask cell up` builds, imports and names the stub, and mounts subject links, only when two things hold:
   - lane SI's crate (`crates/mandate-stub-issuer`) is in the workspace, with its entry point
     implemented: its tests land first with `main` a `todo!()` (DEC-137), which would crash-loop
     the sidecar and keep the server from starting;
   - the server carries E21-53's check, as DEC-2100 item 9 requires.

   Otherwise the cell runs no stub and mounts no links, every sign-in is refused, and `cell demo` names the sign-in step as skipped. The stub is built in the dev profile, the only one that compiles it.
5. **One demo owner, linked by the CLI's own gesture.**
   - `cell up` runs `mandate identity link --issuer http://127.0.0.1:8090 --member 01KDEM0000000000000000000P` in the image it built, with no network, giving it the subject `demo-owner` on standard input.
   - The resulting file becomes the ConfigMap `subject-links`, which the chart mounts at the fixed path ([DEC-1023](DEC-1023.md)).
   - The subject names a demo principal, never a person.
6. **The demo signs in as `web/` does.** `cell demo` forwards local port 8090 to the stub alongside the API, so the stub sees the `Host` it requires.
   - It asks the stub for a token for `demo-owner`, then sends `POST /v1/sessions` from the app origin with `X-Mandate-Request: 1`.
   - It requires 204 and the `__Host-mandate_session` cookie.
   - This checks sign-in only. What the session may read waits on the founding membership (lane ID1).

## Rationale

- **Item 1:** a loopback sidecar is what DEC-2100 item 3 asks for, a stub reachable only inside the server's network namespace. It adds no Service, no ingress and no policy.
- **Item 2:** the wait turns a race the server would lose silently, a five-minute sign-in outage, into an ordered start.
- **Item 4:** gating on the checkout lets this wiring land before lane SI's code, and lets the cell switch sign-in on by itself the run after that code merges. It never runs the stub before E21-53.

## Alternatives considered

- **A separate stub pod with a Service.** It would put the stub on the cluster network, and DEC-2100 keeps it on loopback.
- **A startup probe on the stub.** Kubernetes probes reach the pod's address, not its loopback, and the stub binds loopback only.
- **Computing the link digest in xtask.** It would duplicate the canonical encoding. Running the CLI's own gesture keeps one implementation.
