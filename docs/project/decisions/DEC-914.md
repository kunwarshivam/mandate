DEC-912 pinned the four pure seams — `grant`, `cross_check`, `lt10`, `evidence` — as #1303's
pending pins, and #1308 implemented them. What remains before the founder's R0 rehearsal is the
wiring: calling those seams from the run's cycle. #1308's review left five notes for that wiring,
and none of them is bound by a test yet: (a) the journal read's control-stream records reach
`grant()` verbatim, in journal order; (b) `Asked` is built from the run's journaled
`ApprovalRequested` — never a hash recomputed over a rebuilt order; (c) `cross_check()` receives
the gate's own `collar_x`, never a second number; (d) `lt10()` replaces the watch's bare terminal
read; (e) `evidence()` lands at the run's report with the run's own typed ids. A tests PR comes
first (DEC-77), and the call sites themselves — inside `run()`'s live arm, which no pin of this
PR may edit — cannot be pinned directly without driving the implemented cycle, which does not
exist yet. So this decision records what the wiring's **run-level seams** bind: the values each
call site must derive, from the journal it appends to, its clock, its registered configuration
and its report, and the answers it must take from the merged seams. The seams land as
`mandate-paper` stubs with final signatures (`src/wiring.rs`, every one reporting
`Unimplemented { story: "E7-26" }` per DEC-137, the wiring row's own story), and the
implementation PR implements them and calls them from the cycle, its review judging the call
order this file cannot: the wait holding the submit, the cross-check before the intent leaves
(`trading-domain` spec §4.2: "or the opening is refused and nothing is sent"), and the LT-10 end
in place of the watch's bare terminal read (DEC-912 item 3).

## Decision

1. **The ask the run waits on (`asked`).** The wait's `Asked` is read verbatim off the
   `ApprovalRequested` the run's own cycle journaled (mandate spec §6.4, journal spec §9.6):
   `rows` are the journal's own read (`ORDER BY seq`) of the agent stream the run appends to,
   and the ask the wait serves is the **youngest** `ApprovalRequested` among them — the run
   journaled it after the gate passed, and nothing after it can exist while the run holds the
   cycle's one-order door (FT-1); an older ask belongs to another run, and waiting on it would
   release this run's submit on another run's answers. Its members are the row's own: the
   approval is the row's event id, the content hash is the payload's `content_hash` member, the
   deadline is the payload's `deadline` seconds — **never recomputed**: a hash recomputed over
   the row's content object, or over an order the cycle rebuilt, is not the hash the approver's
   grant repeats, so binding it could only refuse a true grant or release a drifted order
   (#1308's review note (b), LT-4). A member the run cannot read is never a guess (`AGENTS.md`
   rule 3): an ask whose members cannot be read, and a stream holding no `ApprovalRequested` at
   all, refuse `content_mismatch` with nothing sent — "a grant that cannot be shown to bind the
   request the run journaled sends nothing" (DEC-912 item 1) covers the empty case a fortiori.
   The youngest ask whose deadline is already at or past `now` denies `approval_timed_out`: the
   timeout is a deny (rule 3) and the wait is bounded by the request's own deadline, so the wait
   falls back on no older, still-live ask.
2. **The answers' fold (`answers`).** `rows` are the journal's own read (`ORDER BY seq`) of the
   workspace control stream, and each row is mapped one-to-one to its record — its `seq`, its
   `event_type`, and its body's `payload` member, the same mapping the run's own control-stream
   read performs — before the records are handed to `grant()` **verbatim, in journal order**
   (#1308's review note (a)): never re-sorted by another key, never filtered to the answers
   alone, no read of a row's members from anywhere but the row's own payload. The first
   `ApprovalResponseSubmitted` naming the ask's approval decides wherever it sits in the read,
   including an answer committed after the run began waiting, and every refusal is `grant()`'s
   own (DEC-912 item 1), because the release the cycle took is the one this fold returns.
3. **The collar the cross-check reads (`collar_x`).** The `x` handed to `cross_check()` is the
   collar's own aggressiveness for the asset class — trading-domain spec §9.6's tier: the crypto
   member for crypto; for an equity the liquid member when the 20-day median dollar volume is
   **at least** the registered threshold (the spec's own `≥`), the other member when it is known
   and below it, and the narrower liquid member when it is unknown ("the ambiguous case admits
   fewer prices, not more", DEC-163 item 2) — read through the registered gate configuration's
   own members, which arrive typed and validated before the run (#1308's review note (c):
   `mandate-risk`'s `conduct.rs`, never a second number). The derivation that turns members
   into `x` stays the gate's: the wiring PR exposes the gate's own `collar_x` rather than
   re-implementing the tier beside it, so no second number can sit between the gate's collar and
   the cross-check's band. The seam returns `Result` so its stub can report per DEC-137; the
   implemented seam refuses nothing, because a configuration it could not read already refused
   the run.
4. **The watch's facts (`watched`).** The `Watched` each wake's LT-10 question reads carries:
   the entry **terminal** only in the four states the watch ends on — `filled`, `canceled`,
   `expired` or `rejected` (DEC-858 item 4) — so a broker read absent, unknown or still working
   leaves the run reading (rule 3), never guessed terminal; `uncovered` exactly as the
   executor answers it — a filled quantity left with no protection resting over the whole of it
   — because the executor owns that fold and the runner re-folding account-stream rows beside
   it would be a second fold to drift; and `alerted` only when the run's report's own keys hold
   **the interval's own** alert key, `unprotected_interval_limit` (notifications spec §4.2's
   `protection` row) — DEC-912 item 3: "what the seam observes is the run's report holding the
   interval's alert key" — never a key synthesized from rows and never another alarm's
   (`stop_watchdog` shows nothing for this interval).
5. **The watch's cap (`session_cap`).** The cap its reads fail at is DEC-877 item 1's instant:
   the end of the regular session the watch's bound is in, on the same
   `mandate_time::ExchangeCalendar` DEC-853 item 5's close-window bound read — 16:00 New York
   on a full day, the early close on a short one — so the live watch fails at the same instant
   the paper watch does and no reading of this seam can outlive the day. A bound no regular
   session holds places no cap and refuses `Cause::Absent`: the close-window bound already
   refused such a run (FT-8), so the stop only fails closed again, and `now` and the wake's
   reads stay the wiring's, handed in per DEC-912 item 3 ("the run's clock" each wake).
6. **The report's evidence (`reported`).** The exportable evidence is named **at the run's
   report** (the founder's run's steps 4 to 6; DEC-912 item 4), from the journal the run
   **appended to**: the arguments' journal held only while placing (DEC-157 item 6,
   `run()`'s own `args.journal.clone().filter(|_| args.place_one_order)`), so a run without
   `--place-one-order` wrote nothing a `journal export` could read and names no stream at all —
   the DSN at hand or not (R0 step 4's dry run exports nothing;
   `EvidenceRefusal::JournalAbsent` at the report seam) — and a placing run names the three
   streams of the founder's run's step 6, in its order, derived from the run's own workspace,
   agent and account ref (#1308's review note (e): the typed ids), so they parse as journal spec
   §2 stream ids of their types. Where the naming attaches inside the run's report is the
   wiring PR's to build (the shell's `Report` cannot hold a `mandate-paper` type), bounded by
   these pins: only a placing run names anything, and it names exactly these three.
7. **What this PR does not bind.** The call sites' order — the wait holding the submit inside
   the cycle's `ask`, the cross-check before the intent leaves, the watch asking LT-10 before
   it ends — is the wiring implementation PR's to write and its review's to judge against the
   task file's row and LT-4's own sentence; the pins bind the values that reach the merged seams
   and the answers taken from them. The pending tag is E7-26's, the row's own story (the task
   file's row G1b, [DEC-77](../04-decision-log.md#decisions), `cargo xtask markers`' registered
   form).

## Rationale

Each reading is the one that refuses more or removes a second implementation someone could
drift. The youngest ask denies where a first-live reading would wait on another run's still-live
ask and release this run's order on its answers; waiting on the journaled member rather than a
recomputation can only refuse a grant that does not bind the order the approver saw (LT-4's own
sentence); handing the records verbatim keeps the journal's own order total and replay-stable,
the same discipline DEC-912 item 1 pinned on the fold's records. Reusing the merged refusal
vocabularies (`GrantRefusal`, `QuoteRefusal`, `Lt10Refusal`, `EvidenceRefusal`, the shell's
`Cause`) adds no reason code a review has not already read, and the seams that never refuse keep
their `Result` only because DEC-137's stub report needs it — the alternative is a stub that
cannot name its story.

## Alternatives considered

- **Wait on the first still-live ask instead of the youngest:** rejected — a previous run's
  ask left live by a long timeout would then release this run's submit on its answers, which is
  the grant-binding failure LT-4 exists to refuse.
- **Fold the account-stream rows to derive `Watched`'s `uncovered`:** rejected — the executor
  owns protection state (DEC-912 item 3 names the interval's journaling the executor's); a
  runner's second fold beside the executor's own is precisely the two-admissions drift DEC-912's
  alternatives reject, and every error of it could only hold the run open or end it early.
- **Take `&GateConfig` or `&GateInput` in `collar_x`:** rejected for this PR only —
  `mandate-paper` does not depend on `mandate-risk`, and a tests PR adds no dependency row; the
  members the tier reads land as typed arguments now, and the wiring PR exposes the gate's own
  derivation behind them so the tier is never written twice.
- **`session_cap` reading the calendar itself rather than the bound's session:** rejected —
  the cap is defined as the bound's session's end (DEC-877 item 1: "the end of the regular
  session the bound is in"), and a calendar read keyed on `now` could pick a session the run's
  bound is not in at a midnight boundary.
- **Pin the call sites by driving `run()`:** rejected — the live arm of `run()` does not exist,
  and a pending test that drove it would fail on the run's answer rather than at its story's
  stub, which the pending gate refuses (DEC-137 item 1); the binding lands with the seams the
  implementation calls, and the review of that implementation reads the call order.
