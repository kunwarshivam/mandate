## Context

The founder asked for a demo on staging, Alpaca paper, real data, within two days, in his words: "I
want to find ticker to trade using search, ask agent to take action, buy it". Workspace API §4.6
specifies `POST /agents/{id}/requests` and journal spec §9.9 closes `OwnerRequestSubmitted`, but
the server does not serve the route, and the runtime does not consume the record. The coordinator
put three questions to the founder: which instruments a request may name, whether an owner's
request reaches the approvals inbox, and whether the request must carry a size. The founder chose
every recommendation: "go nd fix and do recommendation" [sic].

[DEC-528](earlier-303-599.md#dec-528) already settles what search leads to, and this decision amends neither of its
items. Item 2 keeps instrument search display-only: it ranks, flags and suggests nothing. Item 1
makes every purchase go through an agent, "an owner request to an agent the owner already has", and
PRD FR-8.6 has an instrument page offer "ask an agent", never "buy". This decision serves that
owner request over the API: search finds the instrument, and "ask an agent" is the action, worded
as an ask, never a buy.

## Decision

1. **The agent's own instrument only** (the founder). A request names an instrument the agent's
   deployed mandate document pins (`universe.pinned_instruments`); anything else, and any request
   to an agent whose universe is not pinned, is refused `invalid` at `/instrument` with nothing
   committed. A request never changes the envelope (`AGENTS.md` rule 11).
2. **Autonomy decides, as for any proposal** (the founder). An owner's request goes through the
   order builder, the gate and the autonomy rules (mandate spec §6.2, `requested_by` `owner`). It
   reaches `/approvals` when the mandate's rules `ask`, as the demo mandate's rule for `open` does;
   that is a mandate setting, and this decision adds no ceiling for owner requests.
3. **The size is required in v1** (the founder). The server refuses a request without a positive
   `size` (`invalid` at `/size`); the builder only clips it to the mandate's caps and classifies
   it, and no sizing rule for an owner request is added. The schema keeps `size` optional for the
   rule a later version may add.
4. **Users only until client tokens land.** The route takes the "Make an owner request" row for a
   user; a client's cell is not served until E10-14, as every other route's.
5. **Refused before journaling.** The agent must be deployed here and not stopped (else
   `not_found`), and the workspace `paper` (else `live_unavailable`), checked after the matrix row
   and before the body's own rules, so a request that fails the checks above is never journaled.
   A request that passes them is journaled and may still be refused by the runtime: a paused,
   exits-only, restricted or kill-switched agent, a closed session, and the gate's own denials
   refuse it there, as they refuse the agent's own proposals.
6. **No step-up.** A request adds risk only through the builder, the gate and the autonomy rules,
   which judge it as they judge the agent's own proposals; an approval it reaches takes its own
   step-up (§5.2).

7. **Buy only in v1.** `side` `sell` is refused `invalid` at `/side`, before anything is
   journaled. An owner's sale is an exit, and exits are the owner exit's (§5.4, `AGENTS.md` rule
   13); the runtime has no decision that records a sale an owner requested (lane X's DEC-2858),
   so a committed sell request would do nothing. The schema keeps `sell` for a later version.
8. **The runtime's half.** How the runtime copies the request, the builder clips it, and the
   journal records the decision (the owner decision's null convictions, the ask as the limit, and
   the runtime's own refusals) is lane X's DEC-2858, which cites this decision for the
   checks above.

## Rationale

Each item keeps the request inside what the mandate already allows: the instrument is the
envelope's, the size is clipped to its caps, and autonomy decides as for any proposal. The
checks above refuse before anything is journaled; whatever the runtime refuses after them, it
refuses as it refuses the agent's own proposals.

## Alternatives considered

- **Any instrument search returns.** Refused by the founder: it would let a request widen the
  universe, which rule 11 forbids; a new instrument needs a confirmed mandate version.
- **Owner requests always `ask`.** Not chosen: the client ceiling (MI-30) exists because a client
  reads untrusted content; the owner is the one who set the rules.
- **Size optional, sized by the builder.** Deferred: v1 has no sizing rule for an owner request,
  and inventing one in two days is a mandate-spec change.
