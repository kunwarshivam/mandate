## Context

The founder wants Owlhead to work like Meta Muse, Claude Duet, OpenAI Dots and Grok Bot, applied to
one domain, the user's brokerage account. That means a long-lived agent per agent the user creates,
which the user talks to in plain words, which keeps working and messages the user first, and which
never acts outside the mandate the user confirmed.

The desk of agent harness spec §15 (DEC-2240) specified a read-only question-and-answer surface with
heavy checks. They were written before DEC-2243 let an owner's mandate, positions and activity reach
the hosted model. The founder went through §15 one requirement at a time on 2026-10-29. This records
his rulings.

## Decision

1. **Citations.** No forced per-sentence citation (§15.2 EX-4 is withdrawn). A reply that explains
   a past trade or decision links that decision record.
2. **Advice.** No advice-phrase filter (EX-5 is withdrawn). The system prompt keeps the agent to
   what it found and what it can do inside the mandate, and tells it never to say what the user
   should do with their money. The founder: "rely on system prompt".
3. **Numbers.** No numeric scrub (EX-6 is withdrawn). Positions, prices, P&L and the user's
   numbers reach the model under DEC-2243. Keys, passwords, and account or broker numbers never do,
   and the gateway's prompt guard stays on. The founder: "drop it, it is of no use to scrub it".
4. **Isolation (kept).** An agent's chat reads only that agent's records, and the workspace chat
   only that workspace's. The code fixes the scope: no tool argument names an agent, a workspace or
   a stream, and a foreign or absent ref is the same `not_found` (EX-2, EX-3). The founder: "table
   stake".
5. **Actions.** The model only proposes; deterministic code sizes, gates and places
   (`AGENTS.md` rule 4).
   - The user's explicit instruction is an owner request (`requested_by` `owner`), `auto` under
     DEC-2159.
   - The agent's own ideas follow the mandate's autonomy rules.
   - Anything outside the mandate is refused, with the reason.
   - An envelope change is a draft version that the user confirms (rule 11).
   - Whether an action is the owner's is read from the journal's causation chain to an owner's own
     message, never from the model's words.
   - No step-up on paper (DEC-2158).

   This replaces §15.12's separate card-digest send for the owner's explicit instructions.
6. **Bounds.** No caps on turns, tool calls, run time or message count (§15.7's bounds are
   withdrawn). The only hard bounds are money:
   - a daily model spending cap per agent, a setting with default 5 USD;
   - the gateway's workspace and deployment caps.

   A Stop control ends a run. A hung model call is bounded by its entry's deadline. The pinned
   loop bounds the gateway requires are set as technical ceilings that no ordinary run reaches.
   The founder: "there is [no] guarantee how much turns, tool calls etc one would need".
7. **Journal (kept).** Every message, model call, tool call and result is journaled before it is
   shown or acted on, and the thread is read back from the journal. Replay of the thread is reading
   it; no reproduction of the model's words is required.
8. **Modes.** The chat works in every mode and is never on the trading path.
   - Paused: it answers and takes commands.
   - Stopped or killed: it answers only.
   - The agent's own wake-ups run only while it is active.

   This replaces §15.1's "mode gates them".
9. **Notifications.** A push names the agent and the kind of event, never a ticker, quantity,
   price, P&L or message text (rule 6, in the founder's option (b)).
10. **Untrusted text.** News, filings and stored research text are marked as untrusted data in
    every prompt, and a reply links the sources it relied on. EX-12's exact-provenance property is
    withdrawn.
11. **Privacy (kept).** Each member has a private thread per agent (§15.3). Admins and auditors
    read it through the journal, and connected clients have no chat.
12. **Disclaimer.** None (§15.8 is withdrawn). The founder: "lame, no need".
13. **No evaluation gate for chat, compiler or research entries for now.** System prompts guide
    them, and the entries are registered `offered`. This suspends DEC-2216's gate until the founder
    reinstates it; every action still passes the order builder, the gate and autonomy. The founder:
    "we can do a lot of things with system prompts in the beginning".
14. **Models.**
    - The chat model is a per-agent user setting, defaulting to Sonnet; routine wake-ups default to
      Haiku.
    - The research model stays a mandate field (rule 11).
15. **Architecture.**
    - **Where the chat runs.** In the workspace API process, off every trading path. It calls the
      model through the gateway service and acts only through the routes and records the web
      already uses, so it adds no writer to any stream.
    - **Records.** Its own records are on the control stream: `ChatMessagePosted`,
      `ChatTurnRecorded`, `ChatRunEnded`, `ChatSettingsChanged` and `AgentGoalsUpdated` (journal
      spec §9.39).
    - **Agent creation.** It uses the gateway's `compiler` purpose and `mandate-spec`'s
      validation.
    - **The web.** Two screens and one settings page.

## Consequences

- Agent harness spec §15 is rewritten to these readings.
- The journal spec gains the chat records, and the workspace API spec gains the chat routes.
- The founder may reinstate any withdrawn check later with a new decision.
