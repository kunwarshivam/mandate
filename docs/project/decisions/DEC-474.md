# DEC-474: Name E6-13's live stub-sentinel test replacements

| | |
|---|---|
| **Status** | Accepted |

| **Story or claim** | E6-13 implementation; PR #618 |

## Decision

Under DEC-77's review-ruling exception, the E6-13 implementation PR may replace exactly one live
stub-sentinel test in each of these files:

1. `crates/mandate-executor/tests/tripwires.rs`:
   `the_tripwire_fold_stub_fails_closed` becomes
   `the_tripwire_fold_applies_an_empty_boundary`.
2. `crates/mandate-spec/tests/tripwires.rs`:
   `tripwire_stubs_fail_closed` becomes `tripwire_parser_and_classifier_are_live`.
3. `crates/mandate-refcases/tests/mandate_harness.rs`:
   `a_tripwire_case_reaches_the_fail_closed_e6_13_adapter` becomes
   `a_tripwire_case_reaches_the_implemented_e6_13_adapter`.

No other tests-PR assertion may change. The pending behavioral tests change only by deleting their
`#[ignore = "pending E6-13"]` attributes. Review-requested mutation-boundary coverage remains
in-module under `#[cfg(test)]`, as DEC-77 requires.

## Rationale

The three named live tests prove that the tests PR's public entry points reach their fail-closed
E6-13 stubs. Keeping those assertions after replacing the stubs would require production entry
points to keep returning `Unimplemented`, contradicting the story. Each replacement keeps the
same entry point live and pins its smallest implemented success boundary: an empty executor fold,
one parsed and classified tripwire, and MC-W27 reaching the implemented adapter.

This ruling makes the existing narrow exception explicit. It does not alter fixture expectations,
pending behavioral assertions, mutation scope, or any safety invariant.

## Alternatives considered

- Delete the three sentinels: rejected because that loses the live entry-point checks.
- Keep the old assertions and special-case production behavior: rejected because the implemented
  API would remain fail-closed for valid inputs and create a test-only workaround.
- Rewrite or add other external tests in the implementation PR: rejected; DEC-77 places new
  review coverage in-module and freezes the tests-PR assertions.
