# DEC-2803: Closed schemas for the account stream's `ExternalActivityIngested`, `RejectObserved` and `OrderAbandoned`

| | |
|---|---|
| **Status** | Accepted (agent, under DEC-79 and DEC-176: closing three schemas the executor already drafts only tightens what `append` admits, and turns a refusal that stopped the executor into a record; the coordinator assigned the work and rules 297 to 300, of which this takes 297 and 298) |
| **Date** | 2026-10-26 (UTC) |
| **Decided by** | Lane MC (Claude Code), number from the coordinator's trading-core range |
| **Story or claim** | X10 (the account stream's schema gap; lane L1 closes `KillSwitchActivated`); journal spec §9.5, v0.93 |

## Context

The executor drafts `ExternalActivityIngested` (reconciliation's open order of no order of ours, and
a fill that names none), `RejectObserved` (a reject the broker answered with) and `OrderAbandoned`
(an intent given up on) on the account stream. `mandate-journal` registers no schema for any of them,
so `append` refuses each as `unknown_schema`: the first broker reject, external order or abandoned
intent refuses the executor's whole batch, and the process stops and restarts into the same batch.

## Decision

1. **Close all three at `schema_version` 1** (journal spec §9.5, v0.93), every member present (§9.1),
   each with `risk_clock` last as the executor writes it.
2. **Every member the broker supplies is nullable** (`text?`): a broker can send an empty string,
   which `text` refuses, so the executor writes an empty one as `null`, and none of these three
   records refuses a batch over a broker's empty field. That does not reach `FillApplied`, whose
   `fill_id` stays `text`: an external fill the broker sends with an empty id is still refused
   there (the backlog holds the row). The members the executor derives itself (`source`,
   `http_status`, `client_order_id` and `intent_id` of an abandonment, `reason`) are never `null`.
   `RejectObserved.message` is the broker's text as it came; it may name the account as the broker
   words it, and like every journal member it never reaches a notification (`AGENTS.md` rule 6).
3. **`ExternalActivityIngested` names its `source`**, `open_order` or `fill`, and carries every
   member of both shapes, `null` where its source has none. Rules 297 and 298 bind each source's
   members: a fill names only its fill id; an open order names no fill id, and always its
   instrument, side and quantity, which the executor reads from its own typed values.
4. **`OrderAbandoned`'s `reason` is closed** to the four the executor writes (`intent_too_old`,
   `gate_recheck`, `released_to_owner`, `unprotected_interval_limit`), and its `intent_id` is an `id`,
   not a `ulid`, since the watchdog's and a kill switch's own exits are `w-…` and `k-…`.
5. **`RejectObserved` and `OrderAbandoned` take no rule.** Any combination of a status, a code, a
   message and a named order is a reject a broker may send. An abandonment's `client_order_id` is
   `md-` and its intent as the executor derives it (DEC-449, DEC-860, DEC-485), but trading spec
   §2.3 still states `"{intent_ulid}-{attempt}"`; a journal rule would make that form normative
   from the wrong place, so none is added until §2.3 states the executor's form (the backlog holds
   the row). Rules 299 and 300 stay unused.
6. **The executor follows in the code change.** It writes `source`, the `null` members, and `null`
   for an empty broker string; a catalogue test proves every type the executor can draft on the
   account stream is registered. Until then its drafts are still refused, now at a member rather
   than at the schema.

## Rationale

- A closed schema is what lets the journal refuse a malformed record rather than any record; the
  only rules added hold of the executor's drafts by construction, so none can turn a valid reject
  into a refusal that stops the process.
- Nullable broker members keep the broker's data out of the journal's power to refuse: the journal
  records what the broker said, empty included.

## Alternatives considered

- **Allow absent members for the optional ones** (what the executor drafts today). Rejected: §9.1's
  absent-member rule holds for every closed schema; one exception would make every reader guess.
- **Two event types for external activity.** Rejected: the event type is in the catalogue already,
  and the trading spec's table names one record for unattributed activity.
- **A rule that `http_status` is 4xx or 5xx.** Rejected: the connector's reject may not come from
  HTTP, and a refused reject would stop the executor, the failure this decision removes.
