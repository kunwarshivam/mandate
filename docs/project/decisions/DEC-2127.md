## Context

§4.10 route 2 item 3 counts each failed assertion against the address and the device that
presented it. The device is the `__Host-mandate_device` cookie, and a call that carries none, a
malformed one, or two counts as carrying none. The spec does not say which device such a call's
failure counts against. The challenge route sets a fresh cookie on a call without one, but the
assertion route never sets or clears it, so a client can present without one.

## Decision

1. **One shared device key.** On `POST /v1/reduction-sessions`, a call that carries no device
   cookie counts its failure against a single device key that every such call shares: the digest
   of the empty value. Its limit is the device limit, 10 failures in 300 s. The address limit
   applies as for any other call.
2. **For counting and the alert only.** The shared key changes no answer. Reaching its limit raises
   `reduction_failures_over_limit` once, as any device's limit does, and refuses nothing: a
   verified assertion over an outstanding challenge opens the session whatever any limit holds.
3. **The test.** `reduction_sessions_http.rs`'s
   `clients_without_a_device_cookie_share_one_device_budget` pins it: ten cookie-less failures
   from ten addresses reach the one device's limit and raise the alert at the tenth.

## Rationale

A client that drops the cookie should not escape the device count, or a flood could leave it off
and be counted only per address. Pooling every cookie-less call into one key bounds them together.
Because the limit only reports, pooling can make an honest cookie-less client share an alert with a
flood, but it can never cost that client its session.

## Alternatives considered

- **Count no device at all for a cookie-less call**, so only the address limit applies. Rejected:
  dropping the cookie would then hide a flood from the device count.
- **A fresh device per cookie-less call**, as a plain `http` cell gets one by accident. Rejected:
  each failure would count against a new key, and the device limit would never bind.
