## Decision

1. The `schema-mutants` matrix runs six shards, `0/6` to `5/6`, `fail-fast: false`, in place of
   DEC-688 item 2's three. Everything else in DEC-688 stands: each shard runs the three checkers on
   the unmutated tree first, the required `full` verdict passes only when every shard succeeded,
   and `cargo xtask check` and the nightly run the sweep unsharded.
2. The xtask test that pins the job's lines pins the six shards.

## Rationale

The sweep was 645 mutants over three shards. The backtest and evaluation read models (DEC-1001,
DEC-1002) add 267 mutants and make each checker pass about twice as slow, because every mutant
validates every example: about 1.8 seconds a mutant locally, so three shards would hold about 300
mutants each, roughly nine minutes before setup, over DEC-464's ten-minute bound once the A1 read
models land too. Six shards hold about 150 mutants, under five minutes each, with room for the
next schemas.

## Alternatives considered

- **Fewer examples.** Rejected: every example kills a mutant, and DEC-464 forbids removing tests
  or safety gates to meet the bound.
- **A larger timeout.** Rejected: DEC-464's bound is per job.
