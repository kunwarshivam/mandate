# DEC-987: The beta form is closed in a production build until Supabase is configured

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-17 (UTC) |
| **Decided by** | An agent (Claude Code, lane W1 builder), under DEC-176: a reversible product-behaviour choice with no spending, credential, legal or compliance text |
| **Story or claim** | E21-38, lane W1, claim [#1447](https://github.com/kunwarshivam/mandate/issues/1447); revises [DEC-731](DEC-731.md) item 4 |

## Decision

1. **Open or closed.** `betaOpen` in `web/src/lib/beta.ts` decides. The form is always open in
   development, the tests and the e2e builds, which keep a local file or stub the route. In any
   other build, it is open only once both `NEXT_PUBLIC_SUPABASE_URL` and
   `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` are set.
2. **Closed, the form shows a status and sends nothing.** It says "The private beta isn't taking
   requests yet. Check back soon." in place of the fields. The route answers 403 with
   `{"error":"closed"}` before reading the body. It writes nothing to Supabase or to a file. A form
   that meets that answer turns closed as well.
3. **Open, nothing changes.** DEC-731 item 4 still holds: a missing table or another Supabase error
   answers 503, and only development and tests fall back to the local file.

## Rationale

The demo may run before Supabase is set up. Without this, every request in a production build
would fail with 503 and a "try again" message that never comes true. A closed form is honest and
writes nothing. Setting the two public variables opens it at the next deploy, with no code change.

## Alternatives considered

- **Leave the 503.** The demo would show an error.
- **Hide the form.** That changes the landing page's layout and its tests. The closed status keeps
  the layout.
- **Store requests somewhere else** (Workers KV, R2): new bindings, which DEC-731 already turned
  down.
