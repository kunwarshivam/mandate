# DEC-452: Bind executor decisions to complete risk-gate inputs

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-05 (UTC) |
| **Decided by** | The founder, for the one-PR delivery instruction; the implementing agent under DEC-79 and DEC-176 for the conservative integration boundary |
| **Story or claim** | E7-7; claim [#171](https://github.com/kunwarshivam/mandate/issues/171) |

1. `mandate-executor::handle` requires a pure input source for the trusted values outside its
   account-stream fold that complete trading-domain §9.1's `GateInput`. The source returns facts,
   never a verdict.
2. The executor derives `ProposedOrder` from its own intent and calls `mandate_risk::evaluate`
   directly. An advisory decision has no path into this call and cannot override a binding denial.
3. The existing account-stream checks run first and may only narrow the result. A completed
   binding run journals the full gate evidence and removes `evaluation: account_stream_only`;
   a local-only decision keeps that marker.
4. Missing, mismatched, or unreadable binding inputs fail closed for an opening or increase. They
   do not turn snapshot availability into a new denial of a risk reduction: the local result
   remains binding for that reduction, preserving `AGENTS.md` rule 13.
5. This is a pure crate boundary. It adds only the existing workspace dependency on
   `mandate-risk`, introduces no network or broker activity, and does not change paper-only scope,
   journal-before-acting, CI, mutation, or independent-review requirements.
