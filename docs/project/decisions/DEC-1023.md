# DEC-1023: The subject-link file is fixed at `/etc/mandate/subject-links`, and a symlink there is refused

| | |
|---|---|
| **Status** | Accepted by an agent under DEC-176: it only narrows where the server reads the file from and what it accepts there, adds no risk, and weakens no safety rule |
| **Date** | 2026-10-17 (UTC) |
| **Decided by** | `claude-code` (lane A1, claim [#1444](https://github.com/kunwarshivam/mandate/issues/1444)); the root confirmed by the coordinator, who tells lane ID1 and the chart lane |
| **Story or claim** | E21-31; [workspace API spec](../../specs/workspace-api.md) §3.11 items 2 and 7; DEC-978 item 7 |

## Context

§3.11 item 7 read the subject-link file from a path named by `MANDATE_API_SUBJECT_LINKS`. CodeQL
reported the setting's flow into `fs::metadata` and `File::open` as an uncontrolled path (alerts
119 and 120 on #1457). No request reaches that path: the setting is read once at start, and the file
is refused unless it is a regular file the process's user or root owns that group and others cannot
write. But a configurable path admits any file a deployment names, and `fs::metadata` follows a
symlink to wherever it points.

## Decision

1. **The path is fixed:** the server reads `/etc/mandate/subject-links`, a constant in its code.
   `MANDATE_API_SUBJECT_LINKS` is no longer read; a deployment places the file there, and lane ID1's
   `mandate identity link` writes it there.
2. **A symlink at that path is refused** as an exposed file (a refresh reads it as an outage, a
   sign-in as the one 401), before the file is opened. The existing checks stand: a regular file,
   owned by the process's user or root, not writable by group or others.

## Consequences

The server's subject links can only come from that one root-owned location, and CodeQL's alerts
close with no input reaching the path. A deployment that set `MANDATE_API_SUBJECT_LINKS` moves its
file to the fixed path; the demo cell's chart mounts it there. Tests keep passing their own path to
the reading function, which the server never exposes as a setting.
