# DEC-455: Make runtime decisions and intents conform to the closed agent-stream schemas

| | |
|---|---|

## Decision

1. E7-7 also closes the integration defect between the runtime's legacy `DecisionMade` and
   `IntentProposed` payloads and journal §9.1's already-accepted closed schemas.
2. The runtime records the complete deterministic proposal, decision evidence, autonomy result,
   request origin, and causation required by those schemas. Replay and retry read the same canonical
   field names; legacy aliases are not emitted.
3. The runtime returns the two related drafts as one journal append batch. The shell preserves that
   batch so journal §9.1's cross-record consistency rule is enforced atomically before the intent is
   handed to the executor.
4. Facts the deterministic tracer does not use take the schema's explicit `null` or empty-list
   representation. No shell adapter manufactures a permissive autonomy or gate result.

## Rationale

The journal already rejects the legacy payloads. E7-7 cannot prove journal-before-acting through
the real runtime while the writer and replay disagree with the accepted journal contract. Batching
the decision and intent lets the journal validate their duplicated order facts before either is
committed and preserves the effect order that keeps the handoff behind both records.

## Alternatives considered

- Append each draft separately: rejected because the journal's companion consistency rule can only
  validate drafts presented in one batch.
- Register the legacy payloads as another schema version: rejected because they omit the evidence
  and classification facts §9.1 requires.
- Defer the correction: rejected under the founder's one-PR instruction because it is on E7-7's
  only end-to-end path.
