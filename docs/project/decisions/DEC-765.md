## Decision

1. Every export builds the canonical export first. Its anchor is the canonical export's verifier
   digest (journal spec §12, DEC-265 item 3: `ExportBundle::verifier_digest`), which
   `ExportCreated` records as bare hex (planned: journal spec #772 adds the member). JSON and CSV
   views are derived from it and name it as `verifier_digest`, printed as a `sha256:` ref.
2. **JSON lines:** a header line `{kind: "audit_view", view_version: 1, format: "jsonl",
   verifier_digest}` then one canonical JSON line per event with the envelope members and payload.
3. **CSV:** RFC 4180, UTF-8 without BOM, CRLF, every field double-quoted, quotes doubled; the
   header row of workspace API spec §4.8.1; `verifier_digest` on every row; `payload` as canonical
   JSON; null as an empty field.
4. **Formula injection:** a cell whose first character is `=`, `+`, `-`, `@`, U+0009, or U+000D is
   prefixed with `'`.
5. A time range exports, per stream, the contiguous `seq` range from the first event with
   `recorded_at ≥ from` to the last with `recorded_at < to`, so each range has a trusted start.
   Every stream's range is read in one database snapshot.
6. Only the canonical export is checkable: the views hold no canonical body bytes and are for
   reading, checked against the canonical export their `verifier_digest` names. The CSV view
   leaves out `config_refs`; the JSON lines view carries them.

## Rationale

Repeating the verifier digest per row keeps a cut-out row traceable to its source. Quoting every
field makes the output deterministic. The escape is the OWASP CSV-injection rule; it alters only
the view, and the canonical export stays the record.

## Alternatives considered

- **Quote only when needed.** Rejected: two correct writers would produce different bytes.
- **Escape by dropping the character.** Rejected: loses data silently.
