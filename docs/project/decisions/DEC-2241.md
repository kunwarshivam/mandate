## Decision (proposed)

1. **Until the founder decides,** every shown explanation and every approval draft carries the
   placeholder key `NOTE-EXPLAINER-NOT-ADVICE`, rendered as a named placeholder (for example
   "Disclosure NOTE-EXPLAINER-NOT-ADVICE (pending)"), never as drafted legal text. The journal
   records the key shown (`ExplanationRecorded.disclaimer`).
2. **The conservative option in force:** owner and explain runs describe what the agent did and why, from
   records; it never recommends a trade, an approval answer, or a mandate change; the template
   says so; a deterministic check refuses the advice fixture list (DEC-2240 item 6).
3. **For the founder:** the disclaimer text; whether explaining the platform's own research agent's
   reasoning changes the answer to question 31; whether the approval draft may be shown before
   counsel answers. Until then it is shown only in the platform's own demo and development
   workspaces, behind the deployment flag `desk.approval_explanations`, off by default (DEC-2240
   item 10). The recommendation is yes, with the placeholder, since it only restates the journaled
   reason for asking.
4. **A disclosed residual for counsel:** the advice check refuses a fixed phrase list; a paraphrase
   outside it can pass. Counsel's answer to question 41 may require a stricter check or templated
   text.

## Rationale

Disclaimer and compliance wording are the founder's (DEC-79). A named placeholder lets the feature
be built and demonstrated without drafting legal text, as DEC-1003 does for the forward-paper
disclosure.

## Alternatives considered

- **Draft a disclaimer now.** Not an agent's to write.
- **Hide the desk until counsel answers.** Safer still, but it also hides DEC-192's
  deterministic fallback, which is already accepted; the placeholder plus the advice check is the
  conservative reading that lets the demo run.
