# DEC-2142: The catalogue reads list only what their read model and a mandate document can carry

## Context

DEC-2136 item 2 says every model V-007 admits is listed by `GET /signal-models`, "no admitted one is
missing", and item 4 says a model's `content` keeps its members "member by member". The served read
(#2617) omits a registered model whose `model_version` is off the mandate schema's version pattern,
or that registers more than 32 parameters or a parameter name off the mandate schema's key pattern,
and keeps a `content` member only within the bounds `read-models/signal-models` publishes. V-007
reads only the registration row, so it still admits such a registration. A review of the spec PR
marking the reads served (#2665) found the disagreement.

## Decision

1. **A model no mandate document can name is not listed.** The mandate schema's `signal_model`
   bounds `version` to its pattern, `params` to at most 32 entries, and each `key` to
   `^[a-z][a-z0-9_]{0,63}$`, and V-007 compares a document's parameters with the registered ones.
   So a registration off those bounds is one no valid document can pin, and the list omits it, as
   DEC-2136 item 2 already omits an instrument no document can pin. Item 2's "no admitted one is
   missing" reads: no model a valid document can name and V-007 admits is missing.
2. **`content` keeps a member only within the read model's published bounds.** `authorship` up to
   64 characters, `methodology` up to 4000; `constraints` when there are at most 32, each up to 200
   characters; `params` when there are at most 32, each kept with only its `name` (the key pattern),
   its `type` (up to 32 characters), and its integer `min` and `max`, and a parameter without a
   valid `name` dropped alone. A member off its type or bound is absent, never cut short, so what is
   shown is always the registered text.
3. **Follow-up.** The registration path and V-007 should stop admitting what neither the mandate
   schema nor the read model can carry, or the read model's bounds should match V-007's, so the two
   never disagree. Backlog E10-11v holds it.

## Rationale

The list exists so the set-up offers what a version can name. Leaving out a model no document can
name, and a description longer than the published read model carries, only narrows what the owner
is offered; it never lets a version name something the create would refuse, and it changes no
check. Omitting a member rather than truncating it keeps every shown word the registered one.

## Alternatives considered

- **Widen the read model to serve whatever V-007 admits.** Rejected for now: a schema change in the
  served read, for registrations no document can use; E10-11v weighs it against tightening V-007.
- **Truncate long text.** Rejected: a cut methodology could misstate the registered model.
