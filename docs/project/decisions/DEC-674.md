# DEC-674: A later check that finds an allowlisted MCP tool missing suspends the connection; contract drift alone still degrades it

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-09 (UTC) |
| **Decided by** | The L2 lead, under DEC-176 (a reading that only tightens), on the coordinator's ruling of #825's review |
| **Story or claim** | E7-12, claim [#764](https://github.com/kunwarshivam/mandate/issues/764), [#825](https://github.com/kunwarshivam/mandate/pull/825) |

## Context

Two texts give different states for a later failure of the same MCP check.

- Connections spec §8.1 check 1 (scope) includes "for MCP, the allowlisted tools are present", and
  a later failure of check 1 is `suspended`.
- Journal spec §9.8's reasons table files `tools_missing` under the `contract` check. Connections
  §8.2 and §9.1 put contract drift (the pinned hash differs) in `degraded`, and §8.1 check 7's
  "failure later" column says only "Contract drift (§9)".

#825's tests had a later `tools_missing` degrade, as contract drift does.

## Decision

1. At a later check (occasion `executor_start` or `daily`), a failed `contract` check with reason
   `tools_missing` moves the connection to `suspended`. The executor journals it as
   `ConnectionStateChanged` with reason `check_failed`.
2. A failed `contract` check with reason `contract_drift`, and no other failure, still moves the
   connection to `degraded`.
3. A failed scope, environment, or account check still suspends, whatever else failed with it.
   A connect-time occasion (`connect`, `reconnect`, `reauthorize`) still changes no state, because
   its failure is a refusal.
4. `CheckReport::later_state` in `mandate-connections` implements items 1 to 3. The tests that pin
   them are `a_later_failure_suspends_unless_only_the_contract_drifted` and
   `a_later_failure_suspends_and_drift_degrades`.

## Rationale

DEC-176 lets an agent take the reading that only tightens and adds no risk. Here that reading is
§8.1 check 1's `suspended`. It is a pure tightening because:

- **Openings:** connections §9.1 halts openings in both `degraded` and `suspended`. Both set the
  account state `closing_only`, and both make the agents `exits_only`.
- **Exits:** both keep exits, protection, and the kill switch. For `suspended`, §9.1 says exits
  are "attempted while any call succeeds". With `tools_missing` the credential still works, so
  calls succeed. AGENTS.md rule 13 is unchanged.
- **Recovery:** only this gets stricter. Leaving `suspended` needs re-authorization: the owner
  replaces the credential, a `reauthorize` check passes every §8.1 check, the rotation is accepted
  (journal §9.8 rule 68), and then the owner acknowledges. Leaving `degraded` needs only the
  condition to clear and the owner's acknowledgment.

**Consistency with DEC-839 item 4** (the MCP client: a missing allowlisted tool halts openings,
and only a new connection with a new pin lifts the client's halt; exits are allowed). The
connection state and the client's halt are separate. Both block openings, and neither holds an
exit. Clearing `suspended` does not lift DEC-839's halt.

## Consequences

- Journal spec §9.8 gets a small clarifying change: a later `tools_missing` is journaled as
  `ConnectionStateChanged` with reason `check_failed` into `suspended`. Rule 59 already allows
  this, since `check_failed` is one of the suspending reasons. The change is its own journal-spec
  PR in the coordinator's queue. Code that journals the transition waits for that PR.
- Rule 60 is unaffected: `suspended` is entered from `active` or `degraded`, never the reverse.

## Alternatives considered

- **Degrade on a later `tools_missing`, as on drift** (#825's earlier reading). Rejected: it takes
  the looser of two texts. A connection missing a tool it was built for would be restored by a
  probe and an acknowledgment, with no re-authorization.
- **Treat `tools_missing` as a scope failure in the report** (`check` `scope`). Rejected: journal
  §9.8's reasons table names it under `contract`, and changing the report's shape is a journal
  spec change, not a reading.
