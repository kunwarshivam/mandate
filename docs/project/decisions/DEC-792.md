# DEC-792: Web push endpoints only on the browsers' own push services

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-08 (UTC) |
| **Decided by** | The L3 builder agent under DEC-176 (it only refuses more and adds no spend), at the L3 lane lead's direction: the browser push services are dictated by the browsers, with no contract or vendor choice (DEC-79 is not engaged) |
| **Story or claim** | E8-14, claim [#753](https://github.com/kunwarshivam/mandate/issues/753); [control plane design](../../design/control-plane.md) CP-1 (`PushEndpoint`, "validated against the allowed push-service origins"); [notifications spec](../../specs/notifications.md) §4.6, NT-2 |

## Decision

1. **An allowlist of push-service hosts.** A push subscription's endpoint is accepted only if it is
   `https` on one of the deployment's allowed push-service hosts, and is refused otherwise: when the
   browser hands it over, when the workspace stores it, and when the sender or the relay builds a
   request.
2. **The list is deployment configuration**, with this default. Each entry is either one exact host
   or a domain whose subdomains are all allowed:
   - `fcm.googleapis.com`, exact (Chrome and other Chromium browsers);
   - `updates.push.services.mozilla.com`, exact (Firefox);
   - any subdomain of `push.apple.com` (Safari; Apple asks servers that restrict endpoints to allow
     every subdomain of it, and endpoints today are `web.push.apple.com`);
   - any subdomain of `notify.windows.com` (Edge, through the Windows Push Notification Services,
     whose endpoints are regional `wns2-*` hosts).

   The retired `android.googleapis.com` (GCM) is not on it. A customer-run deployment may shorten the
   list; adding a host is a configuration change that is reviewed like any other.
3. **Where it is enforced.** `mandate_webpush::PushEndpoint` enforces it in the next Rust slice
   (not in #800), and the relay (E20-8) enforces it again. A port, a user-information part, or a
   host outside the list is refused before anything is sent.

## Rationale

The endpoint is the one place where a workspace sends a request to a host chosen by someone else:
the browser picks it, and a malicious page or a tampered subscription could pick any URL. An
allowlist turns the push sender into a client of four known services rather than an open
forwarder, which CP-1 already assumes. It refuses more and spends nothing.

## Alternatives considered

- **Any `https` host** (S8a's parser today). Rejected: the sender and the relay would POST to any
  address a subscription names.
- **The list fixed in code.** Rejected: a browser can move its push service, and a customer-run
  deployment may want a shorter list; configuration with a reviewed default covers both.
