# DEC-922: The live-path rehearsal reaches the Robinhood simulator through a separate rh-sim build feature, and runs the real OAuth login

## Decision

1. A build feature, `rh-sim`, separate from `live`, is the only build in which the pinned MCP
   endpoint accepts an http loopback host. The `live` build without `rh-sim` never accepts a
   loopback or any host other than the pinned Robinhood host (LT-1 unchanged).
2. A binary built with `rh-sim` refuses to start against any non-loopback host, so it can never
   reach a real broker.
3. The simulator serves OAuth metadata and a token endpoint, so the rehearsal runs the real
   OAuth login code (O1b `AuthServer`, `CallbackListener`). There is no OAuth bypass.
4. `mandate-rh-sim` gets a runnable binary with scripted fills for the rehearsal.

## Rationale

The rehearsal must exercise the same code that R0 runs. OAuth is otherwise first exercised
against real Robinhood at R0.

## Alternatives considered

- An OAuth bypass in the sim: faster, but leaves the login untested before live money.
- Loopback accepted in the live build: weakens host pinning in the production binary.
