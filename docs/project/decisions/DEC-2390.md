## Context

**The zero row.** Robinhood, like the simulator, can list a sold-out position as a row of quantity
zero (DEC-902 item 3). The runner's lapse (`mandate-paper/src/connection.rs`, `lapse`) and the
shell's preflight judge (`mandate-shell/src/paper/judge.rs`, `judge`) count position rows, not
quantities, so an account a stop sold out reads as not flat. DEC-1152 item 4 left the reading to
the founder. The coordinator asked: "After a Robinhood position is fully sold, the broker still
shows it with quantity 0. Should the agent treat that as 'no position' so it can trade again?" The
founder answered, verbatim, **"Yes, treat as flat (Recommended)"**. The option read: "A 0-quantity
row means flat. Without this, an account a stop sold out can never restart."

**Where the always-on agent runs.** DEC-2135 recorded the founder's "Runner first
(Recommended)", which rested on lane LV's estimate of about four PRs. This decision's first draft
designed that runner path, and its independent review (#2510) found the estimate wrong: the R0
runner is single-deployment by design. Its preflight judge refuses any held position or open
order; its gate and builder read first-deployment constants for equity, the high-water mark,
positions and today's buys, and DEC-470 item 9 keeps `cycle_already_open` precisely so those
constants cannot reset limits; and a reconciliation mismatch pauses the agent and stops the run.
An always-on runner would have to rebuild the gate's and the builder's state from the journal,
which the cell's runtime and executor already do. The coordinator relayed the founder's later
instruction, at about 08:40 UTC, to "build real product … no shortcuts, no hacks, no bad
decisions" (relayed, not seen in the founder's own words by lane LV).

## Decision

1. **A position row of quantity exactly zero is flat.** Wherever a flatness check counts the
   broker's positions (the runner's lapse, the shell's preflight judge), a row whose quantity is
   exactly zero counts as no position. Any row with a non-zero quantity, long or short, still
   counts, and any working order still counts. The shell's judge is shared by the Alpaca paper
   path, so the reading applies there too; it accepts only a row of exactly zero, which adds no
   risk on either broker. It amends DEC-470 item 1's and DEC-933 item 3's "every position record"
   to every record of a non-zero quantity. `LapseSnapshot::fresh` still treats a snapshot with any
   row as naming an instrument, so the preflight reads the account again (DEC-956 item 1). Nothing else changes: the lapse's
   `connection_spent` still refuses a second live run on the same record (DEC-910 item 3), so on
   the R0 runner an account a stop sold out is now refused for the designed reason, the spent
   record, rather than `account_not_flat`. Tests first.
2. **Proposed: the founder's always-on agent is built on the cell.** It runs as the product does: the
   runtime, the executor and the deployment manager as separate processes, reading their state
   from the journal. The work is DEC-2386 slice C (the executor process's Robinhood broker, tested
   on fixtures synthesized from Robinhood's published contract), then DEC-2382 items 4 and 7 (the
   executor's live build and the vault credential), then the founder's enable through DEC-2137's
   gate. The R0 runner stays as it is on `main`, for the founder's one-order runs (DEC-529).
   If the founder confirms, DEC-2135's consequence "lane LV builds first on the runner" is
   superseded; its other items stand either way. DEC-2300's sell booking and `quant.ma_crossover` 1.1.0 are needed on the cell too and
   continue.

## Rationale

A row of quantity zero is the broker's own way of saying nothing is held; reading it as a holding
only blocks a clean restart. The cell already folds every risk figure from the journal, which is
what an agent that keeps running needs, and building it there is the product rather than a second
implementation.

## Alternatives considered

- **Keep reading a zero row as a holding:** offered to the founder and declined.
- **The always-on agent on the R0 runner** (this decision's first draft): rejected after its
  review. It needs the runner's gate and builder state rebuilt from the journal, a restart-aware
  judge and new pause semantics, duplicating the cell.
