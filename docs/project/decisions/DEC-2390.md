## Context

DEC-2135 lets the founder's agent keep trading real money on the founder's own Robinhood agentic
account, within a 100 USD cap, one ETF and `ask` on every opening, and the founder chose to run it
first on the runner the founder already has (`mandate-paper --features live`, DEC-529's R0).

The runner today is built for one order:

- **The lapse** (`mandate-paper/src/connection.rs`, `lapse`) refuses a live run unless the
  account is flat, and refuses `connection_spent` once the account stream holds any fill
  (DEC-910 item 3). It counts position rows, not quantities, so a sold-out row of quantity zero
  reads as not flat (DEC-1152 item 4).
- **Booking.** A live run books none of its own fills (`Booking::book` skips a live connection),
  since a live record was meant to be spent by its first fill.
- **No output, no cycle.** When the model answers `Flat` or `Undecided`, `run` returns
  `Outcome::NoOutput` before any cycle, so nothing reconciles and nothing checks protection.
- **No signal exit.** The builder already has §8.3's exit branch (c ≤ −`exit_threshold` exits the
  whole position), but `quant.ma_crossover` 1.0.0 answers `Flat` with no output (DEC-157 item 4),
  so c is never negative and the agent never sells on its signal.
- **A sell is never booked.** Robinhood publishes no sell price, and DEC-2300's booking at the
  limit is not built, so after any sell the journal's position stays above the broker's.

## Invariants first

1. **Never adopt.** A run never books, adopts or trades on a holding its own journal does not
   explain. Anything the broker holds that the account stream's own fills do not explain refuses
   every opening; it never becomes the agent's position.
2. **Risk reduction is never denied** (`AGENTS.md` rule 13). Nothing here holds an exit, a
   protective order or a kill switch: a restart that refuses openings still reconciles, protects
   and exits.
3. **Every opening asks.** No path here sends an opening without the founder's grant for that
   order (DEC-2135 item 3).
4. **No double count.** A fill already on the account stream is never booked again, by any run.
5. **No unprotected hold.** Whenever the agent holds a position, each run ends with a protective
   order resting for it at the broker, or with an alert saying it could not place one.
6. **Only the founder's always-on agent changes.** A paper run, and any live run that is not the
   founder's always-on agent, behaves exactly as on `main`.
7. **Journal before acting** (`AGENTS.md` rule 5). Every order this adds is journaled with its
   idempotency key before it is sent.

## Decision

1. **A restart is the same agent on the same connection.** A live run whose account stream
   already holds a fill (today's `connection_spent`) is a restart of the founder's always-on
   agent when the confirmed mandate is live on a Robinhood connection the founder recorded
   (DEC-2135 item 1). A restart is not refused `connection_spent`. Every other live run keeps
   DEC-910 item 3's refusal unchanged. The first start keeps DEC-470 item 1: the account must be
   flat.
2. **A restart's lapse compares quantities, and refuses openings on any difference.** Before
   anything is sent, the restart reads the broker's positions and working orders and the account
   stream's own state, and refuses every opening (`holding_unexplained`) unless all of these hold:
   - each broker position's quantity equals the ledger's position in that instrument, folded from
     the account stream alone;
   - every broker working order is one of the journal's own working orders, matched by the
     broker order id the journal holds for it (DEC-1150 item 7);
   - the account stream holds no `Unknown` order (DEC-529 item 4);
   - the reconciliation the run performs at start finds no unexplained difference.

   A refused restart still runs items 4 and 5: it reconciles, re-protects and exits as rule 13
   requires. It only never opens. The founder resolves the difference by hand; the run never
   adopts it (invariant 1).
3. **A live run books its own fills.** At start, a live run books the fills its own orders
   imply, as a paper run does (DEC-955): buys by DEC-1151's `recorded_fills`, and sells by
   DEC-2300 once that lands. Until DEC-2300 lands, a sell leaves the journal's position above the
   broker's, so item 2 refuses every later opening. That is the safe side: the agent stays able
   to exit and protect, and never opens on a position it cannot explain.
4. **Every run reconciles and protects, whatever the model says.** A run whose model gives no
   opening output still runs the cycle's reconciliation, books its fills (item 3), checks
   protection (item 5), and applies the builder to its held position (item 7). It returns
   `NoOutput` only after them. The model's silence never skips risk work.
5. **Protection is checked on every run.** When the ledger holds the instrument, the run checks
   that the protective GTC stop-limit DEC-529 item 7 placed still rests at the broker for the
   whole position. Robinhood's GTC expiry is not published, and the founder may cancel it in the
   app. If it is gone, the run places a new protective stop-limit for the whole position, a
   `protective` order exempt from every conduct, eligibility and buying-power check (rule 13),
   journaled before it is sent. If it cannot be placed, the run raises the `protection_missing`
   alert, which carries only opaque ids (`AGENTS.md` rule 6), and refuses every opening.
6. **A sold-out row of quantity zero reads as flat** (DEC-1152 item 4). **Proposed for the
   founder.** Item 2 compares quantities, so a row of quantity zero equals a ledger of zero and is
   explained. Until the founder accepts this, the code keeps today's reading: any row, of any
   quantity, is a holding, and a first start on such an account refuses `account_not_flat`.
7. **A signal exit needs a model version that says so.** **Proposed for the founder.** §8.3 exits
   the whole position when c ≤ −`exit_threshold`, but `quant.ma_crossover` 1.0.0 gives no output
   on `Flat`, so c is never negative. A new version, `quant.ma_crossover` 1.1.0, answers `Flat`
   with conviction −1 and confidence 1; `Long` is unchanged, and `Undecided` stays no output. It
   is a new content hash, so it reaches the agent only when the founder confirms a mandate
   version that pins it (`AGENTS.md` rule 11). The exit it causes is a `discretionary_exit` under
   rule 13: paced by conduct controls, waiting for the regular session for equities, never
   denied, and sized by the builder to the whole position less working exits. Until the founder
   pins it, the agent exits only by its protective stop, a risk exit, or the founder's own exit.
8. **The loop.** `--keep-running` (live only, and only with `--place-one-order` replaced by it)
   runs item 4's cycle once per regular session, at the mandate's evaluation time, in one process
   that keeps its Robinhood session in memory (DEC-529 item 10). It stops on Ctrl-C, on any refusal
   the run would stop on today, and on any read the connector cannot authorize, which the founder
   ends by logging in again with a new run. It sends nothing while it waits. Each pass is a
   restart under items 1 and 2, so no pass trusts the last one's state.
9. **The kill switch.** Until `mandate agent kill` reaches the CLI (DEC-1152), the runbook says
   the kill switch is Ctrl-C and the Robinhood app, and it does not tell the founder to leave the
   agent unattended (DEC-2135).

## Rationale

The runner already holds the whole order path: the gate, the approval flow, the executor and the
journal. What it lacks is a way to run again on the same agent without trusting what it has not
read. Comparing quantities against the agent's own journal, and refusing openings on any
difference, keeps the never-adopt rule while letting a clean restart trade. Running the cycle when
the model is silent keeps reconciliation, protection and exits from depending on the model.

## Alternatives considered

- **A fresh connection record per run** (DEC-1152's "by design"): rejected. Each run would need a
  new connect check, record, version and deployment, which is not an agent that keeps trading.
- **Adopting the broker's holdings at restart:** rejected (invariant 1, the coordinator's rule).
- **Exit on `Flat` inside the runner, outside the builder:** rejected. Exits are the builder's
  (§8.3), and a second exit path would bypass its pacing and its record.
- **Keep the model and accept no signal exits:** possible, and the default until the founder
  answers item 7. The protective stop still bounds the loss.
