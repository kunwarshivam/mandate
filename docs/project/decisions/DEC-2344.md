## Context

The deployment manager stops an agent's runtime on its `AgentStopped`, and the account's executor
once every agent of the account is retired (journal spec §9.21). The executor learns of a kill
switch only from the runtime's copy on an agent's stream, so after that point a kill switch reaches
nothing on the account. Today that strands nothing: the only writer of `AgentStopped` is the CLI's
retirement of an agent no process ran (DEC-2039), which holds nothing, and the runtime's owner Stop
only sets mode `stopped` and leaves the agent deployed. But the specs let a retirement leave
something behind:

- mandate spec §3.1's `profit_stop` retires "after" a discretionary exit of every position, which
  does not say the exits filled, so an equity exit waiting for the regular session could still be
  working;
- `release` hands the positions to the owner as external holdings, which an account- or
  workspace-scoped kill switch (trading spec §5.5, broker cancel-all and close-position) is still
  meant to reach.

Keeping the executor while the account's fold shows positions or working orders was considered and
rejected: the manager reads only the control stream, and released owner holdings are positions by
design, so it would keep an executor up for ever.

## Decision

1. **A covering kill switch starts an executor no agent wants** (the deployment manager). An
   executor slot that is not desired, has no live instance, and has a covering kill switch it has
   not answered gets exactly one start for it, cause `kill_switch`, journaled first, as journal
   spec §9.21 already gives a crash-looped slot. Once that generation's switch is answered the
   manager stops it again, with cause `agent_stopped`. A slot with no covering kill switch is never
   started by this item. The start applies something only once the executor reads a kill switch
   from the control stream itself (DEC-2343).
2. **Retirement leaves nothing of the agent's** (mandate spec §3.1, journal spec §9.2). A runtime
   writes `AgentStopped` for an agent that ran only once the account stream's fold shows no
   position attributed to the agent and no working order of its own, none open and none `Unknown`:
   after its exits fill (`profit_stop`, a passed `end_date`), after `PositionReleased` and the
   confirmed cancels of its protective orders (`release`), and for the owner's Stop under DEC-136's
   flat-or-release precondition. It is the writer's rule: no journal member, rule, or vector
   changes, since a control-stream check does not read the account stream. The runtime's property
   test is an E6-5 backlog row.
3. **An executor stays desired until a switch it was started for is answered** (the deployment
   manager). A covering kill switch the manager has journaled a start for keeps the executor
   desired until that start's generation answers it, even if the account's last `AgentStopped` is
   read in between, so a switch issued just before a retirement is not cut off.

## Rationale

Every route to `AgentStopped` then ends an agent that holds nothing, so stopping its runtime and
its account's executor on that record alone strands no order or position of the agent's. What the
owner holds after a release is still reached by an account-scoped kill switch, because item 1
starts the executor for it, and item 3 closes the window between a switch and a retirement. Each
item only delays an end or adds a start in answer to a kill switch, which reduces risk.

## Alternatives considered

- **The manager folds each account stream and keeps the executor while it shows positions or
  working orders.** Rejected: it gives the manager reads and a fold it does not own, and released
  owner holdings would keep the executor up for ever.
- **Leave it to the writer alone (item 2).** Rejected: it does not cover released owner holdings,
  which only an account-scoped kill switch reaches.

## Risks

- Items 1 and 3 apply nothing until the executor reads a control-stream kill switch (DEC-2343),
  and an account- or workspace-scoped switch needs the executor's cancel-all and close-position
  path (lane LV's A2b, DEC-2333).
- Item 2 binds a writer that does not exist yet; until it does, the CLI's retirement of an agent no
  process ran is the only `AgentStopped` writer, and it holds nothing.
