## Decision

1. **Two public build-time values choose the source.**
   - `NEXT_PUBLIC_WORKSPACE_SOURCE`
   - `NEXT_PUBLIC_WORKSPACE_API_URL`

   `dataSourceFrom` (`web/src/api/workspace-source.ts`) reads them, and the result is one of
   `fixtures`, `api`, or `unconfigured`. The values carry no secret, because the API authenticates
   with the session cookie (spec §3.3).
2. **Fixtures only when named.**
   - `NEXT_PUBLIC_WORKSPACE_SOURCE=fixtures` selects fixtures in any build.
   - A development or test build that names neither fixtures nor an API also uses fixtures, so
     `npm run dev` and the unit tests work as they do today.
3. **The API needs an `https` origin.** Plain `http` is accepted only to `localhost`,
   `127.0.0.1`, or `[::1]`, for local development.
4. **Anything else is `unconfigured`, and `unconfigured` renders as unreachable.** That covers:
   - a production build with no source and no API;
   - naming both fixtures and an API;
   - an unknown source name;
   - a URL that fails item 3.

   An unconfigured build shows "cannot reach your workspace", with no agent data (G1, G4). It never
   shows fixtures, which would put invented figures in front of an owner as if they were theirs.
5. **The workspace is never a build value.** Which workspace a session reads comes at run time,
   through `resolveWorkspace` and an injected `IdentityApi`. The two identity routes it reads are
   specified in identity spec v0.3 §4.5 ("One's own memberships" and "One's own session"), with
   §6.2, §6.4 route 2, and DEC-816 items 1, 5, and 6. That spec change is
   [#811](https://github.com/kunwarshivam/mandate/pull/811), head 0953a0b, still in review.
   - A build-time workspace id would pin every user of a build to one tenant, so none is read.
   - Fixtures need no workspace, and neither route is asked.
   - `GET /v1/me/session` comes first.
     - A **reduction-only** session (§6.4 route 2) covers exactly the workspaces it lists, each as
       `{workspace_id, label}`. The membership index (`GET /v1/me/workspaces`) is never read for
       it.
     - A **full** session (§6.2) reads `GET /v1/me/workspaces`, which lists each active membership
       as `{workspace_id, label, roles}`. `roles` holds the effective roles, possibly none.
   - One workspace is read directly. Several are offered by label (G1's switcher). The last-used
     workspace is offered as the default only while it is still listed, and it is never selected
     on its own. The device remembers only that opaque id; the API refuses a foreign id itself
     (API-9).
   - Any failure is `unreachable`, never fixtures. That covers:
     - either read failing, or no answer at all (retryable);
     - `membership_unavailable` (503, retryable);
     - a response that does not decode, such as a single `role` or an unknown session kind (not
       retryable).

     When the session read fails, the memberships are not read.
   - These make the source `unconfigured`: no workspace, a workspace listed twice, or an id that
     is not a path segment.
   - The identity reads send the session cookie with `credentials: "include"`, because the API may
     be on its own origin.
   - Until the routes are served, the default `identityNotServedYet` answers nothing, so an API
     build shows "cannot reach your workspace".
6. **No cached content.** When a read fails or its response cannot be decoded, the dashboard state
   becomes unreachable. Nothing from an earlier load survives: no agent, approval, decision,
   position, or account figure (spec §7, brief G4).

   Stop stays reachable, as the shell already makes it (G1).
7. **Ages are the server's.** A value's age is `Freshness.age_seconds`, which the server measures
   to `served_at`, and the server's `stale` flag always wins. Each stream's age is measured from its
   own watermark, so one response can be current on one stream and behind on another (spec §6.1).
8. **Refetch only what moved.** A `/changes` notice refetches a view only when it carries a
   higher `seq` for a stream that view's `as_of` names (spec §3.1, §6.3).
9. **D1 on the API is the summary** (spec §4.7). `ApiDashboard` renders what `GET /dashboard`
   carries: each agent's label, mode, restrictions in the explainer's words, P&L with the paper
   note once, its marks' age, and its owl glyph, which needs only the id and the mode. With no
   agents it says so, and when unreachable it shows the notice. These fixture members of D1 need
   the full agent and move to S3, which reads
   `/agents/{id}`, `/agents/{id}/positions`, and `/agents/{id}/orders`:
   - the headroom line, which needs the mandate and `LimitState`;
   - the account equity chart;
   - the holdings section, which needs positions;
   - the decision timeline, which needs gate decisions;
   - the Needs you request sentences, which need the approvals read model.

## Rationale

Before this slice, the app read fixtures unconditionally. Once it can read a real workspace, a
deployment with a missing or wrong API value must fail visibly. If it fell back to fixtures, an
owner could be shown invented positions and P&L in a real deployment, with nothing to tell them
apart. Requiring fixtures to be named costs one environment value on the fixture deployments.

## Consequences

A deployment that is meant to show fixtures must say so in its build environment, with
`NEXT_PUBLIC_WORKSPACE_SOURCE=fixtures`. Otherwise it shows "cannot reach your workspace". The
founder's deploy steps for the move to Cloudflare Workers (DEC-823) carry that value until the
workspace API is live.

## Alternatives considered

- **Fall back to fixtures whenever no API is configured.** Rejected: the failure is silent and
  shows invented data as real.
- **Choose the source at run time, from a cookie or query parameter.** Rejected: it lets a viewer
  switch a real deployment onto fixtures. A build-time value cannot be changed from the browser.
- **Keep the last good dashboard when a reload fails, marked stale.** Rejected for an unreachable
  deployment, because G4 asks for no cached content. Staleness is for values the deployment still
  serves with their age.
