## Context

DEC-2011 picks OpenTofu, DOKS and GitOps, two environments, and a $150 monthly cap, and keeps cloud
tokens in GitHub environments the founder approves. Lane IAC builds everything up to a reachable,
empty cluster with its buckets, DNS and Access; lane GO installs the cluster's add-ons and the
applications.

## Decision

1. **Layout.** `deploy/tofu/modules/` holds one module per concern: `network` (VPC and firewall),
   `doks` (the cluster and its one node pool), `spaces` (the state and journal-archive buckets),
   `cloudflare` (tunnel, DNS and Access) and `budget` (the cost estimate and its cap).
   `deploy/tofu/environments/staging/` and `.../production/` are each a root module that calls
   them with that environment's values, so the two differ only in values and a plan of one cannot
   touch the other.
2. **Pins.** OpenTofu `1.13.1`; providers `digitalocean/digitalocean` `2.103.0` and
   `cloudflare/cloudflare` `5.27.0`, exact versions, each root's `.terraform.lock.hcl` committed
   with the hashes for `linux_amd64` and `darwin_arm64`; tflint `0.64.0` with only its bundled
   `terraform` ruleset, so it downloads no plugin. Each was published at least two weeks before
   this decision.
3. **State.** Each environment's state is in its own Spaces bucket, `<prefix>-tofu-state-<env>`,
   through the `s3` backend. The founder creates that bucket once by hand (OpenTofu cannot store
   its state in a bucket it has not made yet); the root then adopts it with an `import` block and
   holds it private and versioned, with `prevent_destroy`. State is encrypted on the client by
   OpenTofu's own state encryption (`pbkdf2` key provider, `aes_gcm`, `enforced`), from a
   passphrase that is a secret of the environment, so the tunnel token and the archive key that
   state must hold are never stored readable in Spaces. Runs are serialised by the workflow's
   `concurrency` group per environment, not by a lock file, since Spaces' support for the
   conditional writes OpenTofu's S3 lock needs is not documented.
4. **Network.** One VPC per environment in `nyc3` (DEC-995 item 2) with its own range, and one
   cloud firewall on the cluster's node tag whose inbound rules admit only the VPC's own range.
   DigitalOcean firewalls add up rather than narrow each other, so this firewall cannot close what
   DOKS's own managed worker firewall opens; the guarantee is that nothing in `deploy/tofu/` opens
   a public port, no `digitalocean_loadbalancer` exists, and lane GO creates no Service of type
   `LoadBalancer` or `NodePort` (the chart already creates none, DEC-967 item 6).
5. **The cluster.** One DOKS cluster per environment, Kubernetes version pinned exactly
   (a precondition fails the plan, listing the versions DigitalOcean offers, when the pin is not
   one of them), `auto_upgrade` off, `surge_upgrade` on, no HA control plane, no registry
   integration. One node pool of exactly two nodes, `s-2vcpu-4gb` by default, autoscaling off.
   The control plane's firewall is on, and admits only the CIDRs the founder sets in the GitHub
   environment's `KUBE_API_ALLOWED_CIDRS`; a world range (`0.0.0.0/0`, `::/0`) or an empty list is
   refused by the variable's validation.
6. **Ingress.** A remotely managed Cloudflare Tunnel per environment (its token is the chart's
   `cloudflared-tunnel` Secret, which lane GO places), one proxied DNS record for the API's
   hostname pointing at the tunnel, and one Access application on that hostname whose policy
   allows only the emails in `ACCESS_ALLOWED_EMAILS`. The tunnel's ingress maps that hostname to
   the API's origin and everything else to `http_status:404`.
7. **The budget.** No DigitalOcean API sets a billing alert, so the 80% alert of DEC-2011 item 2
   ($120) is a step the founder takes in the billing settings, named in the runbook. In code, the
   `budget` module adds up each environment's monthly estimate (the node size's price as
   DigitalOcean's size list reports it, times the node count, plus Spaces and block storage at
   list price) and a precondition fails the plan when it passes that environment's share of the
   cap: $75 each, so both together never plan past $150.
8. **Checks without credentials.** Every pull request that touches `deploy/tofu/` runs
   `tofu fmt -check`, `tofu init -backend=false` and `tofu validate` in each root, tflint, and
   `tofu test` with mocked providers as the policy check: no public firewall source, no load
   balancer, buckets private and versioned, auto-upgrade off, the pinned version, two nodes, the
   control plane's firewall on, the DNS record proxied, Access in front of the API host, and the
   estimate under the cap; each refusal also has a test showing it fails. None of these reads a
   secret or reaches a cloud API. `infra.yml` alone runs `plan` and `apply`, from `main`, on manual
   dispatch, under `infra-staging` or `infra-production`, which the founder approves (ES-12,
   DEC-1005's pattern; the details are DEC-2014's).
9. **The journal archive is versioned, not write-once.** Spaces has no S3 Object Lock, and the
   provider exposes none, so DEC-2011's "write-once retention where Spaces supports it" has
   nothing to set. The archive bucket keeps every version with no expiry of old versions, and the
   key Barman uses is a Spaces key granted read-write on that bucket alone, never full access. Its
   holder can still delete versions; that residual is disclosed in the ADR and the runbook, and a
   store with object lock is the backlog's follow-up, not a change made here.

## Rationale

A root per environment is the simplest layout in which a staging plan provably cannot change
production, and modules keep the two from drifting. Client-side encryption is the one way to keep
the tunnel token and archive key out of readable state without another service. Testing the plan
against mocked providers checks the same resources `apply` would create, with no credential,
which is what ES-12 requires of a pull-request job.

## Alternatives considered

- **Workspaces in one root** instead of a directory per environment: one backend and one set of
  variables for both, so a mistyped workspace plans production.
- **Terraform:** its licence is BUSL since 1.6; DEC-2011 names OpenTofu.
- **A separate policy engine (OPA/conftest, checkov) over a plan's JSON:** a new tool, and a plan
  needs credentials; `tofu test` with mocks needs neither.
- **The state bucket made by a bootstrap root with local state:** that state would live on a CI
  runner and be lost, or need its own bucket.
- **Isolated workers and a NAT gateway** so nodes have no public address: the gateway's price
  would take a large part of the cap; recorded as a later hardening.
