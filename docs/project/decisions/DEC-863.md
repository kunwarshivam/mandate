## Decision

1. **Item 2 corrected.** A wider window does not "only leave the order `Unknown`". It can also
   take in a record of an older order of ours with the same members. If the lost order is not
   listed, that stale lookalike would be the one match and would be adopted. Items 2 and 3 below
   close that.
2. **The exclusion.** A listed record is never a match for the `Unknown` order if it is another
   order the account stream already journals:
   - it carries the client order id of another of our orders (DEC-862 item 4 already refuses this);
   - its broker order id is one the stream journals for another of our orders. Today the stream
     journals none (`OrderStateChanged` is closed, and DEC-860 item 7 owes the field), so this leg
     applies once that field exists.
3. **Until then, lookalikes.** A record with no client order id is not a match when any other
   order the account stream journals, in any state, has the same instrument, side, quantity, limit
   price, order type and time in force. The two cannot be told apart, so the order stays `Unknown`
   and its instrument blocked until the owner reconciles it (§5.3 rule 9).

## Rationale

A wrong adoption frees the instrument for a second order; a wrong `Unknown` only waits for the
founder (rules 3 and 13, LT-6). Item 3 may block a repeat order of identical members; that is
the safe side.

## Alternatives considered

Excluding by broker order id only: the stream has no broker ids today, so it would exclude
nothing. Excluding lookalikes only within the listing window: the window compares our clock with
the broker's, so it cannot be relied on.
