# DEC-2606: CodeQL analyses no draft, and a new push cancels the analysis it replaced

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-18 (UTC) |
| **Decided by** | the agent, as a reversible CI change (DEC-79) |
| **Story or claim** | No story; CI throughput (lane CT). Approved pull requests' `ci` runs queued for over an hour on 2026-10-18 |

## Decision

1. The "CodeQL Advanced" workflow (`.github/workflows/codeql.yml`) skips its `analyze` job while
   the pull request is a draft, as `ci` does (DEC-610). It adds `ready_for_review` to its
   `pull_request` types, so marking a pull request ready starts the analysis, and every later push
   runs it again.
2. A pull request's CodeQL runs share one concurrency group and a new push cancels the run it
   replaced. A push to `main` and the weekly schedule each have a group of their own
   (`github.run_id`) and are never cancelled.
3. Nothing else changes: the same four languages, the same config and queries (DEC-500, DEC-794),
   the same triggers on `main` and the schedule. Every ready pull request's head is still analysed.

## Rationale

The account runs at most 40 jobs at once, and on 2026-10-18 it was full: 38 jobs in progress and
about 390 queued, while `merge` jobs that do twelve seconds of work waited a median of ten minutes
and up to thirty. Of about 9,400 runner-minutes between 2026-10-17 18:00 and 2026-10-18 20:45 UTC,
CodeQL took 17 percent (28 percent of the latest 300 runs), four `Analyze` jobs a push. It ran on
134 pull request pushes while `ci` ran on 57: the rest were drafts, which `ci` skips, and pushes
already replaced by a newer one, which `ci` cancels. Analysing a draft head that nobody will merge,
or a head a newer push replaced, finds nothing the analysis of the ready head misses, so skipping
those runs gives the runners back without testing less.

## Alternatives considered

- **Run CodeQL only on `main`.** Declined: a finding would surface after the merge rather than on
  the pull request that introduced it.
- **Skip CodeQL on documentation-only pull requests (`paths-ignore`).** Not taken here: it changes
  which ready heads are analysed, which this decision avoids. It can be decided on its own.
- **Buy more concurrency (larger runners or a higher plan).** Spending is the founder's (DEC-79).
