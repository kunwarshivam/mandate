## Decision

What main held: the executor already lists an `Unknown` order at `Input::Started` on a profile
with no query by client order id, and adopts exactly one match (B2b, `listing.rs`, DEC-862); the
shell's start hands that `ListOrders` to the connector before its startup reconciliation. Two
pieces were missing, so no restart could adopt anything: the Robinhood connector answered
`ListOrders` `NotSent` (`not_offered`), and every record the shell's executor wrote before its
first watch tick carried `risk_clock` `1970-01-01T00:00:00Z`, so the listing's `created_at_gte`
would have been the intent's `OrderSubmitted` time less five minutes, that is, before the epoch.

1. **The mapping (C3).** `ListOrders` is one `get_equity_orders` read of the agentic account
   through `read_sole_member` (CN-8, DEC-875), with `symbol` the listing's instrument id as
   the connector already sends it on `place_equity_order`, `placed_agent` `agentic`, and
   `created_at_gte` the listing's start as RFC 3339 text at nanosecond precision (`mandate-time`'s
   form). Its answer is `Listed` with every record, unmatched: the executor alone matches
   (DEC-862 item 4), and the connector never places.
2. **The simulator.** `mandate-rh-sim` gains a broker clock (`Event::Clock`) stamped on each order
   it creates, and `get_equity_orders` serves `symbol`, `created_at_gte` (inclusive) and
   `placed_agent`. Every order the simulator holds was placed through the agentic account's
   tools, so `agentic` keeps all and `user`, `recurring` and `drip` keep none. `order_id`,
   `state` and `cursor` stay refused, never ignored. No answer shows the creation time: the
   contract does not list `orders[]`'s fields, and the connector's order record shape is closed
   (DEC-902 item 4).
3. **"All pages" is read as "a whole answer or none".** The contract takes a `cursor` but does not
   say how an answer names the next page. An answer holding anything beside `orders`, a cursor
   included, is unreadable, as the preflight's reads are (DEC-902 item 5): adopting from a first
   page could miss a second match and adopt an order that is not ours. A refused, lost or
   unreadable listing, or any record that is not exactly an order record whose `type` is
   `limit`, `market` or `stop_limit` and whose `time_in_force` is `gfd` or `gtc`, is
   `Unknown` (`Ambiguous`), so the order stays `Unknown` and blocks its instrument (trading
   spec §5.3 rule 9). Following a cursor waits for the founder's run to show the real member.
4. **`ref_id` in a record.** A record that carries our derived `ref_id` names our key; one that
   carries another `ref_id` names that text, which is never a key of ours, so it is never adopted;
   one with none names nothing, and DEC-863's look-alike rule decides.
5. **The run's clock (shell).** Once its startup reconciliation is clean or adopted, the shell
   steps its executor with `Input::Tick` at the run's injected clock (`Setup::now`, ES-21), so
   every record from the cycle on, the intent's `OrderSubmitted` included, carries the run's
   time, and a restart's listing starts five minutes before it. The startup records keep the
   journal's last clock, as before. Nothing reads a wall clock.

## Rationale

DEC-529 item 4 makes listing the only recovery for Robinhood, and an order left `Unknown` blocks
the instrument until the founder looks in the app. Without the mapping that is every lost answer;
without the clock the window either starts before the epoch, which no answer can honour, or would
have to be widened to the whole account history, which could adopt an older identical order the
lost one never was. Item 3 and item 4 take the readings that can only leave an order `Unknown`,
never adopt a wrong one. The tick is the one the watch already sends on its first wake; sending
it at the end of the start moves it before the cycle and changes nothing the gate or the
reconciliation reads.

## Alternatives considered

- Clamp a pre-epoch `created_at_gte` to the epoch: rejected, it lists every agentic order in the
  symbol the account ever had, so an older order with the same shape could be adopted in place
  of one that never arrived (DEC-176).
- Follow a guessed cursor member (`next_cursor`, `next`): rejected, a guessed name that is wrong
  reads as a whole answer and could hide a second match.
- Tick the executor before the startup reconciliation: rejected, the tick's own work (lookups
  due, held releases, overdue openings, the ladder) would run before the reconciliation it
  should follow.
- Map the instrument id to a Robinhood ticker here: out of scope; the connector sends the
  instrument id as `symbol` on every call, and the listing must use the same value as the place.
  A production run's instrument id is the broker asset's id, not a ticker, which the live wiring
  must settle before a Robinhood run places (reported with this decision).
