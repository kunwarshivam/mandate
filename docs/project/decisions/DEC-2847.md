# DEC-2847: The executor reads its hot streams only past the head it last read

| | |
|---|---|
| **Status** | Accepted (agent: a reversible engineering decision under DEC-79. It adds no risk: each record is read and verified once, the state it folds to equals a fold of the whole stream, and a read that fails holds as before) |
| **Date** | 2026-10-27 (UTC) |
| **Decided by** | an agent (Claude Code, lane D1), asked for by the coordinator on 2026-10-27 |
| **Story or claim** | The research executor's crash loop in lane DR's rehearsal cell, 2026-10-27. [DEC-2819](DEC-2819.md), [DEC-994](DEC-994.md) item 5 |

## Context

In lane DR's rehearsal cell the research workspace's executor was killed by its liveness probe
about once a minute from 14:14Z. The deployment manager restarted it each time, until it raised
`crash_loop`. The probe passes while a pass of the loop ends within `LIVENESS` (10 s). For a
research deployment, every port ask re-read every stream from Postgres, verified it from its first
record, and folded it again: the scheduler's clock stream (one record a tick, 2,841 by then) twice
per ask in `today` and `now`, and the agent stream in the thesis replay and `ever_admitted`.
A pass asks several times: for each mark, fill, exit and binding-gate input. So a pass cost grew
with the streams' length. Under the pod's 250m CPU limit it crossed 10 s after about 15 minutes,
and every restart started on the same long streams.

## Decision

1. **A read past the head.** The journal reads a stream from a trusted start: the records from
   a seq on, their chain checked from the hash the reader holds (`PgJournal::rows_from`, with
   `PgStore::rows_from` and `MemoryStore::rows_from` over it). A record whose `prev_hash` is not
   the held hash fails, so the read is as sound as a read from the first record.
2. **Kept folds.** The executor's deployment keeps, per stream, the seq and hash of the last record
   it read and what it folded:
   - the scheduler's clock, folded (`now`, and `today` from it);
   - the control stream's records;
   - each research agent stream's thesis records.

   Each ask reads only what follows the head. The thesis replay and `ever_admitted` run over the
   kept thesis records, so they cost what the agent's theses are, not the stream's length.
3. **Exactly the old reading.** Each kept fold is of one stream in its own order, so it equals a
   fold of the whole stream at every point. That includes the thesis replay DEC-2819 reads at
   every ask.
   - A read past the head that the store refuses is read again from the first record onto a fresh
     state, so a held head that is not the stream's is never folded on.
   - A read that fails gives what it gave before, with nothing read from the kept state.
   - The binding gate's fold of an opening's three streams still reads them whole, once per opening.
4. **What a kept fold does not see again.** A record already read is not checked again, so a
   rewrite of history the process has read is found on its next start or at a read the store
   refuses, not at every ask. A stream cut shorter than the held head reads as nothing new, so its
   kept clock stops, which holds openings and adds no risk. The runtime process verifies its tails again every minute
   ([DEC-2852](DEC-2852.md) item 6); the executor's tail follows in its own change.
5. **The probe stays.** `LIVENESS` stays 10 s, so a hung pass is still killed in bounded time, and a
   shorter pass never slows a kill switch.

## Alternatives considered

- **Memoize each stream once per pass.** A pass would still read and fold whole streams, so its
  cost would still grow with uptime and the loop would come back days later.
- **Raise `LIVENESS`, or heartbeat around each call.** Either hides the growth, and the second hides a
  hung pass from the probe.
