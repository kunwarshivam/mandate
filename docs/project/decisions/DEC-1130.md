## Context

The data-plane spec (v0.2, §4) and the agent harness spec (§6.3, §10.2) say what news and filings
the research agent may read and how, but nothing held the allowlist's contents (E2-19), there was
no news or filings store, and no reader. Lane I2 (the harness research loop) needs a typed read
behind a trait. Lane M2 (E2-6, #1453) owns the workspace data service and market data. Each item
below is a reading of those specs, not a change to them; no spec, schema, or reference case
changes here.

## Decision

1. **The allowlist is a file a version, and E17-7 holds its contents** (closes E2-19).
   `config/sources/allowlist-v<N>.toml`, whose `version` is `N`; a change is a new file, and a
   file on `main` is never edited. Each source has an id, a kind (`news` or `filings`), whether
   its text is licensed, whether counsel confirmed it, a minimum request interval, a response cap,
   and its endpoints, each an `https://` host and a path prefix. Unknown keys, version 0, a
   repeated id, a source with no endpoint, a zero cap, and a non-HTTPS endpoint refuse the file.
2. **A source is in effect only while `counsel_confirmed = true`** (DEC-433 item 20: allowlist only
   sources whose terms allow keeping what a thesis cited, as counsel confirms per vendor). An
   unconfirmed entry is listed for review, permits no fetch, gives no reader any item, and is
   absent from the `SourceAllowlist` admission check 14 reads. Version 1 confirms SEC EDGAR
   (public data, DEC-433 item 16) and lists Alpaca news **unconfirmed**. Confirming it is a new
   allowlist version and the founder's call (DEC-79: legal).
3. **Only the allowlist builds a URL a transport may send to** (DP-9, DEC-433 item 11). A
   `PermittedUrl` has a private constructor, `Allowlist::permit`; the `Transport` trait takes only
   that type. `permit` requires the source to be in effect, the scheme `https://`, the host equal
   to an endpoint's host, the path to start with its prefix (on a segment boundary when the prefix
   has no trailing `/`), and every byte after the scheme from `A-Z a-z 0-9 - . _ ~ / ? & = : , +`,
   with no `..` and no `//`. So `%`, `@`, `#`, `\`, whitespace, ports, and user info are refused,
   and nothing can be decoded into a traversal. The HTTPS transport follows no redirect, so a 3xx
   answer is a refused status, never a second host. No fetch takes a URL from an item. A vendor's
   page token may hold no `+` (a server decodes it as a space, and `%` cannot escape it here): a
   page whose token holds one, or anything outside the token's form, ends the paging, which reads
   fewer items, never other ones.
4. **Knowledge time** (data-plane spec §5.2, DEC-433 item 4): receipt for a live capture; for a
   backfill, the later of the item's published and updated times (news) or its acceptance time
   (filings). An item whose source time is more than 1,000 ms after its receipt is refused
   `future_dated` in either mode, the news and filings reading of §3.4's `future_skew_ms`.
5. **Bounds.** A response over its source's cap is refused whole. An item naming more than 32
   tickers is refused `too_many_tags`. Every structured field has a closed form (ticker, CIK,
   vendor id, accession number, form type, document name, page token), and one outside it refuses
   its item (`bad_field`); one bad item in a page is refused and counted, and the rest are kept
   (§3.1's rule). Stored text is capped (headline 1,000, summary 4,000, link 2,000, excerpt 8,000
   bytes), and reads apply the harness caps of §6.3: news 48 hours, 50 items, 2,000 bytes of text
   an item, headline first, then link, then summary; filings 7 days, 20 entries, 4,000 bytes an
   excerpt. A query's window and limit can only narrow them. A query naming an allowlist version
   other than the one in effect is refused.
6. **Licensed text is withheld from reads by default** (agent harness spec §6.2's third
   precondition, DEC-431 item 17). `LicensedText::Withheld` returns a licensed source's items with
   every typed field and no text, until the inference spec's prompt record keeps licensed text out
   of the artifact store; the harness switches to `Included` only then.
7. **De-duplication and story groups** (§4.4). An exact copy (same source, same SHA-256 of the
   item's raw bytes) is stored once. A later vendor version of a stored item is a new record that
   names its predecessor and joins its group; different content at the same or an earlier version
   is refused `revised_in_place` (DP-2). So an older version that arrives after a newer one, for
   example a backfill after a live capture, is refused and counted rather than stored: reads miss
   it between its knowledge time and the newer one's, which reads less, never the future. A news
   item's group is the digest of its normalized
   headline and summary (lowercased, whitespace collapsed), so syndicated copies share it; a
   filing's group is its accession number, so an amendment (`10-K/A`, its own accession) is a new
   record and the original stays readable as of any earlier time (DP-1). A one-character change
   to a headline splits a group, so a reworded copy still counts as a second source; closing that
   needs more than the spec's three keys, and E2-15 still owns making admission check 15 count
   groups.
8. **Persistence waits for M2.** Both stores are in memory and append-only, with raw bytes kept by
   digest before parsing (§4.2 step 2). Where records live in a cell is the workspace data
   service's (E2-6, lane M2); the stores move onto its storage interface once that is on `main`,
   rather than this lane adding a second one. The in-memory record also holds a bounded copy of
   each text field, derived from the raw bytes, so a read need not re-parse; data-plane spec §4.5
   keeps text only as the raw artifact, so when the records are persisted, only the raw artifact
   is, and the text is derived again at read.
9. **The drift observation is the item's typed record at its knowledge time** (data-plane spec
   §4.6, agent harness spec §6.3): source, class (`News` or `Filing`), knowledge time, content
   hash, and byte length, never text. Folding each item once is the harness core's (lane I2).
10. **Credentials.** The Alpaca news fetcher takes a `NewsAuth` the caller read from the
    workspace's `SecretSource` (lane V2, E21-32); nothing here reads an environment variable.
    V2's policy table has no identity for a news reader yet; that row is V2's to add when the
    fetcher is wired into a process.
11. **The order path cannot reach text** (DP-8). `mandate-sources` sits at layer 6, level with the
    executor and above the builder, the gate, and accounting, so none of them can depend on it
    (`xtask/layers.toml`); a test pins it. Text exists only as `UntrustedText`, which has no
    `Display`, `Deref`, or conversion, and whose `Debug` prints only its length. The HTTPS
    transport is a separate impure crate, `mandate-sources-http`, so the safety-critical core
    stays pure.

## Rationale

Every item narrows what the research agent can read or how a fetch can go wrong, and none changes
a gate rule, a limit, or the envelope. Item 2 is the conservative reading of a founder decision
whose condition (counsel's confirmation) has not been met. Item 6 is the harness spec's own
precondition, enforced in the reader rather than left to each caller.

## Alternatives considered

- **One allowlist file edited in place:** loses the version a thesis recorded; refused by the
  spec's "versioned configuration".
- **Allowlisting Alpaca news now:** DEC-433 item 20 asks for counsel's confirmation first.
- **A URL type built by the fetcher:** any caller of the transport could then send anywhere; the
  private constructor makes DP-9 unrepresentable instead of checked.
- **Persisting to Parquet here:** would duplicate M2's storage interface (E2-6).
