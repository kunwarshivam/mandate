# DEC-1142: `EvaluationRunRecorded`'s `theses_head` is a `digest`, not a `ref`

| | |
|---|---|
| **Status** | Accepted (agent: a reversible engineering reading under DEC-79; it resolves a defect in journal spec §9.18 by the reading that removes an impossible requirement and adds no risk, DEC-176) |
| **Date** | 2026-10-17 (UTC) |
| **Decided by** | The lane I4 builder (Claude Code), under DEC-79 and DEC-176 |
| **Story or claim** | E17-8; journal spec v0.50 §9.18; DEC-1002 item 7, DEC-1141; claim [#1463](https://github.com/kunwarshivam/mandate/issues/1463) |

## Context

Journal spec v0.45 §9.18 typed `EvaluationRunRecorded`'s `theses_head` as `[ref]`, with the
meaning "per agent stream read, the hash of the last record read". A `ref` (§9.2) is `sha256:` and
hex naming a stored artifact: it is listed in `artifact_refs` (§3), and §11 check 6 reads the
object back and re-hashes it. A record's hash is not a stored artifact. Registering the record
(DEC-1002 item 7) with the vectors of DEC-1141 showed the consequence: an evaluation record
verifies only if the evaluator also stores, under each head's digest, some object that hashes to
it, which no record hash can be. §9 already has the right type: `digest` (§9.13), 64 lowercase hex,
"an event's `hash` or `prev_hash` (§3)... It is not a `ref`: it names no stored artifact, so it is
not listed in `artifact_refs` and §11 check 6 does not read it".

## Decision

1. **The type.** `theses_head` is `[digest]`: per agent stream read, the `hash` (§3) of the last
   record read, in the same order as `theses_from` and `theses_to`. Rule 145 is unchanged.
2. **`artifact_refs`.** The heads are not listed in `artifact_refs`. Every other digest member of
   both §9.18 records stays a `ref` to a stored object.
3. **Where it lives.** Journal spec v0.50 §9.18; `control.py` types the member as the bare
   `digest`; the vectors' `backtest_records` section refuses a `sha256:`-prefixed head as
   `non_canonical` at its index and a head listed in `artifact_refs` as `artifact_refs`, and admits
   a draft whose `artifact_refs` leaves the heads out; `mandate-journal` follows in its code change.

## Rationale

The `ref` reading imposed a requirement no record can meet, so the record could never be appended
and verified; the `digest` reading removes it and loosens nothing a verifier relies on. A head is
checked against the journal itself: a verifier reads the record at `theses_to`'s position and
compares its `hash`, which §11 already proves by the chain. This is the type §9.13 gives every
other record hash (`prev_hash`, `to_hash`, `last_hash`), and DEC-1141's writer reading is
unaffected.

## Alternatives considered

- **Keep `ref` and store each head record's body as an artifact.** Rejected: the artifact's digest
  is the hash of its canonical bytes, not the record's chain `hash` (which covers the envelope and
  `prev_hash`), so the value would no longer be the head the meaning names, and the store would
  hold copies of records the journal already holds.
- **Drop `theses_head`.** Rejected: it binds the evaluation to the exact chain state it read, which
  `theses_to`'s position alone does not.
