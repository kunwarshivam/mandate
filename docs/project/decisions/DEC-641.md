# DEC-641: The grammar of the identity permission matrix, and ID-2 scoped to the rows it names

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-08 (UTC) |
| **Decided by** | The lane L1 builder agent, under DEC-79 and DEC-176: each item refuses at least as much as the matrix's plain reading and grants nothing new |
| **Story or claim** | E9-2 (claim #757), E9-12 item 2; [identity spec](../../specs/identity.md) v0.2 §4.2 |

## Decision

1. **Cells.** Each row of identity spec §4.2 is one permission. The **S** cell is blank (no
   step-up), `S` (every use), `S for invite` (only an invitation; deactivating or removing a
   member needs none), or `S for grant` (only a grant; removing a role needs none). Each
   principal cell is exactly one of: blank (denied); `✓` (granted); `own` (granted for the
   principal's own credential only, at the scope of any membership it holds that reaches that
   scope); `✓ (propose only)` (granted; confirming is its own row);
   `✓ (org)` (granted at org scope only); `✓ (not owner)` (granted, except that granting or
   removing the org owner role is refused `owner_role_reserved`). Any other text is a spec defect,
   and the ID-2 test fails on it.
2. **Column scopes.** OO, OA, and Bill apply only at an organization's scope, through an org
   membership; WA, Op, Ap, Vi, and Au only at a workspace's scope, through that workspace's
   membership (§4.1, no inheritance). Cl applies only in the one workspace its token names, and
   only while its user holds a membership there that reaches it and whose effective roles grant
   the same row. SA applies only in the workspaces it names, HC only in its own deployment's workspace,
   PO only in the workspace of a break-glass window in force. None of the four applies at org
   scope.
3. **Effective roles.** A membership reaches its scope when `active` or `cooling_off`, with its
   roles effective as §8.3 allows: a role still in its cool-off grants nothing. ID-2, ID-3, and
   the Cl column use this one wording.
4. **Inactive rows.** A row whose permission says it applies only if a Proposed decision creates
   its state (today: re-enabling a halted scope, DEC-437 item 21) is refused for every principal
   (`inactive_permission`) until that decision is accepted and the row's text edited.
5. **Leaving is a row.** "Leave: deactivate one's own membership" is granted to every member
   column, with no step-up, at the scope of the membership left (a workspace membership at the
   workspace's scope, an org membership at the organization's); the last-owner and last-admin
   rules still apply. §5.2 already lets a member leave; the row closes the gap of a grant made
   outside the matrix, and leaving only removes access.
6. **ID-2 is scoped to the rows the matrix names** (E9-12 item 2). An operation with no row and
   no mapping in workspace API §3.7 has no route until a row is added.

## Rationale

ID-2's test parses the matrix from the spec itself, so the cell texts need a closed grammar, and
the parser must fail on a cell it does not know rather than guess. Reading the client column as
bounded by its user's roles, and an inactive row as refused, only refuse more.

## Alternatives considered

- **Treat unknown cells as blank.** Silently hides a spec edit from the test.
- **Add rows for saving a draft, a backtest, and resolving a notice now** (E9-12 item 2's other
  option). New surface during a freeze; saving a draft is already the draft row.
