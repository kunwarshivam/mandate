# DEC-1021: The approval read model carries the order it binds

|---|---|
| **Status** | Accepted (agent: a reversible engineering reading under DEC-79 and DEC-176; it closes an unclosed contract by the reading that adds no risk) |
| **Date** | 2026-10-17 (UTC) |
| **Decided by** | `claude-code` (lane A1, claim [#1444](https://github.com/kunwarshivam/mandate/issues/1444)), under DEC-79 and DEC-176, at the request of lane W2 through the coordinator |
| **Story or claim** | E21-31 and E10-10 (the web app's Approvals screen, D5 and D6, lane W2); [workspace API spec](../../specs/workspace-api.md) §4.3; DEC-979, DEC-942 |

## Context

DEC-979's single approval read returns `ApprovalRequested`'s `content` object whole, and the inbox
returns none of it. The web app shows the bound order on both: instrument, side, quantity, limit,
the order's dollars, its purpose, its time in force, and its protection. Those members are journaled
in `content.action` and, from version 2 (DEC-942), `content.execution`; a client should not have to
know the event's versions to find them.

## Decision

1. **Every approval read carries `order`**, the list and the single read alike: from
   `content.action`, `instrument`, `asset_class`, `side`, `qty`, `limit`, `order_usd`, and
   `purpose`; from `content.execution` (version 2), `tif` and `protection` (`{stop, take_profit}` or
   `null`). A version-1 request has no execution plan, so its `tif` and `protection` are `null`.
2. **Values pass through as journaled**, decimals as their canonical strings; the server computes
   nothing, and the content hash still binds what the owner answers (API-12).
3. **Nothing else is added.** The request's `evidence` and `risk_impact` stay in `content` on the
   single read; the runtime writes `risk_impact` empty today, and no scorecard, profit estimate, or
   price target is ever added (DEC-126).

## Rationale

The bound order is the fact the owner approves; carrying it as one closed member lets the inbox show
it without the whole content object and keeps the client off the event's internal versions.

## Alternatives considered

- **Let the client read `content`.** It would tie the client to `ApprovalRequested`'s versions, and
  the inbox would need the whole content object for every row.
