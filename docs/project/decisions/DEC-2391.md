# DEC-2391: A thesis that ends sells its position

| | |
|---|---|
| **Status** | Accepted (agent, under DEC-176 and DEC-79: it only adds an exit, which `AGENTS.md` rules 2 and 13 never deny, and loosens no limit, approval, opening, or envelope field; number assigned by the coordinator) |
| **Date** | 2026-10-26 (UTC) |
| **Decided by** | `claude-code` (lane NE, news and exits), under DEC-176 |
| **Story or claim** | Product-flow map step 6, "Thesis exit"; E17-3's "removed to exits-only when a thesis is invalidated"; mandate spec v0.10 §2.3, §8.3, §8.6, MI-34; journal spec v0.86 §9.4, §9.22; agent harness spec §6.7 |

## Context

Mandate spec §8.6 removes an instrument when its thesis expires, is invalidated, or its lineage
retires. §6.1 lists a removed instrument as an origin of `discretionary_exit`, journal spec §9.1
gives `DecisionMade.exit_origin` the value `removed_instrument`, and the gate (`Origin::
RemovedInstrument`) and trading spec §9.1 accept it. But no rule says **when** the order builder
proposes that exit, or how much it sells:

- §2.2 says a removed instrument stays exits-only and that "model outputs are still requested so
  discretionary exits work", which leaves the position to §8.3's signal exit (c ≤
  −`exit_threshold`);
- the research agent's `ModelOutputRecorded` that admitted the thesis stays fresh until its own
  `expires_at`, so after an invalidation the combined exit conviction is unchanged, and nothing
  sells;
- §8.6 says the horizon is when "the position and its score end together", which only holds if
  the expiry sells.

On `main` the runtime's fold ignores `ThesisInvalidated` (`mandate-runtime` state.rs), and nothing
writes the account stream's `UniverseChanged` (`removed`). That record is the executor's E17-3
side, which is not built. So an agent that holds a position on an invalidated thesis keeps it
until the thesis's horizon, and then keeps it still.

## Decision

1. **§8.3 step 2 gains a first branch.** When an instrument's thesis has ended (item 2) and no
   fresh thesis for it has been admitted since, while the agent holds it and the version in effect
   leaves the universe unpinned, the order builder proposes a discretionary exit of the whole
   position less working exits:
   - at the bid within the collar, marketable inside the close window as the signal exit is
     (DEC-70);
   - with `exit_origin` `removed_instrument`, whatever c and b are, and with no model output
     needed at all;
   - with the agent's working opening orders in the instrument cancelled first (trading spec §5.3
     rule 5, as for the signal exit);
   - with no c, b, or s and no outputs, weights, or clips on its `DecisionMade` (journal spec §9.1
     rule 8), and exempt from §8.3 step 5's minimum order value, as a full close (trading spec
     §5.3 rule 2).

   The branch is checked first, so the instrument never reaches the entry branch, and it holds
   when the position less working exits is zero. It repeats at every evaluation until the agent is
   flat or a fresh thesis is admitted. A proposal the gate defers or the executor holds is one
   working exit, which the next evaluation subtracts, so it is never stacked.
2. **When the runtime knows a thesis has ended** (§8.6). A thesis is current for its instrument
   from the latest `ThesisProposed` or `ThesisRevised` with `admitted` `true` that names the
   instrument; this is what journal spec §9.22 rule 187 already lets an invalidation name. It ends
   at the first of these:
   - a `ThesisInvalidated` naming it;
   - the risk clock reaching its `expires_at`;
   - a refused thesis record with reason `lineage_retired` in its own lineage (a retired lineage
     never ends another lineage's thesis);
   - an account-stream `UniverseChanged` (`removed`) for this agent whose `thesis_id` is the
     thesis's, with a thesis reason. A late copy naming a superseded thesis ends nothing.

   All but the last are on the runtime's own agent stream, so the exit never waits for the
   executor's copy. Whichever arrives first ends the thesis, since an end only reduces risk.
3. **Only the thesis reasons sell.** `eligibility_lost`, `operator_halt`, and a version's removal
   from a pinned list keep §2.2's reading (exits-only, signal exits work). An operator halt says
   "exits and protection continue" rather than "sell", and a version removal is the owner's own
   change, made with the exit classification §9.2 already gives it.
4. **Treatment.** The exit is built-in AUTO and paced by the conduct controls. For equities it
   waits for the regular session (the gate's `defer`). It is never denied, except as
   `sell_exceeds_available` once the exits already allowed sell the whole position (DEC-410
   item 3, `AGENTS.md` rule 13). It is held only by mode `paused` or `stopped`, an `Unknown` order
   in the instrument, or the broker. New invariant MI-34 states this.
5. **A pinned universe** takes no such branch: a version that pins the universe makes the owner's
   list the universe, and the research agent is off (V-037).
6. **Re-admission.** A later admitted thesis record for the instrument makes that thesis current,
   and the branch stops proposing. Whether the instrument may be bought again is still the working
   universe's and the gate's (§2.3, §5.3), and `reentry_cooldown_s` applies.

## Consequences

- **Spec slice first.** This change is text only: mandate spec v0.10, journal spec v0.86 (no
  record or rule changes), and one sentence in agent harness spec §6.7.
- **The code slice follows:**
  - `mandate-runtime` folds the thesis records and `ThesisInvalidated` into each instrument's
    current thesis, and hands the set of ended theses to the order plan in `SignalInputs`;
  - `mandate-builder` adds the branch as a pure function;
  - `mandate-ports` sizes it with `ExitOrigin::RemovedInstrument`;
  - the daemon's production plan proposes it for an instrument the agent's fills hold.

  The tests come first, with property tests over random thesis, invalidation, clock and fill
  sequences, each checked by an independent oracle that is shown to catch a seeded bug.
- **Adversaries:**
  - A **bad model** that invalidates every thesis sells every researched position. That adds no
    risk; it can churn, but re-entry needs a fresh admission with corroboration and
    `autonomy.admission`, plus the re-entry cooldown, and the churn shows in the forward-paper
    scorecard (DEC-99).
  - A **bad tick** cannot price the exit below the collar.
  - An **outage** of the research agent changes nothing here: an ended thesis sells with no model
    output, and a live thesis is never ended by a missing output.
- **An invalidation now sells without approval.** A model's invalidation, which a news item or
  filing may prompt (prompt injection is the top technical risk, RAID R-05), now ends in an
  unapproved sale of the whole position. That only reduces risk (rule 2), so it is not a DEC-79
  matter, and it is disclosed here: the allowlist bounds what the model reads, the harness bounds
  what it can do (an invalidation only removes, HI-10), and the forward-paper scorecard shows
  the churn.
- **Residual risk:** a thesis whose instrument is removed for a non-thesis reason keeps the
  signal-exit reading (item 3), so a position under an operator halt is held until a signal or
  risk exit. That is deliberate and unchanged.
- **Two minors the independent review left, recorded rather than built:**
  - The executor's `lineage_retired` copy names the refused proposal's `thesis_id`, so only the
    agent stream's own retirement trigger ends that thesis. That trigger always comes first, so
    nothing waits on the copy.
  - A version that pins the universe and a later one that unpins it again leave an ended thesis
    ended, so the branch sells it again. That only reduces risk.
