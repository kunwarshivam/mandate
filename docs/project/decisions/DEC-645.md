# DEC-645: Identity test support at layer 11, the identity seal crate and its allowlist now, and mandate-tenant with E9-8

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-08 (UTC) |
| **Decided by** | The lane L1 builder agent, on the L1 lead's ruling (option (b) for the testkit), under DEC-79 and DEC-176: reversible engineering choices that close a seal sooner and loosen nothing |
| **Story or claim** | E9-2 (claim #757); I1-kit; DEC-642 item 7 |

## Decision

1. **`mandate-identity-testkit` sits at product layer 11**, above every product crate. A crate may
   then take it only as a dev-dependency, because `cargo xtask layers` requires a normal dependency
   to point to a lower layer, the precedent `mandate-rh-sim` set at layer 10 (DEC-124); the
   `dev_only = true` key this change adds to `cargo xtask layers` holds it there as well. It
   provides an in-memory `MembershipLookup` (`StaticLookup`), an
   outage (`FailingLookup`), and `session` and `membership` builders, so other crates' tests can
   call the real `authorize`.
2. **`mandate-identity-seal` lands now, and `allowed_dependents` with it.** The seal crate (layer 0,
   safety-critical, pure) holds the `Seal` token that `Session::new` and `Membership::new` take,
   and `LookupSeal`, the supertrait of `MembershipLookup`. A seal crate is closed only by its
   allowlist, so the `allowed_dependents` key and its check in `cargo xtask layers` land in the
   same change rather than with E9-8. Its list is `mandate-identity` and `mandate-identity-testkit`;
   `mandate-authn` and the workspace store join it when they are created.
3. **`mandate-tenant` waits for E9-8.** Nothing needs it before `SystemContext` exists, and until
   then `Tenant` stays sealed in a private module of `mandate-identity`, which no crate can reach.
   E9-8 creates it, with its own `allowed_dependents` list (`mandate-identity`,
   `mandate-identity-system`), and re-exports `Tenant` from `mandate-identity` at the same path.
4. **The ULID text codecs** (`to_ulid_text`, `from_ulid_text` on `PrincipalId`, `OrgId`,
   `WorkspaceId`, and `SessionRef`; `AssertionId` is text already, DEC-644 item 3) arrive as
   `Unimplemented` stubs with pending tests (DEC-77), implemented with I1's implementation.
   `to_ulid_text(self) -> Result<String, UlidTextError>` is the final signature. Once implemented,
   the encode never fails: every `u128` has a ULID text. It returns a `Result` only so that the
   implementation PR changes no signature and no test under DEC-77. The only error it can return
   is the stub's `Unimplemented` variant, which the implementation removes, leaving `Invalid`,
   which `from_ulid_text` alone returns.

## Rationale

L2, L4, and B3's tests need a `Session` and a lookup. The testkit gives them both without a Cargo
feature (features unify across a build) and without loosening the layer rule. Landing the
allowlist check with the first seal crate means no seal is ever open. Deferring `mandate-tenant`
keeps the `Tenant` seal closed until its own allowlist can hold it.

## Alternatives considered

- **Testkit at `layer = "tool"`.** `cargo xtask layers` refuses any product-to-tool dependency,
  dev-dependencies included, so it would need an xtask exception for every tool crate.
- **A `test-support` Cargo feature in `mandate-identity`.** Features unify, so a production build
  that also builds tests could see the constructors.
- **Create `mandate-tenant` now.** It would open the `Tenant` seal to any crate until E9-8's
  allowlist.
