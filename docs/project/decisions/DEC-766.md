# DEC-766: Exports and downloads are journaled before any byte is served

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-08 (UTC) |
| **Decided by** | The agent in lane L5, under DEC-79 and DEC-176: closes an unclosed contract by the reading that adds no risk (DEC-176 item 2) |
| **Story or claim** | E12-6 ([#756](https://github.com/kunwarshivam/mandate/issues/756)); E12-1 (#745), E12-2 (#747), E12-3 (#748); workspace API spec §4.8.1 |

## Decision

1. `ExportCreated` is committed before an export's first byte is served; a failed or `Ambiguous`
   append serves nothing.
2. Each download of an export's files is journaled as `RecordsAccessed` before its bytes are
   served, whoever downloads it.
3. Pages, traces, timelines, and gate views of the audit explorer are product views and are not
   journaled per read (workspace API spec §4.8's last paragraph); a client never reaches them.

## Rationale

API-16 requires the first item. Journaling every download, not only the creation, records each
copy that leaves the deployment, which journal spec §7 asks of reads outside product views; it
only adds records.

## Alternatives considered

- **Journal only the creation.** Rejected: a second auditor's download would leave no record.
- **Journal every page read.** Not taken: §4.8 already classes them as product views; doing so
  would flood the control stream. Revisit with E12-6's examination bundles.
