# DEC-408: #485's invariant: live exits and the rungs a ladder may still send never exceed the position

| | |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-02 |
| **Decided by** | The stream K builder (`claude-code`) under DEC-79 and DEC-176, on the coordinator's ruling on #468 (2(i)): it tightens rule 12's Σ check and weakens nothing |
| **Story or claim** | E7-4, issue [#485](https://github.com/kunwarshivam/mandate/issues/485), found on [#468](https://github.com/kunwarshivam/mandate/pull/468) |

## Decision

1. **The invariant.** After every input, the live non-protective sells at the broker, plus what
   every exit ladder between rungs may still send, sell at most the position (§5.3 rules 3 and 4,
   §5.6 step 2, rule 12). A ladder is **between rungs** from the confirmation of a step's cancel
   that leaves part of its rung unsold, until it sends its next rung for that part, or ends.
2. **The oracle counts it on its own record.** The rule-13 oracle in `protection.rs`'s
   `sequence_tests` follows each remainder from the drafts and the broker's answers, never from
   the fold:
   - **It starts** when the oracle confirms the cancel of a rung that was asked as a step
     (`ladder_step`) with part of it unsold.
     - A lone ladder (DEC-260 (14)) always starts one.
     - A sequence starts one only while its ladder still climbs: not paused, not stopped, and not
       past its interval's bound (`interval_limit`). A sequence that no longer climbs ends at
       that confirmation (DEC-409).
   - **It ends** at the exit's next rung, at the exit's abandonment, or at the instrument's
     `unprotected_end`, unless the exit was parked for the next open (DEC-260 (18)). A parked
     remainder outlives the protection's return.
   - **The check.** The remainders add to the live exits in a second Σ check, beside the existing
     check of every live order. A protective order is left out of the second, since the
     ladder's next rung cancels it first.
3. **No exit is refused for a remainder.** The oracle accepts a sized first rung only at the size
   its own count leaves, and never an order for nothing. It accepts the hold `exit_between_rungs` only while that count leaves
   nothing (DEC-410). A denial stays acceptable only for an over-sell against the live exits and
   the waiting ones, as before.
4. **The pending tests** are in `sequence_tests`, marked `pending E7-4` (the kill switch's
   `pending E7-3`). They are:
   - `a_risk_exit_beside_a_sequence_between_rungs_never_over_sells`: #485's minimal script, a
     rung stepped while paused.
   - `a_ladder_stopped_between_rungs_never_resumes_beside_a_new_exit`: the same, stopped.
   - `a_risk_exit_held_overnight_beside_a_parked_ladder_is_sized_to_what_is_left`: the parked
     route. It over-sells 12 against 10 with no pause at all.
   - `a_risk_exit_beside_a_parked_ladder_selling_everything_waits`: with nothing left beside
     the remainder, the new exit waits `exit_between_rungs`.
   - `a_risk_exit_at_the_open_beside_a_parked_sequence_is_sized_to_what_is_left`: a parked
     sequence that protection's return has not yet turned into a lone ladder counts too.
   - `a_restart_between_rungs_still_counts_the_parked_remainder`.
   - `a_refused_rung_leaves_its_remainder_to_the_next_exit`.
   - `a_kill_switch_between_rungs_never_over_sells`.
   - `rule_13_holds_over_random_scripts_from_between_rungs`: the oracle over random scripts that
     start from a rung stepped while paused or stopped, or from a parked ladder beside a held
     exit. Their tails include stops, refused rungs and restarts.

   The eight E7-4 tests fail on the oracle's count, not at a stub. Each is a named
   `BEHAVIOUR_ONLY_TESTS` row, which the fix deletes. The kill switch's test stops at E7-3's stub.
5. **Nothing is weakened.** The existing oracle's checks stand. No seed is pinned. The existing
   generator is unchanged: the new moves (stop, a refused rung, a restart, the kill switch) are
   drawn only by the new property and named scripts.
6. **The scripts' pauses are journaled.** A pause or a stop is committed as `AgentModeApplied`
   and folded, rather than set on the live state. So a restart, and the end-of-script refold,
   read the mode each decision was taken under, as DEC-409's fold needs. It is not stepped as
   an input, because the executor's reaction to a mode change is still E7-4's stub.

## Rationale

The rule-13 property found the over-sell while #468 was in review: a sequence that lingers between
rungs counted nothing in the gate's `available`. The coordinator ruled that the tests hold the Σ
with the remainders counted, so the invariant holds at every input rather than only once the
next rung is live. The parked route was found while writing these tests. It needs no pause, only
an exit held overnight beside a ladder parked at 20:00, so it is pinned by name too.

## Alternatives considered

- **Count only the live orders, as before.** Rejected: it catches an over-sell only once both
  rungs are live, and says nothing about the state that caused it.
- **Count every stepped rung's remainder until its next rung.** Rejected: the first draft of the
  oracle did this. It failed on every seed, because a sequence past its bound or paused at its
  step never sends its next rung. The oracle has to follow the ladder's own lifecycle.
