## Context

SP1 writes [DEC-529](DEC-529.md) and [DEC-531](DEC-531.md) into the trading, connections and
mandate specs. Three rows needed a reading that neither decision states. Each is taken the way
that adds no risk. One more gap is not a tightening, so it was left open (trading spec §15 q9) for
the founder, who decided it as [DEC-539](DEC-539.md).

## Decision

1. **Day-trading regime.** Robinhood's regime in trading spec §7.2 is `legacy_pdt` (§9.2, "generic
   brokers not yet transitioned"), because the published contract does not show Robinhood has moved
   to the intraday margin standard. A pattern-day-trading alert from `review_equity_order` also
   refuses an opening or an increase before the place. It never refuses a sell or a protective
   order: those are placed with the alert journaled, and the broker accepts or rejects them
   (`AGENTS.md` rule 13). `legacy_pdt` can only deny openings that `intraday_margin` would allow
   at 1×. It never denies an exit.
2. **Buying power on the attested account.** DEC-529 item 11's "the lower of cash and the broker's
   figure" uses §7.2's cash-account row (settled − reservations − accrued fees). That counts no
   unsettled cash, so it is never more than the margin-account row.
3. **Partial fills under one stop-limit.** On a profile with no OCO or bracket, the entry is
   protected once it fills completely (DEC-529 item 7). If it is not complete within
   `bracket_partial_fill_timeout`, or ends partly filled, the executor cancels the remainder,
   confirms, and places the stop-limit for the filled quantity, as §5.4 does for a bracket. This
   bounds the unprotected interval, which DEC-529 left open.
4. **The stop-limit's limit price stays open.** `crypto_stop_limit_offset` is defined only for
   crypto (mandate spec V-008, W-002). Choosing a limit for an equity stop-limit trades fill
   likelihood against price, so it is not a tightening. Until the founder decides, no equity
   mandate deploys on a profile whose only protection is a stop-limit (principle 3). This blocks
   DEC-529's order until it is decided. **Resolved by [DEC-539](DEC-539.md)** (founder,
   2026-10-08): one general `stop_limit_offset`, which V-008 requires wherever the profile protects
   with a stop-limit, so the refusal now falls only on a mandate that leaves it null.

## Rationale

Each reading either refuses more or protects sooner. None loosens a rule for any broker, and none
changes an Alpaca outcome or a reference case.

## Alternatives considered

- **`intraday_margin` for Robinhood:** no evidence that Robinhood has moved to it. Rejected until
  Robinhood confirms.
- **The margin-account row on the attested account:** it counts unsettled cash. Rejected as the
  looser reading.
- **Reusing `crypto_stop_limit_offset` for equities:** it changes the mandate schema's meaning and
  W-002's worst-case loss, so it is the founder's call (item 4).
