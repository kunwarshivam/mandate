| | |
|---|---|

| **Date** | 2026-10-06 (UTC) |

## Decision

This amends [DEC-182](../04-decision-log.md)'s presentation of A0 and A1, and [DEC-472](DEC-472.md)
item 1's "three questions, or a description". The compiler's contract (mandate spec §7) and the
review's rules are unchanged: every value is the owner's or a labeled proposal, nothing is active
until its section is confirmed, and A5 is the record.

1. **A0 to A2 are one conversation at `/agents/new`.** The platform asks one question at a time:
   the money, what it is for, the loss the owner could stand, the symbols, the model, and each of
   the model's settings. The owner may answer one question or say everything at once; the
   conversation asks only what is still missing. The questions carry no example amounts or
   returns. Once money, goal and loss are known, the draft appears in the conversation (the
   contract card and the Not enforced list), followed by one section at a time, each with its own
   Confirm section button. The owner can change any answer by saying so; a change unconfirms the
   sections it touches, shows the draft again, and asks those sections again. When all five are
   confirmed, Review and confirm opens A5 as before.
2. **A model reads the owner's words.** Each message goes to the compiler's model, with what the
   conversation last asked. Its answer is untrusted JSON.
3. **The model only points.** It returns readings `{field, quote, value}` and nothing else.
   `validateTurn` (`web/src/components/new-agent/compiler.ts`) keeps a reading only when:
   - its quote appears verbatim in the owner's latest message, and
   - the deterministic readers the draft uses read the same value back from the quote.

   Any other reading is dropped. The model can name only money, loss, goal, symbols, model, and a
   model setting. Autonomy, delegations, the environment, the connection, and every limit are
   outside its vocabulary (V-022). A symbol counts only as a whole word the owner wrote, so a
   company name never becomes a ticker (V-038). A model counts only when the owner named it, and a
   setting only when the owner wrote its value.
4. **A value the owner wrote in words is a question, not a value.** "About three grand" becomes a
   card, "We read “about three grand” as $3,000.00, the money it may use. Is that right?", with Yes
   and No. Nothing is kept until the owner answers Yes. No asks for the amount in figures.
5. **The account's rules apply when a value is said, and again when a section is confirmed.** A
   loss above the workspace ceiling or the money, more money than the account has free (V-002), a
   symbol another agent trades (V-006), and a setting out of its range are each refused in the
   conversation, with the reason. The value is never moved to fit. The runtime repeats V-002 and
   V-006 at application (DEC-472 item 3).
6. **The model's replies are quotations, and deterministic code draws every action.**
   - **Quotations.** A reply is shown under "The model said", as a block quote, never with a
     button (PX-18).
   - **Advice is withheld.** A reply that reads as advice (recommends, predicts, or promises) is
     withheld whatever the prompt said, and the conversation says so (DEC-52).
   - **A malformed answer fails whole.** None of it is used, and the conversation says "We could
     not compile this." (brief A2's error state).
   - **A model that does not answer** shows "The model did not answer." with Try again and "Read it
     without the model". Without the model, the conversation reads figures only, through the same
     guard.
   - **Loading.** While the model reads, the composer shows "Reading your words…" and takes no
     second message.
7. **Proposed for the founder: which real model reads the words, and how it is reached.** Today a
   fixture model stands in. It is fixed rules over the owner's words, with no network and no key.
   It answers in the same JSON, through the same guard, after 650 ms. The composer says so: "In
   this workspace a fixture stands in for the model, and nothing leaves this page." A real model
   needs choices that DEC-79 reserves for the founder:
   - **Route.** Through the gateway (E15), or an interim server route. The inference spec allows
     neither yet. Only the gateway calls models, with provider keys in the vault (INF-14). And until
     the journal names a stream for the compiler's call record (DEC-432 item 19), the compiler makes
     no call through the gateway (inference spec §6).
   - **Spend.** The pinned model and its spend cap.
   - **Data terms.** The owner's words would leave the deployment for a model provider.

   Until the founder decides, the fixture stays, and nothing leaves the page. Swapping in a real
   model changes only the `Compiler` passed to `NewAgentFlow`; the guard and the conversation stay
   as they are.

## Rationale

- **The founder found the forms confusing.** Owners expect a chat, as in the assistants they
  already use. One conversation removes the choice between "answer three questions" and "describe
  it yourself", and a chat asks only what is missing.
- **A model reads intent better than a regex, but it must not author the mandate.** Making the
  model point at a quote, and re-reading the value from that quote deterministically, keeps rule 4
  (opinions, never orders) and rule 11 (the owner sets the envelope) with no trust in the model's
  numbers. A model that invents an amount, a symbol, or an autonomy grant has the reading dropped,
  not shown.
- **Asking back about words, never guessing.** Reading "about three grand" as $3,000.00 is a
  model's interpretation, so the owner confirms it. Figures are read exactly as written.

## Alternatives considered

- **Let the model fill the mandate fields directly, then show them for review.** Rejected: the
  model would author envelope values, and a confident wrong number reads like the owner's (rules 4
  and 11, V-022).
- **Keep the forms and add a chat beside them.** Rejected: two paved paths for one task, and the
  founder's point was that forms confuse.
- **Call a provider directly from a Next.js route now, with a key in Cursor Secrets.** Not taken: it
  bypasses the gateway the inference spec requires (INF-14), journals no call, and spends money.
  Item 7 puts it to the founder.

## Not covered

- Journaling the compiler's call as `ModelInvocationRecorded` (DEC-432 item 19).
- Editing a proposed limit by saying so (brief A3). The conversation changes only the owner's own
  fields: money, goal, loss, symbols, model, and settings.
- The A4 warnings are still not shown (DEC-472).
