# DEC-1016: A runtime process reads its connection and approvers from its agent's mandate document

## Context

A pod the deployment manager starts names only its workspace and agent (DEC-1015). The rest of the
deployment is in the journal: the latest `AgentDeployed` of the agent names its mandate version,
the hash of the stored canonical document, and `AgentDeployed` never restates the connection
(journal spec §9.2). The document gives the connection and the approvers. The version's creator is
the user who journaled its `MandateVersionCreated`. Lane S provides the cell's shared artifact
store, read-only to the runtime, at `MANDATE_ARTIFACTS`.

## Decision

1. **A launch with neither `--connection` nor `--owner` resolves both.** It reads them from the
   workspace's control stream and the artifact store at `MANDATE_ARTIFACTS`. A launch naming only
   one of the two refuses `deployment_missing`. A fixture run naming neither cannot resolve,
   because its journal is in memory, and refuses `deployment_unresolved`, as does a launch with no
   store named.
2. **The store must already be one, and is only read.** The process opens it with
   `FsArtifactStore::open_existing`, which creates nothing, not even the temporary directory a
   writer needs. A root without its `sha256` directory refuses `artifact_store_unavailable`, and a
   read-only mount without `tmp/` still reads.
3. **The latest deployment decides.** The latest `AgentDeployed` or `AgentStopped` of the agent,
   among the control rows of the process's environment, decides. Stopped or never deployed refuses
   `agent_not_deployed`, and a redeployment runs again. A record of either type that cannot be read
   refuses `control_unreadable` rather than being skipped for an older one, so a stopped agent never
   starts on the deployment before its stop.
4. **The document must be whole and of the process's environment.** A document that is missing,
   does not re-hash to its version, or does not parse as a mandate refuses
   `mandate_document_unavailable`. One for another environment refuses
   `mandate_environment_mismatch` (`AGENTS.md` rule 8).
5. **What is taken.** *(Amended by [DEC-2388](DEC-2388.md) item 11: the approvers now resolve
   through `mandate_identity::approvers`, as the shell's and the executor's do, so a `role:`
   approver resolves among the workspace's members and a `user:` one only to a member; this
   item's reasoning that leaving roles unresolved "can only make an approval harder" no longer
   applies.)* The connection is the document's `connection_id`. The approvers are its
   `autonomy.approval.approvers` named as `user:`. A `role:` approver is not resolved against the
   workspace's members here, and an approver set without it can only make an approval harder to
   grant, or a quorum harder to meet. The deny-all wiring never asks anyway. The author is the user
   actor of the version's first `MandateVersionCreated` in the process's environment, so a later
   creation of the same document by another user never makes the true author independent of their
   own mandate. None, or a non-user actor, refuses `mandate_author_unknown`.
6. **The connection's own state is not checked here.** Whether the connection is established,
   revoked, or suspended reaches the runtime through its account stream (DEC-1014), and every
   order still meets the executor's gate (`AGENTS.md` rule 1).
7. **The resolution is read once, at the start.** A redeployment to a new version reaches a
   runtime only when a new process starts.

## Rationale

The journal and the documents it names stay the one source of a deployment. The manager passes
ids, and a runtime cannot start against a connection its deployment does not name. Resolving roles
against membership, and the rest of the production `MandateView`, belong to the post-R0 wiring.

## Alternatives considered

- **Treat a `role:` approver as its members now.** That needs the identity fold of the workspace's
  membership, which is the production view's (P5).
- **Create the store if it is missing.** A wrong root would then start a runtime on an empty
  store, which hides the misconfiguration.
