# Dependency registry

Every direct dependency of a workspace crate or Python project needs a row here, added in the same
change that introduces it ([ADR-0001](adr/0001-engineering-setup.md) ES-14). `cargo xtask deps`
fails on any direct dependency without a row, which also blocks misspelled or invented package
names. This file is founder-owned (CODEOWNERS): adding a row is the approval.

A cargo row's "Used by" cell is always `` `cargo xtask deps --used-by` ``, which lists every cargo
dependency with the crates that use it, derived from `cargo metadata`; the check refuses any other
text there, and a name with two rows in one ecosystem ([DEC-2600](project/decisions/DEC-2600.md)
item 4). So a PR that adds a crate edits no existing row's list, and two PRs that add two rows
never touch the same line. Say what a crate uses a dependency for in its Purpose cell only when the
use is new.

Safety-critical crates may also use only the external crates listed in their `allowed_external`
entry in `xtask/layers.toml`.

The web app's npm rows (`web/`, DEC-200) are one summary row per top-level framework. A row also
covers the packages that framework's standard setup installs with it (TypeScript and ESLint with
Next.js, `react-dom` with React, Testing Library with Vitest, and the `radix-ui`,
`class-variance-authority`, `clsx`, `tailwind-merge`, and `tw-animate-css` packages
the shadcn/ui components import); any other npm package needs its own row. `cargo xtask deps` reads only the
cargo and python rows, so the npm rows are reviewed, not machine-checked; `web/package-lock.json`
is the exact record.
