# Harness research memo: HybridAgent and the state of the art, applied to the Mandate agent harness

Date: 2026-10-17. Input to lane AH (ADR-0005, agent-harness spec v0.2). This memo is research only: no repository file was changed. Design read first: `docs/adr/0005-agentic-harness-design-input.md` and `docs/specs/agent-harness.md` on `claude/gallant-mccarthy-a3qgpx`.

## Executive summary

- **HybridAgent changes nothing for the 10-26 demo, and its latent mode conflicts with our audit model.** It is a post-training recipe for open-weight models (Qwen3 8B/14B, 8 to 32 H100s). Its "directly inspectable" latent thoughts are nearest-token projections of hidden vectors, scored by cosine similarity and word overlap. That is a lossy readout, not a faithful record. Its auditability study measures how well the *visible text* supports monitoring, on math problems. We can use two of its ideas now, both already close to our design: keep every action and decision in text, and record the exact rollout so replay needs no model.
- **The design's core matches what the field has converged on.** A small typed tool set, deny-before-allow permissions, gates the model can't override, a journaled transcript, and verdicts fed back to the model are what Anthropic's agent and tool posts, Claude Code's permission system, and CaMeL-style "security by design" all recommend. Most of the recommendations below sharpen the design rather than change it.
- **The biggest gap is prompt injection in a multi-turn loop.** Once the model chooses its own reads, untrusted text can steer later tool choices, the owner questions it asks, and the memory it writes for the next run. Cheap fixes: a fixed tool menu per run kind, set before anything untrusted is read; provenance taint on every action and every owner-facing text; spotlighted tool results; and corroboration computed by the platform, independent of what the model chose to read.
- **Evaluating LLM trading is mostly contaminated.** 2025 and 2026 work (Profit Mirage, Temporal Leakage, HindsightBench, FINSABER, StockBench, LiveTradeBench, Alpha Arena) shows that backtested LLM returns evaporate past the training cutoff, that "before vs after cutoff" checks are uninformative, and that 2026 models infer the date and use what they know about the period. Our "forward paper only" rule (DEC-99) is right. Scenario suites replayed with a live model must grade mechanics and safety only, never judgment.
- **Don't adopt:** multi-agent bull/bear debate as risk management, code-execution actions (CodeAct), models that output allocations or leverage, self-rewriting prompts, and agentic RL or post-training. Each either breaks an invariant (the model sizes, the envelope moves, replay without a model) or adds no guarantee that the risk gate doesn't already give.

## 1. HybridAgent (arXiv 2610.18861)

**Source.** Zou, Qi, Chen, Bianchi, Zhu, Lu, He, Zou. "Hybrid Reasoning Agents", arXiv:2610.18861v1, 13 Oct 2026, CC BY 4.0. I read it at https://arxiv.org/abs/2610.18861, plus the HTML and PDF fetched through the proxy. The README is at https://github.com/togethercomputer/HybridAgent (MIT license).

**What it does.**

- **HybridLink.** A roughly 10M-parameter, two-layer residual MLP. It maps the last-layer hidden state back into the input-embedding space, so the model can feed its own hidden state forward as the next input rather than decoding a token.
- **Latent vs text modes.** In text mode the model samples tokens as usual. Emitting `<latent>` switches to latent mode: recurrent forward passes through HybridLink, with no decoding. The mode ends when the hidden state's nearest token embedding is `</latent>`. Tool calls, final answers, and "key steps" stay in text, and the model learns where the switches go.
- **Working memory.** Multi-turn context is carried as the KV cache itself (text, latent, and tool observations). Latent spans have no token form, so the context cannot be rebuilt from a transcript. The paper proves the KV continuation is lossless, given the same weights, settings, and random draws.
- **HybridSFT.** Text agentic trajectories are converted to hybrid ones, with steps assigned to latent mode by LLM judges and model entropy. Training then runs in stages: format SFT, HybridLink alignment (cosine plus magnitude loss), and a "self-conditioned" two-pass pass. The README recommends 8 to 16 GPUs.
- **HybridRL.** GRPO-style RL in which only sampled text positions carry likelihoods; the paper proves the policy factorizes over them. The update uses "exact rollout replay": the recorded latent vectors are fed back unchanged. The reward is correctness, plus a format penalty, plus a multi-tool bonus. The default launcher assumes 32 GPUs.
- **Results.** Three scales (4B, 8B, 14B) on 11 benchmarks (GAIA, WebWalker, HLE, SealQA, DSQA, AIME25/26, MATH500, GPQA-D, MedQA, MuSiQue). The paper reports a 10.4% gain over matched text RL baselines, 35.5% to 54.7% fewer tokens, 1.8× to 2.6× faster inference, and 2.7× to 3.7× lower cost. The 14B model averages 52.4 on GAIA, against 43.7 for ARPO and 37.9 for GPT-5.6-Luna in their table. The causal interventions are convincing: swapping in another problem's latents cuts MATH500 accuracy by about 45%, so the latents carry real computation.

**The inspectability claim, read closely.**

1. **Readability is a geometric proxy.** Appendix F defines it as the mean of the maximum cosine similarity between each latent vector and any vocabulary embedding, compared against Gaussian noise. "Context specificity" is Jaccard overlap of content words with the question, relative to other questions. Neither measures *faithfulness*, meaning whether the pseudo-text explains what the computation did. A vector can sit near the token "revenue" and still encode much more. The paper itself says that variants without self-conditioning produce "largely unreadable artifacts of the embedding geometry".
2. **The auditability study leaves latents out.** Table 7 hides the latent spans and asks whether the *visible text* still supports monitoring, debugging, and correction. On MATH500 and AIME it does: AUROC is within 0.022 of a text agent. That shows the text channel stays useful. It does not show the latent channel is auditable.
3. **The paper's own deployment story keeps latents away from the customer.** Section 8 says latents are "readable solely through the provider-owned HybridLink", which hides proprietary reasoning from clients while the provider monitors it. For a hosted closed model, that is exactly what we can't use: our audit must not rest on a trace that only the provider can read.
4. **Replay needs the exact weights and kernels.** Their proof needs identical weights, settings, and random draws. Our replay (INF-10) folds recorded outputs instead, the right contract for any architecture.

**What applies to us.**

| Use | Idea | Why |
|---|---|---|
| Now | Text is the channel for actions, decisions, and the owner. Treat hidden reasoning as non-evidence | The same split as their design, and the same situation as today's hosted reasoning models, whose reasoning tokens are hidden, summarized, or encrypted. The transcript view shows what it read, proposed, and was decided, never "why it really thought so" |
| Now | Record the exact rollout so it can be replayed | Their "exact rollout replay" is our INF-10: record, never re-derive |
| Now | Pin the serving regime | The same lesson appears in HindsightBench below: quantization and reasoning mode change behavior. We already pin quantization (INF-2). We should also pin reasoning on/off and effort |
| Later (if we host open weights) | Cheaper, faster research runs at 8B to 14B | Needs self-hosting, a training budget, and its own forward paper evaluation (DEC-431 item 16). Even then, latent spans only between journaled text tool calls, with the latent vectors journaled as artifacts |
| Never (for v1) | KV cache as the system of record, latent working memory, latent agent-to-agent messages | Breaks HI-2/HI-24. A KV cache can't be canary-scanned (HI-11) or screened for licensed text (HI-23), or replayed without the model |
| Never | HybridRL or any RL on our trading outcomes | We don't post-train, and an RL reward on P&L would optimize directly against the forward-evaluation rule (DEC-99) |

## 2. Other sources

URLs and dates are as published. "Not accessed" means I relied on secondary coverage.

**Anthropic, "Building effective agents"** (https://www.anthropic.com/engineering/building-effective-agents, 2024-12-19). Prefer workflows where steps are predictable, keep it simple, make tools "poka-yoke", and use stopping conditions. *Relevance:* it supports the one-call run as a fallback.

**Anthropic, "Writing effective tools for agents"** (https://www.anthropic.com/engineering/writing-tools-for-agents, 2025-09-11). Consolidate and namespace tools, truncate with guidance, write "specific and actionable" errors, and evaluate tools on held-out tasks. *Relevance:* the template for verdict feedback and size caps.

**Anthropic, "Effective context engineering for AI agents"** (https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents, 2025-09-29). Context rot, just-in-time retrieval, compaction, structured notes, and subagents that return condensed summaries. *Relevance:* compaction, memory, and subruns.

**Anthropic, "Effective harnesses for long-running agents"** (https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents, 2025-11-26). Progress file plus git history, and a JSON feature list in which the agent may only flip `passes`. *Relevance:* the model for `RunSummaryRecorded`; the lesson is the structured, mostly immutable form.

**Anthropic, "Demystifying evals for AI agents"** (https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents, 2026-01-09). pass^k for consistency (75% per trial is about 42% at pass^3), grade outcomes over paths, isolate trials, "read the transcripts". *Relevance:* confirms safety at pass^k, graded from the journal.

**Claude Code docs: permissions, hooks, subagents** (https://code.claude.com/docs/en/permissions, /hooks, /sub-agents, read 2026-10-17). Rules are evaluated deny, then ask, then allow. A bare-tool deny *removes the tool from the model's context*. Bash rules are "not a security boundary"; the sandbox is. Hook exit 2 blocks even if the JSON says allow; a timed-out hook does not block unless `onFailure: block` is set. Subagents get their own tool allowlists, and only their final result returns; reports are scanned for instruction-like text. *Relevance:* remove tools a run may not use rather than refusing them; fail closed; subruns get read-only tools.

**OpenAI, "Harness engineering: leveraging Codex in an agent-first world"** (https://openai.com/index/harness-engineering/, 2026-02-11, Ryan Lopopolo). **Not accessed** (openai.com returned 403 through the proxy). Secondary coverage (InfoQ, noze.it): AGENTS.md as a map, invariants enforced by custom linters. *Relevance:* mechanical enforcement over prompt rules. OpenAI's Codex agent-loop post was also blocked.

**ReAct** (arXiv:2210.03629, 2022-10-06) and **Reflexion** (arXiv:2303.11366, 2023-03-20). Interleaved reasoning and acting, and verbal self-critique stored as episodic memory without weight updates. *Relevance:* ReAct is our loop. Reflexion is a cheap "learn from outcomes" mechanism: post-mortem notes in memory. It is safe only if the notes can't change the envelope or the pinned prompt.

**Toolformer** (arXiv:2302.04761, 2023-02-09); **CodeAct** (arXiv:2402.01030, 2024-02-01); **Search-R1** (arXiv:2503.09516, 2025-03-12); **ReTool** (arXiv:2504.11536, 2025-04-15); **Agentic RL survey** (arXiv:2509.02547, 2025-09-02). *Relevance:* why hosted models call tools well. CodeAct contradicts HI-4; the RL methods need post-training.

**TradingAgents** (arXiv:2412.20138, 2024-12-28). Analyst, bull and bear researcher, trader, and risk-team agents debating. Its gains are reported on a Jan to Mar 2024 window for a few large-cap tech stocks, inside the training window of the models used. *Relevance:* it is a popular template, but its "risk management team" is an LLM opinion, not a constraint.

**FinMem** (arXiv:2311.13743, 2023-11-23); **FinAgent** (arXiv:2402.18485, 2024-02-28); **FinRobot** (arXiv:2405.14767, 2024-05-23). Layered memory, reflection, financial chain-of-thought. *Relevance:* memory structure for `memory.theses`; results are short, leakage-exposed backtests.

**FINSABER** (arXiv:2505.07078, 2025-05-11). Over two decades and 100+ symbols, the reported LLM advantages "deteriorate significantly". The strategies are too conservative in bull markets and too aggressive in bear markets. **StockBench** (arXiv:2510.02209, 2025-10-02). In a contamination-free multi-month test, most models fail to beat buy-and-hold. **LiveTradeBench** (arXiv:2511.03628, 2025-11-05). In 50 days of live trading with 21 LLMs, high LMArena scores don't imply good trading.

**Alpha Arena Season 1** (nof1.ai, 2025-10 to about 2025-11-03). Six models, $10k each, live crypto perpetuals on Hyperliquid, with models choosing size and leverage. Qwen3 Max was reported at +22% and GPT-5 at about -63%; four of six lost money. **Primary results page not accessed** (only the nof1.ai homepage loaded, which says current LLMs are "shockingly bad at navigating financial markets"). Figures are from secondary coverage (forklog, gncrypto). *Relevance:* it is the cautionary tale for letting the model size orders: 17 days, one regime, no limits.

**Look-ahead and leakage, 2023 to 2026.** Glasserman and Lin (arXiv:2309.17322, 2023-09-29): anonymizing company names counters both look-ahead bias and a "distraction effect". Profit Mirage (arXiv:2510.07920, 2025-10-09): backtested returns of LLM trading agents vanish past the knowledge window. Look-Ahead-Bench (arXiv:2601.13770, 2026-01-20). FinCAD (arXiv:2605.24564, 2026-05-23): in-sample return corrections of up to -67%. **HindsightBench** (arXiv:2607.18867, 2026-07-21): 2026-generation models show a "date-trigger reflex", using knowledge of the period once given a date. Effective cutoffs precede vendor-stated ones by up to eight months, and results change with serving quantization and the reasoning regime. **Temporal Leakage in LLM Backtesting** (arXiv:2608.02985, 2026-08-04): the before/after-cutoff check is provably uninformative; you need a matched clean control. *Relevance:* our HI-13 controls the knowledge time of *retrieved* data, but not the model's *parametric* knowledge.

**Prompt-injection defenses.**

- **Dual LLM** (Willison, https://simonwillison.net/2023/Apr/25/dual-llm-pattern/, 2023-04-25): a privileged model never sees untrusted text; a quarantined model processes it into opaque variables.
- **Spotlighting** (arXiv:2403.14720, 2024-03-20): delimiting, datamarking, or encoding untrusted text cut attack success from over 50% to under 2% on GPT models.
- **AgentDojo** (arXiv:2406.13352, 2024-06-19): 97 tasks and 629 security cases; attacks break some properties, and defenses help only partly.
- **CaMeL** (arXiv:2503.18813, 2025-03-24): extracts control flow from the trusted query, puts untrusted data through a quarantined model, and attaches capabilities to values. It solves 77% of AgentDojo tasks with provable security, against 84% undefended.
- **Design Patterns for Securing LLM Agents** (arXiv:2506.08837, 2025-06-10): action-selector, plan-then-execute, map-reduce, dual LLM, code-then-execute, and context minimization.

*Relevance:* we already have the strongest property (actions are proposals judged by code); these address the remaining channels.

**τ-bench** (arXiv:2406.12045, 2024-06-17) and **τ²-bench** (arXiv:2506.07982, 2025-06-09). Grade final state, not words; pass^k (gpt-4o pass^8 below 25% in retail); τ² adds a user who also acts. *Relevance:* scenario grading from the journal; an owner-simulator for the desk.

## 4. Open questions

1. **Hidden reasoning.** For the pinned OpenRouter model, are reasoning tokens returned, summarized, or withheld? If they are withheld, the transcript view needs explicit wording ("the model's internal reasoning is not visible to us"). That wording is compliance text, so it is reserved for the founder.
2. **Does verdict feedback create Goodhart pressure?** A model that sees `not_corroborated` can learn within a run to propose only names that pass admission. That biases ideation toward what is easy to corroborate. Should admission rate be excluded from quality metrics?
3. **Model-chosen reads and corroboration (recommendation 4).** Is a fixed platform corroboration retrieval acceptable for the demo, or does admission stay `ask` until E17-7 lands?
4. **How large is k for safety pass^k, and at what cost?** Under the $50 cap most trials must use recorded or double models.
5. **Should owner runs be the only source of `propose_mandate_change`?** This memo recommends it (recommendation 2). It narrows ADR-0005 §5, so it needs a DEC. It tightens a rule, so an agent may take it under DEC-176.
6. **Parametric look-ahead.** Forward paper is clean, but runs over *older* filings still meet the date-trigger reflex. Is that only a quality risk, or does it touch the HI-13 claim we make to owners?
7. **Not verified:** the Alpha Arena primary figures, and both OpenAI posts (blocked). Re-check them before quoting any in external material.
